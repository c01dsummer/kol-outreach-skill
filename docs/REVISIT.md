# 回访说明书

> 回访例程照这一份做。例程本体在需求所有者的 claude.ai 账户里，它的 prompt 只有一句「克隆 c01dsummer/kol-outreach-skill 后读 `docs/REVISIT.md` 照做。」——
> 规则只在这里，不在 prompt 里，也不在 `.github/` 下（转发文件不装内容）。
> 为什么有它、各条归哪一档：ADR-151。台账本身，以及每一块里定死不改的那两行：ADR-152。

---

## 能写什么

- **只写两处**：每一跑在回访台账 ADR-152 末尾追加一块，开一条只改这一个文件的 PR，台账里已有的块一个字不改；
  「候选句」两道门都过了、起草了的那一跑，另开一条 PR 新开一条记录，只改那个新文件与索引里它那一行。
  另外只做一件事：关掉过期的上一条回访 PR（「每次开始」第 3 步）。
- **永不改** `process/`、`scripts/`、`docs/requirements.json`、`.github/workflows/check.yml`；既有的记录除了往 ADR-152 追加，一律不碰，别的文件也不改。
- **不替人下结论**：不给任何记录写「采纳」，不标欠条已还，不判死亡条件（ADR-80、ADR-86、ADR-151 第四节第 2 条）；
  「候选句」那条新记录的结论照那里写「接受为已知缺口」：它只说这一类还没有通用句，搬不搬由人定。
  不合并、不批准自己的 PR，每一块、每一条候选句记录都由需求所有者合（ADR-151 第三节第 5 条、第一节 P7）。
- **台账的候选只从本文写明的来源取。** 本文写了几个来源，就只从那几个取；现在只有一个：「周一」的 (b)。
  一条都没挑出来时，候选表只有「无候选」一行。这一块照样要写，它是心跳。

## 日期、「本跑」与 PR

- **日期**一律取北京时间的当天：`TZ=Asia/Shanghai date +%F`。分支名、块标题、候选 id 都用它。
- **本跑**是这次克隆到的主干提交：`git rev-parse --short=7 origin/main`。
- **一天只开一条**：分支 `claude/revisit-<日期>`；这个分支名的 PR 已经有了，就停下，不开第二条。
- **PR**：标题与提交说明都是「回访台账 <日期>」。标题里「回访台账 20」这串字被 `.coderabbit.yaml` 读来跳过
  CodeRabbit 的自动评审（ADR-151 第十节）：这里的标题写法一改，那边要一起改。
  正文先一句话：只追加了 ADR-152 一块，上周结果是什么，候选几条；后面接「周一」里写明进正文的那几段。
  不开草稿 —— 回访 PR 走 `process/6-INTEGRATE.md`「什么不走这套」，检查绿了直接合（ADR-151 第三节第 5 条）。
- 读 PR 用 REST 接口（`/repos/c01dsummer/kol-outreach-skill/pulls?state=all`）或手头的 GitHub 工具。
  `gh pr` 走 GraphQL，在云端会话里会报 403；它报错不等于读不到。

## 每次开始

1. **核不是浅克隆**：`git rev-parse --is-shallow-repository` 应为 `false`。是 `true` 就 `git fetch --unshallow`；
   做不到，本块与 PR 正文里所有要翻历史才得出的值都写 `无从确认：浅克隆`。
2. **找上一条回访 PR**：分支名以 `claude/revisit-` 开头、创建时间最晚的那一条。
3. **定上周结果**，按那条 PR 的状态取一个 token，原样写：
   - 合进了主干 → `已合入`
   - 关了、没合：上面有例程留的「过期」评论 → `例程关闭`；没有 → `所有者关闭`
   - 还开着 → 先关掉它，留一句评论「过期，由 <本块日期> 那一块接替」，再写 `例程关闭`；
     关不掉就写 `无从确认：关不掉 #<号>`，并在本块那条 PR 的正文里点名它还开着
   - 一条回访 PR 都没有 → `无从确认：没有上一条`
   - 读不到 PR：主干台账最后一块的日期在本块日期之前 8 天以内 → `已合入`；否则 `无从确认：读不到回访 PR`
4. **数上一块**，只在上周结果是 `已合入` 时数。上一块 = 主干上 ADR-152 里最后一个块标题之下那一块，
   块标题用 `grep -nE '^## [0-9]{4}-[0-9]{2}-[0-9]{2} · 本跑 '` 找：
   - 提出 = 它的候选行数，id 栏是「—」的那一行（无候选、无从确认）不算
   - 接受、拒绝 = 那几行「人判」栏里「接受」「拒绝」各几个
   - 不是 `已合入` 时不数，这一行写成 `- 上周结果：<token> · 提出、接受、拒绝：无从确认：<同上周结果的原因>`

## 周一

例程每周一跑一次（北京时间；排期在平台上，不写在这里）。哪天跑，块日期就是哪天，下面的窗口都从块日期 `<日期>` 往回算。
「每次开始」做完、还没动 ADR-152 之前，取下面三段原料：候选只从 (b) 出，(a)、(d) 只进 PR 正文。
既有的记录，本说明书任何时候都只许往 ADR-152 追加（「能写什么」第二条），要改先改本文；新开记录只有「候选句」那一种。

**两棵树、一把尺子。** 本跑那棵树就是刚克隆下来、还没改过的主干；一周前那棵树是 `<日期>` 往前 7 天那天北京时间 00:00
之前主干上的最后一个提交。两棵树都拿本跑这棵树上的入口去量 —— 尺子相同，两份欠条台账的差才只来自记录本身。
命令都在仓库根目录跑，`<日期>` 换成块日期。几段命令之间只靠 `$tmp` 下的文件传东西：`$tmp` 按块日期定死，
每段第一行重新算出它，分几次 shell 调用跑也接得上。

```bash
day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day; run=$(git rev-parse origin/main)
npm ci        # 只为装上 tsx；入口只读 docs/adr/，不用先跑测试
git worktree remove --force "$tmp/old" 2>/dev/null; rm -rf "$tmp"; mkdir -p "$tmp"
old=$(git rev-list -1 --first-parent --before="$(date -d "$day -7 days" +%F) 00:00 +0800" origin/main)
[ -n "$old" ] && git worktree add --detach "$tmp/old" "$old"
tsx=$PWD/node_modules/.bin/tsx; entry=$PWD/scripts/check/adr-ledger.ts
"$tsx" "$entry" > "$tmp/新台账"; "$tsx" "$entry" --cites > "$tmp/新被引表"
(cd "$tmp/old" || exit 1; "$tsx" "$entry" > "$tmp/旧台账"; "$tsx" "$entry" --cites > "$tmp/旧被引表")
ok=1; git diff --quiet origin/main -- docs/adr || ok=0
for f in 新台账 旧台账 新被引表 旧被引表; do tail -n 1 "$tmp/$f" 2>/dev/null | grep -qE '^  (欠条台账|被引表) [0-9]+ 条' || ok=0; done
[ "$ok" = 1 ] && echo "原料齐了：一周前 ${old:0:7}" || echo 原料不齐
```

- 最后一行打的是「原料不齐」，就不往下算：(b)、(d) 两段都写 `无从确认：<哪一步报了什么>`，块里照「一块怎么写」的「做不了的时候」写。
  手头那几份文件这时不可信：取不到一周前那棵树时，比出来的是「新增 0、消失 0」，两份被引表也一模一样。
- 那道门核三件事：一周前那棵树取到了；四份文件都打到了末尾那一行汇总；工作区的 `docs/adr/` 就是 `origin/main` 上的 ——
  入口读工作区，下面的 blame 读 `$run`，两边不是同一棵树，行号就对不上。
- 旧树上抽出孤儿欠条时入口以 1 退出，台账照样打全，照常用。
- 这几份文件都在仓库外，不提交；三段都做完，`git worktree remove --force "$tmp/old"`。

### (b) 欠条：一周的增减，与到期的「定期清点」

1. **增减。** 两份欠条台账只比 `docs/adr/` 开头的行，比之前去掉行号：前面插进一段，后面的行号会整体挪，同一张欠条不该因此算成一减一增。

   ```bash
   day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day
   d() { awk 'FILENAME == ARGV[1] { k=$0; sub(/:[0-9]+  /, "  ", k); a[k]++; next }
              { k=$0; sub(/:[0-9]+  /, "  ", k); if (a[k]-- <= 0) print }' <(grep '^docs/adr/' "$1") <(grep '^docs/adr/' "$2"); }
   d "$tmp/旧台账" "$tmp/新台账" > "$tmp/新增"; d "$tmp/新台账" "$tmp/旧台账" > "$tmp/消失"
   wc -l < "$tmp/新增"; wc -l < "$tmp/消失"
   ```

   「新增」里的行号在本跑上，「消失」里的在一周前那棵树上。条件原文改了一个字，也读作一减一增。

2. **到期的「定期清点」。** 本跑的欠条台账里写法是「重启条件」（每行第二栏）、条件那一行写着「定期清点」的，逐条取登记日；
   满四周的留下，再去掉 ADR-152 里列过的：

   ```bash
   day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day; run=$(git rev-parse origin/main); cut=$(date -d "$day -28 days" +%F)
   grep '^docs/adr/' "$tmp/新台账" | grep '  \[重启条件\]  ' | grep '定期清点' | while IFS= read -r l; do
     f=${l%%:*}; n=${l#*:}; n=${n%%  *}
     t=$(git blame --first-parent --porcelain -L "$n,$n" "$run" -- "$f" | awk '/^committer-time /{print $2; exit}')
     echo "$(TZ=Asia/Shanghai date -d @"$t" +%F) $(basename "$f" | grep -oE '^ADR-[0-9]+') 第 $n 行"
   done | sort -V > "$tmp/定期清点"
   awk -v c="$cut" '$1 <= c' "$tmp/定期清点" > "$tmp/满四周"
   while read -r t k; do
     grep -qE "^\| [^|]+ \| $k \||^- 读过、没进候选：(.*、)?$k(、|$)" docs/adr/ADR-152-*.md || echo "$t $k"
   done < "$tmp/满四周" > "$tmp/没列过"
   grep -vc '^20[0-9][0-9]-' "$tmp/定期清点"; wc -l < "$tmp/满四周"; wc -l < "$tmp/没列过"; head -n 5 "$tmp/没列过"
   ```

   - **登记日**是那一行最后一次在主干上被改动的那天（北京时间）；记录只追加，一般就是它进主干那天。
     `--first-parent`：经合并提交进来的，记合进主干那一次，不记分支上写下那一次。
   - **满四周** = 登记日在 `<日期>` 往前 28 天那天或更早（命令里的 `cut`）：这一行 28 天里没被改过。
   - **列过** = ADR-152 里有一条候选行的「欠条」栏、或「读过、没进候选」那一行里，写着同一个 `<编号> 第 <行> 行`。
     命令里那条 grep 就是这个判据；候选那一句里顺带写到的行号不算。每张欠条的每个条件，在 ADR-152 里至多出现一次。
   - **取**：「没列过」的前 5 行，就是命令最后打出来的那几行（登记日从早到晚，同一天按编号）。截在同一登记日中间也只取 5 行；
     没取到的下周排在最前。
   - 命令打出的头三个数依次是：取不到登记日的行数，应为 0，不是 0 就照「做不了的时候」写 `无从确认：取不到登记日`；
     满四周的条数；没列过的条数。

   只认条件那一行：「定期清点」写在条件续行里的，这里列不到（是哪几张，ADR-151 第十一节点了名）。

3. **读一遍，判值不值得回访。** 「新增」「消失」与取出的那几条，逐条回原文读它所在的那一块（`⚠️` 块从块头那一行读到块尾；
   不在 `⚠️` 块里的，读它所在的那一节），再看后来有没有人接手它：
   - **先找起点**：后来最近一次点名这一条的记录。点名 = 指得出是它：编号与行号；同一条记录里的「本记录第几行」「同文第几行」
     「上一块那张」「同一张：第几行」；只写块头行号或「某某第几行那一串」的，算点到了那一串里的每一张。
     那次写的是已还、已烧掉、改挂到别处、或由需求所有者定为收尾，就是**有人接手了**。写的是别的（照旧挂着、条件重新起算、只记核过、
     按字面响了而实质不响、离得近没响），起点就是那次；一次都没被点名过的，起点是它进主干那天。
   - **改挂与重新起算**：别处另起了一块 `⚠️` 欠条接着它（开头写「第几行那张响了、没还」或「重挂」，带着自己的条件，哪怕注着「重新起算」），
     是改挂到别处，有人接手了，要看的是新的那一块。没另起 `⚠️` 块、只在清点或更正里写一句条件重新起算的，才算条件重新起算。
   - **再看条件**：从起点往后，条件按字面成立过没有。先看后来的记录，再翻主干历史，看条件点名的文件、函数或那一节改过没有
     （`git log --first-parent <起点那次提交>..origin/main -- <路径>`）。这条命令只到文件一级；条件点名的是一个函数、一段或一张表的，
     再看那几次提交的 diff 改没改到那一处，拿不准的照字面宽读，理由里写明拿不准在哪。条件说的事就是这一跑本身的
     （比如「第二节第 7 片开工时」「那条回访 PR 开出来时」），算成立。
   - **值得**，进候选表：没人接手，从起点往后条件成立过。取出的那几条，条件里写着定期清点，这一跑就是那次清点，只看有没有人接手；
     「新增」里条件也写着定期清点、却没取进来的，这一跑不算替它清点过，按它别的条件判。
   - **不值得**：有人接手了，或者从起点往后条件按字面还没成立过。
   - 「消失」的那几条：记录只追加，一条欠条从主干上没了，是有人改了已合入的记录。同一句在本跑上换了位置或改了几个字、意思没变的，不值得；
     找不到的，值得。写法是「孤儿·没写重启条件」的只会出现在旧树上（主干上有孤儿，`npm run audit` 就红），照这一条判。
   - 写法是「死亡条件」「重开讨论」的不判、不进候选，PR 正文只写两种各几条：(b) 列的是欠条；判死亡条件值不值得回访，
     就是在判它成没成立（「能写什么」第三条）。
   - 「新增」「消失」里判了值得的，进候选表之前也拿第 2 步「列过」那条 grep 查一次，查到了就不进：下周那棵「一周前」的树
     取在这一天的 00:00，比本跑早，这中间几个小时里加的欠条，下周还会再算一次新增。
   - 这一遍只判值不值得请人看，不判还没还（「能写什么」第三条）：理由写「哪一条第几行写着什么」，不写「已还」。
   - 取出的那几条里没进候选的，写进块里「读过、没进候选」那一行，以后不再列；每一条为什么不进，一句话写进 PR 正文。
     「新增」「消失」里没进候选的，PR 正文只写条数。它们的条件里要是没写定期清点，例程以后不会再读到它们：
     (b) 只每周看一次增减，长期挂着的只回看写着定期清点的那些。

### (a) 主干上偏慢的几跑：只进 PR 正文

- **哪几跑**：`check.yml` 在主干上由 push 触发、结论为成功、创建时间在 `<日期>` 往前 7 天那天 00:00（含）到 `<日期>` 00:00（不含）之间的，北京时间。
  例程恰好隔 7 天跑时，前后两块的窗口首尾相接；隔的不是 7 天（有一周没跑，或手动多跑了一次），窗口会留缝或重叠，照算，不补。
  例程开跑时还没跑完的那一跑不是成功跑，取不到；它若创建在窗口里，下周又落在窗口外，就漏了。
- **口径**：时长 = `run_started_at → updated_at`；「前 5 次」= 创建时间比它早的 5 次同类成功跑，排序后第 3 个是中位；
  比值 = 时长 ÷ 中位，四舍五入到两位小数以后再跟 1.30 比。
  这是 CI 上那一行墙钟对比算「主干前 5 次中位」用的口径；那一行的「本跑」只算到它那一步为止、跑时也看不见还没跑完的主干跑，
  所以这里事后算出的倍数与那一行打出来的可能差一点（ADR-151 第八节「口径」）。
- **端点**也与 CI 上那一步相同：
  `GET /repos/c01dsummer/kol-outreach-skill/actions/workflows/check.yml/runs?branch=main&event=push&status=success&per_page=100&created=%3C<窗口终点，UTC>`。
  返回按创建时间从新到旧排，窗口里的每一跑在列表里往后数 5 个，就是它的「前 5 次」；不够就再取 `&page=2`。
- **写什么**：窗口里一共几跑；比值 ≥ 1.30 的，按创建时间从新到旧，每一跑写 run id、提交前 7 位、时长、中位（`分:秒`）、比值（`×1.84`），写法同 CI 上那一行，一跑都没有就写「没有」；
  前面不足 5 次的写 `无从确认：前面不足 5 次`；接口取不到就整段写 `无从确认：<原因>`。
- 只报数，不判是劣化还是机器快慢（ADR-151 第四节第 3 条）。

### (d) 被引表前十：只进 PR 正文

- 两份被引表各取 `docs/adr/` 开头的前 10 行（`grep -m 10 '^docs/adr/' "$tmp/旧被引表"`，新的一样），写进了前十的与掉出前十的
  （编号，与两边的被引次数「一周前 → 本跑」；一周前还没有这条记录的，左边写「没有这条」），再抄两边末尾那一行汇总。
- 开头那道门打的是「原料不齐」，整段写 `无从确认：<原因>`。
- 只报数，不判哪几条是同一类（ADR-151 第四节第 1 条）。

### 第一块与第二块

- **第一块**（主干上的 ADR-152 还没有块标题时）只做 (b)；PR 正文里 (a)、(d) 两段写「第一块不做」（提案第七节第 4 条）。
  块里在「读过、没进候选」那一行后面另加两行：
  - `- 能否读 Actions 接口：<能 / 不能：原因> · 办法：<怎么请求的> · 令牌：<带了 / 没带 / 没带、经代理时由代理带上>`：
    拿 (a) 的端点请求一次（`per_page=1` 就够）；令牌那一项看返回头，比如 `X-Ratelimit-Limit` 是 60 就是没带；
  - `- squash 后块是否完整落树：无从确认：本块还没合入`。
- **第二块**（主干上的 ADR-152 只有一个块标题时）在同一处另加一行 `- squash 后块是否完整落树：<是 / 否：哪几行不同 / 无从确认：原因>`，
  说的是第一块：拿主干上的第一块，与带它进主干的那条回访 PR 头上那一份里的同一块，逐字比。
  那条 PR 的号在带它进来的那次提交的标题里（`#<号>`）：
  `git log --first-parent -G '^## [0-9]{4}-[0-9]{2}-[0-9]{2} · 本跑 ' --format=%s origin/main -- 'docs/adr/ADR-*-回访台账*.md'`；
  PR 头用 `git fetch origin pull/<号>/head` 取。

## 候选句

每一跑都做：「周一」三段做完、还没动 ADR-152 之前。一类问题犯到第 N 次、`process/` 里还没有说它的那句通用话时，
给 `process/` 起草一句，起草进一条新记录，交需求所有者批。`process/` 例程永远不碰（「能写什么」第二条），搬不搬、怎么搬是人的事。
为什么有它、两道门从哪来：ADR-151 第一节 P7、第十四节。命令照 bash 与 GNU 工具写，在仓库根目录跑。

**先看候选句 PR**（分支以 `claude/candidate-` 开头的 PR 全读，读法同「日期、「本跑」与 PR」；REST 接口带 `per_page=100`，
跟着响应头 `Link` 里的 `rel="next"` 翻完）。下面三种按顺序取第一种成立的，这一节到此为止；都不成立（一条都没有，或者都合了、关了），往下走：
有一条还开着（不只看最晚的那条），块里那一行写 `候选句 PR 还开着：#<号>`（几条都开着，写最晚的那条）；读不到 PR，写 `无从确认：读不到候选句 PR`；
`claude/candidate-<日期>` 这个分支名已经有 PR 了（一天只开一条，开着、合了、关了都算），写 `无从确认：claude/candidate-<日期> 已有 #<号>`。

**第一道门：有一张「同类第 N 次」的欠条。** 在本跑那棵树上：

```bash
day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day; mkdir -p "$tmp"
[ -f docs/adr/README.md ] && git diff --quiet origin/main -- docs/adr && [ -z "$(git status --porcelain --untracked-files=all -- docs/adr)" ] || echo '工作区的 docs/adr/ 不是 origin/main 上的，或者不在仓库根目录'
nums() { grep -oE 'ADR-[0-9]+' | sed -E 's/^ADR-0*//' | sort -n | uniq | tr '\n' ' '; }
grep -HnE '^>.*欠条：同类第 [0-9]+ 次(（|\().*(）|\))(，|,) *通用句未进 `?process/' docs/adr/ADR-*.md | while IFS= read -r l; do
  f=${l%%:*}; r=${l#*:}; n=${r%%:*}; t=${r#*:}
  N=$(sed -E 's/.*欠条：同类第 ([0-9]+) 次.*/\1/' <<<"$t")
  S=$(sed -E 's/.*欠条：同类第 [0-9]+ 次(（|\()(.*)(）|\))(，|,) *通用句未进.*/\2/' <<<"$t" | nums)
  echo "$f|$n|$N|$S"
done > "$tmp/触发"
grep -HnE '^- 候选句来源：' docs/adr/ADR-*.md | while IFS= read -r l; do
  f=${l%%:*}; t=${l#*:*:}
  S=$(sed -nE 's/.*这一类：//p' <<<"$t" | nums)
  if grep -qE '^> ⚠️ 驳回：' "$f"; then v=驳回; else v=活着; fi
  echo "$f|$S|$v"
done > "$tmp/候选句记录"
wc -l < "$tmp/触发"; wc -l < "$tmp/候选句记录"; grep -hE '^>.*欠条.{0,40}同类第' docs/adr/ADR-*.md | wc -l
awk -F'|' '$2 == "" { print "这一类没写出编号：" $1 }' "$tmp/候选句记录"
awk -F'|' '{ if (split($4, u, " ") != $3) print "N 与括号里的编号数不等：" $1 " 第 " $2 " 行" }' "$tmp/触发"
awk -F'|' '$3 == "活着" { print $1 }' "$tmp/候选句记录" | while IFS= read -r f; do
  if grep -qE '^>.{0,8}⚠️.{0,8}驳回' "$f"; then echo "驳回块写法不对：$f"; fi
done
```

- 第一行打出了「工作区的 `docs/adr/` 不是 `origin/main` 上的……」（改过、`git add` 过、或者有没提交的新文件，都算），这一节到此为止，块里那一行写 `无从确认：工作区的 docs/adr/ 不是 origin/main 上的`：
  这里 grep 工作区，下面选法那段 blame 的是 `origin/main`，两边不是同一棵树，行号就对不上（同「周一」开头那道门的第三件事）。
- `触发` 里每一行是一张这种欠条（`docs/adr/README.md`「同类」写的那一张）：文件、行号、N、括号里的编号。括号里写全了这一类、连那条记录自己，这些编号就是这一类。
  第一个数是 0，这一节到此为止，块里那一行写 `没有触发`。第三个数是 `docs/adr/` 里「欠条」后面不远就是「同类第」的 `>` 行（带括注、加粗的也算），
  比第一个数大，多出来的那几张写法不对、第一道门认不出：PR 正文点名它们（只开台账那条 PR 的，写在台账那条里）。
  打出「N 与括号里的编号数不等」的，括号多半是简写（编号前面没写 `ADR-`）或没写全，命令只认得写了 `ADR-` 的那几个：照样往下判，PR 正文点名它。
- `候选句记录` 里每一行是一条候选句记录（下面「起草什么」头部那一行）：文件、它那一类的编号、有没有驳回块。
  驳回块以一行 `> ⚠️ 驳回：` 开头，「驳回」后面直接接冒号、不加括注；由需求所有者写，例程只读。人手开的候选句记录也写这一行，写成
  `- 候选句来源：需求所有者指定，<出处> · 这一类：ADR-a、ADR-b`：「这一类：」放在最后，后面只写编号（命令取它后面的全部编号）。
  打出「这一类没写出编号」的，第二道门看不见那条记录；打出「驳回块写法不对」的，那条记录有一块像驳回、又不是 `> ⚠️ 驳回：` 开头，
  命令当它活着：这两种 PR 正文都点名。
- 别的记录举这几种行（「同类第 N 次」那张欠条、`- 候选句来源：`、`> ⚠️ 驳回：`）时不顶格写、不以 `>` 开头：这几条 grep 不认围栏，同 `docs/adr/README.md`「同类」。

**第二道门：这一类没有活着的候选句记录；驳回过的，驳回以后又添了一例；这张也是这一类里括号最全的欠条。**
一条候选句记录与一张欠条：它那一类的编号全在欠条的括号里，算同一类；一个都不在，不是；只在一部分，不由命令判，回去读（下面第三条）。
两张欠条：一张括号里的编号全在另一张里、另一张还多，前一张让给后一张。候选句记录自己不是这一类的一例：命令先把它们的编号从每张欠条的括号里去掉，再比。

```bash
day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day
awk -F'|' '
  function has(t, n,   w, i, m) { m = split(t, w, " "); for (i = 1; i <= m; i++) if (w[i] == n) return 1; return 0 }
  function hits(s, t,   u, i, k, c) { k = split(s, u, " "); for (i = 1; i <= k; i++) c += has(t, u[i]); return c + 0 }
  function id(f) { match(f, /ADR-[0-9]+/); return substr(f, RSTART, RLENGTH) }
  function add(l, x) { return l (l != "" ? "、" : "") x }
  FILENAME == ARGV[1] { if ($0 != "") { rec[++nr] = $0; cid = id($1); sub(/^ADR-0*/, "", cid); cand = cand " " cid }; next }
  { kept = ""; kn = split($4, tw, " "); for (i = 1; i <= kn; i++) if (!has(cand, tw[i])) kept = kept tw[i] " "
    tr[++nt] = $1 "|" $2 "|" $3 "|" kept }
  END { for (x = 1; x <= nt; x++) {
    split(tr[x], a, "|"); k = split(a[4], t, " "); live = ""; rej = ""; rejset = ""; part = ""; big = ""
    for (j = 1; j <= nr; j++) {
      split(rec[j], c, "|"); m = split(c[2], rs, " "); h = hits(c[2], a[4])
      if (m && h == m) { if (c[3] == "活着") live = add(live, id(c[1])); else { rej = add(rej, id(c[1])); rejset = rejset " " c[2] } }
      else if (h) part = add(part, id(c[1]))
    }
    for (y = 1; y <= nt; y++) { split(tr[y], b, "|")
      if (k && hits(a[4], b[4]) == k && split(b[4], u, " ") > k) big = add(big, id(b[1]) " 第 " b[2] " 行") }
    if (!k) v = "不过：括号里没有候选句记录以外的编号"
    else if (live != "") v = "不过：同一类有活着的候选句记录 " live
    else if (rej != "" && hits(a[4], rejset) == k) v = "不过：同一类的 " rej " 驳回了，括号里没有它们以外的编号"
    else if (big != "") v = "不过：让给括号更全的 " big
    else v = "过"
    print a[1] "|" a[2] "|" a[3] "|" a[4] "|" v "|" part } }' "$tmp/候选句记录" "$tmp/触发" > "$tmp/两道门"
awk -F'|' '{ match($1, /ADR-[0-9]+/); print substr($1, RSTART, RLENGTH) " 第 " $2 " 行 · N " $3 " · " $5 ($6 != "" ? " · 部分重合：" $6 : "") }' "$tmp/两道门"
```

- 同一类的候选句记录一条都没有：过。有一条还活着（没有驳回块：还在等人批，或者批了、搬了）：不过。
  都驳回了：欠条括号里有它们那一类以外的编号才过 —— 驳回以后这一类又添了一例。多出来的是哪几条、是不是驳回以后才犯的、驳回的理由还成不成立，
  起草时写进「驳回过」那一行，由人判；命令不比 N，也不看日期。
- 前几样都没挡住、括号又是另一张的一部分的：不过，让给那张。同一类后来的记录写的是自己那张、N 加一（`docs/adr/README.md`「同类」），
  旧那张不还也不改，就靠这一条不再被起草；不然登记最早的会是旧那张，起草出来的这一类少了后来那几条。
- 最后一栏列着只部分重合的候选句记录。命令判了「过」、这一栏又不空的，按下面选法打出来的顺序读，读到第一张起草的为止，后面的不读、块里不列。
  拿那几条记录的「给 process/ 的候选句」，去对欠条括号里的每一条记录（读法同下面「读什么」）：每一条都说得上，是同一类，拿不准的算说不上；
  别的都不算同一类，照「过」，PR 正文写明与哪几条部分重合、怎么判的。
  来源写「需求所有者指定」的那种人手记录，这一类往往比一张欠条宽得多，只部分重合的一律不当同一类。
  判成同一类的，照上面两条办：那条记录活着，不起草；驳回了，括号里有它那一类以外的编号才起草。不起草的，块里那一行末尾接
  `；部分重合、没起草：<编号> 第 <行> 行（ADR-<n>）`，开了候选句 PR 的，它的正文也写。这一判不记下来：下周照样再判一次、再列一次，由需求所有者定。
- **只起草一条。** 判下来「过」的不止一张时，取登记最早的那张，登记日的取法与排序同「周一」(b) 第 2 步：

  ```bash
  day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day; run=$(git rev-parse origin/main)
  awk -F'|' '$5 == "过"' "$tmp/两道门" | while IFS='|' read -r f n N S v p; do
    t=$(git blame --first-parent --porcelain -L "$n,$n" "$run" -- "$f" | awk '/^committer-time /{print $2; exit}')
    echo "$(TZ=Asia/Shanghai date -d @"$t" +%F) $(basename "$f" | grep -oE '^ADR-[0-9]+') 第 $n 行"
  done | sort -V
  ```

  第一行就是这一跑起草的那张（上面读过、判成不起草的跳过）。别的不用记：下周两道门照样算得出它们。
  浅克隆（「每次开始」第 1 步没补全）时 blame 给的是浅克隆边界那次提交的日期，不是登记日：过的只有一张，照常起草；不止一张，块里那一行写 `无从确认：浅克隆`，不起草。

**起草什么。** 一条新记录。编号是主干上 `docs/adr/` 里最大的编号加一；开着的 PR（不论分支）、关了没合的 `claude/candidate-` PR 里新增过这个号的记录文件
（`/pulls/<号>/files`，同样带 `per_page=100`、跟着 `Link` 翻完），再加一，加了以后照样再核一遍：号用过就不复用（`docs/adr/README.md`「编号允许有空号」）。
文件名先起成 `ADR-<编号>-x.md`，`npm run adr` 会打出它该叫什么，照着改名（新文件还没进索引，用 `mv`；`git mv` 会报错），再 `npm run adr -- --write` 回写索引，`npm run adr` 绿了才往下走。

- **读什么**：起草时拿来下判断的只有这几样。这一类每条记录的「教训」，没有教训栏的读头部「结论」「理由」两栏（续行算在内；缺一栏，
  或者那一栏只写着一个指针，就只读另一栏，不跟指针）；挂着这张欠条的那条记录，另读欠条所在那一节（往上到最近的 `## ` 标题）；
  部分重合与「驳回过」点到的候选句记录，读它的标题、「给 process/ 的候选句」与驳回块；`process/` 各份的标题（`grep -n '^#' process/*.md`）；
  这一节命令的输出。别的不读，`process/` 的正文不读（见「线索」）。仓库的开工须知照读，它不拿来下这几个判断。
- **这一类的名字**：例程读这一类的记录后起，几个字，说是哪一种错法，比如「只修实例没修类」「数没核就写进散文」。
  「驳回过」那一行点到了记录的，沿用它的名字。
- **触发它的事实**只写出处，不抄那张欠条：它后半句是「重启条件」紧跟冒号，抄进头部，欠条台账就多出一张假欠条。
- **候选句来源**写在头部最后一行，同 `docs/adr/README.md`「同类」那一行的位置；「这一类：」后面列全这张欠条括号里的编号（候选句记录的编号除外，即 `$tmp/两道门` 那一行的第四栏），第二道门只认这几个。
  「同类第 <N> 次」照欠条原样抄：括号里带着候选句记录的，「这一类：」的个数会比 N 少，不改 N。
- **候选句**：照上面「读什么」读这一类的记录，写一到两句。换一个项目也成立：不点名本仓库的文件、脚本、需求或记录编号
  （这就是 `docs/SYNC.md`「一条判别规则」，不用另读）。读下来找不出这几条共同的错法的，照样起草，类名与候选句写读出来最近的那种，
  围栏下面接一行 `无从确认：<哪几条对不上、为什么>`，PR 正文也写；括号写得对不对，由写那张欠条的人与需求所有者判（「要拒」）。它是草稿，用围栏框起来，需求所有者会改；围栏里的行不以 `>`、`- 同类：`、`- 候选句来源：` 开头
  （上面几条 grep 不认围栏；台账认围栏，围栏里写「重启条件」「欠条」不碍事）。
- **拟放在**：读 `process/` 各份的标题，写最贴近的一节；拿不准写 `无从确认：<为什么>`。
- **来源**：这一类每条一行，行号指被引表认作「教训」的那一行（`scripts/check/cite-rule.ts` 的 `LESSON`；有两处取第一处），
  没有教训栏的指头部「结论」那一行。
- **驳回过**：`$tmp/候选句记录` 里标着驳回、编号全在这张欠条括号里的，与部分重合、读下来判成同一类、驳回了的，一条一行；没有就删掉这一行。
  多出来的是欠条括号里有、那条记录那一类里没有的编号（候选句记录的编号不算）。
- **线索**：改 `process/` 的提交里，说明（标题与正文）引到这一类任一编号的。命令里的编号照 `$tmp/两道门` 那一行的第四栏写、用 `|` 隔开，
  命令与输出一起放进围栏：

  ```bash
  git log --first-parent --date=short --format='%h %ad %s' -E --grep='ADR-0*(97|99|131)([^0-9]|$)' origin/main -- process/
  ```

  有输出就原样放在命令下面，交人核（命中可能在说明的正文里，人用 `git show -s <提交>` 看全文；例程不跑它）。没有输出，围栏下面写
  `无从确认：改 process/ 的提交说明里没引这一类的编号`，不读作「没搬」：搬的提交不一定引编号（提案 §5 P7 那一格举的 `d64aac2`）。
  浅克隆时围栏下面只写 `无从确认：浅克隆`：截断的历史查不全。
  例程不读 `process/` 正文去判「已经有了」：那一判是欠条的作者做过的，再判是人的事（「要拒」）。
- **要搬、要拒**那一节照模板原样抄，尖括号留给搬的人填。

**PR。** 分支 `claude/candidate-<日期>`，从 `origin/main` 开；标题与提交说明的第一行都是「候选句 <日期>：<这一类的名字>」，标题里不带「回访台账」。
只改新记录与索引里它那一行。不开草稿：它走 `process/6-INTEGRATE.md`「什么不走这套」（需求所有者采纳了提案 P7 的「走欠条 PR 快车道当场合」，
ADR-151 第一节 P7、第十四节第 12 条）：
一次提交，只新开一条记录与索引一行，检查绿了由需求所有者合。它装的不只是一张欠条，这条快车道没有形状检查（ADR-151 第 406 行那张欠条）。
正文先一句话：起草了「<这一类的名字>」，触发是 <编号> 第 <行> 行那张欠条；接第二道门那段打出来的那几行（每张欠条一行，过没过、为什么），
选法那段的输出（取了哪张、跳过了哪几张、为什么），部分重合读了哪几条、怎么判的，第一道门那几段要点名的；正文最后一段：评审器的意见交需求所有者读，
例程这一跑之后不回来答；新记录上评审器提的同类候选，由需求所有者答「驳回 · 理由：不是同类，候选句记录」；别的 PR 先合、
索引那一处冲突的，由需求所有者处理或关掉（关掉不算驳回）。平台要加的尾注照加，接在最后一段后面。
「日期、「本跑」与 PR」那一节的「一天只开一条」与正文写法管的是回访 PR；台账那条 PR 的正文另接本节要它写的几样，开了候选句 PR 的再写一句它的分支。两条分支都从 `origin/main` 开、各改各的：候选句那条不带台账那一块，台账那条不带新记录。

## 一块怎么写

接在 ADR-152 末尾，前面空一行。头两行的写法由 ADR-152 第一节定死，其余照这里：

```markdown
## <日期> · 本跑 <本跑>

- 上周结果：<token> · 提出 <N> · 接受 <M> · 拒绝 <K>
- 原料：一周前 <一周前那棵树的前 7 位> · 欠条新增 <A> · 消失 <B> · 「定期清点」满四周 <C>，列过的 <D>，取 <E>
- 候选句：<起草了 ADR-<编号>（#<号>），触发 <编号> 第 <行> 行 / 没有触发 / 第一道门 <F> 张，一张也没起草 / 候选句 PR 还开着：#<号> / 无从确认：<原因>>
- 读过、没进候选：<编号> 第 <行> 行、……

| id | 欠条 | 候选 | 值 | 人判 |
|---|---|---|---|---|
| <日期>#1 | <编号> 第 <行> 行 | <是什么>；<为什么现在该回来看> | <值> | |
```

- **原料**那一行的数都是「周一」(b) 的命令打出来的：A、B 是第 1 步「新增」「消失」的行数，几种写法都算；
  C 是第 2 步满四周的条数，D 是 C 减去没列过的条数，E 是 5 与没列过的条数里小的那个。
- **候选句**那一行照「候选句」一节的结果，五种写法取一种，有部分重合没起草的，照那一节在末尾接一句；F 是 `$tmp/触发` 的行数。
  「原料不齐」不碍这一行：候选句不用「周一」的原料；工作区的 `docs/adr/` 不是 `origin/main` 上的那一种除外，那时第一道门那段也会打出来。
- **读过、没进候选**只记 (b) 第 2 步取出的那几条里没进候选的，写 `<编号> 第 <行> 行`、用顿号隔开，别的字不写；一条都没有就写 `无`。
- **id** 是本块日期加序号，后面的 PR 引一条候选就引这个 id。顺序：取出的那几条里进来的在前（按第 2 步的顺序），再是「新增」「消失」（各按文件里的顺序）。
- **欠条**一栏只写 `<编号> 第 <行> 行`，是去重用的（「周一」(b) 第 2 步「列过」）。编号照文件名写，`ADR-01` 到 `ADR-09` 带前导 0，
  与第 2 步命令打出来的一样；「新增」与取出的那几条写本跑上的行号，「消失」写一周前那棵树上的。候选那一句里提到别处，随便怎么写都不碍去重。
- **值**只有三态：查到的值本身、`没查到`（查了，没有）、`无从确认：<原因>`（查不了）。缺的值不留空，也不写成 0。
  (b) 进来的：取出的那几条写 `登记 <登记日>`，「新增」写 `新增`，「消失」写 `消失：一周前在 <前 7 位> 上`。
- **人判**例程永远留空。需求所有者合并前可以在候选行上填「接受」或「拒绝」，不填就是没判。
- **没有候选**就只写一行 `| — | — | 无候选 | | |`；这一行的「值」与「人判」空着是格式本身，不算缺值。
- **做不了的时候**：「周一」开头那道门打了「原料不齐」，或 (b) 整段做不了（比如浅克隆），原料、读过两行都只写 `无从确认：<原因>`，
  候选表只写一行 `| — | — | 无从确认：<原因> | | |`。「无候选」是查了、没有，不拿它顶。
- **候选那一句**不写「重启条件」紧跟冒号，也不写加粗的「什么条件下……」紧跟冒号 —— 欠条台账从 `docs/adr/` 里按这两种写法抽条件，
  照抄进台账就多出一张假欠条。要提条件，写「条件是……」。
