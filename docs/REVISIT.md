# 回访说明书

> 回访例程照这一份做。例程本体在需求所有者的 claude.ai 账户里，它的 prompt 只有一句「克隆 c01dsummer/kol-outreach-skill 后读 `docs/REVISIT.md` 照做。」——
> 规则只在这里，不在 prompt 里，也不在 `.github/` 下（转发文件不装内容）。
> 为什么有它、各条归哪一档：ADR-151。台账本身，以及每一块里定死不改的那两行：ADR-152。

---

## 能写什么

- **只写两处**：每一跑在回访台账 ADR-152 末尾追加一块，开一条只改这一个文件的 PR，台账里已有的块一个字不改；
  「候选句」两道门都过了、起草了的那一跑，另开一条 PR 新开一条记录，只改那个新文件与索引里它那一行。
  另外只做一件事：关掉过期的上一条回访 PR（「每次开始」第 3 步）。
- **永不改** `process/`、`scripts/`、`docs/requirements.json`、`.github/workflows/check.yml`；既有的记录除了往 ADR-152 追加，一律不碰，别的文件也不改。
- **不替人下结论**：不给任何记录写「采纳」，不标欠条已还，不判死亡条件（ADR-80、ADR-86、ADR-151 第四节第 2 条）；
  「候选句」那条新记录的结论照那里写「接受为已知缺口」：它只说这一类还没有通用句，搬不搬由人定。
  不合并、不批准自己的 PR，每一块、每一条候选句记录都由需求所有者合（ADR-151 第三节第 5 条、第一节 P7）。
- **台账的候选只从本文写明的来源取。** 本文写了几个来源，就只从那几个取；现在只有一个：「周一」的 (b)（含它第 5 步的条件探针）。
  条件探针那一步例程只抄命令打的结果：越线、没越线是命令按字面算的，例程不自己判条件成没成立，也不替命令补算（ADR-252）。
  一条都没挑出来时，候选表只有「无候选」一行。这一块照样要写，它是心跳。

- **读台账时读两份。** ADR-152 过了大小线，旧块会挪进 `docs/adr/历史/` 下的同名历史文件（ADR-152「过线时把旧块挪进历史文件」那一节）。
  本文凡是读 ADR-152 里的块（最后一块、上一块、有几个块标题、候选表里列过什么、写着同一个记法），都是历史文件接主文件两份一起读，
  先历史文件、后主文件，例如 `cat docs/adr/历史/ADR-152-*.md docs/adr/ADR-152-*.md`（历史文件还没有时只有主文件）。往里写只写主文件末尾。

## 日期、「本跑」与 PR

- **日期**一律取北京时间的当天：`TZ=Asia/Shanghai date +%F`。分支名、块标题、候选 id 都用它。
- **本跑**是这次克隆到的主干提交：`git rev-parse --short=7 origin/main`。
- **一天只开一条**：分支 `claude/revisit-<日期>`；这个分支名的 PR 已经有了，就停下，不开第二条。
- **PR**：标题与提交说明都是「回访台账 <日期>」。标题里「回访台账 20」这串字被 `.coderabbit.yaml` 读来跳过
  CodeRabbit 的自动评审（ADR-151 第九节）：这里的标题写法一改，那边要一起改。
  正文先一句话：只追加了 ADR-152 一块，上周结果是什么，候选几条；后面接「周一」里写明进正文的那几段。
  不开草稿 —— 回访 PR 走 `process/6-INTEGRATE.md`「什么不走这套」，检查绿了直接合（ADR-151 第三节第 5 条）。
- 读 PR 用 REST 接口（`/repos/c01dsummer/kol-outreach-skill/pulls?state=all`）或手头的 GitHub 工具。
  `gh pr` 走 GraphQL，在云端会话里会报 403；它报错不等于读不到。

## 每次开始

1. **核不是浅克隆**：`git rev-parse --is-shallow-repository` 应为 `false`。是 `true` 就 `git fetch --unshallow`；
   做不到，本块与 PR 正文里所有要翻历史才得出的值都写 `无从确认：浅克隆`。
2. **找上一条回访 PR**：分支名以 `claude/revisit-` 开头、创建时间最晚的那一条。
3. **定上周结果**，按那条 PR 的状态取一个 token，原样写：
   - 合进了主干 → `已合入`
   - 关了、没合：上面有例程留的「过期」评论 → `例程关闭`；没有 → `所有者关闭`
   - 还开着 → 先关掉它，留一句评论「过期，由 <本块日期> 那一块接替」，再写 `例程关闭`；
     关不掉就写 `无从确认：关不掉 #<号>`，并在本块那条 PR 的正文里点名它还开着
   - 一条回访 PR 都没有 → `无从确认：没有上一条`
   - 读不到 PR：主干台账最后一块的日期在本块日期之前 8 天以内 → `已合入`；否则 `无从确认：读不到回访 PR`
4. **数上一块**，只在上周结果是 `已合入` 时数。上一块 = 主干上 ADR-152 两份里最后一个块标题之下那一块（「读台账时读两份」），
   块标题用 `grep -nE '^## [0-9]{4}-[0-9]{2}-[0-9]{2} · 本跑 '` 找：
   - 提出 = 它的候选行数，id 栏是「—」的那一行（无候选、无从确认）不算
   - 还、收尾、留、接受、拒绝 = 那几行「人判」栏里这五个词各几个；没判 = 提出减去这五个数（空着的、写了别的字的）
   - 写成 `提出 <N> · 还 <a> · 收尾 <b> · 留 <c> · 接受 <d> · 拒绝 <e> · 没判 <f>`；上一块是这套数法以前写的，照样这么数
   - 不是 `已合入` 时不数，这一行写成 `- 上周结果：<token> · 提出、人判：无从确认：<同上周结果的原因>`
5. **量台账大小**：`wc -c` 主干上 ADR-152 主文件。超过 30 000 字节（`docs/adr/README.md` 定的大小线）时，照常往主文件末尾追加本块，
   PR 正文第一句后面加一句「回访台账主文件 <N> 字节，过了 30 000 的线，要把旧块挪进历史文件」。挪块不归例程做，
   谁做、什么时候做见 ADR-152「过线时把旧块挪进历史文件」那一节。

## 周一

例程每周一跑一次（北京时间；排期在平台上，不写在这里）。哪天跑，块日期就是哪天，下面的窗口都从块日期 `<日期>` 往回算。
「每次开始」做完、还没动 ADR-152 之前，取下面四段原料：候选只从 (b) 出，(a)、(d)、(e) 只进 PR 正文。
既有的记录，本说明书任何时候都只许往 ADR-152 追加（「能写什么」第二条），要改先改本文；新开记录只有「候选句」那一种。

**两棵树、一把尺子。** 本跑那棵树是 `origin/main`；一周前那棵树是 `<日期>` 往前 7 天那天北京时间 00:00
之前主干上的最后一个提交。两棵树的 `docs/adr/` 都从 git 里直接读，拿本跑这份代码的台账与被引表去量 ——
尺子相同，两份欠条台账的差才只来自记录本身。命令都在仓库根目录跑，`<日期>` 换成块日期。几段之间只靠 `$tmp` 下的文件传东西：
`$tmp` 按块日期定死，每段第一行重新算出它，分几次 shell 调用跑也接得上。判定都在 `scripts/check/revisit-raw-rule.ts`，有需求测试守着。

```bash
day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day
npm ci        # 只为装上 tsx；入口只读 git 与 docs/adr/，不用先跑测试
rm -rf "$tmp"; mkdir -p "$tmp"
"$PWD/node_modules/.bin/tsx" scripts/check/revisit-raw.ts --gather --today "$day" --dir "$tmp"
```

- 打一行。`原料齐了：一周前 <提交前 7 位> · 新增 <N> 行、消失 <M> 行`，以 0 退出；
  `原料不齐：<为什么>`，以 1 退出，就不往下算：(b)、(d) 两段都写 `无从确认：<那一行冒号后面的话>`，块里照「一块怎么写」的「做不了的时候」写。
  不齐时 `$tmp` 里那几份不可信（取不到一周前那棵树时，比出来的是全部都算新增）。
- 不齐的几种：一周前那棵树取不到；哪棵树的 `docs/adr/` 读不出；哪份没打到末尾那一行汇总；工作区的 `docs/adr/` 与 `origin/main` 不同（改过的、还没提交的新文件都算） ——
  (b) 第 2 步读工作区、问 git 读 `origin/main`，两边不是同一棵树，行号就对不上。
- `$tmp` 里六份：`新台账`、`旧台账`（同 `adr-ledger.ts` 打的全表）、`新被引表`、`旧被引表`（同 `adr-ledger.ts --cites`）、`新增`、`消失`（(b) 第 1 步）。
  都在仓库外，不提交。

### (b) 欠条：一周的增减、到期清单、轮到的死亡条件与条件探针

1. **增减。** 开头那段已经算好，`$tmp/新增`、`$tmp/消失` 各一份，条数就是那一行里的两个数。两份欠条台账只比 `docs/adr/` 开头的行，
   比之前去掉行号：前面插进一段，后面的行号会整体挪，同一张欠条不该因此算成一减一增；同一行出现两次算两张。

   「新增」里的行号在本跑上，「消失」里的在一周前那棵树上。条件原文改了一个字，也读作一减一增。

2. **到期清单。** 开着的欠条（台账里写法是「重启条件」、没有关上它的状态行）到了期的，交需求所有者判还、收尾还是留：

   ```bash
   day=<日期>; run=$(git rev-parse origin/main)
   "$PWD/node_modules/.bin/tsx" scripts/check/revisit-due.ts --list --today "$day" --run "$run"
   ```

   - 判定在 `scripts/check/revisit-rule.ts`，有需求测试守着；下面几条是它的口径，两个数是需求所有者 2026-11-22 批的（ADR-167 第三节）。
   - **到期**：登记日往后满 28 天；续挂过的，到续挂写的那天才到期；在 ADR-152 里列过、人判栏判了的，判的那一块的日期再过 28 天之前不再列
     （判了还、收尾，等下一条欠条 PR 写状态行；判了留，等续挂行。四周过去还开着，说明没写下来，照样再列）。几种都有的取最晚的那一天。
   - **列过没判**：在 ADR-152 候选表里列过、人判栏空着或写的不是还、收尾、留三个词之一的（以前的「接受」「拒绝」也算没判），不管到没到期，排最前面，每周照列，不换一批。
   - **列过**只认 ADR-152 候选表「欠条」那一栏（两份都认，见「读台账时读两份」）：写着同一个记法，或者它拆之前的旧行号、旧名字，或者整张改挂过来之前那几张的记法，认一个就算。以前块里「读过、没进候选」那一行没有列给需求所有者，不算列过。
   - **登记日**是条件那一行最后一次在主干上被改动的那天（北京时间）；一般就是它进主干那天。
     `--first-parent`：经合并提交进来的，记合进主干那一次，不记分支上写下那一次。
   - **拆过的记录**（`docs/adr/历史/` 里有同名文件，ADR-211）：拆的那次提交把原文整份挪进历史文件、开着的欠条重写进主文件，
     这两处的 blame 都只给得出拆的那天。脚本改取拆之前那份原文：历史文件里拆前那一段与原文逐行相同，取原文同一行；
     主文件里重写过、之后条件没再改过的那张，顺着历史文件末尾指向它的那行「已重挂」取原文那一行；拆以后条件又改过，就按改的那天算。
   - **整张改挂过来的**（别处一行「已重挂：…现行的是 <这一张>」）：接着算原来那张的登记日与续挂过没有（`process/6-INTEGRATE.md`「登记怎么做」第 5 条）。
     「现行的是」后面写的不是 `<编号>「<短名字>」`、`<编号> 第 <行> 行`、`本条第 <行> 行` 三种之一的，脚本认不出，末行数出有几行；
     别处有一行补记点名了它、指同一张旧欠条、自己认得出的，那行不数。2026-11-24 补完时这个数是 0（ADR-167）。
     不是 0 时由人（或接手的会话）补，例程不补（它只往 ADR-152 追加）：旧行不改，读原文定了接手的是哪一张，在别处追加一行
     `⚠️ 已重挂：<旧的那张> · 补记接手者：照 <原来那行在哪>那一行原文认定；现行的是 <接手那张>`。「原来那行在哪」写 `ADR-N 第 M 行`，
     拆过的记录写 `ADR-N 主文件第 M 行` 或 `ADR-N 历史文件第 M 行`（拆之前写下的、不带这两个词的补记，拆了以后照样认作指历史文件那一行）；接手那张写 `<编号>「<短名字>」` 或 `<编号> 第 <行> 行`。
   - **有短名字的欠条**（块头 `⚠️ 欠条「…」`）按 `<编号>「<短名字>」` 记，不按行号 —— 主文件每次重写都可能挪行。
   - 打出来的：第一行是几个数（到期几张、列过没判几张、取不到登记日几张、这次列几张）；中间每行 `<登记日> <记法>`，
     列过没判的后面接「 · 列过没判」，续挂过、或以前判过留的后面接「 · 续挂过，只能还或收尾」；末行是改挂认不出接手的行数。
   - **取**：中间那几行全取，一张不漏，都进候选表（每次最多 10 张，最老的先列；列过没判的在最前）。不判值不值得：到了期就请人判。
     要回原文读它所在的那一块，候选那一句写这张欠条缺的是什么（一句白话）、为什么这一周列它（到期、列过没判、续挂写的那天到了），
     续挂过的写明只能还或收尾；不照抄条件（见「一块怎么写」最后一条），不判条件成没成立。
     取不到登记日、也没续挂过、没列过的不列，只在第一行里数（列过没判的、续挂写的那天到了的照列，日期栏空着）；第一行这个数不是 0 就在 PR 正文点名这件事。
   - 欠条条件里写的「定期清点」，就是到期清单列出它的那一跑。

3. **轮到的死亡条件。** 死亡条件（「什么条件下撤掉、退成只报数」那一种）没有登记日、也不会被还上，按记录编号除以 4 的余数分四组，每周列一组，四周轮完一遍；
   需求所有者 2026-11-23 定了列进候选表、由他判（ADR-167 历史文件「周回访按到期列」一节）：

   ```bash
   day=<日期>
   "$PWD/node_modules/.bin/tsx" scripts/check/revisit-due.ts --deaths --today "$day"
   ```

   - 第一行是几个数，后面每行是记法、两个空格、条件的第一行（续行要回原文读）。主文件与历史文件里的都算；拆的时候原样抄进主文件的（从条件那一行到空行为止整条相同，只差空白），只列主文件那一份。
     拆过的记录，主文件里的死亡条件都记作 `<编号> 主文件第 <行> 行`，`<编号> 第 <行> 行` 指历史文件那一行。
   - 同一条规则的死亡条件后来改写过的，新旧两条都可能列出来；候选那一句照原文写明哪一条是改写过的、现行的是哪一条，判的人一眼看得出。
   - **取**：全取，都进候选表。例程不判它成没成立（「能写什么」第三条）：候选那一句只写这一条管的是哪条规则、要怎么撤或退、条件是什么，不写满了没满；
     条件原文不照抄（照抄会带出「什么条件下……」紧跟冒号的写法，见「一块怎么写」最后一条），用自己的话写「条件是……」。

4. **「新增」「消失」读一遍，判值不值得回访。** 逐条回原文读它所在的那一块（`⚠️` 块从块头那一行读到块尾；
   不在 `⚠️` 块里的，读它所在的那一节），再看后来有没有人接手它：
   - **先找起点**：后来最近一次点名这一条的记录。点名 = 指得出是它：编号与短名字；编号与行号（拆过的记录，`<编号> 第 <行> 行` 指的是历史文件那一行）；同一条记录里的「本记录第几行」「同文第几行」
     「上一块那张」「同一张：第几行」；只写块头行号或「某某第几行那一串」的，算点到了那一串里的每一张。
     那次写的是已还、已烧掉、或由需求所有者定为收尾，就是**有人接手了**；写的是「已重挂」、指到现行那一张的，换成看现行那一张。
     写的是别的（照旧挂着、续挂、条件重新起算、只记核过、按字面响了而实质不响、离得近没响），起点就是那次；一次都没被点名过的，起点是它进主干那天。
   - **另起一块接着它，算续挂一次**：别处另起了一块 `⚠️` 欠条接着它（开头写「第几行那张响了、没还」或「重挂」，带着自己的条件，哪怕注着「重新起算」），
     不算有人接手：条件响了没还，就是续挂了一次（`process/6-INTEGRATE.md`「登记怎么做」第 5 条：续挂只许一次，改挂也不清零）。
     要看的是新的那一块，它接着算这一张的登记日和续挂过没有；候选那一句写明续挂过，人判栏只剩还或收尾。
     没另起块、只在清点或更正里写一句条件重新起算的，也算续挂一次。这两种都只算 2026-11-22 起写的：续挂只许一次是那天定的，
     之前写的「重新起算」不回头算作续挂过（与到期清单同一个口径，ADR-167 历史文件「到期清单」一节第 7 条）。
   - **再看条件**：从起点往后，条件按字面成立过没有。先看后来的记录，再翻主干历史，看条件点名的文件、函数或那一节改过没有
     （`git log --first-parent <起点那次提交>..origin/main -- <路径>`）。这条命令只到文件一级；条件点名的是一个函数、一段或一张表的，
     再看那几次提交的 diff 改没改到那一处，拿不准的照字面宽读，理由里写明拿不准在哪。条件说的事就是这一跑本身的
     （比如「第二节第 7 片开工时」「那条回访 PR 开出来时」），算成立。
   - **值得**，进候选表：没人接手，从起点往后条件成立过。「新增」里条件写着定期清点的，这一跑不算替它清点过，按它别的条件判
     （定期清点由到期清单管，满 28 天还开着就会列出来）。
   - **不值得**：有人接手了，或者从起点往后条件按字面还没成立过。
   - 「消失」的那几条：一条欠条从主干上没了，多半是有人改了已合入的记录。同一句在本跑上换了位置或改了几个字、意思没变的，不值得；
     找不到的，值得。拆记录那一周是例外（ADR-211）：同一句从主文件挪进了 `docs/adr/历史/` 同名文件（「新增」里会有一行一模一样、只差路径的），
     不值得；主文件里重写成带短名字的那张，按「新增」判，起点取历史文件末尾指向它的那行状态之前的原文那张。写法是「孤儿·没写重启条件」的只会出现在旧树上（主干上有孤儿，`npm run audit` 就红），照这一条判。
   - 写法是「死亡条件」「重开讨论」的不判、不进候选，PR 正文只写两种各几条：判死亡条件值不值得回访，
     就是在判它成没成立（「能写什么」第三条）；死亡条件四周里会在第 3 步轮到一次。

     取在这一天的 00:00，比本跑早，这中间几个小时里加的欠条，下周还会再算一次新增。
   - 这一遍只判值不值得请人看，不判还没还（「能写什么」第三条）：理由写「哪一条第几行写着什么」，不写「已还」。
   - 没进候选的，PR 正文只写条数。还开着的欠条满 28 天会进到期清单，那时再请人判。

5. **条件探针。** 决策记录里有一批条件能由确切数据按字面判定（某条 PR 合入了没有、另一张欠条还了没有、树里某个数过没过线）；
   这些条件登记在 `scripts/check/condition-rule.ts` 的登记表里，一行绑台账里一条欠条或死亡条件（ADR-252）。命令照登记表逐条算：

   ```bash

   "$PWD/node_modules/.bin/tsx" scripts/check/conditions.ts --today "$day" --run "$run"
   ```

   - 打出来的：第一行是几个数（登记几条、越线几、没越线几、无从确认几、这次列几、判过先不列几、续挂没到那天先不列几）；

     最后是无从确认的每条一行 `无从确认：<记法> · <这一行算的是什么> · <为什么>`。

     第 4 步「新增」里判了值得、记法又是这一步打出来越线的（不管这一周列不列），只留这一步的那一行，不在「新增」里再列、也不再数进提出与没判；以 1 退出的那一周照第 4 步原样。

### (a) 主干上偏慢的几跑：只进 PR 正文

- **哪几跑**：`check.yml` 在主干上由 push 触发、结论为成功、创建时间在 `<日期>` 往前 7 天那天 00:00（含）到 `<日期>` 00:00（不含）之间的，北京时间。
  例程恰好隔 7 天跑时，前后两块的窗口首尾相接；隔的不是 7 天（有一周没跑，或手动多跑了一次），窗口会留缝或重叠，照算，不补。
  例程开跑时还没跑完的那一跑不是成功跑，取不到；它若创建在窗口里，下周又落在窗口外，就漏了。
- **取接口**（手头的 GitHub 工具或 REST 都行，存原样返回）：
  `GET /repos/c01dsummer/kol-outreach-skill/actions/workflows/check.yml/runs?branch=main&event=push&status=success&per_page=100&created=%3C<窗口终点，UTC>`。
  返回按创建时间从新到旧排；窗口起点之前要至少再有 5 跑（窗口里最早那一跑的「前 5 次」都在起点之前），不够就再取 `&page=2`，
  几页存成一个 JSON 数组（每个元素是一页原样返回）。存成 `$tmp/a-runs.json`。接口取不到就整段写 `无从确认：<原因>`。
- **算**：

  ```bash
  day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day
  "$PWD/node_modules/.bin/tsx" scripts/check/revisit-raw.ts --slow --today "$day" --runs "$tmp/a-runs.json"
  ```

  打出来的原样抄进 PR 正文：第一行是窗口里一共几跑；比值 ≥ 1.30 的，按创建时间从新到旧，每一跑一行 run id、提交前 7 位、时长、中位、比值，
  写法同 CI 上墙钟对比那一行（那一行后面的型号与工作量不抄），一跑都没有写「没有」；比它早的不足 5 跑写 `无从确认：前面不足 5 次`；
  最后一行是工作量。交进去的文件形状不对，或混进了不是上面那一种的跑（别的分支、别的工作流、别的事件、没成功、没跑完），入口以 2 退出、说哪一跑哪一样不对，不打别的 —— 回头重取，不手算。
  有一跑写了 `无从确认：前面不足 5 次`、而交进去的跑比页上 `total_count` 说的少，会多打一行「前面不足 5 次的可能是没取够 …… 再取下一页」：
  加下一页再取、一起存，重跑这一条，这一行不抄；翻完了还不足 5 次才是真不足。
- **口径**（脚本照这个算）：时长 = `run_started_at → updated_at`；「前 5 次」= 创建时间比它早的 5 次同类成功跑，排序后第 3 个是中位；
  比值 = 时长 ÷ 中位，四舍五入到两位小数以后再跟 1.30 比。
  这是 CI 上那一行墙钟对比算「主干前 5 次中位」用的口径；那一行的「本跑」只算到它那一步为止、跑时也看不见还没跑完的主干跑，
  所以这里事后算出的倍数与那一行打出来的可能差一点（ADR-151 第七节第一条）。
- **工作量**那一行：`工作量：变异 <N> 条（比窗口前 <±d>） · 摊到每条的秒数中位 <X>（<k> 跑）`。
  滚动的中位跟着代码一起长，变异条数一周周涨上去，比值里也看不出来；这一行把「量涨了」与「摊到每条上的秒数变了」分开报，后者也随变异以外各步与机器快慢变。
  - N：窗口里创建时间最晚的那一跑，它的 `head_sha` 上 `scripts/check/mutations.json` 里 `mutations` 的条数（不是数组算取不到；从本地 git 取）。CI 上那一行的「变异 N 条」是同一个数。
  - ±d：交进去的跑里窗口起点之前最晚的那一跑，照样取它 `head_sha` 上的条数，N 减去它，带正负号，差 0 写 `±0`。例程恰好隔 7 天跑时，这一跑就是上一个窗口里最晚的那一跑。
  - X：窗口里每一跑的时长 ÷ 它 `head_sha` 上的条数，排序取中位（偶数跑取中间两个的平均），保留两位小数；k 是进了中位的跑数。
    某一跑的提交上取不到条数（比如被强推掉了）或条数为 0，不进中位，后面接一句少了几跑；哪一样取不到就那一样写 `无从确认：<原因>`；窗口里一跑都没有写 `工作量：没有`。
- 只报数，不判是劣化还是机器快慢（ADR-151 第四节第 3 条）。

## 候选句

每一跑都做：「周一」三段做完、还没动 ADR-152 之前。一类问题犯到第 N 次、`process/` 里还没有说它的那句通用话时，
给 `process/` 起草一句，起草进一条新记录，交需求所有者批。`process/` 例程永远不碰（「能写什么」第二条），搬不搬、怎么搬是人的事。
为什么有它、两道门从哪来：ADR-151 第一节 P7、第十一节。命令照 bash 与 GNU 工具写，在仓库根目录跑。

**先看候选句 PR**（分支以 `claude/candidate-` 开头的 PR 全读，读法同「日期、「本跑」与 PR」；REST 接口带 `per_page=100`，
跟着响应头 `Link` 里的 `rel="next"` 翻完）。下面三种按顺序取第一种成立的，这一节到此为止；都不成立（一条都没有，或者都合了、关了），往下走：
有一条还开着（不只看最晚的那条），块里那一行写 `候选句 PR 还开着：#<号>`（几条都开着，写最晚的那条）；读不到 PR，写 `无从确认：读不到候选句 PR`；
`claude/candidate-<日期>` 这个分支名已经有 PR 了（一天只开一条，开着、合了、关了都算），写 `无从确认：claude/candidate-<日期> 已有 #<号>`。

**第一道门：有一张「同类第 N 次」的欠条。** 在本跑那棵树上：

```bash
day=<日期>; tmp=${TMPDIR:-/tmp}/revisit-$day; mkdir -p "$tmp"
[ -f docs/adr/README.md ] && git diff --quiet origin/main -- docs/adr && [ -z "$(git status --porcelain --untracked-files=all -- docs/adr)" ] || echo '工作区的 docs/adr/ 不是 origin/main 上的，或者不在仓库根目录'
nums() { grep -oE 'ADR-[0-9]+' | sed -E 's/^ADR-0*//' | sort -n | uniq | tr '\n' ' '; }
grep -HnE '^>.*欠条(「.*」)?：同类第 [0-9]+ 次(（|\().*(）|\))(，|,) *通用句未进 `?process/' docs/adr/ADR-*.md | while IFS= read -r l; do
  f=${l%%:*}; r=${l#*:}; n=${r%%:*}; t=${r#*:}
  N=$(sed -E 's/.*欠条(「.*」)?：同类第 ([0-9]+) 次.*/\2/' <<<"$t")
  S=$(sed -E 's/.*欠条(「.*」)?：同类第 [0-9]+ 次(（|\()(.*)(）|\))(，|,) *通用句未进.*/\3/' <<<"$t" | nums)
  echo "$f|$n|$N|$S"
done > "$tmp/触发"
grep -HnE '^- 候选句来源：' docs/adr/ADR-*.md | while IFS= read -r l; do
  f=${l%%:*}; t=${l#*:*:}
  S=$(sed -nE 's/.*这一类：//p' <<<"$t" | nums)
  if grep -qE '^> ⚠️ 驳回：' "$f"; then v=驳回; else v=活着; fi
  echo "$f|$S|$v"
done > "$tmp/候选句记录"
wc -l < "$tmp/触发"; wc -l < "$tmp/候选句记录"; grep -hE '^>.*欠条(「.*」)?.{0,40}同类第' docs/adr/ADR-*.md | wc -l
awk -F'|' '$2 == "" { print "这一类没写出编号：" $1 }' "$tmp/候选句记录"
awk -F'|' '{ if (split($4, u, " ") != $3) print "N 与括号里的编号数不等：" $1 " 第 " $2 " 行" }' "$tmp/触发"
awk -F'|' '$3 == "活着" { print $1 }' "$tmp/候选句记录" | while IFS= read -r f; do
  if grep -qE '^>.{0,8}⚠️.{0,8}驳回' "$f"; then echo "驳回块写法不对：$f"; fi
done
```

- 第一行打出了「工作区的 `docs/adr/` 不是 `origin/main` 上的……」（改过、`git add` 过、或者有没提交的新文件，都算），这一节到此为止，块里那一行写 `无从确认：工作区的 docs/adr/ 不是 origin/main 上的`：
  这里 grep 工作区，下面选法那段 blame 的是 `origin/main`，两边不是同一棵树，行号就对不上（同「周一」开头那道门的第三件事）。
- 这一段只读主文件（`docs/adr/ADR-*.md` 不进 `docs/adr/历史/`）：拆过的记录，还开着的欠条都重写在主文件里，历史文件里原来那张补了状态行（ADR-211）。
- `触发` 里每一行是一张这种欠条（`docs/adr/README.md`「同类」写的那一张）：文件、行号、N、括号里的编号。括号里写全了这一类、连那条记录自己，这些编号就是这一类。
  第一个数是 0，这一节到此为止，块里那一行写 `没有触发`。第三个数是 `docs/adr/` 里「欠条」后面不远就是「同类第」的 `>` 行（带括注、加粗的也算），
  比第一个数大，多出来的那几张写法不对、第一道门认不出：PR 正文点名它们（只开台账那条 PR 的，写在台账那条里）。
  打出「N 与括号里的编号数不等」的，括号多半是简写（编号前面没写 `ADR-`）或没写全，命令只认得写了 `ADR-` 的那几个：照样往下判，PR 正文点名它。
- `候选句记录` 里每一行是一条候选句记录（下面「起草什么」头部那一行）：文件、它那一类的编号、有没有驳回块。
  驳回块以一行 `> ⚠️ 驳回：` 开头，「驳回」后面直接接冒号、不加括注；由需求所有者写，例程只读。人手开的候选句记录也写这一行，写成
  `- 候选句来源：需求所有者指定，<出处> · 这一类：ADR-a、ADR-b`：「这一类：」放在最后，后面只写编号（命令取它后面的全部编号）。
  打出「这一类没写出编号」的，第二道门看不见那条记录；打出「驳回块写法不对」的，那条记录有一块像驳回、又不是 `> ⚠️ 驳回：` 开头，
  命令当它活着：这两种 PR 正文都点名。
- 别的记录举这几种行（「同类第 N 次」那张欠条、`- 候选句来源：`、`> ⚠️ 驳回：`）时不顶格写、不以 `>` 开头：这几条 grep 不认围栏，同 `docs/adr/README.md`「同类」。

**第二道门：这一类没有活着的候选句记录；驳回过的，驳回以后又添了一例；这张也是这一类里括号最全的欠条。**
一条候选句记录与一张欠条：它那一类的编号全在欠条的括号里，算同一类；一个都不在，不是；只在一部分，不由命令判，回去读（下面第三条）。
两张欠条：一张括号里的编号全在另一张里、另一张还多，前一张让给后一张。候选句记录自己不是这一类的一例：命令先把它们的编号从每张欠条的括号里去掉，再比。

  浅克隆（「每次开始」第 1 步没补全）时 blame 给的是浅克隆边界那次提交的日期，不是登记日：过的只有一张，照常起草；不止一张，块里那一行写 `无从确认：浅克隆`，不起草。

**起草什么。** 一条新记录。编号是主干上 `docs/adr/` 里最大的编号加一；开着的 PR（不论分支）、关了没合的 `claude/candidate-` PR 里新增过这个号的记录文件

文件名先起成 `ADR-<编号>-x.md`，`npm run adr` 会打出它该叫什么，照着改名（新文件还没进索引，用 `mv`；`git mv` 会报错），再 `npm run adr -- --write` 回写索引，`npm run adr` 绿了才往下走。

  部分重合与「驳回过」点到的候选句记录，读它的标题、头部「候选句来源」那一行（来源是不是「需求所有者指定」，下面判部分重合要用）、「给 process/ 的候选句」与驳回块；`process/` 各份的标题（`grep -n '^#' process/*.md`）；
  这一节命令的输出。别的不读，`process/` 的正文不读（见「线索」）。仓库的开工须知照读，它不拿来下这几个判断。

  「驳回过」那一行点到了记录的，沿用它的名字。
- **触发它的事实**只写出处，不抄那张欠条：它后半句是「重启条件」紧跟冒号，抄进头部，欠条台账就多出一张假欠条。
- **候选句来源**写在头部最后一行，同 `docs/adr/README.md`「同类」那一行的位置；「这一类：」后面列全这张欠条括号里的编号（候选句记录的编号除外，即 `$tmp/两道门` 那一行的第四栏），第二道门只认这几个。

  （这就是 `docs/SYNC.md`「一条判别规则」，不用另读）。读下来找不出这几条共同的错法的，照样起草，类名与候选句写读出来最近的那种，

- **拟放在**：读 `process/` 各份的标题，写最贴近的一节；拿不准写 `无从确认：<为什么>`。
- **来源**：这一类每条一行，行号指被引表认作「教训」的那一行（`scripts/check/cite-rule.ts` 的 `LESSON`；有两处取第一处），

- **线索**：改 `process/` 的提交里，说明（标题与正文）引到这一类任一编号的。命令里的编号照 `$tmp/两道门` 那一行的第四栏写、用 `|` 隔开，

## 一块怎么写

接在 ADR-152 末尾，前面空一行。头两行的写法由 ADR-152 第一节定死，其余照这里：

```markdown
## <日期> · 本跑 <本跑>

- 上周结果：<token> · 提出 <N> · 还 <a> · 收尾 <b> · 留 <c> · 接受 <d> · 拒绝 <e> · 没判 <f>
- 原料：一周前 <一周前那棵树的前 7 位> · 欠条新增 <A> · 消失 <B> · 到期 <C>，列过没判 <D>，列 <E> · 死亡条件轮到 <G> · 条件探针越线 <H>，列 <I>
- 候选句：<起草了 ADR-<编号>（#<号>），触发 <编号> 第 <行> 行 / 没有触发 / 第一道门 <F> 张，一张也没起草 / 候选句 PR 还开着：#<号> / 无从确认：<原因>>

| id | 欠条 | 候选 | 值 | 人判 |
|---|---|---|---|---|
| <日期>#1 | <编号> 第 <行> 行 | <是什么>；<为什么现在该回来看> | <值> | |
```

- **原料**那一行的数都是「周一」(b) 的命令打出来的：A、B 是第 1 步「新增」「消失」的行数，几种写法都算；
  C、D、E 是第 2 步第一行的到期张数、列过没判张数、这次列的张数；G 是第 3 步第一行「这一周轮到」的条数；H、I 是第 5 步第一行的越线条数与这次列的条数。
- **候选句**那一行照「候选句」一节的结果，五种写法取一种，有部分重合没起草的，照那一节在末尾接一句；F 是 `$tmp/触发` 的行数。
  「原料不齐」不碍这一行：候选句不用「周一」的原料；工作区的 `docs/adr/` 不是 `origin/main` 上的那一种除外，那时第一道门那段也会打出来。
- **id** 是本块日期加序号，后面的 PR 引一条候选就引这个 id。顺序：第 5 步条件探针越线的那几条最前，再是第 2 步到期清单那几张，再是第 3 步轮到的死亡条件（都按命令打的顺序），再是「新增」「消失」（各按文件里的顺序）。
- **欠条**一栏只写记法：`<编号> 第 <行> 行`，有短名字的写 `<编号>「<短名字>」`，死亡条件照第 3 步打的写（可能是 `<编号> 主文件第 <行> 行`）；
  到期清单按这一栏认「列过」（「周一」(b) 第 2 步）。编号照文件名写，`ADR-01` 到 `ADR-09` 带前导 0，
  与第 2、3 步命令打出来的一样；「新增」与第 2、3 步进来的写本跑上的行号，「消失」写一周前那棵树上的。候选那一句里提到别处，随便怎么写都不碍去重。
- **值**只有三态：查到的值本身、`没查到`（查了，没有）、`无从确认：<原因>`（查不了）。缺的值不留空，也不写成 0。
  (b) 进来的：条件探针越线的写 `越线：<命令打的算出来的那一段>`，后面原样接命令打的标记（如「 · 列过没判」）；到期清单那几张写 `登记 <登记日>`，后面原样接命令打的标记（如 `登记 2026-10-15 · 列过没判`），
  轮到的死亡条件写 `轮到`，「新增」写 `新增`，「消失」写 `消失：一周前在 <前 7 位> 上`。
- **人判**例程永远留空，由需求所有者判；不填就是没判。认这几个词：
  - 欠条那几行（到期清单、「新增」，条件探针越线的欠条）：**还**（该还了，当周开工还它）、**收尾**（不做了，为什么由他说）、**留**（再挂四周，只许一次；标着「续挂过，只能还或收尾」的不能再留）。
    没判的，到期清单下周照列。判了的照判落状态行：还 —— 当周开工，还上它的那条 PR 写已还；收尾 —— 下一条欠条 PR 写收尾行，出处是这一块；
    留 —— 下一条欠条 PR 写续挂行，到判的那一块日期加 28 天。
  - 死亡条件与「消失」那几行（条件探针越线的死亡条件也是）：**接受**（死亡条件：条件成立了，那条规则该撤或退，当周开工；消失：这张不该没，当周查）、**拒绝**（还没成立；消失得没问题）。
    没判的死亡条件四周后轮到再列。
  - 他可以在合并前自己填，也可以由开这条回访 PR 的会话或协调会话照他的原话代笔填（ADR-151 历史文件第十九节，2026-11-16 那次就是这样填的），
    代笔的在 PR 上留一句出处（他在哪里说的）。合入就是他拍板的痕迹。
- **没有候选**就只写一行 `| — | — | 无候选 | | |`；这一行的「值」与「人判」空着是格式本身，不算缺值。
- **做不了的时候**：「周一」开头那道门打了「原料不齐」，或 (b) 整段做不了（比如浅克隆），原料那一行只写 `无从确认：<原因>`，
  候选表只写一行 `| — | — | 无从确认：<原因> | | |`。「无候选」是查了、没有，不拿它顶。
- **候选那一句**不写「重启条件」紧跟冒号，也不写加粗的「什么条件下……」紧跟冒号 —— 欠条台账从 `docs/adr/` 里按这两种写法抽条件，
  照抄进台账就多出一张假欠条。要提条件，写「条件是……」。
