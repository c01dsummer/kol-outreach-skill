# 回访说明书

> 回访例程照这一份做。例程本体在需求所有者的 claude.ai 账户里，它的 prompt 只有一句「克隆后读 `docs/REVISIT.md` 照做」——
> 规则只在这里，不在 prompt 里，也不在 `.github/` 下（转发文件不装内容）。
> 为什么有它、各条归哪一档：ADR-151。台账本身与一块的格式：ADR-152。

---

## 能写什么

- **只写一处**：在回访台账 ADR-152 末尾追加一块，开一条只改这一个文件的 PR，分支 `claude/revisit-<YYYY-MM-DD>`（例程跑的那天）。
  台账里已有的块一个字不改。
- **永不改** `process/`、`scripts/`、`docs/requirements.json`、`.github/workflows/check.yml`，也不改台账以外的任何文件。
- **不替人下结论**：不给任何记录写「采纳」，不标欠条已还，不判死亡条件，不合并、不批准自己的 PR（ADR-80、ADR-86、ADR-151 第四节第 2 条）。
  候选表的「人判」栏永远留空。
- **候选只从本文写明的来源取。** 本文没写的来源，不自己去找。没有候选也照样写一块，候选表只有「无候选」一行 —— 这一块就是心跳。

## 每次开始

1. **核不是浅克隆**：`git rev-parse --is-shallow-repository` 应为 `false`。是 `true` 就 `git fetch --unshallow`；
   做不到，本块里所有要翻历史才得出的值都写「无从确认：浅克隆」。
2. **找上一块**：主干上 ADR-152 里最后一个以真实日期开头的块标题，即 `grep -nE '^## [0-9]{4}-[0-9]{2}-[0-9]{2} · 本跑 '` 的最后一行；
   那条记录第一节格式里尖括号占位的那一行不算。
3. **定上周结果**，四个 token 取一个、原样写：
   - `已合入`：上一条回访 PR 合进了主干，上一块就在主干的台账里
   - `所有者关闭`：上一条回访 PR 没合就被关了，关的不是例程
   - `例程关闭`：上一条回访 PR 到这一跑还开着 —— 例程把它关掉，留一句评论「过期，由 <本块日期> 那一块接替」，本块写这个
   - `无从确认`：读不到上一条回访 PR 的状态；台账里还没有上一块时也写这个，后面注明「没有上一块」
4. 结果是 `已合入` 时，数主干上那一块：候选几行（「无候选」那一行不算）、「人判」栏里几个「接受」、几个「拒绝」，写进同一行；
   不是 `已合入` 时三个数都写「无从确认」。
5. 本块小标题里的「本跑」写这次克隆到的主干提交：`git rev-parse --short=7 origin/main`。

## 一块怎么写

格式只在 ADR-152 第一节，照那个形状写，这里不另抄一份。
