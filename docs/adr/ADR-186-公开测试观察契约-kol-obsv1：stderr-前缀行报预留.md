## 一、原文放在哪、名字从哪来

原文是 `skill/references/output-format.md` 最后那一节「测试观察用的 stderr 行与保存失败注入（契约 kol-obs/v1）」，从那一行起到文件末尾，字节与上面那个 SHA256 对得上。它接在「收尾输出」后面、用三级标题，是确认时就定的位置与写法；README 只有一句指过去，不另说一遍。

行前缀 `KOL-OBS `、契约名 `kol-obs/v1`、开关 `KOL_OBS_EVENTS`、控制文件 `.kol-save-fault.json` 与它的 `kol-save-fault/v1`、四种记录名、五种被拒原因，都是写原文的人起的，随原文一起确认。要改其中任何一个，就是改契约：先改原文、再经需求方确认，`kol-obs/v1` 跟着换版本。

## 二、实现怎么对上原文

| 原文 | 实现 |
|---|---|
| 就绪行「读取任何输入（命令行参数、配置、`task.json`）之前」 | 三个入口 import 之后的第一句 `obsReady(...)`；collect 读注入文件排在它后面 |
| 预留行「每一次预算预留尝试写一行，成没成都写」 | 三个入口的预留都经 `Budget.reserve`，那里一处写：成了的在保存回调之后、返回去发请求之前；被拒的在抛出的那一刻 |
| `scope` | 看入口，不看账：collect、enrich 是 `task`，probe 是 `process`。账坏了的时候账上的 `scope` 读不出，按入口才总写得出 |
| `attempt_id` | 预留之后账上那笔未结预留的序号；只在 `task` 且 `reserved` 时写 |
| 五种原因 | 抛出点当场标上：根预算与账上上限对不上（账本身认得、合起来不可用）→ `root-conflict`；账缺席、坏、版本认不得 → `ledger-unavailable`；账上有未结预留 → `pending`；额度不够付这一次 → `budget`；这次预留存不进、或本跑早先已有保存失败 → `save-failed` |
| SP-R、SP-200、SP-N200、SP-NS | `Budget` 每次调保存回调时说明这是哪一次：预留之后是 SP-R；结算之后按结果分，HTTP 200 是 SP-200，别的 HTTP 状态是 SP-N200，没拿到状态是 SP-NS。collect 的回调先问注入、再写盘 |
| SP-BUD「注入时作者文件和 `task.json` 都不写」 | collect 收尾那次 `stopped === 'budget'` 的保存先问注入，抛出时两样都还没写 |
| 「和磁盘写失败走同一条路」 | 注入就是在保存的位置抛一个错：前四个点经 `Budget` 记成 persistence-failed、锁住本运行，与真的写盘失败同一个 catch；SP-BUD 与那次保存真失败一样从 `main().catch` 退 1 |
| 未命中记录「退出时如果注入一直没生效」 | 读到注入文件就挂 `process.on('exit')`，`process.exit` 的各条路都经过它 |
| 「只写 stderr」 | 同步写 fd 2：入口出错会立刻 `process.exit`，排队没写出去的会丢；与 `console.error` 同一个 fd，次序就是调用的次序，预留行因此排在那次请求之前 |

两样都关着时，`obs.ts` 除了看一眼 `.kol-save-fault.json` 在不在，什么也不做；`Budget` 多出的那一步也只是算单价、问序号，不碰盘、不改账。

## 三、为什么不登需求登记表

登记表里的判据说的是用户拿到什么。这份契约在平时一个字节都不改变用户拿到的东西，它是给测试看的接口，和 ADR-70 的观察器同一类，只是一半长在入口里。需求方逐字确认的是对外文档里的原文，验收的对象是那段原文，不是一条新编号。

控制文件放进去，collect 会照它让一次保存失败。这是对外可见的行为，所以原文写明了「平时使用不需要、也不应该放这个文件」，README 也说了一句。哪天评审认为这一面也该有一条判据守着，就走 `process/2-CHANGE.md` 补登，不在这里替它定。

## 四、做不到字面的几处

> ⚠️ 欠条：原文「入口给人看的提示从不以 `KOL-OBS ` 开头」只在提示不以用户给的文字开头时成立。现在有几句提示是把用户给的东西放在行首的，比如 probe 配置出错时那句以配置路径开头，collect 出错时 `main().catch` 原样打出的报错。用户真把路径起名成以 `KOL-OBS ` 开头，那一行也会以它开头，按前缀剥掉的就多了一行。正常使用碰不到；测试观察用的路径都是观察器自己起的 · 来源：本条作者自记 · 档：登记 · 重启条件：下次有改动碰到这几处报错的写法，或同一缺口被点名，先到为准

> ⚠️ 欠条：原文「每一次预算预留尝试写一行」有两种尝试写不全。一种是价目里没有的端点，算不出单价就不写这一行（预留照样抛 `unknown-price`）。另一种是运行时缺精确 JSON、尝试序号到顶，这时写成 `ledger-unavailable`，那是五种里最近的一种，字面并不贴。两种都只在实现有缺陷或运行时不对时出现，调用方现在走不到 · 来源：本条作者自记 · 档：登记 · 重启条件：下次有改动碰到 `scripts/lib/budget.ts` 的 `reserve` 或价目表，或同一缺口被点名，先到为准

被信号硬杀的那一跑不经过 `exit`，没有未命中记录。原文说的是「退出时」，硬杀不算退出，不另登。
