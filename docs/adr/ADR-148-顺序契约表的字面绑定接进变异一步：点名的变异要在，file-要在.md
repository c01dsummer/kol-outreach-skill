## 一、为什么建、为什么是这个样子

ADR-78 撤 `arch-sync.ts` 时把三件事的去向逐件说了（ADR-78 第 38–49 行），第三件「ORDER 表绑变异」跟着一起没了，改法写在它的重开条件里：「把『ORDER 表每行绑一条变异』接进 `mutate.ts`（它本来就读 `mutations.json`），让绑定和变异跑在同一个地方」（第 72–74 行）。那条重开条件的字面（「出现一次没有变异守着的行，而且它真的坏了」）没有成立；本条是按需求所有者的裁决建的，不是那一条响了（ADR-145 第 760 行：「照判据该有、实际没有，不是眼下有错」）。

它该建，因为它替代的是「跑」：判据写得成一条命令，ADR-78 第 93 行就是那条命令（`process/README.md`「替代『读』的那些不要建」一段的两问）。它也不该拿撤闸门那把尺子量：两个东西之间近乎零维护、近乎不误报的机械关系不在那把尺子的量程里（同一份文件同一节；ADR-81）。

放在变异那一步、而不是另起一步，理由有两条。一是 ADR-78 说的：变异一步本来就读变异目录，绑定和变异跑在同一个地方，改了变异的人在同一步就看见。二是读变异编号的消费者不多出一个：变异一步开跑前先拦重复编号（`attribution-rule.ts`），绑定排在它后面，按编号查不会查到两条同名的里面错的那一条（ADR-78 第 42–46 行说的正是旧闸门抢在前面时的这个毛病；ADR-34 第 3–7 行那张欠条说的「第三处读变异编号的消费者」也就不出现）。

判定放在新模块里、不放在 `mutate.ts`：`mutate.ts` 是自检的工具种子，施在它上面的变异要么被「自己验自己」拦下（指名自检），要么抓不到（需求测试只读它的源码、不起它的入口）—— 同 ADR-145 第 946 行那句。所以截表、切行、切格、认编号、展开区间、比位置，全在纯函数里；入口只读两个文件、把裁定翻成人话、设退出码（`docs/CONVENTIONS.md` 第 145–151 行：扫描范围被悄悄缩小和判定写错一样致命，所以它也是判定）。

## 二、判什么：字面规则

输入是 `docs/ARCHITECTURE.md` 的全文与变异目录（每条的 `id` 与 `file`）。行号是全文的行号，从 1 起，按 `\n` 切；每行末尾的 `\r` 先去掉。下文的「空白」都指 JavaScript 认的空白字符（正则 `\s` 那一类，含全角空格）；「一串」都是至少一个。

### 1. 截出那张表

- `BEGIN:ORDER` 与 `END:ORDER` 这两段字（子串，不要求独占一行）在全文里**各恰好出现一次**，且 `BEGIN:ORDER` 的位置（按字符偏移）在 `END:ORDER` 之前。否则只报一条「起止标记不对」，带两段字各出现几次，不往下看。
- **表的范围**是含 `BEGIN:ORDER` 的那一行之后、含 `END:ORDER` 的那一行之前的各行（两段字在同一行时范围是空的）。
- 范围里每一行分三种：**空行**（只有空白）、**表格行**（第一个非空白字符是 `|`）、其余叫**散行**。
- **表头**是范围里的第一条表格行；**紧接着的下一行**必须是分隔行：一条表格行，每一格都由一串 `-` 组成、两头各可带一个 `:`，至少一格（格数不必与表头相同）。表头的各格里恰好有一格是 `位置`、恰好有一格是 `守它的变异`（整格等于这两个词）。没有表格行、紧接着的不是分隔行、表头没有恰好一个 `位置` 或恰好一个 `守它的变异`：只报一条「表头不对」，不往下看。
- 表头与分隔行以外，范围里的每条表格行是一行**数据**；每条散行报一条「散行」，带行号。空行不管。

**切格**：去掉这一行第一个 `|` 及它前面的部分；剩下的去掉行尾空白后若以 `|` 结尾，去掉那个 `|`；再按 `|` 切开，每格去掉首尾空白。`| a | b |` 与 `| a | b` 都是两格 `a`、`b`；`|a||b|` 是三格，中间一格是空的。

### 2. 一行数据怎么核

- **格数**与表头不同：报一条「格数不对」，带这一行的格数与表头的格数，这一行别的不看。
- **位置**是「位置」那一格里每一对反引号之间的文字，原样（不去空白），可以有好几个：反引号从左起两两配对，落单的最后一个不算，两对之间的文字也不算；一个反引号也没有就是空的。
- **守它的变异**那一格切成**词**：分隔符是空白与这几个字符 `、，；：。,;:（）()「」`，空词丢掉。每个词归一类：
  - **一个编号**：整个词是 `M-` 加一串大写字母加一串数字加 `-` 加一串小写字母，比如 `M-D16-ab`、`M-H47-a`。
  - **一个区间**：整个词是一个编号紧跟 `…`（U+2026）或 `–`（U+2013）再紧跟一串小写字母，并且后面那串**排在**编号末尾那串**之后**（顺序：`a` 到 `z`，再 `aa` 到 `az`、`ba`……，即把字母串当成没有零的二十六进制数比大小）。展开成从起点到终点的每一个编号，含两端，从小到大。`M-H47-a…n` 是 `M-H47-a` 到 `M-H47-n` 十四个。
  - **写错的**：不是上面两类，可词里含有 `M-` 或 `m-` 后接一串字母（大小写不限）、一串数字、一个 `-` 的片段，或者含有 `…`、`–`。比如 `M-D6-C`、`m-d6-c`、`M-H47-a2`、`M-D26-a-i`、`M-D26-a…M-D26-i`、`M-H47-n…a`、`M-H47-a…a`、单独一个 `…`。每个报一条「写错的」，带这个词。
  - **散文**：其余的词，不管。
- 这一行读出来的**编号**是各个词依次给出的编号（区间按展开顺序就地放进去），同一个编号在这一行里第二次出现起不再算。
- 一个编号也没读出来（不论有没有写错的词）：报一条「这一行没点名变异」。
- 否则逐个编号：变异目录里没有这个编号，报一条「不在」，带编号；有（目录里同一编号有好几条时以第一条为准 —— 重复由变异一步更早的体检拦下），而它的 `file` 不等于这一行位置里的任何一个，报一条「不在位置里」，带编号与那条变异的 `file`。区间里缺了号，缺的那几个就报「不在」（同 ADR-78 第 93 行）。

### 3. 报出来的先后

全部问题按行号从小到大排；同一行里，先是各个「写错的」（按词的先后），再是「这一行没点名变异」或逐个编号的「不在」「不在位置里」（按第 2 小节读出来的先后，不按编号的字面排序）。截表那一步的三种（读不到文件、起止标记不对、表头不对）各自只有它一条。一处都没有就是空的 —— 只有空才算对得上。

## 三、不判什么

- **守不守这一行。** 一条变异算不算守一行，按 ADR-146 第一节看施加之后的后果（拿掉一步、先做后拒、调换先后），那是读，不是跑。本条只核「点名的变异在、`file` 落在位置里」；`file` 落在位置里只说明它是候选（ADR-78 第 85 行）。所以：**一条存在、`file` 也在位置里、却不守这一行的变异，照样对得上**（`process/4-VERIFY.md`「什么东西能在事实不成立时，也让这个检查通过」）。
- **漏列。** 往某一行的位置里的文件新增了守这一行的变异、表上却没点名，本条不知道（ADR-78 第 85 行，同一个理由）。
- **反方向。** 位置里的文件有没有一条点名的变异指着它，不核；今天 31 行里有 11 行的位置栏有点名变异都不指着的文件（比如第一行的 `mutate.ts`，那一行第四格自己写明那一段由独立真实入口负测试守），那是那一行的写法，不是错。
- **散文里的编号。** 文法认不出的写法看不见：`M-D21-w、x` 这样的简写里 `x` 是散文；只写一个家族 `M-H47` 也是散文。写错的那一类只兜得住「长得像编号、又不完全是」的词。
- **变异的 `file` 在不在磁盘上。** 那是变异一步施变时的事（锚点失效）。
- **锚点表覆盖。** 需求所有者定了不建；ADR-145 第 762 行那张欠条的这一半照旧挂着，重启条件不变。

## 四、接口

写测试的上下文只读这一节、第一到第三节、第七节与 `process/4-VERIFY.md`；不读 `order-rule.ts` 的函数体。

```ts
// scripts/check/order-rule.ts
/** 变异目录里与绑定有关的两样 */
export interface OrderMutation { readonly id: string; readonly file: string }

/** 第二节的各种问题；line 是 docs/ARCHITECTURE.md 里的行号（从 1 起） */
export type OrderFault =
  | { readonly kind: 'unreadable' }                                    // 文件读不到（入口交 undefined）
  | { readonly kind: 'markers'; readonly begins: number; readonly ends: number } // 起止标记不对：两段字各出现几次
  | { readonly kind: 'header' }                                        // 表头不对
  | { readonly kind: 'stray'; readonly line: number }                  // 散行
  | { readonly kind: 'shape'; readonly line: number; readonly cells: number; readonly expected: number } // 格数不对
  | { readonly kind: 'malformed'; readonly line: number; readonly text: string } // 写错的词
  | { readonly kind: 'empty'; readonly line: number }                  // 这一行没点名变异
  | { readonly kind: 'unknown'; readonly line: number; readonly id: string }   // 不在
  | { readonly kind: 'off-site'; readonly line: number; readonly id: string; readonly file: string } // 不在位置里

/** 按第二节核整张表；返回第二节第 3 小节的先后。纯函数，不读文件、不起进程 */
export function orderBindingFaults(doc: string | undefined, mutations: readonly OrderMutation[]): OrderFault[]
```

返回值里每种问题恰好带上面写的那几个字段，不多不少；字段的书写先后不算契约。

## 五、接在哪、怎么报（第二片）

- **位置**：`mutate.ts` 开跑前那几道变异集体检的最后一道 —— 点名的夹具立得住之后、`--brief` 之前。排在重复编号之后，理由见第一节；排在「自己验自己」与清册之后，按那一段注释的由粗到细：前几道判的是一条变异的证据算不算数、记在谁名下，这一道判的是一份文档对变异目录的说法，最细，放最后。它在 `--brief` 与 `--worker` 下照样跑，同前几道。
- **读**：入口读 `docs/ARCHITECTURE.md`，读不到交 `undefined`；变异目录就是开头已经读进来的那一份。
- **报**：有问题就以 1 退出、不施任何变异，同前几道体检的形状：一行 `✗ 变异集：顺序契约表有 N 处与变异目录对不上 —— …`，逐条一行 `第 <行号> 行  <这一条的话>`，末尾一行改法，并写明这里只核点名的变异在不在、`file` 在不在位置栏里，守不守这一行要人按后果判（ADR-146 第一节）。每种问题的话由入口按种类说（`docs/CONVENTIONS.md` 第 10 条）。
- **自检**：变异一步的玩具树今天都没有 `docs/ARCHITECTURE.md`，接上以后它们开跑前就会因为读不到文件被拦下。所以第二片给每棵会走到这一道的玩具树写一份最小的 `docs/ARCHITECTURE.md`（起止标记、表头、分隔行，没有数据行）；`claims-restoration-entry` 拷的是真的 `docs/`、换的是一份玩具变异目录，那一份也要换成最小的。再加一棵玩具树证明接线：表上点名一条不在的变异、一条 `file` 不在位置里的变异，`mutate` 以 1 退出、两条都报、目标文件一个字没改；`--brief` 同样拒。

## 八、死亡条件
