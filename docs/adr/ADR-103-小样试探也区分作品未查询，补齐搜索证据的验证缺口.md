# ADR-103 小样试探也区分作品未查询，补齐搜索证据的验证缺口

- 日期 · 2026-09-23 · 接续交付表作品三态的合入后审查
- 类型：事实证伪与需求补充
- 触发它的事实：`probe` 的作品未查询仍被印为空串；现有补齐测试只从旧记录起步，未覆盖本轮新建记录再被命中的路径；文档把空文案和搜索样本说成了更强的证据。
- 冲击的需求：P1.e、P1.i（新增，细化 P1 对小样试探输出的约束）、F3、F4
- 结论：采纳。先固定输出契约，再写验证，最后修改输出；不改变评分、分层与搜索请求。
- 理由：Agent 用小样试探输出判断关键词方向；缺失作品不能伪装成已取得作品但文案为空。搜索命中的文案不能冒充主页最新作品样本。
- 连带改动：需求登记表与生成的 SPEC、架构缝隙契约、试探入口、需求测试与自检、变异、Skill 示例与输出说明；ADR-102 只追加更正和可检索欠条。

## 输出与证据边界

`probe` 的 `sample[].top_post`：作品字段缺席或旧空数组 → `（未查询）`；有作品 → 第一条文案的前 120 字符；第一条文案为空串 → 空串。保留现有第一条口径，不改成挑最高播放量。

`best_post_desc` 的空白只说明所选作品的文案值为空。适配层当前把缺失文案也归为空串，不能从它反推作者没写文案；将文案改为可选是另一项工作，欠条追加在 ADR-102。

语义判断只对实际见到的搜索命中作品作陈述，不称为「最近十条」，不从这个偏置样本推出整个人的近期发帖构成。

## 事前验证约束

- 补齐测试必须从空累加器连续合入两页：先没有作品，再取得作品。第二次合入不增加人数、保留两次来源、作品补齐；不能靠手造旧记录代替本轮新建记录。
- 最高播放作品放在样本中间，让「取最后一条」无法冒充正确结果。
- 试探输出用假响应从入口运行，逐条检查未查询、空文案、有文案与截断；先在未修改入口上观察缺失状态断言失败。
- 新变异使用未占用编号：`M-P1-y` 守本轮新建记录补齐，`M-P1-z` 守小样试探未查询。沿用的历史复用编号在 ADR-102 追加消歧，不再改它们的含义。

这批改动回答同一个问题：传给 Agent 和交付表的作品证据，是否被准确表达并有验证守住。作品 id 并集、图文样本口径与分页接线各自另做；它们需要额外来源证据或产品决定。

## 2026-09-23 验证与独立复核

修改入口前，`npm run selfcheck -- --only=probe` 的「小样试探：未查询作品明确显示未查询」失败：
预期 `（未查询）`，实际为空串；空文案、首条文案与截断断言通过。修改入口后，独立上下文运行同组自检通过，
并核实新变异的失败标签唯一归属 `probe`。独立复核未参与实现，未发现本改动的阻塞问题。

入口不读盘上旧记录，当前搜索生产者也不产生空作品数组，因此入口自检未伪造该不可达输入；
空数组与字段缺席的共同分支由代码复核，交付表旧空数组另有需求测试。不能把这一限制说成入口端到端已覆盖。
