# ADR-59 分支寿命从第三层提到第二层

`process/6-INTEGRATE.md` 一开始把「分支活不过 48 小时」放在第三层,理由写的是
「仓库里查得到,但该不该红是人的判断」。

**那句话不成立。** 该不该红确实是判断 —— 而这类闸门本来就有一条给判断用的
通道:具名豁免。说不出理由的长命分支,和说得出理由的长命分支,不是同一回事;
逼着把理由写下来,正是体量闸门在做的事。把它留在第三层,等于用「有判断成分」
换掉了「能报错」,而这个仓库的判据是反过来的:

> 每一条你真正在乎的纪律,能变成检查就变成检查 —— 散文里的纪律是期望,
> 能报错的检查才是保证。(`docs/CONVENTIONS.md`)

## 战绩摆在仓库里

写这条 ADR 时,三条在途分支各自分叉 91.5 / 91.5 / 102.8 小时,彼此 92% 相同,
都碰同一批 23 个文件,而这期间**没有任何东西说过一句话**。体量闸门管得住
「一次改动多大」,管不住「一条分支开多久」——后者才是让三条分支互相重写
同一批文件的那一个。

## 阈值不是拍的

| | 提交 | 分叉时长 |
|---|---|---|
| 已合并 PR #1–#4 | 2–9 | 0.3–1.3 小时 |
| 已合并 PR #6 | 34 | 22.9 小时 |
| 在途三条 | 18–23 | 91.5–102.8 小时 |

48 小时对最长的健康分支有一倍余量,对三条出事的分支只有一半 ——
落在这两组数之间的空档里。校准方式和体量阈值同一条:量自己的历史,不抄别人的。

> ⚠️ 就地更正（ADR-64 之后）：这张表把 #6 列进了健康组，48 小时是按它留一倍余量定的。复盘 15 条
> PR 之后 #6 归到另一类：分叉 22.9 小时在线内，却吞了 22 轮评审、52 条豁免，源码长到开 PR 时的
> 近三倍；#7 同形。分叉时长在线内、评审也没让它长大的一组是 #1–#4 与 #8–#15，全部在 2.2 小时内合入；
> 其中 #10、#12 是先合再审，#10 让主干带着一个静默错跑了一个多小时，重新校准时不能当健康样本。
> 48 小时仍是红线，不是目标 ——
> 这条闸门量的是分叉时长，量不到评审中长了多少，那在 `process/6-INTEGRATE.md`「评审中的发现」
> 一节。阈值要不要收紧，等那一节跑出数据再另立记录。`age-rule.ts` 文件头的表同步改了。

## 三个取舍

**量分叉时长,不量「最后一次提交距今多久」。** 后者量的是活跃度。一条天天在
提交、却四天没合的分支,正是这条纪律要拦的东西,而按活跃度算它永远是新的。

**用作者时间,不用提交时间;再和一个改写不了的锚取更早的一个。** 提交时间被
rebase 重写,拿它计时等于留下一条「rebase 一下就免检」的通道。但作者时间只挡得住
普通 rebase —— `git commit --amend --reset-author` 一句就能把一条两百小时的分支
洗成 0 小时(实测)。所以出生时间再与 **PR 的创建时间**取更早的一个:那个时间在
服务端,改写不了。

**这把锚买到的东西要说准。** 它按得住 PR 开出来**之后**的改写;PR 之前就把作者
时间洗新的话,两个时间戳都是新的,它按不住。而如果干脆另开一条分支把改动搬过去,
那东西在服务端**每一个可观测量上都是新的**(新 ref、新提交、新 PR),和一条真正的
新分支之间没有可量的差别 —— **「再找一个更可靠的时间戳」这条路没有尽头。**

所以这条闸门是**纪律工具,不是防作弊装置**。它挡的是无意养出来的长命分支;
存心要绕的人,写一行 `age-ok:` 比重写历史便宜得多,而那条路本来就是给他留的 ——
留下的还是一句能被读到的理由。这一段写在这里,是因为上一版我在同一个位置写了
「改写历史只能让分支显得更老,不能更年轻」—— **那句话太满了**,评审当场指出来。
同一轮 PR 里这种事发生了四次(见 `docs/CONVENTIONS.md` 第 11 条):
**能报错的检查,保证不了描述它的那句话还是真的。**

其余缺口:没有 PR 的分支没有这个锚,`--all` 那条路上作者时间仍是唯一的钟;
把一个很老的提交 cherry-pick 到新分支上会报得偏老 —— 那是故意的,那段工作确实
在主干之外待了那么久,报告里点名那个提交。

> ⚠️ 上面「`--all` 那条路上作者时间仍是唯一的钟」那一句已被 ADR-61 改掉:有开着的
> 同仓库 PR 的分支用 PR 创建时间当锚,没有 PR 的仍只有作者时间,报告里逐条标出。
> 实测这处缺口在同一条分支上少报了 10.7 小时 —— 它不只是缺口。

出生时间取的是分支上**所有**提交里作者时间最小的那个。早先取的是
`rev-list --reverse` 的第一条,而 `rev-list` 默认按**提交**时间排 —— 于是同一个
cherry-pick 反而会让分支显得**更年轻**:实测一条含 250 小时前工作的分支报
`✓ 分叉 1.0 小时`,**不是量错,是根本没量到那一条**。

**豁免不设新鲜度。** 体量豁免会过期,是因为「之后又加了行」是一个能观测的事件;
分叉时长没有这种事件,唯一的变化是时间本身流逝。拿时间做新鲜度,等于要求一条
在等评审的分支不断补提交才能保持绿 —— 而它多半没有真东西可提,剩下的只有空提交:
一串只为让检查变绿而存在的提交,历史里全是噪音。代价是一条豁免管一整条分支,所以**报告里那个小时数照打**,
豁免与否都打:豁免让它别拦路,不让它消失。

**豁免用提交信息里的一行,不用决策记录。** 这条规矩最早写的是「写一条决策记录
说明为什么合不了」,当时没有别的通道。但决策记录是留给**活得比分支久的决定**的:
它有不可回收的编号,下游会引用它。而「这条分支为什么还没合」活不过这条分支 ——
合完就没了,留在 `docs/adr/` 里只是噪音。换成分支自己历史里的一行,它跟着分支生、
跟着分支死。`process/6-INTEGRATE.md` 那句话同步改了,否则**机器保证比散文规矩弱**,
而一条写着 A、查着 B 的规则,正是这套方法最反对的东西。

**「跟着分支死」有一处不成立:直接叠在一条没合的分支上开出去。** 实现上豁免只扫
第一父链,而叠出来的分支,下面那条的提交本来就在它的第一父链上 —— 于是 B 继承了
A 那句 `age-ok:`,自己一句话没说过。这和前面两轮是同一个死结:**提交图分不出
「叠上去」和「这些提交本来就是我写的」**,分得出的事实只有「这条 PR 的 base 是谁」,
而它跟 `AGE_PR_HEAD` 一样只在调用方手里。

这一轮没有去接那个事实(要动工作流、要动三条路,而这条分支已经该合了),
改成**把它变得看得见**:报告里点名那句理由写在哪个提交上。继承来的那一句,
写它的提交不属于这条分支,一眼就看得出来。在一个临时仓库里实测(这个仓库
造不出叠分支这个形状):B 叠在 A 上,报 `⊘ 已具名豁免(写在 36f8a1d 上)`,
而 `36f8a1d` 是 A 的提交,不在 B 自己写的那几条里。

**这是「看得见」,不是「挡得住」,两者不要混为一谈。** 挡得住要等把 base 也从调用方
传进来 —— 和下面那张关于变异的欠条一样,写在这里,不假装它被保证了。

> ⚠️ 这张欠条已由 ADR-63 还上:三条跑法都从调用方拿 PR 的 base,base 里已有的提交不算
> 这条分支自己的。没有 base 的跑法、叠分支对着主干开的 PR、下面那条里带豁免的提交被
> 改写过 —— 这三处仍按不住,记在那条记录里。

**时间型的判据要配时间型的触发。** 只把闸门接进检查链是不够的:检查链由
`push` / `pull_request` 触发,而分叉时长自己会长。一条停在 47 小时通过的分支,
没人碰它,第二天就过线了 —— 却不会再触发任何一次检查。**恰好是这条闸门要拦的
那种分支(没人动的那种)最容易漏掉**:三条在途分支停了四天、一次推送都没有。
所以另加一个每天跑的 `age.yml`。它做两件事,因为**它们出现在不同的地方**:

- `--all` 扫全部远端分支,红在 Actions 里 —— 看得见仓库现在什么样
- 每个开着的 PR 各贴一条 check run 到**它自己的 head SHA** 上

第二件不能省。GitHub 的合并闸看的是 PR head 那个 SHA 上的检查,聚合任务红在
主干的 SHA 上,**不会让那条绿失效** —— 聚合红着,PR 照样能合。

最后一步不在代码里:要真正挡住合并,得在仓库设置里把 `age` 加进 required status
checks。**不加的话它只是可见,不是闸门。** 这一条明写在这里,因为它正是这套
方法最容易骗自己的地方 —— 建好了一个能报错的检查,就以为它拦得住。

**新加一道闸门,没有任何东西要求它配变异。** 这套判定的测试当初只写到两拍
(红 → 绿),第三拍 ——「给这条新测试配一个变异,当场确认它会红」(`process/4-VERIFY.md`)
—— 漏了,评审指出来才补上六个。漏的原因是结构性的:`npm run audit` 只对**产品红线**
强制「有测试 + 有变异」,而闸门自己的需求不在需求登记表里;`docs/SYNC.md` 里离它最近的
两行 ——「新增红线」和「新增可执行文件」—— 一行只管产品红线,一行只问「这个文件有没有
出处」,都不问它有没有变异。于是这一次靠的是评审,不是检查。

补上的六个变异各对着一条判定:拒答未来的作者时间、48 小时这个阈值本身、那把锚、
理由必填、豁免只认末尾指令区、拒答排在豁免前面。两张同步表也各加了一行。

**但「每个判定文件都得有变异」本身还不是一条能报错的检查。** 现在把它接上,就要连
`adr-rule.ts` 和 `size-rule.ts` 的变异一起补 —— 而这条分支已经该合了,这正是这条
闸门要拦的那件事。所以它是一张写在这里的欠条,不是一个保证。

> ⚠️ 这张欠条已由 ADR-62 还上:`npm run audit` 对 `scripts/check/` 下每个判定模块(不带
> shebang 的 `.ts`)强制有变异指向它,没有就硬失败;`adr-rule.ts`、`size-rule.ts`、
> `trailer.ts`、`quoted.ts` 的变异也一并补上了。

## 已知会立刻变红的

三条在途分支合主干之后会当场红。这不是副作用,是这条闸门第一次说话 ——
它们本来就已经因为 `DECISIONS.md` 与主干冲突,必须先处理一次。
