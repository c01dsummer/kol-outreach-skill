# ADR-59 分支寿命从第三层提到第二层

`process/6-INTEGRATE.md` 一开始把「分支活不过 48 小时」放在第三层,理由写的是
「仓库里查得到,但该不该红是人的判断」。

**那句话不成立。** 该不该红确实是判断 —— 而这类闸门本来就有一条给判断用的
通道:具名豁免。说不出理由的长命分支,和说得出理由的长命分支,不是同一回事;
逼着把理由写下来,正是体量闸门在做的事。把它留在第三层,等于用「有判断成分」
换掉了「能报错」,而这个仓库的判据是反过来的:

> 每一条你真正在乎的纪律,能变成检查就变成检查 —— 散文里的纪律是期望,
> 能报错的检查才是保证。(`docs/CONVENTIONS.md`)

## 战绩摆在仓库里

写这条 ADR 时,三条在途分支各自分叉 91.5 / 91.5 / 102.8 小时,彼此 92% 相同,
都碰同一批 23 个文件,而这期间**没有任何东西说过一句话**。体量闸门管得住
「一次改动多大」,管不住「一条分支开多久」——后者才是让三条分支互相重写
同一批文件的那一个。

## 阈值不是拍的

| | 提交 | 分叉时长 |
|---|---|---|
| 已合并 PR #1–#4 | 2–9 | 0.3–1.3 小时 |
| 已合并 PR #6 | 34 | 22.9 小时 |
| 在途三条 | 18–23 | 91.5–102.8 小时 |

48 小时对最长的健康分支有一倍余量,对三条出事的分支只有一半 ——
落在这两组数之间的空档里。校准方式和体量阈值同一条:量自己的历史,不抄别人的。

## 三个取舍

**量分叉时长,不量「最后一次提交距今多久」。** 后者量的是活跃度。一条天天在
提交、却四天没合的分支,正是这条纪律要拦的东西,而按活跃度算它永远是新的。

**用作者时间,不用提交时间。** 提交时间被 rebase 重写,拿它计时等于留下一条
「rebase 一下就免检」的通道。代价:把一个很老的提交 cherry-pick 到新分支上会
误报 —— 报告里点名那个提交,人一看就知道。

**豁免不设新鲜度。** 体量豁免会过期,是因为「之后又加了行」是一个能观测的事件;
分叉时长没有这种事件,唯一的变化是时间本身流逝。拿时间做新鲜度,等于要求一条
在等评审的分支不断补提交才能保持绿 —— 那只能靠空提交,而空提交是这个仓库
明令不做的事。代价是一条豁免管一整条分支,所以**报告里那个小时数照打**,
豁免与否都打:豁免让它别拦路,不让它消失。

**豁免用提交信息里的一行,不用决策记录。** 这条规矩最早写的是「写一条决策记录
说明为什么合不了」,当时没有别的通道。但决策记录是留给**活得比分支久的决定**的:
它有不可回收的编号,下游会引用它。而「这条分支为什么还没合」活不过这条分支 ——
合完就没了,留在 `docs/adr/` 里只是噪音。换成分支自己历史里的一行,它跟着分支生、
跟着分支死。`process/6-INTEGRATE.md` 那句话同步改了,否则**机器保证比散文规矩弱**,
而一条写着 A、查着 B 的规则,正是这套方法最反对的东西。

## 已知会立刻变红的

三条在途分支合主干之后会当场红。这不是副作用,是这条闸门第一次说话 ——
它们本来就已经因为 `DECISIONS.md` 与主干冲突,必须先处理一次。
