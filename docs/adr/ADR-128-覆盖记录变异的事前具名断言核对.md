# ADR-128 覆盖记录变异的事前具名断言核对

- 日期：2026-09-29
- 类型：发现更优解
- 起点：PR #228 已合入的 main `07ce0a9a6df3782928b062beebb339cc615c58ea`；771 条变异中 707 条选组、64 条全跑。
- 结论：先核对下表 14 条覆盖记录变异与既有固定需求断言的对应关系。只有正常代码基线通过、隔离 worker 施变后指定名字失败且没有进程或夹具故障的条目才切换路由；未证成的继续全跑。
- 依据：`docs/ARCHITECTURE.md` 的覆盖记录合同（整棵源码指纹、新鲜度、形状、归属、写盘资格、错误分类和两份独立路径）及 `scripts/test.ts` 已有断言；验证资格按 `process/4-VERIFY.md`，可比成本按 `process/6-INTEGRATE.md`。
- 连带改动：实际证成的目录条目只加 `by: "test"` 和 `kills`；不改断言、组声明、依赖、执行顺序、清单条数、施变正文或检查步骤。

## 施变前确定的对应关系

下表从公开合同和现有断言确定，未从施变失败输出回填。所有断言属于现有无依赖的 `h-infra-rules` 组；这组已被其它变异使用。

| 变异 | 必须保持的性质 | 预定应失败的固定断言 |
|---|---|---|
| M-H14-b | 指纹覆盖被需求测试导入的业务实现 | 被 import 的实现也在 —— 改坏它就等于改了指纹 |
| M-H14-c | 指纹相同的合法记录仍新鲜 | 指纹对得上才新鲜 |
| M-H14-d | 断言失败的运行不得写认领 | 断言红过就不写 —— 没通过的运行不是证据 |
| M-H14-e | 变异运行不得拥有、清除或写入完整认领 | 变异运行不拥有它 —— 既不清也不写 |
| M-H14-f | 数组字段的形状必须核对 | 字段在但不是数组，同样认不出 |
| M-H14-g | 文件路径也是指纹的一部分 | 路径也算进指纹 |
| M-H14-h | 指纹递归覆盖子目录 | 子目录要走进去 |
| M-H14-i | 数组元素必须是字符串 | 数组里混进非字符串，认不出 |
| M-H14-j | 无法读取不得误报成尚未运行 | 权限不对，是这个路径读不了 —— 不是没跑过 |
| M-H14-k | 测试期间源码改变不得写认领 | 跑的过程中源码变过就不写 |
| M-H14-l | 缺失判据认领字段的记录不合法 | 缺判据认领那一栏，同样认不出 |
| M-H14-n | 缺失交点认领字段的记录不合法 | 缺交点认领那一栏，同样认不出 |
| M-H28-a | 两份认领必须有不同路径 | 两份记录不是同一个路径 —— 指到同一处就互相抹掉 |
| M-H28-b | 两份认领都必须留在可清理的缓存目录 | 两份记录都在 .check-cache 底下 |

覆盖记录模块是检查工具，但这里的验证者是独立需求测试，不是由该模块保护的自身 `selfcheck`。`M-H14-e` 涉及认领归属，须特别核对施变前后完整认领的原字节、inode 和修改时间；其它条目也不得覆盖或冒充全量 `npm test` 的认领。正常 `h-infra-rules` 基线在同一检查中只完整验证一次，再供本组候选复用。其它断言失败、崩溃、超时或夹具错误均不算上表的断言抓到变异。

PR #228 的一次成功 CI 中，64 条全跑的逐验证者经过时间相加约 800 秒；这不是 job 耗时、CPU 用量或本批收益预测。接入后须以同一源码、同一候选集合、固定 Node 和 worker 做有限全跑/选跑对照，再跑完整检查。已有变异和全部断言保留，独立自检与审计照常执行；局部对照不能证明完整 CI 的十五分钟中位目标。

## 十四条的实际核对与局部对照

代码提交 `a38a28d` 只给上表 14 条增加 `by: "test"` 和预定 `kills`，不改其施变正文、断言或组声明。正常完整 `npm test` 通过，现有 `h-infra-rules` 正常执行 70 条断言通过；后者未清除、覆盖或改写完整测试认领的字节、inode、mtime。随后同一份任务私有仓库中的真实 worker 逐条执行，14 条全得 `caught`，每条验证者自然退出 1，既无其它断言代领、崩溃、超时，也没有源码残留；完整认领原件继续保持不变。

有限对照从同一代码提交复制两份任务私有仓库，锁文件、测试、变异目录和施变正文逐字节相同。两侧都只临时加同一行环境开关到 `mutate.ts` 的选择函数；设 `KOL_COMPARE_FULL=1` 时强制交回全量选择，未设置时执行原选组路径。这个开关只存在于对照副本、不提交；两侧的 14 条 `kills` 与具名判定保持相同。两份副本的完整 `npm test` 各通过一次，选跑副本的 `h-infra-rules` 正常基线另通过一次，之后才施变。

Node 22.23.2、Darwin arm64、worker 1；两侧各预热一遍，不计收益。随后按全跑→选跑、选跑→全跑、全跑→选跑交错三对，每次 worker 自然收齐相同 14 个 ID 的 `caught`，源码还原。全跑验证者在全部具名断言失败后按既有机制提前停，选跑验证者以断言失败的退出码 1 自然结束。选跑副本的完整测试认领每次字节、inode、mtime 均不变。全跑副本的 M-H14-e 会在施变时清掉该副本的认领；worker 退出时原字节恢复，但 inode 与 mtime 不保留。对照副本与正式仓库隔离，不能把这项恢复说成全跑也未触碰认领。

| 同十四条直接 worker | 墙钟秒中位数（范围） | user+sys 秒中位数（范围） |
|---|---:|---:|
| 全跑 | 57.21（56.36–58.81） | 36.77（35.84–37.04） |
| 选跑 | 5.98（5.71–6.05） | 7.60（7.43–7.60） |

局部 worker 墙钟中位数减少 51.23 秒，约 89.5%。CPU 只计命令及系统归给它的子进程，不是 CI job CPU。十四条全跑的 14 次提前停止与选跑的 14 次自然非零退出均保留严格具名判定；以上六次不是完整检查耗时，也不外推十五分钟目标。最终四 worker 完整检查与 Linux PR CI 仍须在实际提交上通过。

## 完整检查接入核对

上述代码与对照记录所在提交 `0e574b4` 以 main `07ce0a9` 为可信比较起点，Node 22.23.2、Darwin arm64、4 worker 完整执行 `npm run check`，自然退出 0。771 条变异全部 `caught`；721 条选组、50 条全跑，仍为 71 种实际子集配置，各启动并通过一次正常代码基线，额外复用 650 次。完整需求测试、独立脚本自检与链路审计均通过；没有减少原检查步骤。Linux PR CI 仍须独立成功，局部三对测量不代表同类 CI 的 job 提速。
