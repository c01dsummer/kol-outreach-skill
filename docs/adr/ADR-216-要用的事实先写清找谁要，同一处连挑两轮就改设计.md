# ADR-216 要用的事实先写清找谁要，同一处连挑两轮就改设计

- 类型：加两条纪律（`process/3-BUILD.md` 第 8 条、`process/6-INTEGRATE.md`「同一处连着两轮被挑出毛病」一节），各在两层分法的第三层表里登记一行（`process/README.md`、`process/6-INTEGRATE.md`「这一层里,什么是机器保证的」）；业务层加一节本仓库的权威清单（`docs/CONVENTIONS.md` 第 13 条）；评审清单加一问（`REVIEW.md`）；术语表加两行。本条只改文字，三道检查另开，见第四节
- 触发它的事实：ADR-198 那道闸门（检查链新加的返回字段，没有一条被测试打红的变异守着就红）的第一片 PR，2026-11-17 合入前推倒重来过两次，两次是同一种错：

  2. 自己解析 `git diff` 给人看的正文找「新加的行」。引号、转义、二进制文件、截断，连着三轮挑在同一个解析函数上。改成 `git diff --name-only -z` 拿文件名、每个文件 `git diff -U0` 只读块头，解析代码整段删掉。

  两次都是**从给人看的文字里推了一件本来有工具能给确切答案的事**。

## 一、为什么写成「先列找谁要的表」，而不是「不要猜」

「不要猜」仓库里已经有好几句：变更评定里不许填猜测值（`process/2-CHANGE.md`）、架构文档要标出哪里的边界是猜的（`process/5-DESIGN.md`）、评审时一条基于猜测的发现比没有发现更贵（`REVIEW.md`）。它们管的都是结论，没有一句管**设计时要用的事实从哪来**。上面两次推倒重来，写代码的人并不觉得自己在猜：按名字认字段、按 `+` 号数新加的行，看上去都是在「读事实」。

所以规则落在一个能在写代码之前做完的动作上：把要用到的事实逐件列出来，每件写清找谁要、拿到的是给机器读的还是给人看的。这张表一列，上面两件事的权威当场就写得出来（语言服务、git 的 `-z` 和 `-U0`），不用等评审一轮轮挑。表先过独立复核，复核只问「找谁要」那一格是不是真正的权威。

实在找不到权威、只能推的，写明推法什么时候会错，并且选错了会多报的那一边：多报当场红、有人看，漏报报绿、没人看。这和 `process/README.md` 第二层「两种失败不对称」是同一个道理。

## 二、为什么把「同一处连挑两轮就改设计」写进仓库

这是丸子 2026-11-15 定的（当时那条 PR 已经评审了十一轮，每轮都挑在同一个函数上）：一个改动量不大的 PR，每次都在同一个地方评审出问题，就该想想是不是要重新设计；而且不能靠不再请评审来假装没问题，「过硬的设计是不会频繁评审出问题的」。这条之前只写在 Claude 的项目备忘里，换个线程就不知道，所以写进 `process/6-INTEGRATE.md`。

它和「从第三轮起只登记」不冲突：后者管零散的发现，防的是没有出口的回路；同一处接连出错是设计的信号，登记掉它等于把同一个坑留给下一个人。两条放在一起写明了分工。

判据看位置不看措辞：两轮发现说的是两件不同的事，落在同一处也算。上面第一次推倒重来，二十多轮的发现措辞五花八门，大多落在「按名字认字段」那一处。

## 三、为什么权威清单放业务层

`process/` 只写换个项目也成立的话：要列表、要问权威、权威是哪几类（编译器与语言服务、版本管理工具给机器读的输出、真跑一遍的结果）。具体到本仓库是 TypeScript 语言服务、git 的哪几个参数、`npm run mutate` 的结果，这些放 `docs/CONVENTIONS.md` 第 13 条，连同上面两次的经过，给下一个写检查脚本的人对照。

## 四、哪些部分能交给检查，哪些不能

「这一步算不算在推」本身不能做成检查：要判断它，得读懂代码；拿一张名单或正则去判，就是又推了一次，违反本条自己。所以这部分留在第三层，靠第一节那张表、独立复核和 `REVIEW.md` 那一问。

但前后两头判得出，丸子选了三道都做，各开一条 PR、各有自己的决策记录：

1. **调 git 只走一个入口**：检查脚本里直接调 git 的文件现在有十几个，每一个都可能自己去解析给人看的输出。收成一个入口模块，只交出给机器读的结果；入口以外直接调 git 的，由编译器认出来、报红。先做这一道。
2. **新的设计记录必须有「找谁要」那张表**：表在不在、每一行「找谁要」那一格有没有填，机器数得出来；填得对不对，仍靠复核。
3. **同一处连着两轮被挑就拦住合入**：每条评审发现锚在哪个文件哪一行，是评审工具给的确切数据，用编译器换算成函数，两轮落在同一个函数就挂上拦截标记，补了设计说明并给需求所有者看过才解除。

三道合入以后，`process/README.md` 第三层那一行和 `process/6-INTEGRATE.md` 第三层那一行里「项目可以建检查」的部分，由各自那条 PR 改写成已经建了。
