## 一、为什么写成「先列找谁要的表」，而不是「不要猜」

「不要猜」仓库里已经有好几句：变更评定里不许填猜测值（`process/2-CHANGE.md`）、架构文档要标出哪里的边界是猜的（`process/5-DESIGN.md`）、评审时一条基于猜测的发现比没有发现更贵（`REVIEW.md`）。它们管的都是结论，没有一句管**设计时要用的事实从哪来**。上面三次，写代码的人都不觉得自己在猜：读测试源码看它比了哪些键、按名字认字段、按 `+` 号数新加的行，看上去都是在「读事实」。

所以规则落在一个能在写代码之前做完的动作上：把要用到的事实逐件列出来，每件写清找谁要、拿到的是给机器读的还是给人看的。这张表一列，上面三件事的权威当场就写得出来（变异真跑的结果、语言服务、git 的 `-z` 和 `-U0`），不用等评审一轮轮挑。表先过独立复核，复核只问「找谁要」那一格是不是真正的权威。

实在找不到权威、只能推的，写明推法什么时候会错，并且选错了会多报的那一边：多报当场红、有人看，漏报报绿、没人看。这和 `process/README.md` 第二层「两种失败不对称」是同一个道理。

## 二、为什么把「同一处连挑两轮就改设计」写进 `process/`

这是丸子 2026-11-15 定的：当时那条 PR 第四到第十轮几乎每轮都打在同一处，他说一个改动量不大的 PR，每次都在同一个地方评审出问题，就该想想是不是要重新设计；而且不能靠不再请评审来假装没问题，「过硬的设计是不会频繁评审出问题的」。ADR-198「第十一轮前改设计」那段末句记下了它，但那是一份具体闸门的记录，写 `process/` 的人和下一个线程都不会去那里找，所以写进 `process/6-INTEGRATE.md`。

它和旧规矩的分工写明了：

- 「从第三轮起只登记」管零散的发现，防的是没有出口的回路；同一处接连出错是设计的信号，不走那一条，那一节加了指向新一节的半句。
- 改设计多半是重构，旧规矩要另开 PR。新一节定：默认关掉这一条、按新做法另开；需求所有者明说在本 PR 里改的，算唯一的例外，写进 PR 描述。轮次从新做法的第一个 head 重新数，作者不能自己合。合并者那张表加了一行核它。
- 「换对了没有」看之后的发现还落不落回同一处，不是合入条件，免得又造出一个没有出口的回路。

判据看位置不看措辞，但只算改的不只是字面的发现：一个长函数里第一轮挑了错字、第二轮挑了排版，不算。拆开、挪走、改名，仍是同一处。规则文字也算「一处」：改流程文档的 PR 连着两轮被挑在同一条规则上，同样可能是规则本身设计得不对。

## 三、为什么权威清单放业务层

`process/` 只写换个项目也成立的话：要列表、要问权威、权威是哪几类（编译器与语言服务、版本管理工具给机器读的输出、真跑一遍的结果）。具体到本仓库是 TypeScript 语言服务、git 的哪几个参数、`npm run mutate` 的结果，这些放 `docs/CONVENTIONS.md` 第 13 条，连同上面三次的经过，给下一个写检查脚本的人对照。

## 四、哪些部分能交给检查，哪些不能

「这一步算不算在推」本身不能做成检查：要判断它，得读懂代码；拿一张名单或正则去判，就是又推了一次，违反本条自己。所以这部分留在第三层，靠第一节那张表、独立复核和 `REVIEW.md` 那一问。

但前后两头判得出，丸子选了三道都做，各开一条 PR、各有自己的决策记录：

1. **调 git 只走一个入口**：检查脚本里有好几个文件各自直接调 git（几个、哪几个，以那条 PR 开工时在主干上实数为准），每一个都可能自己去解析给人看的输出。收成一个入口模块，只交出给机器读的结果；入口以外直接调 git 的，由编译器认出来、报红。先做这一道。
2. **新的设计记录必须有「找谁要」那张表**：表在不在、每一行「找谁要」那一格有没有填，机器数得出来；填得对不对，仍靠复核。
3. **同一处连着两轮被挑就拦住合入**：每条评审发现锚在哪个文件哪一行，是评审工具给的确切数据，用编译器换算成函数，两轮落在同一个函数就挂上拦截标记，补了设计说明并给需求所有者看过才解除。独立复核指出这里有一半要读：「本改动档」是作者自填的，「同一处」跨两个 head、函数拆了改了名时要读才判得出。那条 PR 动手前先按 `process/README.md` 第二层判清楚它替代的是跑还是读，判下来只能列原料不能拦的，回来给需求所有者重定。

三条 PR 串着开：第 1 道在本条合入后开，第 2 道在第 1 道合入后开，第 3 道在第 2 道合入后开 —— 它们都要改本条新加的那两行第三层表、都会改索引。三道合入以后，`process/README.md` 第三层那一行和 `process/6-INTEGRATE.md` 第三层那一行里说可以建检查的那部分，由各自那条 PR 改写成建了什么、守到哪。
