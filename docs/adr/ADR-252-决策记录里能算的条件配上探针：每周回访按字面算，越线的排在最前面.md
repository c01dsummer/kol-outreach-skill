# ADR-252 决策记录里能算的条件配上探针：每周回访按字面算，越线的排在最前面

- 日期 · 2026-11-28
- 类型：新加一道只报不拦的计算（周回访多一步）＋ 检查链多核一张登记表
- 触发它的事实：ADR-203 第五节「主干上连续 3 跑预计与实际差过 25% 就重写秒数文件」，线大约 10 天前就过了，没人看见，CI 从 8 分钟涨到 30 分钟才被人发现。往回清点：欠条台账里开着的条件、死亡条件、重开讨论一共 303 条，机器只看日历（登记满 28 天列一次、死亡条件四周轮一遍），从不看条件本身；逐条读下来能由确切数据判定的 75 条，其中 13 条今天按字面已经越线、没人处理
- 冲击的需求：无（只影响开发流程：每周回访多列几条、检查链多核一张表）
- 决定人与时间：需求所有者丸子，在三张选择卡上：2026-11-28 03:48（UTC）选「能算的配探针自动算」；04:25 选「每周回访时算」（不在每次推主干时算）；04:31 选「越线的欠条算进新登记闸门的『列过没判』，门槛仍是 10，第一次回访把这一批一次列给他」。登记表绑哪几条、三种判法怎么算是本条作者定的，需求所有者合入本条时接受
- 结论：**能由确切数据判定的条件，在 `scripts/check/condition-rule.ts` 的登记表里配一个条件探针：绑台账里一条确切的条目，用三种通用判法之一（某条 PR 合入了没有、另一张欠条还了没有、树里某个数过没过线），带这一条的参数。每周回访跑 `npm run conditions`，越线的排在候选表最前面交需求所有者判，到期清单与死亡条件轮值里不再重列。检查链核登记表：绑的条目还在、种类对、欠条还开着、一条至多一个探针。** 第一批 15 行
- 理由：替代的是「读」：原来条件成没成立靠人每周读原文，读不过来（ADR-167 的到期清单一次只列 10 张）；能算的就让机器按字面算。只算字面，不判条件本身对不对、值不值得做，那仍是人判的事
- 同类：ADR-167（欠条台账、到期清单与死亡条件轮值）、ADR-203 第五节（这次漏掉的那一条）、ADR-129（同样的条件过线没人看见，十月那一次）

## 一、条件探针是什么

登记表里的一行：

- **绑的是谁**：台账里一条欠条或死亡条件，写它在回访里的记法 —— 有短名字的欠条 `<编号>「<短名字>」`，没有的 `<编号> 第 <行> 行`，死亡条件照轮值的写法（拆过的记录主文件里写 `<编号> 主文件第 <行> 行`）。
  到期清单、死亡条件轮值、登记表三处用的是同一个算记法的函数（`revisit-rule.ts` 的 `notationOf`），不问 git。
- **怎么算**：三种通用判法之一，全是纯函数，输入是入口交进来的确切原料，不读散文：

| 判法 | 参数 | 越线 | 原料取不到 |
|---|---|---|---|
| PR 合入 | PR 号 | 主干第一亲代链上有一个提交标题是两种写法之一 | 取不到标题 → 无从确认 |
| 等另一张欠条的状态 | 那一张的记法、要等的状态（已还） | 那一张已还 | 那一张在台账里找不到，或已收尾、已改挂（永远等不到已还）→ 无从确认，每周点名 |
| 树里的数 | 量法、比较符（超过、不少于、等于）、线 | 量出来的数越过线 | 要量的文件不在、取不到受跟踪的路径 → 无从确认；JSON 读不出或那个键不是数组算原料形状不对，整跑以 1 退出 |

量法五种：字节数；行数（数换行，同 `wc -l`）；JSON 顶层一个键下数组的长度；文件在不在（在 1、不在 0）；某几个目录下（含子目录）受跟踪、以某个后缀结尾的文件份数。

每种判法越线、没越线、无从确认各有用例，比较符、线、原料怎么取都有变异。登记表的每一行**不**各配变异：参数填错（PR 号写错）只能靠评审对着原文看，写进第五节。

## 三、每周回访怎么用

改 `docs/REVISIT.md`「周一」(b) 第 5 步：

1. 跑 `npm run conditions -- --today <日期> --run <本跑>`。第一行是几个数，之后越线、这一周要列的每条一行，最后是无从确认的每条一行。**整段每周都抄进回访 PR 正文**，哪怕一条都没越线。
2. 越线要列的进候选表、排最前面；「欠条」栏写记法，「值」栏写 `越线：<算出来的>`。
3. 到期清单与死亡条件轮值的命令先拿掉越线的那几条（不管这一周列不列），再截每周 10 张：越线的不重列，也不占名额（`dueList`、`deathRota` 多一个「先拿掉这几条」的参数）。
4. 人判照种类：欠条认还、收尾、留；死亡条件认接受、拒绝。判过的，从判的那一块的日期起 28 天内越线也不再列（与到期清单同一个读法）；欠条续挂了的，续挂写的那天之前也不列。判了还、收尾的照现有口径等状态行：状态行一写，第四节的核对就让这一行的探针红，逼着撤掉它。
5. 新登记欠条的闸门数「列过没判」时**不**拿掉越线的：越线的欠条列过没判，照现有数法数进去，门槛仍是 10（需求所有者 2026-11-28 选的）。第一次回访把第一批越线的一次列给他。

ADR-151 第四节第 2 条「例程不判死亡条件」照旧成立：判条件成没成立的是命令，按字面；例程只抄结果，不自己判，也不替命令补算。`REVISIT.md`「能写什么」里写明了这一句。

## 四、命令与核对

- `npm run conditions`（入口 `scripts/check/conditions.ts`，判定全在 `condition-rule.ts`）。退出码：全算完 0；某条原料取不到算那一行无从确认，别的照算，仍 0；登记表核不过、原料形状不对 1；参数写错 2。只读，不在检查链里。
- 检查链里 `npm run adr`（`adr-sync.ts`）多核一遍登记表：
  1. 绑的记法在台账里恰好对上一条（拆过的记录主文件与历史文件同名的那张，状态相同算一条），种类与登记的同；
  2. 欠条要开着或续挂：已还、收尾、已改挂的红，说「这个探针管的那条已经关了」；死亡条件没有状态，只核在不在；
  3. 一条至多一个探针；
  4. PR 号是正整数；等的那张在台账里是一张欠条；量的文件在（量「在不在」的除外）、数份数的目录在。
  不放进 `adr-rule.ts` 的 `adrSync`：需求测试在玩具目录上调它，那里没有登记表绑的那些真记录。
- 读第一亲代链的标题不加新的 git 问法：用已有的 `cat-file --batch` 按 `<本跑>~0`、`<本跑>~1`……一路问到 git 答「missing」为止，个数用已有的 `rev-list <本跑>` 封顶；受跟踪的路径用已有的 `ls-files -z`。

**什么条件下退成只报数**：连续 8 次回访里，条件探针越线的行已判的不少于 5 条，且其中没有一条判的是还、收尾或接受。

**什么条件下整个撤掉**：登记表空了满 8 周。

## 五、守不住的

> ⚠️ 欠条「探针只按字面算条件成没成立」：条件写得对不对、按字面越线了是不是真该回来，探针不判；ADR-130 第 110 行、ADR-69 第 20 行就可能是字面成立、原意另有所等 · 还法：越线的交需求所有者判，判了留或收尾的不再列四周；判下来字面与原意对不上的多了，回头改那几条的写法 · 档：登记 · 重启条件：周回访里第一次有越线的行被判「字面成立、原意没到」时

> ⚠️ 欠条「登记表的参数填错只靠评审」：PR 号、路径、线写错，检查链只核形状（PR 号是正整数、文件在），不核是不是原文说的那一个 · 还法：评审对着原文逐行看；参数要是能从原文里按定死的写法取出来，改成取出来 · 档：登记 · 重启条件：周回访里第一次有越线的行被判「绑错了或参数写错了」时

> ⚠️ 欠条「PR 合没合只看主干提交标题」：只认 GitHub 默认的两种标题；有人改了合并时的标题写法会漏（判没合入）；合入后又被回退的照样算合入 · 还法：回访能取 GitHub 接口时改问 PR 的合并状态，回退的另算 · 档：登记 · 重启条件：主干上第一次出现回退一条被探针绑着的 PR 的提交，或仓库改了合并时的默认标题写法时

> ⚠️ 欠条「越线最晚下周一才被看见」：探针只在每周回访里算（需求所有者选的），越线到列出最多差一周；回访停了就没人看见 · 还法：要更快就改成每次推主干时算、在主干上报出来 · 档：登记 · 重启条件：有一条越线的条件，从越线到被列出隔了两周以上时

> ⚠️ 欠条「要 CI 日志或 GitHub 接口的那批没配」：能算的 75 条里 22 条要逐跑翻 CI 日志或问 GitHub 接口，回访的命令现在不联网，没配 · 还法：周回访 (a) 段那种「例程取接口存成文件交进来」的办法扩到这一批 · 档：登记 · 重启条件：下一次给周回访加一种从 GitHub 取来的原料时

> ⚠️ 欠条「死亡条件那一支只有玩具数据走过」：第一批三条死亡条件今天都没越线，「越线 → 判接受或拒绝 → 四周不列 → 从轮值里拿掉」这一串只在需求测试的玩具数据上走过 · 还法：第一条死亡条件越线、判过以后，对着那一周的回访块核一遍 · 档：登记 · 重启条件：第一条死亡条件类的探针越线时（`REVIEW.md` 再多一行就是）

> ⚠️ 欠条「主文件重写会让登记表跟着红」：ADR-70 主文件第 273 行那一行按行号记，ADR-70 的主文件改得勤，行号一挪检查链就红，要在不相干的改动里改登记表；有短名字的欠条按名字记，不受这个影响 · 还法：死亡条件也有了不随行号变的名字时，改按名字绑 · 档：登记 · 重启条件：第一次因为改 ADR-70 主文件挪了行号让这一项检查红时

> ⚠️ 欠条「回访入口拿掉越线那一步没有测试」：到期清单与轮值的入口（`revisit-due.ts`）先算一遍登记表再拿掉越线的，这一步接线没有测试起它（判定那一半有）；接线断了，越线的会在到期清单里重列一次 · 还法：给那个入口加一组在玩具仓库里真起的用例 · 档：登记 · 重启条件：下一条改 `scripts/check/revisit-due.ts` 的改动

另有两处不登记成欠条、在这里说明：受跟踪才数得到（没 `git add` 的手写 `.d.ts` 探针看不见；回访在新克隆上跑，两者相同）；只能人判的积压（88 条）和「看改动」的那一类（131 条，欠条点名提醒已经在每条 PR 上列它们）不在本条解决。
