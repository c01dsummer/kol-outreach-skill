## 二、四句

### 第 1 句：开 PR 前的复核也算第一轮，指着本 PR 自己内容的发现前两轮修在本 PR

要说的：评审发现指着这条 PR 自己写的内容的，是本改动档，不论来自评审器还是开 PR 前的复核；开 PR 前的复核算进第一轮，所以这类发现前两轮修在本 PR、不登记。第三轮起不阻塞的才登记，登记的那张欠条写明档与第几轮，合并者照它核。

起因：ADR-143 第 45、47 行（#301）把两条复核发现登记了：本条测试对根上的键只核 stderr 含键名，probe 把问题用「；」拼成一行分不清边界。两条都指着那条 PR 自己的测试与代码，条件分别是「下一条改 `d28-config-duplicates` 组断言的改动……」「下一条改 probe 拼问题的写法……」（各还有一支）。复核在合入之前（ADR-143 第 36 行：「复核之后补的测试」随那条 PR 一起合了）；是开 PR 前还是评审中第几轮，复核对的那个提交已被 squash 掉，git 上核不到。台账里块头那一行写着「复核发现」的欠条块有 16 个（下面那条命令，`902e63e`）；合入之后的复核走登记是规则允许的，合入之前的要看轮次。规则在两端不对称：`process/6-INTEGRATE.md` 第 190 行写了合入之后那一端（「合入之后才到的意见没有本改动档」）；开 PR 之前那一端没写，而第 149 行的「一轮」只数锚在 PR 某个 head 上的意见，开 PR 前的复核不在任何一轮里，登记就成了默认的出口。

```bash
grep -hE '^>?\s*\*{0,2}⚠️\s*\*{0,2}欠条' docs/adr/*.md | grep -c '复核发现'
```

落到：`process/6-INTEGRATE.md`「五档路由」第 190 行那段之后，补开 PR 之前那一端；「登记怎么做」第 3 条第 249–251 行那个围栏，欠条那一行加档与轮次。

已有的近亲：同一份文件第 179 行本改动档的判据与「前两轮修在本 PR」；第 182 行登记档的判据「不在本 PR diff 里」—— 今天的规则就是这个意思，缺的是开 PR 前那一端没点出来；第 195 行「从第三轮起只登记」那一节；`process/4-VERIFY.md` 第 279 行「复核意见……按 `6-INTEGRATE.md` 的评审路由分档」—— 那句把复核接到了路由上，没说它算第几轮；`docs/adr/README.md`「同类」那一节要求「欠条」后面直接接冒号、不加括注（那条 grep 认的是「欠条：同类」），所以档与轮次写成那一行里的一段，不写成「欠条」后面的括注。

### 第 2 句：扩范围与既有缺陷合入后串行做，作者的下一条改动合入前核它做完了

要说的：一条 PR 留下的扩范围与既有缺陷，合入后由作者串行做（今天已经写着），缺的是核。作者在这之后开的、不在这条队里的改动，合并者合它之前先核：队里每一条开出来了、合了，那几张欠条在主干上记了已还；没做完的不合。

起因：`process/6-INTEGRATE.md` 第 268 行要求合入后「开一条、检查绿、合、再开下一条」，可合并者那张表只核「欠条已在主干上」（第 228 行），没人核队做没做。两个例子：ADR-74 第 198 行（#116，2026-09-18，扩范围，条件「本 PR 已合入 —— 也就是紧接着的那一条」），要搬进自检的那段夹具至今没搬；ADR-70 第 2013 行（`349d425`，2026-09-12，扩范围档，条件「本 PR 已合入」），中间只有 #107 写过拆判据的一版、开了又关（ADR-70 第 2349、2358 行起），到 #132 追记（ADR-70 第 2340–2357 行）才判为不做。

落到：`process/6-INTEGRATE.md`「合并者核对去向」第 228 行「上一条合入的 PR」那一行；同一份文件「另开 PR 的,合入就做」第 268 行那段补「谁来核」。

已有的近亲：第 228 行（核欠条在主干上，不核队）；第 213 行「合并者不能是写档的那一方」；第 272–275 行从主干另开的三个条件 —— 那管的是并行开，这句管串行做完没有。

不写进去的：体检页写的「块头写『去向：合入后第 1 条』」—— 第 171–172 行的回复写法已有「合入后开」，这句只加核，不另立块头。「记了已还」在第 3 句之前照今天的写法，第 3 句之后照它。

### 第 3 句：一张欠条只有两种关法，关它的是一行固定写法

要说的：一张欠条关上只有两种：还上，或需求所有者定不做（收尾，写为什么）。关它的那一行追加在欠条所在那条记录的末尾，按固定写法指到那张欠条的行；被别处接着挂走的旧件，也写一行指到现行的那张 —— 旧件这一行关上，账转到现行的那张。散文里一句「已处理」、清点里一句「只记核过」都不关它。

起因：今天围着台账的四条路，没有一条把欠条标成关上 —— 台账按设计「只抽取，不判已还」（ADR-86）；周回访的说明书写明「不标欠条已还」（`docs/REVISIT.md` 第 15 行）；每条 PR 的清点与需求所有者拍板写的已还、收尾都是散文。`process/6-INTEGRATE.md` 第 255 行只说「还上时在下面再追加一块」，没有写法。于是还了的认不出：ADR-115 第 99 行那张由 ADR-116（#183 开，#184 追加它第六节的入口接线）还了，只有 ADR-115 第 179 行一句「已接入修复」，不指行号；ADR-107 第 40 行那张由 #155（ADR-108）做了，只有 ADR-107 第 113–117 行一节散文。收尾各写各的：ADR-12 第 99 行「由需求所有者定为收尾」，ADR-154 第 299 行「在项目线程里选了『照推荐』」加一块已还；ADR-154 第 210 行给「驳回」定的块头，至今一块都没有。

落到：`process/6-INTEGRATE.md`「登记怎么做」第 3 条第 255 行那句改写，下面跟一个围栏，放关它的两种行与指到现行那张的一种行。

已有的近亲：同一份文件第 255 行；`process/README.md` 第 223 行「开头固定,清点才能把条目机械地抽成一张单子」—— 那句说的是死亡条件，道理一样。本仓库已有两种固定的关法，都不改：候选句记录用 `docs/REVISIT.md` 第 344 行那种已还行与第 345 行那种驳回行（驳回就是需求所有者定不做），ADR-151 第 560 行那条 grep 数的是前一种；ADR-154 那十句用「上文第 N 句那张欠条已还」。

不写进去的：编号形状（`ADR-N 第 M 行`、`#号`）写成占位；「需求所有者」照 `process/2-CHANGE.md` 的叫法。

### 第 4 句：响了没还的，只许续挂一次

要说的：条件响了、这一次还不了的，可以续挂一次：追加一行，写在哪条改动上响的、为什么现在不还、到哪天。同一张再响，或者到了那天，只剩还上或交需求所有者收尾。「条件重新起算」不再用 —— 它让一张欠条可以无限次响而不还。

起因：同一张欠条连着响、连着重挂的链：ADR-94 第 1273 行那张（三态靠字段存不存在来表达，#294）在 #297、#298、#299、#300 上各响一次（同文第 1275、1277、1281、1283 行），每次「响了、没还」、重挂；ADR-139 第 116 行那张（入口脚本里的判定只有自检够得到，#297）在 #299、#300、#301 上各响一次（同文第 126、128、130 行），每次重新起算。条件以数为界的也一样：ADR-86 第 118 行的「条数翻倍」按字面早已成立，重挂到 ADR-151 第 122 行时照抄条件、加「重新起算」，没写从哪一个数起翻倍。`902e63e` 上全部记录里写着「重新起算」的有 146 行、写着「重挂」的有 221 行（下面两条命令；本条自己也含这两个词，在含本条的树上跑会多出本条那几行）。

```bash
grep -h '重新起算' docs/adr/*.md | wc -l
grep -h '重挂' docs/adr/*.md | wc -l
```

落到：`process/6-INTEGRATE.md`「登记怎么做」第 4 条（第 257 行）之后新加一条；续挂那一行的写法放进第 3 句那个围栏。

已有的近亲：没有。`process/` 里没有一句话说一张欠条可以响几次不还。`docs/REVISIT.md` 第 132–133 行把「另起一块接着它」算成有人接手，那是本仓库的说明书，随第五节第 8 片改。

## 三、顺带搬进 process/ 的一处：重启条件的第四种

`process/6-INTEGRATE.md`「登记怎么做」第 4 条（第 257 行）写重启条件「通常是三种之一：下次有改动碰到那个文件、同一缺口再被点名、定期清点」。实际常用的还有第四种：某阶段或某一片开工、合入时 —— ADR-64 第 207 行记过（「落地 4 开工」「落地 2 第 5 步」），ADR-86 第 127–130 行又记一次，两张都还挂着（ADR-64 第 250 行、ADR-86 第 130 行）；ADR-154 第四节十张、本条第七节都是这种（「上一句有了去向」）。改法是第 257 行加一种；这一张原在别的改动线上，2026-10-23 转到本条。

它跟第 4 句碰同一段，所以排在四句之后单开一条，证据问题只有一个：这一种写进清单，换个项目还成立吗。挂在已走完的计划上永远不响的那种，由第四节第 2 小节的到期兜住，不在这一行里另说。

ADR-86 第 130 行的条件是「下一条要动 `process/6-INTEGRATE.md` 欠条那一节的改动」，第 1 片就会按字面响，第 3、4 片也会。照 ADR-154 那串的做法，响的那几片都记「由本条第五节第 5 片还」，不重挂。

## 四、台账、回访、清点与闸门

### 1. 台账认得状态行

状态行一律追加在欠条所在那条记录的末尾（`process/2-CHANGE.md`「新内容加在哪」：块本体一律加在后面），每行自成一段引用；记录只追加不删改，行号因此稳定，这正是今天清点已经在用的引用方式。四种（举例不带行首的 `>`，免得被 grep 当成真的；实际写时行首是 `>` 后跟一个空格）：

```text
⚠️ 已还：ADR-N 第 M 行 · 还在 #号
⚠️ 已重挂：ADR-N 第 M 行 · 现行的是 ADR-X 第 Y 行
⚠️ 收尾：ADR-N 第 M 行 · 需求所有者 YYYY-MM-DD · 不做，因为……
⚠️ 续挂：ADR-N 第 M 行 · 在 #号 · 到 YYYY-MM-DD · 因为……
```

N 是这一行所在记录自己的号，M 是那张欠条在台账里的行号（`npm run adr-ledger` 每行开头那个）。前三种是需求所有者 2026-10-23 认的，第一批标记就用它们；第四种随第 4 句。

`scripts/check/debt-rule.ts` 只多做一件事：把这几种行抽出来，按「记录 + 行号」配到台账上的重启条件，全表多一栏状态，汇总多报「开着 N 张」与每种各几张。它不判任何条件成不成立，读的是人写的那一行，仍是 ADR-87 那句「替代跑的建、替代读的不建」里跑的那一侧。配不上的状态行（指的那一行不是一条重启条件）只报出来、不红：那张欠条照旧算开着，多列一条读的人排除得掉，少列一条没人会发现（ADR-86 第六节「不判已还」那条的理由）。这一片还 ADR-151 第 122 行那张（条件「下一条要往 `debt-rule.ts` 加判定的改动」）。 这里是待新增的状态抽取：现有 `entries()` 只抽条件，并不读取状态行。普通 Markdown 引用行本身不被 `quotedMask()` 遮住；后续状态抽取仍须用遮罩排除围栏、HTML 等语法示例，不能把现有 `entries()` 当成状态读取器。

同一片要顾的三样：

- 已有的固定关法（第 3 句近亲里那两种）照旧用、不改写；第 6 片的抽取怎么认它们，在那一片定。用散文标过已还的那些（体检算它们有已还标记），开第 6 片之前各按新写法补一行，不然台账会把它们算成开着。
- 状态行里「现行的是 ADR-X 第 Y 行」这类引用，今天的被引表（`scripts/check/cite-rule.ts`）会数进主计数，因为它只把以「⚠️ 欠条」开头的块单列。状态行是记账，和欠条块里的引用同类，这一片让被引表把它们也单列。
- 台账从此报得出已还 —— 读人写的那一行，不判条件 —— 写着「不判已还」的那几处跟着改：`debt-rule.ts` 文件头与 `ledgerSummary` 那句限定、`docs/ARCHITECTURE.md` 第 171 行、`docs/SYNC.md` 第 53 行末栏。
