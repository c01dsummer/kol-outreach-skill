## 一、机制是什么（现行）

一张欠条从登记到关上，只有下面几种状态，每种是一行固定写法（写法见 `process/6-INTEGRATE.md`「登记怎么做」第 3 条那个围栏）：

| 状态 | 什么意思 | 谁写 |
|---|---|---|
| 开着 | 登记了，等它的重启条件 | 登记它的那条 PR |
| 已还 | 修好了 | 修它的那条 PR |
| 收尾 | 需求所有者定了不做，写明为什么 | 只有需求所有者能定；写那一行的 PR 指得到他本人的痕迹 |
| 已重挂 | 账转到别处现行的那一张 | 接走它的那条 PR |
| 续挂 | 条件响了、这次还不了，写到哪天、为什么；一张只许一次 | 碰响它的那条 PR |

两条路把一张欠条拿出来：**条件响了**（每条 PR 的欠条清点只写碰响了的那几张，每张写处置），或者**到期了**（登记满 28 天；续挂过的，到它写的那天），不管响没响。到期的由每周一的回访列给需求所有者判，他对每张回一个词：还、收尾、留。「留」算续挂一次。

死亡条件（一条规则什么时候撤、什么时候退成只报数）不是欠条，没有到期；每周回访按记录编号轮着列四分之一，四周轮完一遍，也进候选表，由需求所有者判接受（成立了，当周去撤）或拒绝（还没成立）。

新登记有一道闸门：一条 PR 想新开以「登记」为去向的欠条块时，「已经列给需求所有者、他还没判」的满 10 张，就红（每周最多列 10 张、没判的下周照列，这个数最多就是 10，所以取「满」不取「超过」）。

## 四、证不了的

- 收尾只有需求所有者能定，这一条没有检查守着（第三层，靠合并者核那一行指得到他本人的痕迹）。
- 「清点只写碰响了的」靠写清点的人自觉；碰没碰响由读的人判，台账只抽不判（ADR-86）。
- 续挂只许一次，台账认得续挂行，但只报「续挂」这一栏，不数同一张续挂了几次、也不拦第二次；数与拦归到期清单与闸门那几片。
- 2026-11-22 之前写下的「重新起算」照旧留着，不回头改成续挂行；它们由到期清单兜住。
- 死亡条件轮到了只说明列给了人，成没成立仍由人读、由人判。ADR-80 第 119 行、ADR-81 第 106 行那两条要数 CI 运行，例程不数（`size` 那一行的日志原文在会话里也取不到，只能推）；轮到它们时，要判就得另找会话去数。
