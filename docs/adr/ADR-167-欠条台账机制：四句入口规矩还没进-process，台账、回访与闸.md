## 二、四句

### 第 1 句：指着本 PR 自己内容的发现不登记，开 PR 前的复核也一样

要说的：评审发现指着这条 PR 自己写的内容的，是本改动档，不论来自评审器还是开 PR 前的复核；开 PR 前的复核算进第一轮。第三轮起不阻塞的才登记，登记的那张欠条在块头写明档与第几轮，合并者照它核。

起因：ADR-143 第 45、47 行（#301）把两条复核发现登记了：本条测试对根上的键只核 stderr 含键名，probe 把问题用「；」拼成一行分不清边界。两条都指着那条 PR 自己的测试与代码，条件分别是「下一条改 `d28-config-duplicates` 组断言的改动」「下一条改 probe 拼问题的写法」。复核在合入之前（ADR-143 第 36 行：「复核之后补的测试」随那条 PR 一起合了）；是开 PR 前还是评审中第几轮，复核对的那个提交已被 squash 掉，git 上核不到。台账里块头那一行写着「复核发现」的欠条块有 16 个（下面第一条命令）；合入之后的复核走登记是规则允许的，开 PR 前的不是。规则在两端不对称：`process/6-INTEGRATE.md` 第 190 行写了合入之后那一端（「合入之后才到的意见没有本改动档」）；开 PR 之前那一端没写，而第 150 行的「一轮」只数锚在 PR 某个 head 上的意见，开 PR 前的复核不在任何一轮里，登记就成了默认的出口。

```bash
grep -hE '^>?\s*\*{0,2}⚠️\s*\*{0,2}欠条' docs/adr/*.md | grep -c '复核发现'
```

落到：`process/6-INTEGRATE.md`「五档路由」第 190 行那段之后，补开 PR 之前那一端；「登记怎么做」第 3 条第 249–251 行那个围栏，块头加档与轮次。

已有的近亲：同一份文件第 179 行本改动档的判据与「前两轮修在本 PR」；第 182 行登记档的判据「不在本 PR diff 里」—— 今天的规则就是这个意思，缺的是开 PR 前那一端没点出来；第 197 行「从第三轮起只登记」；`process/4-VERIFY.md` 第 279 行「复核意见……按 `6-INTEGRATE.md` 的评审路由分档」—— 那句把复核接到了路由上，没说它算第几轮。

不写进去的：体检页上的块头还带「来源 PR 号」，那是本仓库的形状，`process/` 里写成「哪条改动上的评审」。

### 第 2 句：扩范围与既有缺陷合入后串行做，作者的下一条改动合入前核它做完了

要说的：一条 PR 留下的扩范围与既有缺陷，合入后由作者串行做（今天已经写着），缺的是核。作者在这之后开的、不在这条队里的改动，合并者合它之前先核：队里每一条开出来了、合了，那几张欠条在主干上写了已还；没做完的不合。

起因：`process/6-INTEGRATE.md` 第 268 行要求合入后「开一条、检查绿、合、再开下一条」，可合并者那张表只核「欠条已在主干上」（第 228 行），没人核队做没做。三个例子：ADR-70 第 2013 行（`349d425`，2026-09-12，扩范围档，条件「本 PR 已合入」），到 #132 追记（ADR-70 第 2340–2357 行）才判为不做，中间没有一条 PR 管它；ADR-74 第 198 行（#116，2026-09-18，条件「本 PR 已合入 —— 也就是紧接着的那一条」），夹具至今没搬进自检；ADR-107 第 40 行（#154，条件「本记录所在改动合入后，立即完整接线」），#155（ADR-108）做了，原块下面没有已还，台账上至今开着。另有一例是档分错：#359 的正文把导出 CSV 不防公式前缀这个既有缺陷推荐成登记，#362（草稿）照着追加；需求所有者 2026-10-23 改判直接修。

落到：`process/6-INTEGRATE.md`「合并者核对去向」第 228 行「上一条合入的 PR」那一行；同一份文件「另开 PR 的,合入就做」第 268 行那段补「谁来核」。

已有的近亲：第 228 行（核欠条在主干上，不核队）；第 213 行「合并者不能是写档的那一方」；第 272–275 行从主干另开的三个条件 —— 那管的是并行开，这句管串行做完没有。

不写进去的：体检页写的「块头写『去向：合入后第 1 条』」—— 第 171–172 行的回复写法已有「合入后开」，这句只加核，不另立块头。

### 第 3 句：一张欠条只有两种关法，关它的是一行固定写法

要说的：一张欠条关上只有两种：还上，或需求所有者写收尾（不做了，写为什么）。关它的那一行追加在欠条所在那条记录的末尾，按固定写法指到那张欠条的行；被别处接着挂走的旧件，也写一行指到现行的那张：旧件这一行关上，账转到现行的那张。散文里一句「已处理」、清点里一句「只记核过」都不关它。

起因：今天围着台账的四条路，没有一条把欠条标成关上 —— 台账按设计「只抽取，不判已还」（ADR-86）；周回访的说明书写明「不标欠条已还」（`docs/REVISIT.md` 第 15 行）；每条 PR 的清点与需求所有者拍板写的已还、收尾都是散文。`process/6-INTEGRATE.md` 第 255 行只说「还上时在下面再追加一块」，没有写法。于是还了的认不出：ADR-115 第 99 行那张由 ADR-116（#184）还了，只有 ADR-115 第 179 行一句「已接入修复」，不指行号；ADR-107 第 40 行同样（见第 2 句）。收尾各写各的：ADR-12 第 99 行「由需求所有者定为收尾」，ADR-154 第 299 行「在项目线程里选了『照推荐』」加一块已还；ADR-154 第 210 行给「驳回」定的块头，至今一块都没有。项目线程「欠条标记第一批」那条 PR 用第四节第 1 小节的三种行，给读出来早已关上的那批补标。

落到：`process/6-INTEGRATE.md`「登记怎么做」第 3 条第 255 行那句改写，下面跟一个围栏，放关它的两种行与指到现行那张的一种行。

已有的近亲：同一份文件第 255 行；`process/README.md` 第 223 行「开头固定,清点才能把条目机械地抽成一张单子」—— 那句说的是死亡条件，道理一样。

不写进去的：`⚠️` 后面的编号形状（`ADR-N 第 M 行`、`#号`）写成占位；「需求所有者」照 `process/2-CHANGE.md` 的叫法。

### 第 4 句：响了没还的，只许续挂一次

要说的：条件响了、这一次还不了的，可以续挂一次：追加一行，写在哪条改动上响的、为什么现在不还、到哪天。同一张再响，或者到了那天，只剩还上或交需求所有者收尾。「条件重新起算」不再用 —— 它让一张欠条可以无限次响而不还。

起因：同一张欠条连着响、连着重挂的链：ADR-94 第 1273 行那张（三态靠字段存不存在来表达，#294）在 #297、#298、#299、#300 上各响一次（同文第 1275、1277、1281、1283 行），每次「响了、没还」、重挂；ADR-139 第 116 行那张（入口脚本里的判定只有自检够得到，#297）在 #299、#300、#301 上各响一次（同文第 126、128、130 行），每次重新起算。条件以数为界的也一样：ADR-86 第 118 行的「条数翻倍」按字面早已成立，重挂到 ADR-151 第 122 行时照抄条件、加「重新起算」，没写从哪一个数起翻倍。全部记录里写着「重新起算」的有 146 行、写着「重挂」的有 221 行（下面两条命令，`902e63e`）。

```bash
grep -h '重新起算' docs/adr/*.md | wc -l
grep -h '重挂' docs/adr/*.md | wc -l
```

落到：`process/6-INTEGRATE.md`「登记怎么做」第 4 条（第 257 行）之后新加一条；续挂那一行的写法放进第 3 句那个围栏。

已有的近亲：没有。`process/` 里没有一句话说一张欠条可以响几次不还。`docs/REVISIT.md` 第 132–133 行把「另起一块接着它」算成有人接手，那是本仓库的说明书，随第五节第 8 片改。

不写进去的：「到哪天」默认多久（第四节第 2 小节定 28 天）—— 数不进 `process/`，照 ADR-151 第五节的做法只写「写明到哪天」。

存量不回头改：第 4 句合入之前写下的「重新起算」照旧留着，那几张什么时候再被拿出来，由第四节第 2 小节的到期管，到期照条件那一行的登记日算。

## 三、顺带搬进 process/ 的一处：重启条件的第四种

`process/6-INTEGRATE.md`「登记怎么做」第 4 条（第 257 行）写重启条件「通常是三种之一：下次有改动碰到那个文件、同一缺口再被点名、定期清点」。实际常用的还有第四种：某阶段或某一片开工、合入时 —— ADR-64 第 207 行记过（「落地 4 开工」「落地 2 第 5 步」），ADR-86 第 127–130 行又记一次，两张都还挂着（ADR-64 第 250 行、ADR-86 第 130 行）；ADR-154 第四节十张、本条第七节都是这种（「上一句有了去向」）。改法是第 257 行加一种；这一条原在「Skill 结构检查与流程文档」那条线上，2026-10-23 转到本条。

它跟第 4 句碰同一段，所以排在四句之后单开一条，证据问题只有一个：这一种写进清单，换个项目还成立吗。挂在已走完的计划上永远不响的那种，由第四节第 2 小节的到期兜住，不在这一行里另说。

## 四、不进 process/ 的四样

### 1. 台账认得状态行

状态行一律追加在欠条所在那条记录的末尾（`process/2-CHANGE.md`「新内容加在哪」：块本体一律加在后面），每行自成一段引用；记录只追加不删改，行号因此稳定，这正是今天清点已经在用的引用方式。四种（`902e63e` 上台账认的一行叫「那张欠条的行」，就是 `npm run adr-ledger` 每行开头的行号）：

```text
> ⚠️ 已还：ADR-N 第 M 行 · 还在 #号
> ⚠️ 已重挂：ADR-N 第 M 行 · 现行的是 ADR-X 第 Y 行
> ⚠️ 收尾：ADR-N 第 M 行 · 需求所有者 YYYY-MM-DD · 不做，因为……
> ⚠️ 续挂：ADR-N 第 M 行 · 在 #号 · 到 YYYY-MM-DD · 因为……
```

N 是这一行所在记录自己的号，M 是那张欠条在台账里的行号。前三种是需求所有者 2026-10-23 认的，第一批标记就用它们；第四种随第 4 句。`scripts/check/debt-rule.ts` 只多做一件事：把这几种行抽出来，按「记录 + 行号」配到台账上的重启条件，全表多一栏状态，汇总多报「开着 N 张」与每种各几张。它不判任何条件成不成立，仍是 ADR-87 那句「替代跑的建、替代读的不建」里跑的那一侧。配不上的状态行（指的那一行不是一条重启条件）只报出来、不红：那张欠条照旧算开着，多列一条读的人排除得掉，少列一条没人会发现（ADR-86 第六节「不判已还」那条的理由）。状态行里「现行的是 ADR-X 第 Y 行」这类引用，今天的被引表（`scripts/check/cite-rule.ts`）会数进主计数，因为它只把以「⚠️ 欠条」开头的块单列；第一批标记那条 PR 量过这个变化。状态行是记账，和欠条块里的引用同类，这一片让被引表把它们也单列。这一片还 ADR-151 第 122 行那张（条件「下一条要往 `debt-rule.ts` 加判定的改动」）。

### 2. 周回访按到期取

`docs/REVISIT.md`「周一」(b) 第 2 步今天只取条件里写着「定期清点」、登记满四周的（第 97 行）。改成：登记满 28 天（续挂过的，到了续挂写的那天）、还开着、没列过的，最老的先列，每周最多 10 张。登记日照今天的取法，用 `git blame --first-parent` 取条件那一行进主干的日子。需求所有者在候选表「人判」栏填三个词之一：**还**（下一条欠条 PR 的作者做）、**收尾**、**留**（续挂一次，四周）；不填就是没判，下周照列，不换一批。下一条欠条 PR 把人判照第 1 小节的写法落成状态行。第 132–133 行「另起一块接着它算有人接手」改成算一次续挂。

这一步要两片：取哪些是判定（登记日、到期、开着、没列过、最老先列、10 张），先进 `debt-rule.ts` 配测试与变异，由一个只读入口打出来；说明书再改成调那个入口。说明书那几段命令今天没有测试跑它们（ADR-151 第 364 行那张，条件是「下一条改『周一』那几段命令的改动」），第一片就是给 (b) 第 2 步配上测试，其余几段命令照那张欠条的条件处置。说明书那一片顺带还 ADR-86 第 182 行那张（死亡条件满了没有东西提醒人去数）：(b) 加一步，台账里的死亡条件每四周轮读一遍，满了的进候选表；怎么轮在那一片定。

### 3. 每条 PR 的清点只写响了的

今天每条 PR 的清点像 ADR-145 第十八节那样分四段写进记录：响了没还、只记核过、按字面响实质不响、离得近没响。第 4 句合入起，只写响了的（按字面响的也算），每张写一个处置：还、续挂、交需求所有者，或者「实质不响」加一句为什么。「离得近、没响」不再逐条写。ADR-154 末尾那十几块清点，每块里「离得最近、没响」那一段都逐条列了十几张，它们一张也没因此还上。

### 4. 只拦新登记的闸门

主干上只报数。只在一种情形红：一条 PR 新开了以登记为去向的欠条块（块头档写登记，或本改动第三轮起不阻塞的），而主干上「到期、开着、没有状态行」的超过 10 张。这时作者有三条路：把那条发现修在本 PR；照扩范围或既有缺陷排队；或者等需求所有者把到期的判了、下一条欠条 PR 把状态行落下。闸门不碰扩范围与既有缺陷的块，不碰回访 PR，不碰只写状态行的 PR。10 是需求所有者 2026-10-23 定的，四周后按回访数据再调。

它能数（登记日、状态行、块头的档都从 git 读得出），有豁免通道（需求所有者的人判），要人维护，所以要有死亡条件，接入口的那一片照 `process/README.md`「往上撤」那一节的写法写进本条末尾。现在定下的两条：连续八周「到期、开着、没有状态行」都是 0 时，退成只报数 —— 它拦的情形不再发生；周回访停了时整个撤掉 —— 到期没人列，闸门就只剩拦路（回访的停用条件见 ADR-151 第四节第 4 条）。

照 `process/6-INTEGRATE.md`「闸门自身走『最后一块砖』」（第 278 行起）：判定、测试、变异一片，接进检查链一片，接入口的排最后。

**开工前要定的一件。** 闸门第一天拦不拦人，取决于那时主干上到期还开着的有多少：存量里条件真没响、改法也不小的那一类，多半已经登记满四周，回访一周只列 10 张。体检页第七节的办法是接入口之前，把那时到期还开着的列成一张表请需求所有者一次判完；可「留」只许一次（第 4 句），四周后那一批再到期时只剩还或收尾，而其中有的条件在本仓库里就是等不到（只在 Windows 上成立的、要真实账单的）。这一类是收尾、还是要第三个词，第五节第 9 片开工时按那时的台账实数请需求所有者定。
