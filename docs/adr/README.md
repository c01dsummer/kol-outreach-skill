## 一条记录 = 一个文件

文件名 `ADR-<编号>-<标题>.md`，第一行是 `# ADR-<编号> <标题>`。
两处编号必须一致，`npm run adr` 会验；下面的索引由它生成，**勿手改**。

装在一个文件里的时候，ADR 是这个仓库最大的冲突面 —— 它在语义上追加、
彼此独立，本该是最不该冲突的东西。三条在途分支各自把整册从 537 行写到
1978~2539 行，而且编号互相交错：第一条合进主干之后，后两条不是「追加到末尾」，
是往文件中间十几个位置插入。

换成文件之后，两份记录**多半**各自落地 —— 文件名撞不撞，看的是两个标题过完 `slugify`
之后一不一样，而 `slugify` 有损（剔标点、连续空白归一成 `-`、截到 32 码点），
所以不同标题也可能同名。
**稳定**冲突的是下面那张生成的索引 —— 新行都加在同一个位置，两条分支各加一条就撞在那儿，
而这道冲突**跟它们是不是抢了同一个号无关**：号不同也照样撞。
**它挡的是并发加记录，不是抢号。** 撞号是另一回事，而且只有一半管得住：两份记录
**各自作为不同文件留下来**时，等两边合到一起由 `npm run adr` 比出来；两个标题过完
`slugify` 同名时，git 在那个 ADR 文件上还会另报一次 add/add —— 人按「留一个」解掉，
合出来的树上就只剩一条记录，`npm run adr` 一路全绿。
还有一个更要紧的后果：ADR 不依赖任何代码，于是它**可以先于实现单独合进主干** ——
一个改动里最大的那块因此不必再挤在代码的 PR 里。

**编号允许有空号。** 号一旦用过就不复用，包括那些活在别的分支上、还没合进来的。

写什么、怎么分类，见 `process/2-CHANGE.md`。
