# ADR-79 收窄决策记录闸门：它守的坏法在 diff 里是一行红字

- 2026-09-18 · 按 Bitter Lesson 原则重整检查链，逐道评定里的第五道
- 类型：缩范围（收窄一道闸门，不撤）
- 冲击的需求：无
- 结论：**留纯文件系统那一半，撤对着主干比历史那一套 git 机器**

## 留什么，撤什么

**留**（`npm run adr` 从此一次 `git` 都不调）：编号唯一、文件名与正文标题一致、
`README.md` 索引与目录一致、`DECISIONS.md` 不许再装整册。

**撤**：`checkAppendOnly` ＋ `Baseline`（`adr-rule.ts`）、`trunkAdrs`（`adr-sync.ts`）、
`check.yml` 传进来的 `GIT_PUSH_BEFORE`，以及守它们的两条变异 `M-H10-c`／`M-H10-d`
和 `test.ts` 里七条夹具。`adr-rule.ts` 189→139，`adr-sync.ts` 268→213。

## 为什么

它守的是「编号不可回收」：**删掉一条记录，把号让给另一条决策**。

而那个坏法在 diff 里长这样：

```
 deleted file mode 100644
 docs/adr/ADR-42-权限收在写完之后，那段窗口里数据是敞开的.md
```

**一行红字，评审第一眼就看见。** 「标题换了」同理 —— 一行 `-# ADR-42 …` 配一行 `+# ADR-42 …`。

这是**响亮的**失败。harness 该守的是那种不看就永远发现不了的坏法；
守一个已经写在 diff 上的东西，换来的是三个联动件（一段 git 调用、一个环境变量、
一段 CI 配置）和它们自己的两条变异 —— 全是为了重复说一句 diff 已经说过的话。

斜率也一样：「对着主干比两份清单」是记账，一个读得了 diff 的上下文顺手就答了。

## 代价，说清楚

- **直推主干那条路没有 diff 可看。** 这套机器当初加的 `GIT_PUSH_BEFORE` 正是为它 ——
  一次直推里删掉一条记录，现在没有东西会红
- **跨分支的号冲突本来就没守住**，撤这套机器不改变这一点（它自己的注释明写
  「编号跨分支没有任何机制守着」）

`docs/adr/README.md` 开头那句对外契约「追加，不删改」已经加了一块 ⚠️ 说明它
现在没有机器守；`process/6-INTEGRATE.md` 的三层表里也补了一行，落在第三层。
**不留一句声称被守住、实际没有的话。**

## 什么条件下重开这个讨论

- **真发生一次**：一条记录被删掉或标题被换掉，而且是事后才发现的。
  那说明 diff 这一层没接住，值得把机器装回来 —— 但装回来要连直推主干那条路一起想
- **改成不再靠人读 diff 时**：比如评审改由独立上下文的 agent 承担，
  那时「谁读 diff」这个前提变了，这条要重判

**谁去数**：没有机器在数。下一个删 `docs/adr/` 下任何文件的人自己知道。

> ⚠️ 欠条：**`--split` 留着没评定。** `npm run adr -- --split` 是给还装着整册
> `DECISIONS.md` 的在途分支用的迁移工具，和本条撤的那套 git 机器无关，所以原样保留。
> 但它今天还有没有用户没核过 —— 主干上 `DECISIONS.md` 早就只做转发了。
> · 重启条件：**下一条碰 `adr-sync.ts` 的 PR**，顺手核一次还有没有在途分支需要它；
> 没有就连它一起撤。
