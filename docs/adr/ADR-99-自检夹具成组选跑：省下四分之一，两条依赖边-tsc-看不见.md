# ADR-99 自检夹具成组选跑：省下四分之一，两条依赖边 tsc 看不见

- 日期 · 2026-09-21 · ADR-97 第六节记的那条主修。起因是用户问「`npm run check` 时长
  又劣化了…这次的『劣化』是不是应该的」，那一轮的结论是「工作量该付、乘数不该付」
- 类型：**既有缺陷**（检查链自身的成本结构）。不触及需求登记表 —— 检查链的成本不是编号需求
- 触发它的事实：见第一节（同机同条件实测，命令在那一节）
- 冲击的需求：无。冲击的是**检查链自己跑得起跑不起**
- 结论：**① 24 组夹具「先登记、后按依赖闭包派跑」，`--only` 选跑；② 依赖图里有两条边
  `tsc` 看不见，只有真跑子集才发现得了；③ 子集跑要收三处口，否则 `survived` 这一态
  对每一条负片都不可达；④ ADR-97 第六节那个估算错了单位也错了量级，本条一并订正**
- 理由：一条负片要证的只有「它点名的那 1–3 条夹具会红」，而今天它要付整段前缀

## 一、省下多少

**每个数各自钉一棵不会再动的树**（`REVIEW.md`：可算的数要么钉树、要么只写命令）。
本机那一组是同一台机器、串行、机器空载；CI 那一组是 GitHub 的 runner，我没有参与。

| 树 | 变异数 | 本机全链 | CI 上 `check` 那一步 |
|---|---|---|---|
| `7c4fd39`（主干） | 389 | **603 s** | **615 s** |
| `d62a175`（代码齐了，ADR 还没写） | 395 | **432 s** | — |
| `25813f4`（含 ADR 那一版） | 395 | 442 s | **479 s** |

**本机省 171 s（−28%），CI 省 136 s（−22%）。** 而且跑的变异还多了 6 条。

`d62a175` 与 `25813f4` 之间只差几份 `.md`，那 10 秒是抖动；两组分别由两台机器、
两套负载量出，量级一致 —— **CI 那一组是这条改动最硬的证据，因为它不是我跑的。**

⚠️ 合进主干的那一版会比 `25813f4` 再多几行 `.md`（就是这张表本身）。**没有重量** ——
只改文档的提交不会动这几个数，而钉着的三棵树都还在。要当下的数就照上面那条命令跑一遍。

⚠️ **要看的是这个数，不是串行 Σ。** 自检负片的串行实付从 737.4 s 降到 145.2 s
（省 592 s），但那是**串行**；真正付钱的是 4 核（本机与 CI 都是），除下来约 148 s，
再加上派工的尾部效应，落在实测的 171 s 上。

量它的命令：

```
git checkout <上表任一棵树> && time npm run check
```

## 二、依赖图：两条边 `tsc` 看不见

把 24 个小节机械包进 `group()` 后跑 `tsc --noEmit`，收 82 条 TS2304：24 条是预期的
`group` 未定义，另 58 条是跨节绑定，共 12 个名字。**十个是无状态的**（纯函数与两个
常量），外提到模块作用域即可；**两个是真运行态**：`dir`（collect 那一跑的产出目录）、
`rendered`（render 那一跑的产出）。

于是我写下的依赖表是：`enrich←collect`、`render←collect`、`regress←{collect,render}`、
`memory←{collect,render}`，并声称「其余 20 节互不依赖」。

**那句话是错的。** 独立复核真跑 `{collect, render}` 子集，当场红两条：

```
✗ HTML 缺少公开指标或其边界声明（违反 U7/P5）
✗ HTML 缺少 KOL 活跃状态（违反 D10/U7）
```

`render` 真的需要 `enrich` —— 它读 `enrich` 落下的 `enrichment.json`。两者之间
**一个名字都不共享**，所以 `tsc` 的 82 条里没有它。

第二条同族的：`bothTmp` 被我列进「十个无状态、外提即可」的名单，而外提的只是那行
路径常量，造目录与写语料还留在原处 —— 用它的地方会拿到 ENOENT，那会打出带（进程）
记号的失败，`notAssertion` 一票否决，整次判「跑不起来」。整段一起搬才对。

> **`tsc` 抓得到名字级的耦合，抓不到文件系统级的。** 各节都往同一个 `tmp` 下写东西，
> 而那种耦合没有名字。**只有真跑每个子集才证得了。** 这条改动的依赖表因此是
> 「跑出来的」，不是「推出来的」。

## 三、先登记，后派跑

一组要不要跑，取决于后面有没有别的组 `needs` 它 —— 边登记边跑的话，第三组执行的
那一刻还不知道第八组会不会点它，于是只能另外维护一张手写的依赖表，而手写清单会烂
（ADR-77 撤掉的那张手写敏感字段表就是先例）。登记完再派，依赖只写在 `group(...)`
的第二个实参上，只此一份。

## 四、`--only` 收组 id，不收夹具名

头一版的理由是「收组 id 要让 `mutate` 多维护一份手写映射」。**那个理由是假的** ——
`mutate` 每跑一次本来就在读验证者源码跑 `labelsOf`，同一趟语法树多收两个字段就够，
ADR-77 碰不着它。

真正的代价在另一侧：收夹具名要让 `selfcheck` 在**运行期** import typescript 扫自己的
源码，实测每跑约 +0.65 s，乘 19 条负片约 **+12.4 s** —— 占这条改动目标的一成。
所以翻译放在 `mutate` 那边。

**任何一条点名的夹具落不进某一组，就整跑。** 宁可多跑，不可漏验 —— 漏掉的表现是
「跑完、没红」，一条本该被抓到的变异会被判成没人抓得住。

## 五、子集跑要收的三处口

**没收之前，每个子集跑都剩一条 `✗`（孤儿检查），而那不是「多一条红」：**
`failed` 一涨退出码就非零，`judgeRun` 第一句 `exitCode === 0` 走不到，于是
**`survived` 这一态对每一条负片都不可达** —— 「这条变异没人抓得住」这个最要紧的
信号被静默换成 `elsewhere`。

- **孤儿检查在子集跑里不判、不计 `failed`**，照 `noShell` 的先例显式打一句
  「这一跑没验『每个可执行文件都有出处』」
- **成功支那句「N 个可执行文件都有出处」**在子集里同样不成立，换成说得准的
- **入口认领既不删也不写**：`claimed` 只装这一跑跑到的那几条判据，写回去等于拿残缺的
  记录盖掉完整的，而审计读的就是这份文件

## 六、老实说，什么缩了

`notAssertion` 的一票否决看的是「这一次运行的输出」。点名的负片走 `judgeRun` 的
`atStop` 那条路，所以**今天它看的已经只是「跑到那条夹具为止」的前缀**；`--only`
把这个前缀从约 50 s 缩到约 1–21 s。

缩掉的是「这条变异顺手把别处弄崩了」这种发现（ADR-70／#139 两轮评审才补上的）。
这是真的缩。换来的是那 171 秒。照 ADR-77：写出来，不假装没缩。

## 七、ADR-97 第六节的两处订正

- **单位**：那里写的「Σ 676.8 s → 约 20–40 s」是**串行 Σ**，不是实付。本条按 4 核实测
  给的是 603 s → 432 s。这个单位错误是本条从第六节继承的，一并改口
- **量级**：「约 20–40 s」把依赖闭包当成了空集，也没算到有几节自己就很贵
  （`memory` 12.0 s、`f9` 10.2 s、`collect-resume` 9.5 s）。实测的子集 Σ 是 **145.2 s**
- 第二节末那行「乘 347 条」与「selfcheck ×18」是当期陈述、已经过期（`7c4fd39` 上是
  370 与 19）。ADR-98 第六节已经更正过一次，本条不再重复记数 —— 要当下的数就跑一遍链

## 八、缺口与欠条

- **`--only` 点得着的只有一半小节。** 24 组里 12 组一个具名夹具都没有（`labelsOf`
  只认 `named(...)`／`endPath(...)` 的字面量），于是点不着。它们不是「不跑」——
  不点名时照样全跑，而且 `collect` 正是靠 `needs` 被别人拖进来的
- **`mutate` 不检查 `find` 在目标文件里是否唯一**，出现两次时静默只改第一处。
  这条在本条改动里真的发作过一次（见提交历史），登记在 `scripts/check/mutate.ts` 名下

  > ⚠️ 欠条：`mutate` 的前置体检不问锚点唯一不唯一，静默只改第一处 —— 错改的那处
  > 恰好有测试守着时，会报「被抓到」而要验的东西一个字没动 · 重启条件：下一条改动
  > 碰到 `mutate.ts` 里 `wiringFault`／`labelFault` 那几道前置体检

- **`mutate` 仍然不打那个乘法。** 每个验证者被几条变异用、每条跑多久，两个数它都手上
  有，却从不相乘给人看。这一条要在 `Ran` 上加字段并穿过 worker 的进程边界
  （`parseReport` 逐字段严格校验），连测试与负片是独立的一件事

  > ⚠️ 欠条：`mutate` 不打「每给一个验证者加一秒要乘以多少条」这个乘法 ·
  > 重启条件：下一条改动碰到 `jobs-rule.ts` 的 `Ran` 或 `parseReport`

- **缺省验证者那一族一点没动。** 本条之后它占串行总量的九成：370 条各跑一整遍
  `test.ts`，而它们一条 `kills` 都没有，`stopIfSeen` 第一句就 `kills === undefined`
  返回 —— 那里没有前缀可砍，因为根本没有「停」这回事

  > ⚠️ 欠条：给 `test.ts` 也切子集的路子没做，而它才是大头 · 重启条件：下一条专门
  > 碰检查链时长的改动

## 九、为什么没有死亡条件

ADR-85 已经给 `selfcheck` 逐半判过（假 fetch 端到端「不该有」、`mutate` 入口接线
「早有，ADR-81」、孤儿检查「补一条」，条件与数法都在那里）。本条没有新立闸门，
只是让孤儿检查在子集跑里不判 —— 整跑那一侧一个字没改，那条死亡条件照旧成立。
写下「判过、早有」，免得下一个人当成漏了去补一份不会响的。

## 什么条件下重开这个讨论

- `--only` 点不着的那 12 组里有谁长出了具名夹具 —— 那一刻要重新问一遍它的 `needs` 对不对
- 有人往 `group(...)` 的 `needs` 里加第五条边 —— 前四条是真跑子集跑出来的，第五条
  也必须这么来，不能靠 `tsc` 或靠读代码推
- 缺省验证者那一族也切了子集之后 —— 那时这两族的成本结构要重新摆一次
