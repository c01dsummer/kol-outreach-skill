# ADR-99 自检夹具成组选跑：省下四分之一，两条依赖边 tsc 看不见

- 日期 · 2026-09-21 起，逐片追记到 2026-11-14
- 类型：既有缺陷（检查链自身的成本结构）。不触及需求登记表
- 触发它的事实：ADR-97 第六节记的那条主修。起因是用户问「`npm run check` 时长又劣化了…这次的『劣化』是不是应该的」，结论是「工作量该付、乘数不该付」；实测见第一节
- 冲击的需求：无。冲击的是检查链自己跑得起跑不起
- 结论：采纳，已落地。自检与需求测试的夹具按组登记、按依赖闭包派跑，`--only=` 选组；每条变异写明由哪个验证者（`by`）的哪几条具名断言（`kills`）抓到，变异一步只跑那几条所在的组。有 `tsc` 看不见的依赖边，只有真跑子集才证得了。省下的是 CPU，不是墙钟
- 理由：一条变异要证的只是「它点名的那几条断言会红」，不该付整段无关前缀
- 连带改动（现状）：`scripts/check/` 下 `group-rule.ts`（登记、闭包、选组读法、组图校验）、`mutate-rule.ts`（路由 `executionRoutes`、`fixtureLabel`、锚点计数、基线判定）、`jobs-rule.ts`（计时记账、`--jobs=`）、`share-rule.ts`；入口 `selfcheck.ts`、`scripts/test.ts`、`mutate.ts`；`mutations.json` 的 `by`／`kills`

> 本文件只写现在定的是什么。节号沿用原文，好让老引用照旧对得上；空着的节号与没收进来的追记是实测、复核、迁移批次与更正的过程，原文在 `docs/adr/历史/` 下的同名文件里（ADR-211）。

## 一、计时怎么报：给 CPU、给区间，或者只写命令

墙钟不是树的函数：同一棵树、同一台机器，全链墙钟先后跑出过 603 s、663 s、706 s、788 s。头一版报的「墙钟省 28%」只是区间最好的一端，作废。交替配对（本条、主干轮流跑）量出的是 CPU（user + sys）：1595.0 s → 1230.6 s，省 364 s（−22.9%），两组不重叠。

规矩：计时只有三条出路 —— **给抗抢占的量（CPU 时间）、给多次与区间、或者只写命令**。一个样本只够证不等式，不够证速率；红了的那一跑不是测量。`REVIEW.md`「钉一棵树」管的是树的函数，时间不在其中。命令：

```
for i in 1 2 3; do
  { time npm run check >/dev/null; } 2>"/tmp/t$i" || { echo "第 $i 跑红了，不算数"; continue; }
  grep -E '^(real|user|sys)' "/tmp/t$i"
done
```

CI 耗时取 Actions 里 `Run npm run check` 那一步的起止，不含排队与 `npm ci`；CI 上没有可比的 CPU。

## 二、依赖图：两条边 `tsc` 看不见

`tsc` 抓得到名字级的耦合，抓不到文件系统级的。真跑子集才发现的两条：`render` 读 `enrich` 落下的文件，所以是 `render←{collect, enrich}`；`bothTmp` 要连造目录、写语料整段搬，不能只外提路径。依赖只写在 `group(id, needs, …)` 的第二个实参上，不另抄表。后来模块级共享状态由 `share-rule.ts` 按语法树扫（ADR-134）；拼出来的路径、当前目录下的相对路径、`process.env` 这类扫不见的通道仍只有真跑证得了（其中当前目录那一种，完整自检收尾时由 `judgeCwds` 补核，ADR-212）（清单在 `share-rule.ts` 文件头）。

## 三、先登记，后派跑

所有组登记完再派跑：一组跑不跑取决于后面有没有组 `needs` 它。

## 四、`--only` 收组 id，翻译在变异那一侧

验证者的 `--only=` 只收组 id；「点名的断言在哪一组」由变异一步读验证者源码翻译，验证者不在运行期 import TypeScript。**任一条点名的断言落不进组，就整跑**：宁可多跑，不可漏验。

## 五、子集跑要收的三处口

带 `--only=` 的一跑：孤儿检查不判、不计失败，照实说「这一跑没验『每个可执行文件都有出处』」；成功支不说「N 个都有出处」；入口认领不删不写。否则「变异没人抓得住」这一态永远不可达。ADR-132 后完整自检拆成按族子进程，子进程不写认领、不说「没验」，父进程全绿时合并写一次。

## 六、缩掉了什么

点名的变异只跑到它点名的那几条为止，缩掉的是「这条变异顺手把别处弄崩了」这种发现。照 ADR-77 写出来。

## 七、ADR-97 第六节的两处订正

那里的「Σ 676.8 s → 约 20–40 s」是逐条之和、不是实付，量级还把依赖闭包当成了空集。实测见第一节。

## 八、当初登记的三处缺口，现状

锚点不唯一时静默只改第一处 —— 已拦（第十一、十二节）；`mutate` 不打「每给验证者加一秒要乘多少条」的乘法 —— 已打（第十四节）；缺省验证者 `test.ts` 那一族没切子集 —— 已迁完，每条变异都有 `by` 与 `kills`，没有整跑的。没有具名断言的组点不着，但整跑与被别组 `needs` 拖进来时照样跑。

## 九、第二轮复核定下的几条

- 新模块进 `docs/ARCHITECTURE.md` 锚点表（这张表没有机器核）。
- `--only=` 点了零个组：退出 1、说出来，不打绿。点错组名等顶层抛出：临时目录挂在 `exit` 上删。
- 「清册数得出的每条标签，归组都翻得出组」有断言钉着，否则选组会静默退回整跑。
- `selfcheck.ts` 文件头写明 `--only` 开的两处例外。

这一节当年登记的五张欠条都已还：子集基线（第十五节）、选组判定挪出入口（ADR-120）、具名判据只写一份（2026-11-13 那节）、组图校验（2026-11-14 那节，余下一半在 ADR-212）、旗标读法统一（第十八节与 `--jobs=` 那节）。

## 十、为什么没有死亡条件

本条没立新闸门，只让孤儿检查在子集跑里不判；ADR-85 给 `selfcheck` 判过的那条死亡条件照旧成立。

## 什么条件下重开这个讨论

- 点不着的组里有谁长出了具名断言 —— 重新问它的 `needs` 对不对
- 有人往 `needs` 里加边 —— 要真跑子集跑出来，不能靠 `tsc` 或读代码推
- 缺省验证者一族也切了子集后，成本结构要重摆一次 —— 这一族已迁完（第八节）；有没有据此重摆过，原文没记，挂成下面「缺省验证者一族迁完后成本结构重摆过没有没记」

## 十一、锚点必须恰好出现一次

变异的 `find` 在目标文件里必须恰好出现一次。按起点数，重叠的也算（`aa` 在 `aaa` 里两处）；空锚点在非空文件里一律不唯一；零次照旧报「锚点失效」。判定 `anchorMatches`，负片 `M-H45-a`、`b`。

## 十二、入口在开跑前拦下

`mutate` 开跑前逐条数锚点，两处以上整跑拒绝、点名编号与处数、退出 1；规矩写在 `mutations.json` 格式说明里。入口这一半只有自检夹具守：指着 `mutate.ts`、由自检来验的变异会被「自己验自己」那道体检拒掉（ADR-70）。

## 十三、打乘法之前先量时长

条数一直数得出，时长原先没量，所以先加计时再打乘法（第十四节）。`mutate` 不认 `--only=`，给了也照跑全部。

## 十四、每条变异计时，收尾按验证者记账

`Ran.ms` 量验证者从进程报 `spawn` 到 `close`（#224 起），没跑的记 0，随汇报行过 worker 边界、逐字段验。收尾每个验证者印一行：条数、平均、逐条合计、「它每慢 1 秒整跑串行多〈条数〉秒」。合计是逐条墙钟相加，不是串着跑的估计，也不是 CPU；乘数是数出来的条数。`mutate` 自己不拿秒数判事；ADR-203 变异负载闸门的秒数文件从这份账派生，规矩在那边。计时与记账本身没有断言守着（欠条现挂在 ADR-203 第 137 行）；起验证者与起 worker 那两处 env 的编译缓存也没人守（ADR-72 第 708 行）。

## 追记（2026-09-24）：PR #174 第三轮评审登记的一条

「串着跑时整跑一定比逐条合计长」不是契约：每条 `ms` 取整后相加，每条最多多记半毫秒，靠的只是不计时的开销够大。已写进 `BillRow.totalMs` 的说明（#283）。

## 十五、需求测试也按已验证的断言选跑

- 点名的断言全落进组才走子集；施变后**点名的断言全红**才算抓到（`judgeRun`），别处红、崩溃、超时、夹具故障都不算。
- 每种「验证者 + 选中组」在施加任何变异前，先在隔离目录用正常源码跑一次基线，同配置只一次；不绿就拒绝派发、退出 1。
- 需求测试子集自然跑完（`finally` 收拾）；自检子集见齐点名的就停。子集都不碰完整认领。
- 检查执行器与选跑判定自身的变异，不许借被改坏的工具给自己判分。

## 十六、拆组时旧组名留作兼容入口

按变异点名的断言把一组拆细时（`config-entry`、第十七节的 `render-input`、后来的 `task-list`），旧组名改成依赖新组的入口，完整自检的顺序与认领条件不变，`kills` 不改、按断言自动归到新组。

## 十八、自检入口也拒绝非法选择

两个入口共用 `parseOnlyStrict`，在认领清理与夹具准备之前解析：空选择、空白组名、重复选择或参数、未知参数都退出 1、不跑夹具；不带选择才全跑。入口接线由独立需求测试与 `M-H42-j` 守，自检不验自己的基础设施。旧 `parseOnly` 只留给原测试与负片。

## 十九、基线先于变异；提前停止会留下目录

每个配置的正常基线都在变异结果之前完成。提前停下的自检变异会留下 `kol-selfcheck` 随机临时目录，这是既有情况，不能称整批零残留。

## 2026-11-14：登记的组图有了校验

## 2026-11-14：`--jobs=` 也照 `--only=` 的读法
