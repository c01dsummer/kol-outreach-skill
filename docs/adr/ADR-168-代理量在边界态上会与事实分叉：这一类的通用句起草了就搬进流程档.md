## 给 process/ 的候选句

```
拿一个代理量判一件事,先核两者在边界态上会不会分叉。「整份解析得了」代「没写坏」、「进程表里还有这一项」代「它还会执行」、「读到了换行」代「这一行写完了」—— 平常两者说的一样,到了正在写、刚结束、只剩空壳这类状态就各说各的。这时上面那一问要两头问:事实不成立时它会不会过(把写了一半的判成写完了),事实成立时它会不会不过(把还没写完的判成写坏了)。读一份别的进程还在往里追加的文件,最后一截先当成可能没写完;确认写的人都结束后,再按记录格式判断尾段是否损坏。
```

放在：`process/4-VERIFY.md`「判据的失效方式」那一节「推论」的末尾，本条那条 PR 已经搬了，字与上面相同（那边按流程档的行宽折了行，头一句加粗）。

来源：
- ADR-70 第 1159–1161 行：变异入口按整行认验证者的输出，第一版把两股输出合起来再截整行，两股之间人为插进的换行被当成行尾，半行算成了写完（#99 评审指出）。代理量是「读到了换行」，要判的是「这一行写完了」。
- ADR-133 第 10 行（「教训」一栏）：「用一个代理量判一件事（这里是「0 号信号送达」代「还会执行」），先核两者在边界态上会不会分叉」。进程成了只剩一个线程的僵尸，信号照样送得到，夹具把它判活，判了红。
- ADR-155 第 10 行（「教训」一栏）：「读一份别的进程还在往里追加的文件，最后一截先当成可能没写完；只有写的人都结束了，半截才是坏」。拿「整份解析得了」代「轨迹没写坏」，在「正在写」上分叉，把还在写的判成写坏了。

## 一、句子怎么来的

头一句照 ADR-133 第 10 行「教训」的前半句写，去掉了括注里本仓库的例子。举的三个代理量是这三条各自用的那一个，换成不点名本仓库的说法（`docs/SYNC.md`「一条判别规则」）。末一句取自 ADR-155 第 10 行「教训」的追加场景，将最终判断收准为确认写者结束后，再按记录格式判断尾段是否损坏。「上面那一问」指同一节开头那一问「什么东西能在事实不成立时，也让这个检查通过」。
「两头问」是三条合起来才看得见的：ADR-133 与 ADR-155 是事实成立时判了不过（误红），ADR-70 是事实不成立时判了过（放过）。同一节开头说判据的失效方式「从来不是「判错」，是「被无关的东西满足」」，那一问只问放过的那一头；新句说的是，到了边界态，这一问要两头问。

## 二、落在那里的理由

那一节问「什么东西能在事实不成立时也让这个检查通过」，表与推论说的都是代理量被别的东西满足。新句补它没说的那一截：代理量与事实只在某一种状态下分叉，平常查不出来，分叉的方向也不一定是放过。

已有的近亲，同一节表里有「源码里搜到某个标记 = 那件事做过了」「容器的类型对了 = 里面的东西能用」，推论里有「"没测量"和"测量结果是零"必须是两个不同的值」「观察器的零记录不能单独证明没有事件」。它们说的都是代理量在某一类输入上失灵，没说正在写、刚结束这类在时间上的边界态。`process/README.md` 第 235 行「每个传感器都写明它怎么失效」说的是反馈回路里的传感器读不到、样本不足、口径变了，也不是这一类。

## 三、不加检查

「哪个量是代理量、它在哪种状态下与事实分叉」要读那个判据才答得出，没有能机器判的字面形状。这句和同一节的推论一样，靠写测试、评审的人读。

## 五、为什么开一条候选句记录

记录只追加，ADR-155 第 117 行那张欠条还上以后照样留在原处，回访例程的第一道门每周照样认得它。本条头部那一行「候选句来源」写全了这一类的三个编号，本条没有驳回块就算活着，第二道门见了它就不再为这张起草（`docs/REVISIT.md`「候选句」）。

照 ADR-153 第 75、77 行的先例，本条末尾把「process/ 里没有这句通用话」欠条与「上文那张……欠条已还」分成两块，中间空一行：挂了又由同一条 PR 当场还。已还块头一行照 ADR-151 第十四节第 11 条定的写法，第四节第 6 条第三个数才数得到这一次搬动。

**本条把开候选句记录和搬进 `process/` 合成一条 PR，偏离 ADR-151 第十四节第 11 条「搬由另一条 PR 做」的约定。** 分开的两块只保住计数，不消除这个偏离；本条走普通草稿 PR，须由合并者明确认可这个例外才能合入。不改那条通用约定，也不据此把以后的候选句都合成一条 PR。

需求所有者不要这句的，照 `docs/REVISIT.md` 的写法在本条末尾追加一块驳回（头一行以 `> ⚠️ 驳回：` 开头，「驳回」后面直接接冒号、不加括注），同一条 PR 拿掉 `process/4-VERIFY.md` 那一条，**并在 ADR-155 末尾追加一块更正，说明第 119 行「已还」的处置不再成立**；不改写原块。驳回以后，本条那张「process/ 里没有这句通用话」欠条照旧挂着（ADR-151 第十四节第 11 条），不是已搬进流程档；欠条括号里出现这三个以外的编号之前，例程不再为这一类起草。

截至 2026-10-24，本条仍是未开 PR 的候选。头部「采纳」、上文「本条那条 PR 已经搬了」与两处「已还」说的是本候选拟交付的改动，不代表主干已经采纳或合入；批准痕迹待需求所有者在真实 PR 上留下。两块里的 PR 号占位符留待取得真实 PR 号后追加提交替换，不能拿占位符当批准依据。
