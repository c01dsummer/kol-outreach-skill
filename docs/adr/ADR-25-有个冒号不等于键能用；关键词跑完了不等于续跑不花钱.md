# ADR-25 「有个冒号」不等于键能用；「关键词跑完了」不等于续跑不花钱

- 日期 · 2026-08-28 · PR #5 第七轮自动评审，两条都成立
- 类型：**事实证伪**（两条都是上一轮的修复只覆盖了它看得见的那一种情况）
- 冲击的需求：**P4**（红线）· D4 · D6 · P3（预算相关的承诺）
- 结论：**采纳**，两条都改

### 一、键的黑洞还有三扇门开着

ADR-22 加了键的规范化与形状校验，判据是「有一个冒号，两边都不空」。
**那只挡住了我当时想到的那一种畸形。** 实测：

| 键 | 修之前 | 修之后 |
|---|---|---|
| `tikok:alice`（平台拼错） | `status: ok`，**已联系的人进名单** | 拦下 |
| `tiktok:alice:old`（多一个分隔符） | `status: ok`，**已联系的人进名单** | 拦下 |
| `youtube:alice`（不支持的平台） | `status: ok`，**已联系的人进名单** | 拦下 |

判据本身就写错了方向：我问的是「这个键长得像不像键」，
**该问的是「查询侧生成的键是什么形状」** —— 那边生成的永远是
`{支持的平台}:{handle}`，恰好一个分隔符。任何别的形状都匹配不到，
都是黑洞。

修法：分隔符恰好一个、平台必须在支持范围内。
顺带把平台的**运行时列表与类型**改成从同一处派生
（`const PLATFORMS = [...] as const` + `typeof PLATFORMS[number]`）——
手写两份迟早分叉，而分叉的后果正是「校验放行一个查询侧永远匹配不到的值」。

### 二、「关键词跑完了」不等于续跑不花钱

ADR-22 把中止时那句承诺改成按 `pendingKeywords` 说话。
**但没干完的活有两种。** 关键词全跑完之后，`--resume` 第一件事是跑
`enrichProfiles`，它对每个 `bio` 未查询或没取到外链的人调**付费**端点。
于是「采集已跑完，续跑不产生新的请求」在这种情况下**仍然是假的**。

修法：把「这个人还要不要补 profile」抽成 `needsProfile`，
**补全循环与那句话共用同一个判定**，消息按两种剩余工作量一起说。

抽出来的第二个理由比第一个更实际：两处各写一份 `c.bio === undefined || …`，
迟早有一边先改，而**先改的那边不会报错**。

### 教训

**修一个「漏了一种情况」的缺陷时，最容易犯的错是只补上被指出的那一种。**

两条都是这个形状，而且都发生在我刚刚为同一个问题写过 ADR 之后：

- ADR-22 补了键的校验 —— 补的是「我当时想到的那种畸形」
- ADR-22 补了续跑的代价 —— 补的是「我当时想到的那种剩余工作」

区别在于问题问得对不对：

> 问「这个输入长得对不对」，答案取决于我能想到几种畸形。
> 问「**消费它的那一侧要求什么形状**」，答案是有限的、可以穷举的。

第二条同理：不去数「有哪些活没干完」，而去问「**续跑会调用哪些付费路径**」——
后者在代码里是可以数清楚的，前者取决于我记得几种。

**把判据从「像不像」换成「对面要什么」，是这两条修复真正的内容。**
