# ADR-14 旧缓存的样本记录也收进窗口，与新抓样本同一形状

- 日期 · 2026-08-27 · PR #4 第二轮评审意见
- 类型：**事实证伪**（ADR-13 的边界建立在一个我没去核实的假设上）
- 冲击的需求：D8（溯源）· D10（零请求补算）· U7（摘要关联到交付行）
- 结论：**采纳**。ADR-13 的「盘上的样本本身不会被重写」作废

### 触发它的事实

`summaryOf` 把样本记录**自己的说法**发布进交付物：记着几条、`sample_size`、`basis`，
经 `attachAssessments` 挂到每一行。所以一份收窄之前写下的缓存（提供方多返回 16 条）
会在交付物上声称 16 条，而指标是按窗口内的 11 条算的 —— 同一行数据里两个数互相打脸，
而运营两个都看得到。

ADR-13 写那条边界时的理由是「重写历史记录会丢掉当初真实抓到的东西」。
这个理由是假的：那批窗口之外的帖子**从来没有任何计算用过**，而新抓那条路径
（`publicPostSample`）从一开始就把它们丢掉了。真正的不对称是形状：旧缓存与新样本
在盘上长得不一样，收窄之后才一致。

### 结论与边界

- 旧缓存走**与新抓样本同一条** `publicPostSample`，所以「盘上的样本记录」
  只有一种形状，与它是哪一版写下的无关
- 收窄不动 `observed_at` 与 `source`：它们属于当初那次采样
- 样本本身是 `unavailable`（私密、账号不可用）时原样留着，不被改形
- 零请求这一条不变；由自检的「超窗样本记录零请求收窄」守，判定由 M-D8-c 守

### 顺带修掉的一个虚报

同一轮评审指出：`calculatePublicMetrics` 只给 `audience_quality_risk` 放一个占位符，
真值由 `assignAudienceRisks` 跨账号赋。把它算进「数换过没有」的比较，
每一轮都会把「占位符 vs 已赋值」当成变化 —— `locally_recomputed` 于是每轮虚报，
而那正是 ADR-13 里我自己声称「变准了」的数字。比较现在排除这一个字段（M-D10-b 守）。

### 教训

**一条边界如果建立在「下游用不到它」上，先去看下游用没用。**

我当时没看 `summaryOf`。ADR-13 那一节读起来是个有分寸的取舍（不重写历史、不丢证据），
而它其实是一句没核实的猜测 —— 而且被写成了决策记录，比留在代码里更难被质疑。
