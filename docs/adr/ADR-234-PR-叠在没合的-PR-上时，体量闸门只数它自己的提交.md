# ADR-234 PR 叠在没合的 PR 上时，体量闸门只数它自己的提交

- 日期 · 2026-11-22
- 类型：不属于反向输入的五类 —— 改的是检查链自己
- 触发它的事实：体量闸门（一个 PR 新增行数的上限，超线要在提交信息里写 `size-ok:` 具名豁免）量的是「分支相对主干的全部新增行」。一条 PR 开在另一条还没合的 PR 上面时，下面那条的新增行算进这条，下面那条写的 `size-ok:` 豁免也被这条捡到。分支寿命闸门在 ADR-63（叠分支不再继承下面那条的豁免）修过一模一样的洞，体量闸门没跟着修。需求所有者 2026-11-15 在「要不要采用堆叠 PR」的选择卡上选了「暂不采用，但先补体量闸门这个洞」
- 冲击的需求：无
- 决定人与时间：需求所有者 2026-11-15 的选择（见上），做法照 ADR-63 的形状，不需要再选
- 结论：采纳。人批痕迹：需求所有者合入本条那条 PR
- 理由：见第一节
- 连带改动：`scripts/check/size-rule.ts`（`resolveBaseline` 多一个可选参数、说明加第 7 步、`Baseline` 多一个可选的 `prBase`）· `scripts/check/size.ts`（读环境变量 `SIZE_PR_BASE`，报告多一行说清用没用 base）· `.github/workflows/check.yml` 检查链那一步加 `SIZE_PR_BASE` · `scripts/check/shard-load-rule.ts` 钉死的工作流跟着加两行 · `scripts/test.ts` 体量闸门起点那组加第 7 步的假应答用例与一个真 git 玩具仓库 · `scripts/check/mutations.json` 新加 M-H234-a 到 f，M-H9-t 的锚点跟上新写法 · `process/6-INTEGRATE.md`「叠分支」两处说法改准 · `docs/adr/README.md` 索引

## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 这条 PR 的 base 是哪个提交 | GitHub 的 pull_request 事件：`github.event.pull_request.base.sha`，由 CI 经环境变量 `SIZE_PR_BASE` 交给闸门 | 机器 |
| 哪些提交已经在 base 里 | git：`merge-base <base> HEAD` 取共同祖先，`rev-list <共同祖先>..HEAD` 列这条自己的提交（按祖先关系，不按提交图的形状） | 机器 |
| 两个提交之间新增了多少行 | git：与原先同一组 `diff --numstat` 问法，起点换成上一行的共同祖先 | 机器 |
| 给的 base 找不找得到 | git：`rev-parse --verify <base>^{commit}` | 机器 |

## 一、决定

照 ADR-63 的形状：**传事实、不传推断**。提交图分不出「叠上去」和「这些提交本来就是我写的」，分得出的事实只有「这条 PR 的 base 是谁」，而它只在调用方手里。

- 入口读环境变量 `SIZE_PR_BASE`。CI 上 pull_request 事件填 `github.event.pull_request.base.sha`；推 main 的那一跑这个表达式是空串，本地不设 —— 这两种都算「没给」，照旧按主干量。
- 判定在 `resolveBaseline` 第 7 步：给了 base、而且 HEAD 不在主干上时，起点改成 base 与 HEAD 的共同祖先，这条分支自己的提交改成从那里列到 HEAD 的那些。base 里已有的提交（按主干算是这条的、按 base 算不是的）记成 `inherited`，报告里说「base 里已有的 N 个提交不算」，**N 是 0 也照说**。
- 给了 base 却找不到、或与 HEAD 没有共同祖先 → 无从判断、退出 1，**不退回按主干量**：退回去，叠分支就又把下面那条的行数和豁免算成自己的。
- base 就是主干那一头（按主干开的普通 PR）时，与 base 的共同祖先就是与主干的共同祖先，量出来的数、找豁免的提交一点不变。
- HEAD 在主干上时不用 base：主干上本来就只报数、不判定，报告说一句「给了 base，但 HEAD 就在主干上，没用它」。

判据是祖先关系（git 列提交按的就是它），不是「链上碰到某个点就截」—— 那是 ADR-63 第一版栽过的：下面那条又长了一个提交、上面那条把它合进来之后，分叉点跑到第二父那边，按形状截一刀不切。

## 二、量出来的

真 git 玩具仓库（`scripts/test.ts` 体量闸门起点那组）：主干一个提交；A 从主干开出，加 400 行源码，提交信息最后一段写 `size-ok: 源码 A 首次落地，拆不开`；B 从 A 的头开出，加 10 行源码，没有豁免。

| 跑法 | 结果 |
|---|---|
| B 上，给 base = A 的头 | 源码 10 行；豁免一条也没捡到；base 里已有的 1 个提交不算 |
| B 上，不给 base | 源码 410 行；捡到 A 的豁免、放行 —— 这是没给 base 时明写的旧行为 |
| B 上，给 base = 主干 | 与不给时量出同一组数、同样的豁免 |

假应答那一组另外钉住：base 找不到、没有共同祖先、按 base 列不出提交，三种都无从判断；HEAD 在主干上时根本不去解析 base。六条变异（M-H234-a 到 f：找不到 base 退回按主干量、没有共同祖先退回按主干量、豁免照旧从按主干列出的提交里找、行数照旧从与主干的共同祖先量起、「不算」的那几个一律报 0、主干上也去用 base）都被点名的那条断言抓到。

## 三、仍然按不住的

- **没给 base 的跑法**：本地跑（除非手设 `SIZE_PR_BASE`）、推主干。报告里明说「没给 PR 的 base，按主干量」。
- **叠上去却仍对着主干开的 PR**：base 是主干，下面那条的提交就是这条要合的内容，它的行数和豁免照样算进来。要挡这一种得再拿一个事实（链上哪个提交是别的开着的 PR 的头），这次没接，同 ADR-63「仍然按不住的」第二条。
- **入口读没读环境变量没有测试守着**：`size.ts` 入口本来就没有入口测试（判定都在 `size-rule.ts`）。CI 有没有把 base 传进来，由变异负载闸门钉死的工作流守着（`shard-load-rule.ts` 那份逐行比）；入口拿到之后有没有交给判定，只有读 diff 的人看。
- **同一个起点的另外几道检查没跟着改**：欠条点名提醒、字段断言闸门、起子进程接口闸门、启动数闸门也用 `resolveBaseline` 定起点，这次都没传 base。叠分支上它们会多算下面那条的改动 —— 多报、不会少报，所以没顺手改；要改另开一条。

## 四、给后来者的提醒

`process/6-INTEGRATE.md`「叠分支」那一段原先说「下面那条的新增行会算进这条、`size-ok:` 也会被捡到」，现在只在没给 base 或对着主干开时才这样，两处说法已改准。叠分支仍是这条纪律要劝退的东西：先把下面那条合了。
