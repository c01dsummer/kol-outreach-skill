# ADR-123 认领字节未变时保留原件，异常改写仍须恢复

- 日期：2026-09-27 · 核对真实成本入口的认领所有权时
- 类型：事实证伪
- 触发它的事实：主干 `f18eedc` 的 `mutate.ts` 退出恢复对已有认领无条件写回；原字节相同也会发生实际写入。既有入口断言只比较最后内容，不能排除同内容重写。
- 冲击的需求：不改变业务需求；落实选组运行不清理或写入完整测试认领的既有边界，保留施变误写后的恢复。
- 结论：采纳
- 理由：认领原件属于完整正常测试。保存最终字节不能证明未动过它；取消恢复又会把施变产生的认领留给审计。
- 连带改动：项目架构、既有 `mutate-restore.ts` 的动作判定及需求测试、具名负片；真实入口另行接入。

## 决定

正常原件字节未变时不写、不删。原件缺失或字节被改写时恢复开跑前的原字节。
开跑前没有认领时，只删除后来产生的文件；两头都缺席时不操作。
空原件仍属于存在；JSON 语义或长度相同不等于字节相同。

动作判定留在既有恢复模块，入口保留读取与落盘。先用独立输入验证判定和错误拒绝，
真实正常认领、变异误写与中断恢复另以实际入口证明。不能用纯判定通过代替入口已经调用。

本次不改 `process/`，不新增业务判据或性能闸门，不删除既有恢复、信号接管与变异。
源码恢复、认领写入资格和具名失败要求保持；检查工具的负片继续遵守基础设施隔离。

## 本次交付边界

本条先交尚未接入入口的动作判定。`mutate.ts` 的无条件写回仍在，
实际认领原件保护尚未修复；后续从合入后的主干独立接入，并取得文件操作和恢复证据。
成本真实观察与自动报告仍未交付，此次修复准备不当作提速收益。

## 判定验证

独立测试上下文只读公开恢复合同与接口的 JSDoc、签名，在实现动作判定前写下案例；
没有读取生产函数体、旧测试、变异正文或运行结果。正常判定通过 20 条具名断言，
覆盖缺席、空原件、长度与逐字节变化、同语义 JSON 和数组视图。

M-H50-a…f 逐条施变，由指定的全部断言拒绝；这六条负片分别点名这 20 条断言。
同一选组的正常基线先通过一次，再由两个隔离 worker 执行全部六条，不以崩溃、
其它断言或夹具故障冒充捕获。既有变异和豁免原样保留，新负片直接使用独立需求测试组。

只读评审核对正常动作、测试登记和执行顺序、标签归组及交付声明，未发现剩余阻塞。
这些证据验证纯动作判定；不证明真实退出路径已采用它，也不替代完整 CI。
