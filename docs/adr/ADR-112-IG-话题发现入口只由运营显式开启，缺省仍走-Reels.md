# ADR-112 IG 话题发现入口只由运营显式开启，缺省仍走 Reels

- 日期 · 2026-09-24 · 交接清单「IG 可选话题发现入口」
- 类型：**产品取舍**（需求所有者裁决）；实现与需求改动另开 PR
- 触发它的事实：`/api/v1/instagram/v2/fetch_hashtag_posts` 只做过实验采样，未接入生产（`docs/data-source-strategy.md`）；
  历史样本摘要里话题页给出了另两路没有的候选，但样本原件不在仓库、跨词与长期交集都没量过
- 冲击的需求：D15.a/b/h（来源要能记话题端点）、D11（话题作品 id 的取值字段）、D12.c（价目要登记这个端点）、D6（话题任务一页一次请求、没有兜底）
- 结论：**采纳，按下面的裁决实现；上线有两个前提（第三节），未满足前不接入口**

---

## 一、需求所有者的裁决（2026-09-24）

- **只由运营显式开启**：任务配置里给某个 Instagram 任务写 `ig_route: "hashtag"`。Agent 不自行添加；
  缺省（字段缺席）仍走 Reels，不改变任何品类的默认发现路径。

## 二、已由现有需求或裁决定死的

- **不复用 `as_hashtag`**：它是配置元数据，不切换端点、不改标签（D15.a、U8.k、ADR-106）。
- **请求**：`keyword` 取任务关键词去掉一个开头的 `#`，`feed_type=top`，首页；不走账号名兜底。
  翻页等 ADR-111 的实现合入、且话题端点的令牌位置有样本后另议。
- **校验**：`ig_route` 只认 `"hashtag"`、只能写在 Instagram 任务上；去掉开头 `#` 后为空或含空白的关键词拒绝。
  这些都在任何预留与请求之前以退出码 2 结束（零请求）。
- **原词保留**：`discovery_sources.keyword`、`source_keyword`、任务标签和关键词行都用任务关键词原样，只有请求参数去掉 `#`。
- **不进任务标签**：同词任务靠任务序号区分（U8.a）；每个账号的实际路线由 `discovery_sources` 的端点表达。
  要在标签或关键词表上标路线，须另改 U8。
- **分派位置**：在 `TikHub.search()` 最前面按 `ig_route` 分派，probe 与 collect 共用 —— 否则会试探用 Reels、采集用话题（F3）。
- **图文**：作为内容匹配证据进入搜索命中作品（文案）。**播放数只给通过现有视频判定的条目**（与主页样本共用同一个判定函数，
  不另写一份）；其余条目不写播放数 —— 该媒体类型的播放字段没有确认过语义，不能当成真实的 0。
  主页绩效样本口径不变（D8）。
- **评分**：搜索命中的播放数会参与现有的 +5 与展示作品排序；评分规则本身不变（D11.p）。
  两条路线命中同一作品 id 时按 D11 先到者保留，播放数可能取决于任务顺序 —— 实现时补跨路线同 id 的测试。

## 三、上线前提（未满足前不接入口）

1. **价目**：固定价目版本 `tikhub-public-20260720-5d52fe8fb109` 只登记了八条生产端点，D12.c 对未登记端点报错。
   用户本地读取定价资产，**SHA256 等于 `5d52fe8fb109a569e4e16b39b611ee9d5233c9131d264f1e856a987f23cc8cbf` 时**，
   才把 `fetch_hashtag_posts` 那一行原样转录进同一版本，并在 ADR-107 末尾追加观察时刻。
   哈希不等或资产取不到：停下，交需求所有者决定是否另开价目版本（另开会让所有端点的新请求改用新版本）。
   不用固定规范 description 里的 $0.002 代替价目。
2. **字段**：用户在本地样本上核对话题响应的列表路径、作品 `id`、`user.username`、`caption_text`、视频标记字段。
   核完才写解析器；没有样本证据的字段不写成判据。

## 四、施工顺序（每步一条 PR）

1. 价目：按第三节第 1 条转录一行，配价目解析的测试；ADR-107 追加。
2. 解析器与来源类型：话题解析、来源端点与显示名扩一项、共用的视频判定；不分派、没有入口。
3. 入口（最后一块砖）：配置校验与 `search()` 分派；同一条 PR 改 D15.a/b/h、D11、D6，按 `docs/SYNC.md` 同步
   `skill/references/providers/tikhub.md`、`_interface.md`、`skill/SKILL.md`、`skill/references/keyword-strategy.md`、
   `docs/ARCHITECTURE.md` 缝隙契约，以及 `tikhub.md` 里「实验 hashtag 不成为生产路径」那句。

## 五、2026-09-24 两个上线前提的核对结果

用户在本机运行只读命令（不发数据请求、不用 key），输出贴回会话：

1. **价目**：本地读取的定价资产 SHA256 为 `5d52fe8fb109a569e4e16b39b611ee9d5233c9131d264f1e856a987f23cc8cbf`，
   与价目版本 `tikhub-public-20260720-5d52fe8fb109` 记录的一致。该资产中的原始元组为
   `["/api/v1/instagram/v2/fetch_hashtag_posts",0.002,0,0,"10/second"]` —— 单价 0.002 USD（2000 微美元），
   阶梯标记 0、免费额度标记 0。第三节第 1 条满足，可在同一版本内转录这一行。
2. **字段**：在用户本地重采样本（`sample-lInRuK`，另一组观测，只用于字段存在性，不用于任何计数结论）的
   4 份话题响应上：列表在 `data.data.items`（各 23–24 条）；首条 `id` 为字符串、有 `user.username`；
   文案字段是 `caption_text`（Reels 与 general 是 `caption.text`）；全部条目的 `media_type` 取值为 1、2、8，
   `is_video` 真假都有，`product_type` 为 `feed`、`clips`、`carousel_container` —— 图文与轮播确实混在话题页里；
   三条路线的响应都有与 `data.data` 同级的 `data.pagination_token`。
   只核了每份的首条的作者与文案字段，逐条覆盖率未核：解析器对缺席字段保持缺席，不推算。
