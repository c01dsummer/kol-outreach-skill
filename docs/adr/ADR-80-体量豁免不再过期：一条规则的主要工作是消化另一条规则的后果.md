# ADR-80 体量豁免不再过期：一条规则的主要工作是消化另一条规则的后果

- 2026-09-18 · 按 Bitter Lesson 原则重整检查链，逐道评定里的第六道
- 类型：缩范围（收窄一道闸门，不撤）
- 冲击的需求：无
- 结论：**体量闸门留着，阈值留着，超线不写豁免照样红。撤掉的只有「豁免会过期」那套机器。**
  并给这道闸门写下**死亡条件**

## 撤的是什么

一条 `size-ok: <类别> <理由>` 写下之后，原先还要算一个数：**从它写下那一刻到最终 diff，
这一类又净增了多少**。净增为正就判「豁免已过期」，红，要求重新写一条。

现在不算了。**一条豁免管整条分支。**

代码上：`size-rule.ts` 的 `Waiver.addedAfter`、`SizeReport.stale`、`Overage.note` 与
`judge()` 里那段过期判定；`size.ts` 里每条豁免各跑一次 `merge-base` ＋ `diff` 的计算
和它的打印段；`scripts/test.ts` 里三条只测过期的夹具；变异 `M-H9-d`。

## 为什么

**它的主要工作是消化这道闸门自己的豁免带来的后果。**

豁免存在的理由是「这次超线是有理由的，理由写下来给人看」。而过期机器要回答的是
「这条理由还管不管用」—— 一个**只有因为存在豁免才存在的问题**。它守不住任何一个
别处守不住的坏法：豁免之后又加了几千行不相干的代码，那件事在 diff 里看得见，
是评审的活。

这和分支寿命闸门撤掉（ADR-76）是同一个形状：**一条规则的主要工作是消化另一条规则的
后果时，至少删一条。** 那次删的是 age，这次删的是「消化」那一半 —— 闸门本体留着，
因为它守的东西（人的评审注意力）仍然有价值。

## 换来的缺口，写在明处

**一条豁免写下之后，这一类再涨多少都照样绿。**

这不是疏忽，是这次换来的东西。原先那句话反过来说也成立：为了堵住这个缺口，
每条豁免都要多跑一次 `merge-base` ＋ 一次 `diff`，还要维护一套判定 —— 而它挡的那个坏法
（拿旧豁免掩护新代码）在 diff 里是明的。`scripts/test.ts` 里留了一条夹具**正面断言这个缺口**，
免得它哪天被当成 bug 顺手"修"回去。

## 撤掉的那段注释里装着什么 —— 搬到这里，别让它随代码消失

`addedAfter` 那个数怎么算，走了**四版才对**，而这段过程**全仓只记在那段注释里**，
没有任何一条记录收过它。撤掉代码之前先把它搬过来：

早先是**按提交序列**算的 —— 数每个提交各自加了多少行，再看某一类最后一次被追加
是不是晚于最后一条豁免。四版都不对：

| 版本 | 怎么错的 |
|---|---|
| 合并提交按第一父计 | PR 检出的 `refs/pull/N/merge` 让**任何豁免永远过期** |
| 合并提交一律按 0 | 冲突解决时新写的代码**不算数** |
| 取各父 diff 的逐类最小值 | 一次干净地合主干就把豁免**顶掉** |
| 按第一父链重排 | 顺序对了，但「**加一行又删掉**」仍误判成过期 |

四个反例的共同点：**它们都在问「历史上发生过什么」，而闸门要守的是「最终这份 diff 有多大」。**
改成**树对树**（`总数(c) − 豁免那一刻的数(c)`，两边相对同一个基线）之后，提交顺序、
合并形状、时间戳一概不参与，四种情形自然全对。

而且树对树自己也有一个明写的已知缺口：两个数相减量的是**净增**，不是「哪些行是后加的」——
豁免之后删掉 100 行被豁免的、又补上 100 行新的，两个数都不变，旧豁免照样放行。
当时试过两种补法都更糟（一种会因为干净地合一次主干就报过期，实测 1 行就够触发；
另一种在主干与分支碰过同一个文件时产生天天响的假阳性）。

**这段历史留在这里的用处**：哪天有人想把过期机器装回来，先读这张表 ——
它不是"没做"，是做过四版、最后做对了，然后因为别的理由撤掉的。

## ADR-59 那句对照

ADR-59 写过「**豁免不设新鲜度** —— 体量豁免会过期，是因为『之后又加了行』是一个能观测的
事件；分叉时长没有这种事件」。本条之后，**那句对照没有活着的另一半了**：两道闸门的豁免
现在都管整条分支。ADR-59 的结论已由 ADR-76 整个推翻（那条记录末尾有更正块），
所以这里只指出来，不再往它上面追加第二块。

## 死亡条件

**这道闸门守的是人的评审注意力**，不是正确性。七次真红全是响亮的失败（超线了，
diff 大到一次读不完），而现在这个仓库只有一个评审者 —— 所以它今天有价值。

> **什么条件下退成只报数、不拦**：评审改由独立上下文的 agent 承担，
> 且那个 agent 读完整个 diff 的成本不随行数显著上升时。
> 那时「一次读得完」不再是约束，阈值就只剩报数的用处。

> **什么条件下整个撤掉**：连续 20 次 CI 运行里，`size` 报红或报豁免的次数为 0 ——
> 说明改动规模已经由别的东西（切片纪律、评审节奏）约束住了，这道闸门在空转。

**谁去数、数什么、多久数一次**：没有机器在数。下一个碰 `size-rule.ts` 的人顺手看一眼
`git log --all --format=%B | grep -c '^size-ok:'` 和 CI 上 `size` 的红史。
**这是有意的** —— 给一道"守人的注意力"的闸门装一个自动清点器，是又一层要维护的东西。

> ⚠️ 欠条：**死亡条件本身没有机器在数。** 上面两条都靠人顺手看，而「靠人顺手看」
> 在这个仓库的历史里执行率趋近于零（`docs/SYNC.md` 开头那句话说的就是这个）。
> 真正的修法是让审计每次打印这类计数，那属于「欠条台账可机读」那条线的活。
> · 重启条件：**欠条台账那道闸门落地时**，把本条的两个死亡条件一并接进去数。

> ⚠️ **上面那条欠条的重启条件在 #121 上触发了，这里换掉它，不是续期。**
> 那条写的是「欠条台账那道闸门落地时，把本条的两个死亡条件一并接进去数」——
> #121 把台账落了（`npm run audit -- --debts` 打全表，`npm run audit` 末尾打一行计数），
> 按字面它响了。
>
> 而那两个死亡条件**没有被接进去数，是有意不接** —— `ADR-86`「六、没做的」第一条给的理由是：
> 本条这两条「都可核，但都几乎不会响」，装一台永远不响的机器按 `process/4-VERIFY.md`
> 等于没装。台账对它们只做了一件事 —— 把它们**列出来**（`## 死亡条件` 是它认的三套写法
> 之一），没有人去数。
>
> 所以本条的缺口从「没有机器在数」缩成「被列出来了，仍然没有人核」。
> · 重启条件（本条自己的，换掉）：**某一条死亡条件的成立方式从「几乎不会响」变成会响时，
> 或者死亡条件的条数超过判定模块数时。** 这与 `ADR-86:113` 那条是同一个条件，但**逐字写出来
> 而不是挂靠** —— 挂靠的那一条哪天被还掉或改写，这条就跟着空了（`ADR-70:2083`）。
> 不再挂「台账落地时」：那个条件已经被消耗掉了，再挂着等于没有条件（`ADR-70:2160`）。
