# ADR-158 检查链改用裸 node 跑预编的 JS，缺一份就照旧 tsx

- 日期 · 2026-10-23 起，分片落地到 2026-10-29
- 类型：改检查链怎么起进程
- 触发它的事实：检查链起的每个 `.ts` 进程都经 tsx 的壳，一次完整检查要起几千个
- 冲击的需求：无。跑的东西不变，变的是起法
- 决定人与时间：需求所有者 2026-10-22 在项目线程里定检查链时长排程（「先照这个排」）里的乙路线；人批痕迹是他合入第一片 #366。之后拍的板见「需求所有者定过的」
- 结论：采纳，已落地。起一个 `.ts` 进程时 `prebuiltCommand` 在三条路里选：owner 域（裸 node 加钩子）、无配置域（N：薄父壳起缓存子进程）、照旧 tsx；拿不准的一律 tsx，只是慢。本条不认领「CI 耗时已恢复」：只有本机局部实测，CI 时长后来由 ADR-197、ADR-200 接着做
- 理由：起一次约为 tsx 的三分之一（历史文件第六节）
- 连带改动（现状）：`scripts/check/` 下 `prebuilt.ts`、`prebuilt-hook.ts`、`prebuilt-parent.ts`、`prebuilt-signals.ts`、`compile.ts`；`mutate.ts`、`selfcheck.ts`、`scripts/test.ts` 起子进程的几处；其余见各节

- 同类：ADR-75（至少第 2 次；查的范围：正文所引 ADR-75 全文及已有同类行，树 3fc68aa）

> 本文件只写现在定的是什么。节号沿用原文，好让老引用照旧对得上；空着的节号是实测、清点、复核、被否掉的候选与更正的过程，原文在 `docs/adr/历史/` 下的同名文件里（ADR-211）。

## 一、哪些起法走它

- 走 `prebuiltCommand`：变异起验证者，自检起入口与工具、拆进程跑起每一族的子进程，需求测试起自检与入口的几处（#366、#368）。
- 照旧 tsx：`npm run` 各步本身；变异的 worker；夹具里有意直接写 `tsxCommand` 的几处。
- 临时目录里的玩具树找不到缓存，照旧 tsx —— 与原型量数时同一个范围。

## 二、缓存、选路与钩子

**缓存。** 仓库根的 `.check-cache/prebuilt/`（不入库）。键由编译身份、文件名、正文算出：改一个字就是另一个键；不含目录，变异 worker 副本里没改的文件与真树共用。编译身份由做法版本、esbuild 版本、node 版本、`compilerOptions` 算出。**配置改变须换身份**：缓存主人的 `tsconfig.json` 每次重读，配置变了，源码没变也换键。每个 `.ts` 存两份：owner 格式（不带源码映射）与 N 格式（第二十二节）。用谁的缓存：从那棵 `scripts/` 的上一层往上找第一个带这个目录的，真树与变异 worker 的副本都找到仓库根。

**什么时候不走 tsx。** 样样成立才走，缺一样就照旧 tsx：

1. 没设 `KOL_PREBUILT=0`、`TSX_TSCONFIG_PATH`；起的是 `.ts`；找得到树与缓存。
2. 这个 node 自己能去掉类型；子进程的 `NODE_OPTIONS` 里没有 tsx 的加载器，也没有 `--no-experimental-strip-types`。
3. 钩子文件（N 域再加 `prebuilt-parent.ts`、`prebuilt-signals.ts`）从本进程装入后没被改过（被测的坏钩子不能兼任启动器）。
4. 缓存主人的配置是不带 `extends` 的普通 JSON，或没有配置；配置归属过得了第十五节或第三十二节（owner 域：cwd 是项目根或它的后代）、或第二十二节（N 域）。
5. **整棵树每个 `.ts` 在缓存里都有现在这一版**。

**钩子：地址不换，只换内容。** 解析出来的仍是 `.ts` 的地址；加载时按这份 `.ts` 现在的正文算出键，交给 Node 缓存里那一份。所以 `import.meta.url`、报错里的文件名都是 `.ts`，同一地址的模块只有一个实例。缓存里没有现在这一版就当场报错、点名那个文件，不拿旧的顶上。`./x.js` 在 `x.ts` 在时认 `x.ts`；**父模块与目标都须在树内**（按真实路径判），其余交给下一个。只承诺这一种映射：头一次用到绝对 `.js`、无扩展名、带 query 的写法时，先支持或回退再用。键怎么算只在钩子里写一份。

**预编。** `npm run compile` 在检查链里紧跟 `npm run typecheck`：缺的编上，不属于现在这一版的删掉；它打印的写、沿用、删三个数数的是缓存条目（每个 `.ts` 两种格式各算一份）。变异每条落盘后只编被改的那一个文件；编不出来就不写，这一条退回 tsx 报错；用完不删，下次预编整棵树时清。所以变异被打断时缓存里没有要还原的。

**退出码。** 裸起没有壳；`asTsx` 把信号死亡换算成 tsx 的壳报的样子（退出码 128+N），读退出码的一侧不分起法。

## 三、为什么不把 `.js` 放在 `.ts` 旁边

Node 自己能跑 `.ts`。旁边放着 `.js` 的话，复制 `scripts/` 的玩具树会带走旧的那份，哪天有一条起法绕过判定，`./x.js` 就认到它。退回 tsx 时不打提示：输出会多出几百行，而退回不改结论。

## 四、信号与退出钩子：起法不同，结果不同

实测（tsx 4.23.12、Node 22.22.0；脚本在历史文件第四节）。INT、TERM、HUP、KILL 指 `SIG` 开头的信号：

| 起法 | 信号 | 进程当时 | 结束时 | 退出钩子 |
|---|---|---|---|---|
| 裸 node | INT／TERM／HUP | 等事件循环 | 以那个信号结束 | 不跑 |
| 裸 node | TERM | 同步等子进程 | 以 TERM 结束 | 不跑 |
| tsx | INT／TERM | 等事件循环，且已过入口求值后的第一轮 | 退出码 130／143 | 跑 |
| tsx | HUP | 等事件循环 | 以 HUP 结束 | 不跑 |
| tsx | TERM | 同步等子进程 | 退出码 143（壳补的 KILL） | 不跑 |
| 裸 node，自己挂了 TERM 处理 | TERM | 同步等子进程 | 处理轮不上，剩下的全跑完、以 0 退出 | 正常结束时才跑 |

- 前五行进程被信号结束，`finally` 都不跑（tsx · INT／TERM 那行跑的是退出钩子，不是 `finally`）；最后一行处理轮不上、进程照常跑完，`finally` 照常跑。
- tsx 第一行的「已过第一轮」是 2026-10-29 的更正：Node ≥22.22.3（CI 在内）上，tsx 的信号转发到那时才装上；之前挨信号，钩子不跑，壳照样报 130／143。
- N 域另有信号预加载（第二十九节），不看裸 node 那几行。
- 结论：要清理就自己接管信号，别把退出钩子当成已保证的事。给自检挂一个 TERM 处理来删临时目录**不成立**（表的最后两行）：各组是同步跑完的，处理轮不上。

## 五、拆进程跑打不开某一族的日志

打开每一族的日志与起子进程在同一个 `try` 里：打不开时那一族报成「没起来」，父进程照常等其余各族、打汇总。`h-selfcheck-shard-open` 与 `M-H63-a` 守着（#366）。

## 八、边界与撤法

- owner 格式的报错栈对不上 `.ts` 的行列号；要看原样的栈，设 `KOL_PREBUILT=0` 再跑。
- 守着这些规则的：需求测试 `h-prebuilt` 开头的十组，变异 `M-H62-*`、`M-H67-a/b`、`M-H68-a`，以及各节点名的那几组。
- 没有死亡条件：这不是闸门，只是一个起法。哪天 tsx 起进程不再贵，删掉 `prebuilt` 开头的四个文件与 `compile.ts`，起法换回 `tsxCommand` 即可。

## 十三、观察器与入口共用预编模块（第二片公开契约）

`fixtureLoader(script, env, cwd)` 交回一个给 Node `--import` 用的地址，必须排在观察器与 fake-fetch 前面。它与 `prebuiltCommand` 用同一子进程环境、同一套选路：owner 域交回同一个钩子地址，否则交回 tsx 的加载器。于是观察器按 `.ts` 地址 import 的模块，与入口按相对 `.js` import 的是同一个实例。原先直接用 Node、IPC 起的夹具不迁移（#369）。

## 十五、配置归属：按子进程真实的工作目录判

tsx 从子进程的 cwd 找配置；缓存主人与 cwd 不同时，缓存齐全不等于编译语义相同。所以只缩窄裸起的资格，不写完整的 tsconfig 解析器。owner 域要求：cwd 就是入口那棵 `scripts/` 的项目根（按真实路径），或它中间没有别的配置的后代目录（第三十二节）；本层配置是不带继承的普通 JSON，没有 `files`、`exclude`、`references`，`include` 缺省或恰为 `scripts/**/*.ts`，编译身份与缓存主人相同。本层没有配置而祖先有、或读不出来，回 tsx。项目根不必是缓存主人：worker 副本的项目根是它自己，缓存来自仓库根（#379）。

## 十八、观察器加载器按子进程真实的 cwd 选

`fixtureLoader` 的第三个参数可省，省略时按调用时的当前目录。**起不同 cwd 子进程的调用方必须传与 `spawn` 相同的 cwd**：否则父进程 cwd 下取到的钩子被带进子进程，仍按缓存主人的编译选项加载（#382）。

## 十九、CI 墙钟对比那一步的测试与来源身份

需求测试 `h-ci-wallclock` 开头的几组从工作流里原样抽出墙钟对比那一步，对假接口跑（#384，原文第十九、二十节）。工作流因此是程序输入：覆盖记录的默认指纹另含检查工作流的正文（`claims.ts`），文件不存在才算缺席，读不了就报错。

## 二十二、无配置域（N；原文叫「恢复候选」）

owner 域不成立，而子进程真实 cwd 到根每一级都确认没有 `tsconfig.json` 时走 N 域；另要缓存主人的配置过第十五节的范围要求（或没有配置），`prebuilt-parent.ts`、`prebuilt-signals.ts` 从本进程装入后没被改过；只在 darwin 与 linux（#390、#400）。

- N 格式与 owner 格式独立：编译选项 `{}`、带内联源码映射，选项相同也不共用。所以每个 `.ts` 两份。
- 起法是 `node prebuilt-parent.ts --hook <钩子> -- <原参数>`。薄父进程起缓存子进程，转发 INT／TERM，60 毫秒后还没关就补 KILL，等子进程真的关了才退。退出钩子由子进程自己跑，父侧不补造。
- 加载时前提失效（cwd 祖先链上有了配置或读不出）报 `CHECK_PREBUILT_CONFIG_INVALIDATED`，不回退 tsx；带观察器的组合另有 `CHECK_PREBUILT_OBSERVER_INVALIDATED`（第二十六节）。
- `fixtureLoader` 在 N 域交回 tsx 的加载器，带着它的命令仍走 tsx。

## 二十六、受控的预算观察器环境与 D27 接线设计

`brandObserverEnv(script, cwd, baseEnv, observerFile)` 交回一份新环境；调用方再拿它连同真实参数、cwd 调 `prebuiltCommand`。只有已知组合才让带观察器的入口走 N 域缓存：`baseEnv` 只预载同树的 fake-fetch（按固定 SHA256 认），观察器文件恰为那份八行模板且不是软链，探测选到 N 域。别的一律重组原来的完整组合。选中之后钩子地址带着绑定；启动或加载时对不上就报 `CHECK_PREBUILT_OBSERVER_INVALIDATED`，不重选。

**D27 接线设计。** 用它的只有两处：自检的 `brand-content-version-entry`，与 D27 那几组共用的 `d27Runner`（#399）；后者只把模板里的日志路径换成环境槽，业务断言不变。

## 二十九、N 域子进程的信号预加载

要求：同一入口、参数、cwd、环境下，N 域的退出状态与入口真实跑到的退出钩子，必须与同一运行时的公开 tsx 命令一致，不写死 0 或 143。

- INT：预加载时就装。Darwin 上 TERM 同样。
- Linux 上 TERM：由预加载自己 import 入口；求值期间保持系统默认；求值完成后，入口没有自己的 TERM 监听、也没无参清空过，才补默认处理。用户自己的处理不抢。
- 求值期间只代理 `process` 这个实例的 `removeAllListeners`，求值完恢复。
- 冻结合同 `prebuilt-clear-term-contract-test.ts` 汇入生命周期组。

## 三十一、具名清空 TERM 之后

代理只记**无参**的 `removeAllListeners()`：无参清空之后不补默认处理。具名清空（只清 TERM）不记：之后入口没有监听就照常补，已有用户处理就不补，与 Linux 22.23.3 上公开命令一致（随 Node 补丁版本变）。

## 三十二、同配置的后代目录也走 owner 域

子进程真实 cwd 是入口项目根的后代时：逐级往上查，中间任何一层有 `tsconfig.json`（软链也算）或读不出，回 tsx；项目根的配置须是普通文件，并过第十五节的要求。只保证配置归属对，不借 N 父壳的生命周期保证。冻结合同 `prebuilt-owner-descendant-contract-test.ts` 守着（#390）。

## 三十三、纯判定不提前初始化 TypeScript 编译器

`mutate-rule.ts`、`share-rule.ts`、`admission-rule.ts` 不在模块顶层取 npm 的 `typescript`，到第一次真要解析 AST 时才同步取；只用纯判定的测试组于是不付编译器的初始化。缺 TypeScript 时在首次 AST 调用处抛，不在启动时抛；与 ADR-126 原验收的出入挂在 ADR-70「TypeScript 取得时机与 ADR-126 原验收不符」。`h-lazy-typescript-contract` 守着（#391）。

## 三十四、变异 worker 写回结论后才接下一条

变异的 worker 每条结论等 stdout 的写回回调，再接下一条或正常退出；写回出错向外失败（原先同步写，管道满时丢结论）。只证明正常收尾，不外推信号与硬杀。`h-worker-output-contract` 守着（#394）。

## 还开着的欠条

> ⚠️ 欠条「见齐就停的验证者留下的临时目录没人收」：变异见齐就停时，被停的验证者留下的临时目录没人删。真要清得由变异一侧收，回收与编译缓存变冷的成本要一起量。⚠️ 条件按宽读响过多次，都记「没还」 · 来源：历史文件第 316 行（承第 72 行）· 档：登记 · 重启条件：留下的目录造成 CI 或本机磁盘占满、或有夹具因此误红；或下一条改变异停验证者那一刀（`stopIfSeen`）或改自检临时目录归属的 PR

> ⚠️ 欠条「拆进程跑时父进程先走子进程没人收」：自检拆进程跑时父进程先退出，在跑的各族子进程没人收。⚠️ ADR-212 改 `runShards` 时条件响过，记「没还」 · 来源：历史文件第 105 行 · 档：登记 · 重启条件：父进程退出之后仍看到 `selfcheck.ts --only=` 子进程在跑并造成了后果；或下一条给 `selfcheck.ts` 加信号处理、改 `runShards` 或父子回报协议的 PR（重新起算）

> ⚠️ 欠条「拆进程子进程判别两处分支没有常驻断言」：自检里子进程判别的红分支、继承回报落点但选择参数异常的分支，没有常驻断言 · 来源：历史文件第 200 行 · 重启条件：下一条改自检收尾那两段、子进程判别，或给拆进程跑新增故障注入夹具的 PR（重新起算）

> ⚠️ 欠条「整跑自检按族摘要的几处分支没有常驻断言」：完整自检写按族摘要那一侧，删旧、失败不写、身份未知不写、日志读坏、写失败几支没有常驻断言 · 来源：历史文件第 202 行 · 档：登记 · 重启条件：下一条改 `runShards` 的计数接线、按族摘要读写或开跑先删逻辑的 PR；或真树整跑首次报告按族计数没写成；或全绿的拆进程整跑之后最后一步报告没有按族计数（重新起算）

> ⚠️ 欠条「墙钟对比那一步的取数与判断还没判还清」：CI 墙钟对比那一步原先缺检查链内的测试与变异，#384 补上了（第十九节），但没有一行记它已还；之后 ADR-197、ADR-200 把变异分到三台，那一步读到的 CPU 型号与分子换了含义，新含义没有测试守着，两处都按宽读记「没还」。缺的是：新含义下那一步取数与判断对不对，有没有测试守着。原文第三支「Git 环境隔离与跨 cwd 配置归属两条修补均合入时」已在 #372、#379 合入时烧掉，去掉 · 来源：历史文件第 312 行 · 档：登记 · 重启条件：下一条改那一步脚本的改动（重新起算）；或那一行在 CI 上打出一次错的数时；或有人给新含义补了测试、能判它还清时

> ⚠️ 欠条「判定的返回字段有没有断言消费没有机器问」：没有机制问检查链每个判定的返回值或输出字段有没有断言消费，只靠复核逐个核。ADR-198 的闸门接进检查链那一片合入时才算还 · 来源：历史文件第 330 行 · 重启条件：下一条给检查链里任何一处判定的返回值加新字段的 PR，或定期清点（重新起算）

> ⚠️ 欠条「覆盖记录过期诊断没提工作流正文」：审计报覆盖记录过期时只说 `scripts/` 下有改动，没提已纳入指纹的工作流正文 · 来源：历史文件第 429 行 · 重启条件：下次修改 `scripts/check/audit.ts` 的过期诊断，或调整 `scripts/check/claims.ts` 的 `sourceFiles` 选取规则时
