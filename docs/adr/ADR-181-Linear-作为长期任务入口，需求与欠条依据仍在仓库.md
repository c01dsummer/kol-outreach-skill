# ADR-181 Linear 作为长期任务入口，需求与欠条依据仍在仓库

- 日期 · 2026-10-27 · 需求所有者确认项目管理入口
- 类型：产品取舍（本项目的协作方式），不触及需求登记表
- 触发它的事实：已建立的 Linear 项目承接了两份交接总览，但仓库没有接手入口；项目摘要仍写着交接与两会话进度，需求所有者指出它看起来只是临时项目。
- 冲击的需求：无
- 结论：采纳。需求所有者在 Codex 会话 `01a17d99-a4c2-75ea-88a8-c608616ff03d` 同意补采用记录、职责边界和接手入口，并要求更新项目描述，原话为「可以的，另外再更新下项目描述吧，现在的描述看起来这只是个临时项目。」本条补记已建项目的采用决定；本条 PR 的批准或合入记录另由 GitHub 保存，不将会话授权写成已取得 GitHub 批准。
- 理由：本项目需要一个跨会话持续维护的任务入口；当前进度集中更新，需求、决定与验收仍能回到仓库及实际交付证据核对。
- 连带改动：`AGENTS.md` 增加接手路由；决策索引由 `npm run adr -- --write` 生成；Linear 项目摘要与描述按本条更新。

## 一、长期入口

[KOL-Outreach-Skill](https://linear.app/c01dsummer/project/kol-outreach-skill-84d60f579773/issues) 是本仓库长期开发、维护与任务管理的入口，承接本次交接及后续明确纳入的任务。
候选与待决事项可以登记，登记本身不批准实施、扩大任务范围或改变既有操作授权。

## 二、各处保存什么

| 内容 | 本项目的依据与维护位置 |
|---|---|
| 当前任务状态、负责人、优先级、依赖与排期 | Linear 项目及对应任务 |
| 需求编号与验收判据 | `docs/requirements.json`；`docs/SPEC.md` 中的登记表由它生成 |
| 流程纪律 | `process/`；本条不修改通用纪律 |
| 正式决定、欠条及更正 | `docs/adr/`，继续按现行规则追加并保留出处 |
| 仓库变更的交付证据 | 实际合入的 PR、提交与适用的验收结果，链接回对应任务 |

仓库已有的欠条登记、状态记录与串行分片后续安排，继续按 `process/6-INTEGRATE.md` 和相关决策记录维护；Linear 任务链接到原记录，不取代这些登记。
涉及需求或正式决定的变化仍走原有评定与同步办法；任务标题、描述或状态不能单独改变已批准内容。

完成状态须有可追溯的交付或裁决证据：仓库变更以实际合入及适用验收为依据，其他事项按各自的完成条件核对。
准备材料、本地候选和历史运行结果不自动代表当前交付完成；取消或决定不做的事项保留对应裁决。
任务票与仓库依据不一致时，核对原批准与交付证据后更正对应内容，保留历史出处。

## 三、本轮交付基线

「固定45项」标签标识本次迁移的固定交付清单，只是本轮统计口径，不是长期项目的全部范围。
查看本轮交付进度时按该标签筛选；后续新增任务不自动计入这份基线。
「历史完成（基线外）」、工作线汇总、CI 子任务与待决／风险跟踪票不计入这 45 项，项目全部票的完成比例也不能代替本轮交付比例。
当前完成数直接读取 Linear，不在仓库维护另一份实时状态表。

本次采用时，CI 耗时恢复仍是最高优先级工作线；后续任务排序在 Linear 按明确的范围与授权维护。

- [另一会话任务总览](https://chatgpt.com/space/page_bdc3f0198dbc8191948fb3ba17deb9c3)

两份总览保留为迁移来源和历史记录；已迁入任务的当前进度在 Linear 更新，原总览不再作为当前状态入口。
任务仍保留原交接、相关 ADR 与 PR 的链接，交接材料不覆盖已批准的需求与验收判据。
接手者从 `AGENTS.md` 的任务路由进入项目，再读对应任务的依据；访问不到 Linear 时明确说明无法核对当前进度，不能把历史总览当成最新状态。
