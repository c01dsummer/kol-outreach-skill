# ADR-01 P2 拆成可执行的一半和只能靠自觉的一半

- 2026-08-25 · 建立需求登记表与审计时发现
- 类型：**需求有歧义**（不是变更 —— 需求没说清，而不是说错）
- 触发它的事实：审计报「P2 是红线但没有测试」。`process/1-REQUIREMENTS.md`
  要求每条红线至少一个测试且被变异验证，但 P2 管的是 Agent 生成的文本内容，
  不经过本仓库任何代码路径，没有可变异的实现。
- 冲击的需求：P2
- 结论：**采纳**（补充定义，不改红线本身）
- 理由：两个都不能选 ——
  降级 P2 不可接受（邮件发出去收不回来，是代价最高的一条）；
  编一个假测试更不可接受（`4-VERIFY.md`：一个从来不会失败的检查等于没有检查）。
  正确的做法是把它**拆开**：
  - **可执行的一半**：产出物必须原样保留占位符。render 不得删除、替换或
    「补全」草稿里的 `{…}` —— 抹掉占位符，运营看不到还有待填项，会把半成品发出去。
    已由 M-P2-a 覆盖。
  - **只能靠自觉的一半**：草稿里的产品事实是否真的来自产品页。
    这是 `process/README.md` 第三层，**显式留在审计报告里，不假装它被保证了**。
- 连带改动：`docs/requirements.json`（P2 的 accept）· `scripts/lib/rows.ts`（提取
  可测函数）· `scripts/test.ts` · `scripts/check/mutations.json`
- 教训：**红线「必须有测试」这条要求，本身会逼出一个有用的区分** ——
  一条红线如果完全测不了，多半是它把「代码该保证的」和「人该保证的」混在一起说了。
  拆开之后两半都变得可管理。这不是 P2 独有的形状。
