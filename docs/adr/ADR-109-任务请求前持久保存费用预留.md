# ADR-109 任务请求前持久保存费用预留

- 日期：2026-09-23
- 类型：需求补充
- 触发事实：PR #155 已统一生产费用账，但预留只在内存，进程被强杀可能丢掉一次已发请求的占用；ADR-107 与 ADR-108 已明确保留此缺口。
- 冲击的需求：新增 D14；承接 D6、D12、D13，与 P1、P3、P4、P5 的交点登记在 D14。
- 结论：采纳
- 理由：只有请求前写入预留，恢复时才能保留尚无结果的占用。费用保存不能顺便保存尚未完成的业务步骤，否则费用安全会制造错误断点与去重声明。
- 连带改动：预算包装、任务费用保存边界、collect/enrich 接线与失败收尾；架构、使用说明、独立故障注入与顺序负片。

## 范围与顺序

只为 collect/enrich 的任务账接入同步保存回调。probe 与直接分页探针仍为 process 范围，不增加落盘或跨进程恢复。纯费用模型仍不依赖文件系统；端点、价目、调度与重试次数不变。

每次请求按「预留并同步内存 → 成功保存 pending → fetch → 按 HTTP 结果结算 → 成功保存终态 → 读取正文/进入重试或 fallback」执行。没有 HTTP 状态只在 fetch 抛出时记录，本地保存失败不属于该状态。预留、结算与当前 state 同步后，由预算包装调用费用检查点；改额仍由入口先保存完整且一致的根上限与账目，随后才允许请求。

费用检查点重新读取既有 task.json，在原读取对象上只替换 cost_ledger/requests 后整体保存，保留精确根预算 token 及盘上业务字段；不能把当前内存 TaskState 整份提前写入。answered、found、pages、offsets、done、memory_status 及其缺席状态均沿用盘上版本；名单、累加器和 enrichment 不在此处写。现有「unknown → 名单 → 最终去重状态」的保存顺序不变。不存在的任务报错，不因检查点产生新任务。

保存回调失败包装成 CostError 的 persistence-failed，保留实际原因并锁定当前预算实例：后续 reserve、settle、setLimit 均失败，不再调用保存回调或网络。该错误穿透供应商 fallback、重试及单账号容错。collect/enrich 入口可尽力保存已完成部分，但最终退出 1，不再进入生成名单，不输出常规结果 JSON 或常规续跑成功提示；收尾保存再次失败仍报告失败，不把第一次错误洗成成功或初始输入错误。

持久化后的 pending 表示没有可信终态，不证明请求已发出或已经扣款；requests 仍只数既有终态净次数。强杀后恢复的未结项照 D12/D13 拒绝新增付费和显式改额，退出 2；仍可按既有规则做零请求本地处理或导出。没有自动退款、重发、人工改账命令或新的迁移机制。

## 可独立验证的公开边界

既有接口只增加可选回调；无回调的纯内存使用及 process 预算行为保持不变。生产任务入口必须接入，不能把“可选”误读成可省略任务接线。

```ts
type PersistCost = (snapshot: CostSnapshot) => void
class Budget {
  constructor(state: CostState, notify?: NotifyCost, persist?: PersistCost)
  // 原有公开方法不变；检查点失败后均不能再变更费用。
}
startBudget(state: CostState, limit: MicroUsd, scope: 'task' | 'process',
            notify?: NotifyCost, persist?: PersistCost): Budget
saveCostCheckpoint(dir: string, snapshot: CostSnapshot): void
// CostSnapshot 与费用字段形状沿用 ADR-107/108。
```

saveCostCheckpoint 属于 task.ts；输入是预算包装给出的已验证快照，不提供任意外部改账入口。测试只依赖需求、以上签名、费用类型与假网络协议；不得读取待改生产函数体。进程测试在假 fetch 入口观察磁盘 pending，以确定事件通知父进程强杀，不用睡眠猜时间窗口。分别注入预留保存、200/非200/无状态终态保存失败，并验证恢复拒绝、后续请求数与退出码。一次写失败后恢复可写的反例需证明“尽力保存成功”不能覆盖原失败。

单独验证检查点保持盘上业务值、字段缺席与精确根预算，不新建任务；同时覆盖 P4/P5 的声明顺序。对应顺序负片随测试与实现补入架构表，不在本文预先声称验证通过。全部测试使用假网络，不读取真实 key、不新增付费采样、不创建 evidence 或替代归档。

## 保留的边界

本项只保证单写者进程被强制中断时，已开始请求的费用不会因缺少后续保存而恢复为可花额度；沿用整体替换文件写入，不承诺主机断电的持久性或多个写者互不覆盖。

终态已经保存而业务响应尚未保存时，恢复仍可能再次查询该业务，但原费用不会丢失；页数、answered 与 found 等业务进度可能停在更早断点。本项不保证所有付费响应可恢复，也不保证任意强杀后绝不重复请求。保存失败后盘上可能是旧 pending，或尽力收尾写成的真实终态；预留保存失败也可能在收尾留下一笔未发出的 pending，均不能由此伪造 HTTP 结果或宣称本轮成功。

## 独立测试追记

实现前的进程测试已用假网络确认旧行为不满足本契约：请求入口没有盘上预留，保存失败后仍读取正文，强杀后恢复会继续请求。旧强杀断言曾明确接受一次请求的费用丢失，现按新契约改为保留 pending 并拒绝新增请求；同时保留上一页作者与分页进度、已完成账号样本缓存、历史终态费用的独立检查，不能用费用保存代替业务保存。保存故障的 after-http 场景改在实际请求开始后才注入，使它继续验证终态保存失败，而非被新增的请求前保存提前截住。
