# ADR-104 资源耗尽夹具在真实派工前施压，避免先撞复制路径

- 日期 · 2026-09-23（Asia/Shanghai）· PR #147 本地验证
- 类型：事实证伪
- 触发它的事实：主干 `e4565cc` 的资源夹具在 macOS / Node 24.10.0 上先因复制目录耗尽文件描述符，未到要验证的进程管道分支；原观察与欠条在 ADR-72 末尾。
- 冲击的需求：不改产品需求；修复守检查链的自检夹具，保持原有失败诊断与清理契约。
- 结论：采纳。在测试进程中、复制结束且即将真实派工时耗尽文件描述符，仍调用真实的系统派工操作，不构造假的子进程对象。
- 理由：原夹具靠低上限猜中耗尽位置，复制与进程启动的资源基线随环境变化。改变施压位置可验证原目标分支，不必把另一条失败分支冒充它。
- 连带改动：`scripts/check/selfcheck.ts` 的资源夹具；`mutate.ts` 的历史夹具说明只改注释；ADR-72 追加欠条处理依据。生产派工与清理逻辑不改。

## 修改测试之前固定的契约

临时预加载只拦截参数含 `--worker` 的派工调用；其他进程启动原样执行。
夹具给复制与运行时启动保留空间（文件数上限 128），到目标调用前打开 `/dev/null`
直到系统实际返回 EMFILE，再调用原始 `spawn`。调用返回或抛出后，释放夹具自己打开的
描述符。Node 的导出同步到 ESM，生产入口仍取得真实的子进程结果。

必须同时看到：夹具真实耗尽的运行记录、原入口的「连管道都没装上」诊断、
退出码 1、没有读属性异常、调高文件数或减少派工的提示，以及隔离目录已清理。
没有到目标分支就是失败，不能凭 EMFILE、非零退出或空输出通过。
POSIX shell 不可用时沿用现有显式未验证报告，不记通过。

施压描述符在派工返回后释放，因此这条夹具验证的是**启动失败后的清理接线**，
不承诺清理时仍没有可用描述符；持续耗尽导致清理失败的边界仍见 ADR-72。
负向复核要在备份后临时移除入口的管道缺失判定，确认原断言报失败，再从备份还原。
修改完成后由未参与夹具编写的上下文独立复核，并跑完整检查。

## 有界诊断证据

改仓库之前的临时诊断沿用主干真实入口。第一次上限 48，仍在复制时失败，
目标派工未发生，未记为通过。第二次上限 128，在派工前打开 107 个描述符直到 EMFILE，
真实派工返回无 pid、stdin 缺席；原入口发出目标诊断，退出码 1、无终止信号，
隔离目录清空，进程组无残留。这些数量只描述此次 macOS / Node 24.10.0 运行，
不作为夹具断言或其他环境的保证；其他环境由 CI 实跑。

## 2026-09-23 夹具正向与反向验证

`selfcheck --only=jobs-resource` 正向运行通过。备份后临时移除入口的管道缺失判断，
真实耗尽记录仍出现，但无读属性错、目标分支诊断、操作提示三个断言失败；
自检正常汇总失败并退出 1。随后从备份逐字恢复入口，生产代码未保留反向改动。
这说明夹具能区分正确处理与仅仅非零退出，未把验证器崩溃记成断言抓到。

独立上下文只读复核确认：预加载调用原始派工函数，标记不包含目标诊断；清理断言
在自检自己的删除之前取值，不能靠自检清目录制造通过。未发现阻塞问题。
