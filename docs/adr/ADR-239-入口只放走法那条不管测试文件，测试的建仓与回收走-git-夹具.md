## 二、业界怎么分

- **git 自己的测试**（`t/test-lib.sh`）：隔开本机设置这件事只在一处做 —— 清掉继承来的 `GIT_` 开头的环境变量、不读系统配置、把 `HOME` 指到每个测试自己的临时目录、跑完删掉那个目录。各个测试脚本不各写一份，测试里的检查照旧写在测试脚本自己身上。
- **《xUnit Test Patterns》**（Meszaros）：建夹具的步骤抽成共用的「建造方法」「测试工具方法」，好让每个测试读起来只剩「准备了什么、该看到什么」；断言留在测试里，测试本身就是一份说明书。

两边分法一致：**准备与收尾抽出去共用，断言留在测试里**。本仓库多一条硬理由：变异点名「该红的是哪几条断言」，认的是验证者源码里写着的断言名字（ADR-120 第 146 行说的「字面声明、单源码标签扫描」），断言搬走就认不到了。

## 三、定下的

1. **第 10 条不管测试文件。** 它说的「入口」是被测的代码。测试文件是验证者：它对不对靠变异来验，不靠再写一层测试，所以「有语义就该能被测、能被测就不该待在入口里」那条判据到这里停住。写进 `docs/CONVENTIONS.md` 第 10 条末尾，CodeRabbit 按约定评审时读得到。
2. **测试里该共用的是建仓、删仓、提交身份、环境。** 这几样漏一样不会红，只会悄悄读到本机配置、留下垃圾。测试要在临时目录里建 git 仓库、或起一个会在那里问 git 的进程时，从 git 夹具模块拿（`withToyRepo`、`toyRepoAt`、`fixtureEnv`），不自己拼。
3. **留在组里的**：具名断言；只有这一组用的观察手段 —— 这一组的预加载探针、目录字节快照、起入口的编排。它们只有一处用，抽出去不省事，反倒让读测试的人多跳一个文件。
4. **旧组改到哪组搬哪组。** 测试与自检里还有十几处自己包一层 `fixtureGit` 加提交身份、自己开临时目录的（树 c8401a5：`scripts/test.ts` 里调 `fixtureGit`／`fixtureGitOrThrow` 25 处，其中一部分是夹具模块自己的测试，`selfcheck.ts` 14 处）。它们的环境已经经夹具隔开，缺的只是建删与身份那一层的共用；不专门去搬，哪条改动改到那一组就顺手搬（与拆大决策记录「改到哪份拆哪份」同一个办法）。

## 四、这一组改了什么

- 独占临时根和三个诱饵仓库都改由 `withToyRepo` 开：建仓带提交身份、不读本机配置，跑完或抛错整个删掉。原先自己 `mkdtempSync`、自己 `try … finally` 删，自己包一层 `fixtureGit` 并在诱饵仓库里写一份提交身份配置。删完再看临时根还在不在、在就抛错，这一句保留。
- 起自检入口的环境改从 `fixtureEnv({})` 拿：去掉继承来的全部 `GIT_` 开头的变量（原先只删六项），再不读系统与用户的配置文件。原先手写的是 `GIT_CONFIG_NOSYSTEM` 与 `GIT_CONFIG_GLOBAL` 两项。要灌进去的六项污染照旧在这份环境之上另加，`NODE_OPTIONS`、`MUTATING` 照旧删。
- 诱饵仓库关掉后台维护（`gc.auto=0`、`maintenance.auto=false`）那两句保留：快照前要仓库静止（ADR-120「CI 的夹具维护竞态修正」）。
- 十二条具名断言、预加载探针、快照、编排一个字没改。

改后对照：这一组单跑 12 条全绿；把 git 夹具里去掉 `GIT_` 变量那一行依次改成放过 `M-H64-a`～`f` 各自那一项（六条变异原样手工施上，跑完复原），每一次都是点名的那条「Git 建历史隔离：不继承 …」红，`GIT_DIR` 那一次另加「继承 GIT_DIR 不改诱饵任何 Git 文件」红。

## 五、拦不住的

- 第三节第 2 条没有机器查：测试里自己拼 git 环境、自己开临时目录建仓，不会红。按字面去搜「`GIT_CONFIG_NOSYSTEM`」「`mkdtempSync` 后接 `git init`」这类写法是猜，搜不全也会误报，不做。靠评审读第 10 条。
- 第 10 条「不管测试文件」只说测试文件不必搬逻辑，不说测试文件可以随便长；测试的体量照样受体量闸门管。
