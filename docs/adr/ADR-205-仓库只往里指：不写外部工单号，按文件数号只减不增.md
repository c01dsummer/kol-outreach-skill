## 一、规矩在本仓库是哪几个字

`process/` 不写本仓库的字眼（`docs/SYNC.md`「一条判别规则」），具体是什么记在这里：

- **外部任务工具**：Linear。
- **工单号**：`KOL-` 接数字。不带数字的 `KOL` 不算（`KOL-OBS` 那个旧词早已撤出，ADR-187）。
- **指向一张卡的链接**：linear.app 上路径里带 `/issue/` 的。指向项目页的（`AGENTS.md` 第 50 行、ADR-181 第四节）是路由，不算。
- **仓库里的文字**：受控文件全部，不分目录。`skill/` 本来就一个号都没有；决策记录、`docs/`、`scripts/`、工作流都算。
- **不受这条管的**：PR 标题与正文、分支名、提交信息。Linear 的 GitHub 联动靠它们把 PR 挂到卡上；提交信息不要求写，也不禁止。

## 二、检查怎么判

`npm run ticket-refs`，检查链里紧跟 `npm run size`：

1. 起点与体量闸门同一个判定（`size-rule.ts` 的 `resolveBaseline`）：分支上是与主干的共同祖先，主干上是上一版。浅克隆、找不到主干、没有共同祖先 —— 无从判断，以 1 退出。
2. 用 `git grep -o` 数两边：基线那个提交的树，与工作区里的受控文件（没提交的改动也算）。每处一行，同一行两个号算两个；卡片链接一直数到空白为止，链接末尾带着的号随链接算一处。
3. 逐个文件比：**比基线多就红**；基线上没有的文件（新文件、改了名的文件）按零个算。少了的列出来，不红。
4. 主干上只报数不判定，与体量闸门同一个理由：CI 跑在推送之后，判红只会让主干变红。

为什么按文件记数、不按 diff 的新增行：决策记录追加不删改，旧记录里的号删不掉、也不该逼人删；按 diff 判，往旧记录末尾追加一块、块里引了一句带号的旧话，就分不清是新写的还是抄的。按文件数，「那份文件里的号变多了」是一个不用解释的事实，需求所有者 06:48Z 那句「旧adr也要防止它们后续继续追加卡号」正是这个。代价：改名一份带号的文件会红（新路径按零个算）—— 这时一并把号撤掉，正是规矩要的。

## 三、没守的

- 不带号、只说「卡片」「那张卡」的话：没有号可数。仓库里还有这类句子（例如 `scripts/check/selfcheck.ts` 里「与卡片「复现步骤与实测结果」一致」），本条不改，读的时候知道它指向仓库外。
- 把号拆开写、或换了别的团队前缀的号：认不出。
- 没 `git add` 的新文件：`git grep` 只看受控文件；提交之后就数得到。
- 主干上直推：只报数（同体量闸门，那是分支保护的活）。
- 基线上已有的号：留着。对照见 ADR-204。
