# ADR-86 欠条台账只抽取不匹配：判断留给会读的那一侧

## 起点，以及它没按预想走

这条线的第 8 步有两件事：给留下的闸门写死亡条件（ADR-85 做完了），
以及让欠条台账可机读。后者原先的设计是**匹配**：读这次改动的文件清单，
去 `docs/adr/` 里找哪几条欠条的重启条件点名了这些文件，命中就报出来。

动手之前先去数了一遍能不能做成。**数完之后这个设计撤掉了一半。**

## 一、先纠一个分母：167 行不是 167 条条件

`git -c core.quotePath=false grep -n '重启条件' -- docs/adr/` 命中 167 行。
逐条读完之后（分类由子代理做，抽样与下面每一处实测由我自己复核）：

| | 条数 |
|---|---|
| 在**谈论**重启条件（统计、引用别处的欠条、元叙述） | 57 |
| 条件**已经还掉了** | 25 |
| **活的、未还的重启条件** | **82** |

82 条按条件里点了什么分：

| 条件点名了什么 | 条数 |
|---|---|
| 文件路径 | 30 |
| 代码标识符（`importsOf`、`SELFCHECK_TOOLS`） | 19 |
| 需求／变异编号 | 2 |
| 计划步骤（「落地 2 开工」「5c」） | 9 |
| 纯散文状态 | 20 |
| 要人拍板 | 2 |

点了东西的是 51/82。对照 `ADR-64:170` 当年记的「21 条欠条里只有 7 条点了具体文件」——
**这个比例从三分之一涨到了六成**，纪律是执行住了的。

## 二、然后是实测：词匹配不成立

那 51 条里，34 条在对抗核验里被判偏窄。三处实测，每一处都自己跑过：

**① 符号名不出现在自己的 diff 里。** `ADR-70:790` 的条件是「下一条要把别的检查脚本
加进 `SELFCHECK_TOOLS` 的 PR」。照字面做那件事（往 `verifier-rule.ts` 里那张表加一行），
`git diff` 的 ± 行只有新加的那一行，**那个词出现 0 次** —— 词写在声明行上，
改动落在表内部，声明行不进 diff。

**② 历史上已经漏报过一次。** `ADR-70:351` 的第二条腿是「落地 4 开工」，
落地 4 就是提交 `6fad02e`。那次 diff 的 ± 行里 `mutatedCrit` 命中 **0** 次
（命中的 7 处是 `mutatedCriteria`，另一个标识符）。**条件真的响了，词一次没出现。**

**③ 条件普遍是析取。**「碰 X 的 PR，**或**落地 4 开工」——
单词匹配天然盖不住第二条腿。

## 三、但撤掉它的理由不是「做不准」，是斜率

做不准可以修：把词解析成它所在的文件，再跟 diff 的文件清单取交，准确率会上去。
**那条路才是真正要避开的那条。**

ADR-76 的斜率判据：涨的（验证、工具、规格）留；跌的（编排、步骤协议、**路由表**）
标死亡条件。「把欠条里的词解析成文件、再决定要不要提醒你」——那就是一张路由表，
而且它要靠一张手写的符号索引表活着。

`ADR-85:116` 刚写过这句：

> **判据写的是全称，实现却是一张手写白名单** —— 那正是 ADR-77 撤掉纪律 lint 的理由，
> 而这一版是在一份引用着 ADR-77 的记录里犯的。

**这条记录差点在下一步里把同一件事再做一遍，规模更大。**

证据就在上面那张分桶表自己身上：57 行要靠判断才排除得掉、25 条已还也要靠判断、
三套写法是**读**出来的不是 grep 出来的 —— 而做这三件事的子代理**靠读全做对了**。
读是会随模型变强的那一侧，正则不是。

## 四、于是只留两件机械的事

**① 抽取。** 把三套写法下的条目抽成一份可列的清单：
`npm run audit -- --debts` 打全表，`npm run audit` 末尾打一行计数。
它**不判哪条已经还了，也不判这次改动踩到了谁** —— 那两件事交给读的那一侧。

清单的价值是省读：`docs/adr/` 今天最大的一份是 2249 行，
一份 125 条的索引比它便宜两个量级。

**② 一道硬失败：`⚠️ 欠条` 块里没写重启条件。**
`docs/SYNC.md:56` 说带重启条件的欠条不算待办，反过来就是不带的那些是纯待办，
而 `process/6-INTEGRATE.md` 写着「写不出重启条件的登记不是登记，是免责声明」。
**今天 88 个块 88 个都写了 —— 这道闸门今天是绿的，它拦的是往后的滑坡。**

判定在 `scripts/check/debt-rule.ts`，配三条负片。

## 五、顺带查出来的：这个仓库有三套写法，只有一套有名字

| 写法 | 在哪 | 抽到 |
|---|---|---|
| `· 重启条件` 后面跟冒号 | 全仓 ADR | 105 |
| `## 什么条件下重开这个讨论` | ADR-76／77／78／79 | 9 |
| `## 死亡条件` 这一节，以及 `**什么条件下……**` 后面跟冒号 | ADR-80／81／83／85，另 ADR-04 一条 | 11 |

第二套整整 9 条，`grep 重启条件` 一条都捞不到 —— **ADR-76 全文 0 处「重启条件」**。
而它们比第一套里的大多数更好认：标题是固定字符串。

**上面这张表的写法是被抽取器逼出来的。** 头一版照原样写着那三个引子，
抽取器当场把自己这两行表格收成了两条真条目 —— 围栏和 HTML 注释盖得住，
行内反引号盖不住。没有为此加判据（那正是白名单长大的方式），改的是这份文档。
**一份讲某个抽取器的记录，躲不开被那个抽取器读到**，这件事记在这里。

## 六、没做的

- **没做「给死亡条件装机器」**，尽管 `ADR-85:316` 把它派给了这一条。理由是
  ADR-85 自己写着那几条「都可核，但**都几乎不会响**」—— 装一台永远不响的机器，
  按 `process/4-VERIFY.md` 的说法等于没装。三套写法都进索引，所以死亡条件
  照样被列出来，只是没有人去数它。
  ⚠️ 欠条：**死亡条件今天只被列出来，没有被核过。**
  重启条件：某一条死亡条件的成立方式从「几乎不会响」变成会响时，或者
  死亡条件的条数超过判定模块数时 —— 那时人读一遍不再够。
- **不判已还。** 125 条里有一批条件已经还掉了，台账不知道是哪些。
  这是有意的偏宽：多列一条读的人自己排除得掉，少列一条没人会发现。
  ⚠️ 欠条：**「这条欠条还了没有」没有任何标记。**
  重启条件：下一条要往 `debt-rule.ts` 加判定的改动，或者欠条条数翻倍时。
- **`ADR-85:144` 与 `:148` 那两条死亡条件抽不到。**
  它们的形状既不带「什么条件下」这个引子，也不挂在 `## 死亡条件` 标题下。
  没有为它们加判据 —— 那正是白名单长大的方式。
  ⚠️ 欠条：**死亡条件的写法没有约定，抽取因此必然漏。**
  重启条件：下一条要新写死亡条件的改动 —— 那一刻顺手把写法定下来，
  或者确认「三种形状够了」。
- **`process/6-INTEGRATE.md:245` 那张三选一清单缺第四种。**
  它写着重启条件通常是「下次有改动碰到那个文件、同一缺口再被点名、定期清点」，
  而实测有 9 条挂在计划步骤上 —— `ADR-64:207` 早就记过这一笔，至今没补。
  本条不动那份流程档（串行，一条 PR 一件事）。
  ⚠️ 欠条：**清单少一种，而写欠条的人正在用清单之外的写法。**
  重启条件：下一条要动 `process/6-INTEGRATE.md` 欠条那一节的改动。
