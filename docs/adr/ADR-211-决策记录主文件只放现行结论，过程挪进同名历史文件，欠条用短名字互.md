## 一、新的存法：一条记录，主文件加一份同名历史文件

一条记录还是一个编号。它可以有两个文件：

1. **主文件** `docs/adr/ADR-<编号>-<标题>.md`：只放**现在**定的是什么。开头那几栏（日期、类型、结论、决定人与时间……）照旧；正文写现行结论；还没还的欠条也在这里，因为它们是「现在还欠着」的事。主文件**可以整段重写**，让它始终说的是现在的规定。
2. **历史文件** `docs/adr/历史/` 下与主文件**一字不差的同名文件**：放「怎么一步步走到这里的」。第一行写同一个编号。原样搬过去，**只追加，不删**。

拍板的痕迹（需求所有者哪天在哪张卡上选了什么、哪条 PR 是他合的）属于结论，**留在主文件**，不压、不挪。

**什么时候拆**：

- 还没拆过的记录，**主文件过了大小线**的（线定在 `docs/adr/README.md` 开头，现在是 30 000 字节，按 `wc -c` 数；量的是这条改动从主干分出来时主干上那份，同一条改动后来加的不算），哪条改动要往里加新内容 —— 新的一节、更正块、新欠条 —— 就在那条改动里先把它拆了，再按拆过的写法落。不专门开 PR 去拆，改到哪份拆哪份。
- 例外：回访台账 ADR-152 过了线不先拆，每周回访照旧往主文件末尾追加，另开一条 PR 把旧块挪进历史文件，做法见 ADR-152「过线时把旧块挪进历史文件」那一节。
- 只补状态行不算新内容，照旧加在末尾，不用先拆。状态行指以「⚠️ 已还／已重挂／收尾」开头、只写指回哪张和还在哪的那一块；里面带新结论或新欠条的，算新内容。
- 没过线的，照旧把新块加在文件末尾（`process/2-CHANGE.md`「新内容加在哪」那一套）。新开的记录也一样：没过线就加在末尾；愿意的可以一开始就分出历史文件（ADR-215 是这样）。
- 欠条 PR（以及搭在本 PR 别的提交里的欠条）要落进的那条记录过了线又没拆过：不往那条追加，按 `process/6-INTEGRATE.md`「登记怎么做」第 3 条的顺序找下一个落点（本 PR 自带的记录，或新开一条只装欠条的记录）。欠条 PR 只加块、直接合，不做拆分。

**怎么拆**：先找决策记录以外按行号指这份的（代码注释、`docs/` 里的文档），改成按节名或短名字指 —— `scripts/test.ts` 里「决策记录以外的文件没有按行号指拆过的记录」那条需求测试不许它们留着；再把旧正文原样搬进历史文件（拆的人用 `cmp` 与主干上的原文比一次，PR 正文写明怎么比的），主文件重写成现行结论；另找一个没参与重写的 Claude 对照历史文件逐条核主文件；开 PR 前照常做欠条清点。从那以后，后来的过程（评审补记、更正、还掉的欠条）加在历史文件末尾，主文件同时把结论改成新的样子。原文里早已用散文写了已还、已由别处接走、台账却认不出的老欠条，在历史文件末尾补一行台账认得的状态行，写明还在哪。

**拆的时候还开着的老欠条**：在主文件里重写一张，起短名字（第三节）；历史文件里原样留着的那一张不动，只在历史文件末尾追加一行 `⚠️ 已重挂：ADR-N 第 M 行 · 现行的是 ADR-N「短名字」`。老欠条**本来就有名字**的，主文件那张**换一个新名字**，不沿用：主文件和历史文件算同一条记录，同名会被重名查验报出来，而历史文件不许改，没法在那边消掉；那行状态行写成 `⚠️ 已重挂：ADR-N「旧名字」 · 现行的是 ADR-N「新名字」`，新旧名字的对应就在这一行。这样台账上开着的只有主文件那张，老欠条有一行状态行指着它的去处；历史文件仍然是「原文 + 后来追加的」，比对原文时只比追加之前那一段。

## 二、为什么改掉「追加，不删改」

那条老规矩护的是「当时只知道这些」不被改掉。新存法照样护住它：过程一个字不删，只是换了个文件。改掉的只是「主文件也只能追加」这一半 —— 正是这一半让最长的几份记录长到几十万字，读的人要从头读完全部过程才知道现在的规定是什么，而中途哪一块已经被后面推翻了，要自己拼。

最大的风险是**重写结论时写错**：漏掉一条还在生效的限制。所以拆一份记录的那条改动，要有一个没参与重写的 Claude 对照历史文件逐条核结论，并用脚本比对「历史文件 = 拆之前的原文」，不靠眼看。

为什么不全拆、要有一条线：拆一份从起草、清点、独立复核到完整检查约要大半天；顺手拆把这份力气花在有人正改着、读着的那份上，代价是碰到过线记录的那条改动会变大 —— 比如旧结论被推翻、要往陈述过它的几份记录各补一块更正时（`docs/SYNC.md`），其中每有一份过线没拆，那条改动就多拆一份。没过线的记录不拆，它们里面的老欠条照旧按行号指（第三节老写法照旧认）。

## 三、欠条用短名字互相指，不再写第几行

主文件可以重写、过程要挪进历史文件，「某份记录第几行」就一定会全断。所以欠条要有一个跟着它走、不随文件变的名字：

- 欠条块头写成 `⚠️ 欠条「<短名字>」：<缺的是什么> …`。短名字是一句白话，最长 40 个字，例：「变异缓存没有检查守着」。同一条记录（主文件加历史文件算一条）里不许重名，重名时欠条台账（`npm run adr-ledger`，审计第 6 节同一份）当场报红 —— 重名的话，按名字关上一张就等于把另一张也当成关了。
- 关上一张欠条时写 `⚠️ 已还：ADR-<编号>「<短名字>」 · <还在哪>`（已重挂、收尾同样）。「欠条点名提醒」（`npm run debt-touch`，改到的文件被哪几条开着的欠条点了名）认这种写法，欠条在主文件还是已挪进历史文件，都关得上。
- 别处要提到一张欠条，也写「ADR-<编号>「<短名字>」」，不写第几行。

老写法「`⚠️ 已还：ADR-N 第 M 行`」照旧认，已经写下的不用改，而且**拆的时候也不改**（它们多半就在要原样搬走的正文里）。它指的是写下那一刻那份文件的第 M 行：没拆过的记录，就是主文件那一行；拆过的记录，旧正文原样搬进了历史文件，行号在那里不变，所以按历史文件的第 M 行认。拆过的记录，主文件已经重写，它里面的欠条**只能按名字关**，任何按行号的状态行都不算到它头上 —— 反过来的话，重写后的主文件第 M 行恰好是另一张开着的欠条，一行老状态行就把它静默算成已关。

每周回访台账里点名欠条，有短名字的写「编号「短名字」」（`docs/REVISIT.md`）。评审替身评论开头的「文件＋行」指的是 PR 里的代码行，不是决策记录，不归本条换：它不随决策记录拆分而断，`AGENTS.md`「汇报纪律」第 5 条与 `process/README.md`「编号只作挂钩」第 2 条把它留在例外里，照旧旁边加一句白话。

## 四、检查改了什么（现状）

- **决策记录索引检查**（`npm run adr`，判定在 `scripts/check/adr-rule.ts` 的 `adrSync`，入口 `adr-sync.ts` 只剩打印与退出码）：`docs/adr/` 下名为「历史」的子目录不当成一份格式不对的记录；其中每份都要是文件、有同名主文件、第一行编号与文件名相同，否则报红。历史文件不进索引。
- **历史文件只加不删**：`docs/adr/历史文件指纹.json` 给每份历史文件记到上次 `npm run adr -- --write` 为止的字节数与 sha256。钉住的那一段一个字节不许变；短了、改了、整份删了都报；末尾新加的还没钉住也报红，让人跑 `--write`；`--write` 碰到改过的旧内容拒绝回写。另拿这边与主干分叉点（`merge-base`，主干先找 `origin/main` 再找 `main`）上的那份表再比一遍（`trunkPinsText`）：主干钉过的每一份，这边还在、不比钉住时短、钉住的那一段没变，否则报红、`--write` 也拒绝；分叉点上有表却读不出来或不是合法的表也报红；找不到主干或没有分叉点就只比本树（检查链里体量闸门排在前面，找不到主干先红）。拦不住的：直接在主干上改，主干自己比自己，那一步靠合并前那条 PR 的检查。拆的那一刻历史文件是不是原文逐字，仍是拆的人用 `cmp` 比一次，检查只管拆以后。
- **欠条台账**（`npm run adr-ledger`，审计第 6 节同一份）：递归读 `docs/adr/` 下全部文件，历史文件里的欠条照样计数、照样查孤儿（写了欠条没写重启条件）。硬失败「短名字有错」：同一条记录里重名；块头起了名字却取不出来（空的、超过 40 个字、书名号没收尾）；拆过的记录，主文件里的欠条没起名字（按行号的状态行不算到它头上，没名字就永远关不上）。只认紧跟在「⚠️ 欠条」后面的那对书名号：块头别处提到「接着某某的欠条「甲」」不是这张的名字。孤儿与短名字有错写成硬失败行的那一段在 `debt-rule.ts` 的 `ledgerGaps`。
- **欠条点名提醒**（`npm run debt-touch`）：认按名字关上的状态行；拆过的记录按第三节的规矩认老行号。两张欠条没隔开时，后一张的条目拿自己的名字，不拿前一张的。
- **被引表**（`npm run adr-ledger -- --cites`，`cite-rule.ts`）：主文件与历史文件按编号并成一行，同一条记录不重复计，教训栏写在历史文件里也算。
- **周回访**（`docs/REVISIT.md`，`revisit-rule.ts`）：登记日对拆过的记录取拆之前原文那一行（`born`）；拆的那一周挪进历史文件的不当成有人改了已合入的记录；「候选句」那几条 `docs/adr/ADR-*.md` 只读主文件，因为开着的欠条都在主文件。

- **决策记录以外不许按行号指拆过的记录**：`scripts/test.ts` 里「决策记录以外的文件没有按行号指拆过的记录」那条需求测试，仓里决策记录以外的文件写着「ADR-N 第 M 行」而 N 拆过就红（决策记录之间按第三节读作历史文件同一行，不管）。

判定都有需求测试和变异（故意改坏它，测试必须红）。只读台账入口与审计入口把「短名字有错」计进硬失败、以 1 退出，由脚本自检在玩具树上真起一次验过；审计入口计进硬失败那一下只有这一道自检、没有变异 —— 指名自检来验、施在审计入口上的变异会被「自己验自己」那道体检拦下，写 `by: test` 的又没有需求测试会红。入口 `adr-sync.ts` 把 git 交给 `adrSync` 的那个实参没人守，现挂在 ADR-220「决策记录同步交 git 的实参没人守」。

**扫描范围**：SPEC 一致性检查与准入读物包只读 `docs/adr/` 顶层，不进历史目录。主文件保留开头那几栏（含「冲击的需求」），编号在不在照旧查得到；挪进历史文件的正文里提到的需求编号，不再查是否悬空。

「过了线的记录要先拆」这一条没有检查守着，只靠写的人记得、评审看 diff，挂成末尾那张欠条。

## 五、两道新闸门：替代的是跑还是读、什么时候撤

两道都替代**读**：没有它们，要人逐份读历史目录核「这份历史跟着哪条记录」、逐张读块头核「有没有重名、名字取不取得出」。都替代不了**跑** —— 它们不证明拆出来的结论写对了，那一半靠拆的时候的独立核对。

> **什么条件下历史文件那道整个撤掉**：决策记录不再拆分（本条被推翻、历史目录整个删掉）时；或者连续半年历史目录里没有出现过一份配不上主文件的文件、也没有人在评审里指出过这类错时，退成只报数。

> **什么条件下短名字那道整个撤掉**：状态行与互相指都不再按名字写（换成别的稳定标识）时；或者连续半年台账上没有出现过一次「短名字有错」、评审里也没人指出过重名时，退成只报数。

## 九、同类欠条也认短名字

`docs/adr/README.md`「同类」的两种欠条模板写成带短名字的；找同类的 grep、`docs/REVISIT.md` 第一道门那几条 grep 与 sed、ADR-151 主文件数同类欠条条数的两条 grep，「欠条」与冒号之间都允许一个 `「…」`。写成 `(「.*」)?` 而不写 `(「[^」]*」)?`：例程的 shell 若在 C 语言环境下跑，`[^」]` 按字节比，名字里的「、」等字与「」」共用字节，会认不出。
