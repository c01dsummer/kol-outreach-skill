## 一、新的存法：一条记录，主文件加一份同名历史文件

一条记录还是一个编号。它可以有两个文件：

1. **主文件** `docs/adr/ADR-<编号>-<标题>.md`：只放**现在**定的是什么。开头那几栏（日期、类型、结论、决定人与时间……）照旧；正文写现行结论；还没还的欠条也在这里，因为它们是「现在还欠着」的事。主文件**可以整段重写**，让它始终说的是现在的规定。
2. **历史文件** `docs/adr/历史/` 下与主文件**一字不差的同名文件**：放「怎么一步步走到这里的」。第一行写同一个编号。原样搬过去，**只追加，不删**。

拍板的痕迹（需求所有者哪天在哪张卡上选了什么、哪条 PR 是他合的）属于结论，**留在主文件**，不压、不挪。

还没拆过的老记录照旧：新块加在文件末尾（`process/2-CHANGE.md`「新内容加在哪」那一套）。一份记录第一次拆的时候，把旧正文原样搬进历史文件，主文件重写成现行结论；从那以后，后来的过程（评审补记、更正、还掉的欠条）加在历史文件末尾，主文件同时把结论改成新的样子。新开的记录本来就只有结论，第一次有过程要补时再建历史文件。

## 二、为什么改掉「追加，不删改」

那条老规矩护的是「当时只知道这些」不被改掉。新存法照样护住它：过程一个字不删，只是换了个文件。改掉的只是「主文件也只能追加」这一半 —— 正是这一半让最长的几份记录长到几十万字，读的人要从头读完全部过程才知道现在的规定是什么，而中途哪一块已经被后面推翻了，要自己拼。

最大的风险是**重写结论时写错**：漏掉一条还在生效的限制。所以拆一份记录的那条改动，要有一个没参与重写的 Claude 对照历史文件逐条核结论，并用脚本比对「历史文件 = 拆之前的原文」，不靠眼看。这两件是试点那条 PR 的验收条件，不在本条。

## 三、欠条用短名字互相指，不再写第几行

主文件可以重写、过程要挪进历史文件，「某份记录第几行」就一定会全断。所以欠条要有一个跟着它走、不随文件变的名字：

- 欠条块头写成 `⚠️ 欠条「<短名字>」：<缺的是什么> …`。短名字是一句白话，最长 40 个字，例：「变异缓存没有检查守着」。同一条记录（主文件加历史文件算一条）里不许重名，重名时欠条台账（`npm run adr-ledger`，审计第 6 节同一份）当场报红 —— 重名的话，按名字关上一张就等于把另一张也当成关了。
- 关上一张欠条时写 `⚠️ 已还：ADR-<编号>「<短名字>」 · <还在哪>`（已重挂、收尾同样）。「欠条点名提醒」（`npm run debt-touch`，改到的文件被哪几条开着的欠条点了名）认这种写法，欠条在主文件还是已挪进历史文件，都关得上。
- 别处要提到一张欠条，也写「ADR-<编号>「<短名字>」」，不写第几行。

老写法「`⚠️ 已还：ADR-N 第 M 行`」照旧认，已经写下的不用改。历史文件里的条目单独按「历史文件 + 行号」认：老状态行写的第几行指的是主文件那一行，不能顺带把历史文件同一行号的另一张也算成关了。没写短名字的老欠条，只能照旧按行号指；拆那份记录时顺手给它起名字，并把指向它的状态行一起改成按名字指。

每周回访台账里点名欠条的写法、评审替身评论开头的「文件＋行」，这次没动：前者等试点量出要改多少处再定，后者是指 PR 里的代码行，不是决策记录。

## 四、检查改了什么

- 决策记录索引检查（`npm run adr`）：`docs/adr/` 下名为「历史」的子目录不再当成一份格式不对的记录；其中每份文件都要有同名主文件、第一行编号与文件名相同，否则报红。历史文件不进索引。
- 欠条台账：本来就递归读 `docs/adr/` 下全部文件，历史文件里的欠条照样计数、照样查孤儿（写了欠条没写重启条件）。新加重名查验，和孤儿一样是硬失败。
- 欠条点名提醒：认按名字关上的状态行；历史文件里的条目另有行号键。

都有测试，每条新的判定都配了变异（故意改坏它，测试必须红）。三份试点合入以前，`docs/adr/历史/` 还不存在，这些分支只在测试里跑到。
