## 一、决定

报告网页（`scripts/lib/report.ts`）改用一个带标签的模板 `html` 来写（新文件 `scripts/lib/safe-html.ts`）：

1. 模板里写死的那部分原样输出；`${…}` 插进去的值一律先转成文字再转义 `&`、`<`、`>`、`"`、`'` 五个字符。
2. 只有一种东西例外：`html` 自己拼出来的结果（类型 `SafeHtml`）。它插进别的 `html` 时原样输出，不再转义一次。
3. `SafeHtml` 只由 `html` 与 `joinHtml`（把一串片段连起来）造，构造函数是私有的，造出来就冻住、改不了。认片段（插值处与 `joinHtml` 的分隔参数）查的是一张只有本模块往里放的表，不看原型，仿造的照样当文字转义（第四节第 4 条、第五节）。
   挡不住的一条路：把 `html` 当普通函数调、手造一个字符串数组传进去（`html([s] as never)`）。写错一处碰不上它，要故意绕；报告里原有的「这一处没转义」变异正是这样造的。
4. 缺值（`undefined`、`null`）写成空。原来 `escRaw` 那几处要把缺值照印成 `undefined` 的（ADR-180 结论），改成自己写 `String(v)`，再交给默认转义；页面输出与原来逐字节相同。

为什么这样做：以前每一处插值都要记得手写转义，忘了一处就是一个口子，测试只能扫到夹具里有的字段（ADR-180 第二节）。现在忘了写也不会出口子：不写就是转义。要原样插标记，只能插 `html` 拼出来的片段；把普通字符串插进去，编译照过，但它在页面上只会是文字。

这是业界写网页模板的通行做法（带标签的模板加一个「已转义片段」类型；lit-html、各家服务端模板引擎的「默认转义、显式标记安全」都是这个形状），不是自造的规矩。

## 二、怎么落地

- `report.ts` 里所有拼页面的函数改成返回 `SafeHtml`，列表用 `joinHtml` 连；最外层 `renderHtml` 取 `.html` 交出字符串，对外接口不变。
- `esc`、`escRaw` 两个函数删掉，仓库里不再有逐处手写转义。
- 改写前后用同一批夹具逐字节比过两种视图，完全相同。
- 报告里原有变异中锚点落在被改写那几行上的，跟着改了：
  - 原来「去掉 `esc(`」那一类，现在改成「把取值包成 `html([String(x)] as never)`」，即伪造一个片段绕过转义，含义仍是「这一处取值没转义」；
  - 原来「转义两次」那一类，现在改成「先 `html` 一次再取 `.html` 当文字插进去」，含义仍是「转义了两次」。
  - M-U11-l（冻结来源原文直接成为页面标签）：最初照第一类改在 `known` 上，可「原任务来源」那一格是先用普通字符串模板拼的，伪造片段在那里变成 `[object Object]`，测试红的原因成了「原文丢了」而不是「原文没转义」（独立复核第一轮指出）。锚点挪到那一格整串插值处，包成伪造片段，点名断言照红。
- 另有一条 M-U12-e（转义漏了大于号）原来改的是 `esc` 函数，挪到 `safe-html.ts` 的 `escapeText` 上。

4. 第一次跑有 2 条红：它写了「挂着 `SafeHtml` 原型、但不是 `html` 拼出来的仿造对象，插进去照样当文字转义」。当时的实现只用 `instanceof` 认片段，这种仿造对象过得去。判据原文「别的东西哪怕长得像片段，也照样当文字转义」管得到它，所以改实现不改测试：认片段改成查一张只有本模块往里放的表（`WeakSet`），不看原型。改完 101 条全绿。
