# ADR-196 改到欠条点名的文件时只提醒地列出那几条欠条

- 日期 · 2026-11-14
- 类型：检查链旁加一个只提醒的入口（不是闸门）。判定在 `scripts/check/debt-touch-rule.ts`，入口 `scripts/check/debt-touch.ts`（`npm run debt-touch`），CI 在检查之后单列一步
- 触发它的事实：Linear 上 KOL-84、85、86 关成「改由 ADR 欠条盯」之后，需求所有者丸子 2026-11-14 12:08（北京时间）在项目线程里问这些欠条是不是真能被识别、被跟踪，「不然写了跟没写也没区别了」。欠条的写法机器认得（`npm run adr-ledger` 列得出），但「这次改动有没有碰到哪张欠条的条件」全靠每条 PR 合入前读改动、对着台账判，没有任何东西提醒，漏判了也没东西报警
- 决定人与时间：需求所有者丸子 2026-11-14 12:09（北京时间）在同一线程答「1-3都做」，本条是第 3 件；卡片 KOL-110 写着做法与关单标准
- 结论：采纳。人批痕迹：需求所有者合入本条那条 PR
- 理由：欠条正文里逐字写着文件路径的，占开着的欠条一半左右（见第二节）；这一半拿改到的文件取个交就能当场点出来，省掉「每条 PR 从几百条里找跟自己有关的」那一步。响没响仍要读条件，所以只列、不判、不拦
- 连带改动：`package.json` 加 `debt-touch`；`.github/workflows/check.yml` 在墙钟对比之后加一步；需求测试加 `h-iou-file-reminder` 一组、变异 `M-H196-a`–`m`；`docs/ARCHITECTURE.md` 锚点表两行；`AGENTS.md` 命令清单一行；自检 `EXEMPT` 一行（见第三节）

## 一、和 ADR-86 的关系：这次做的不是它撤掉的那件

ADR-86 原先的设计就是「读这次改动的文件清单，找哪几条欠条点名了这些文件」，第三节把它撤了。撤的理由写得很清楚：不是做不准，是斜率 —— 「把欠条里的词解析成文件、再决定要不要提醒你」是一张要靠手写符号索引活着的路由表。

本条只做那件事里不需要索引的一小半：

- **认得的名字只有一种来源：受控文件的路径本身**（`git ls-files`）。完整路径都认；按 `/` 切出来的尾段里，只属于一个文件、又带扩展名的也认（`mutate.ts` 认成 `scripts/check/mutate.ts`）。`README.md` 这种不止一份的，只认完整路径。没有一张手写的表，加文件、删文件、改名都自动跟着走。
- **不解析代码标识符、需求编号、计划步骤。** ADR-86 第二节那三处实测（符号名不出现在自己的 diff 里、`ADR-70:351` 真响了而词一次没出现、条件是析取）照旧成立，本条不碰。
- **不判响没响，不拦合入。** 点了名不等于条件成立（「下一条碰 `mutate.ts` 判定或汇总那一段的 PR」，改别的段也会被列出来）；所以它是提醒，替代不了每条 PR 合入前对欠条的清点，只是让清点从一份短单子开始。

ADR-86 第四节那句「台账不判这次改动踩到了谁」说的是台账（`debt-rule.ts`），对台账照旧成立：本条没改台账，判定另放一个模块。

## 二、认得到多少，认不到哪些

主干 `5f68c8b` 上：台账 627 条；已还／已重挂／收尾行（ADR-167 第五节的写法）指到其中 228 条，剩 399 条开着；开着的里面，欠条正文（条目在 `⚠️ 欠条` 块里时是整个块，否则是条目那一行）逐字写了至少一个受控文件的是 196 条。点名最多的几个文件：`scripts/test.ts`、`process/6-INTEGRATE.md` 各 23 条，`scripts/check/mutate.ts` 20 条，`scripts/check/selfcheck.ts` 14 条。

**漏网情形**（报告每次都说一句）：

- 欠条没写文件路径，只写了模块名、代码标识符、需求编号、计划步骤或「某类改动」—— 例如 ADR-180 第 32 行「下次改动给报告加展示字段时」。开着的 399 条里有 203 条是这样，这一半仍靠人读台账判。
- 只写了目录（`scripts/check/`）：目录不认，认了的话改目录里任何一个文件都列一串。
- 文件名不止一份时只写了裸文件名。
- 条件是析取，另一条腿不是文件（「或落地 4 开工」「或定期清点」）：文件那条腿认得到，另一条腿认不到。
- 「改到的文件」只算受控文件：没 `git add` 的新文件不算。
- 状态行指的行号不是一条台账条目时（`5f68c8b` 上有 2 行这样的），那张欠条照旧算开着、照旧列出 —— 多列一条读的人排除得掉，少列一条没人会发现（ADR-86 第六节「不判已还」那条的理由）。

## 三、在哪看得到

- **PR 上**：CI 的 check 那一跑里「欠条点名提醒（只提醒）」那一步。汇总那一句打成一条 notice，PR 的 Checks 页和那一跑的总览页上都看得到；全文（每条欠条的文件、行号、点到的文件、截短的正文）写进那一跑的 Summary。检查红了也照跑。
- **本地**：`npm run debt-touch`。改到的文件与体量闸门同一个起点（分支上是与主干的共同祖先，主干上是上一版），量到工作区为止，所以提交前跑也算正改着的文件。
- 两处都**恒以 0 退出**；取不到改动清单（浅克隆、不是仓库、找不到主干）时说「无从比较」加原因。它不在 `npm run check` 里，CI 那一步另有 `continue-on-error` 兜底。

入口没进自检的工具表，写进了自检的 `EXEMPT`：它在玩具 git 仓库上的真起由需求测试组 `h-iou-file-reminder` 做（改被点名的文件列出那条、改别的不列、不是仓库时无从比较，三次都以 0 退出），自检再起一遍是重复。

## 四、负片

`M-H196-a`–`m`，`req` 都是 `harness`，`by` 都是 `test`，各自只红 `kills` 点名的那几条（逐条手跑过）：文件名不止一份时也认（a）、不带扩展名的尾段也认（b）、名字两头连着路径字符也算（c、d）、只看条件那一行不看整张欠条（e）、围栏示例里的路径也算（f）、已关的照样列（g）、围栏里演示的状态行也算（h）、不认收尾（i）、不管改没改到就列（j）、汇总不说「只提醒、不判响没响」（k）、不说漏网情形（l）、入口只算已提交的改动（m）。
