## 一、和 ADR-86 的关系：这次做的不是它撤掉的那件

ADR-86 原先的设计就是「读这次改动的文件清单，找哪几条欠条点名了这些文件」，第三节把它撤了。撤的理由写得很清楚：不是做不准，是斜率 —— 「把欠条里的词解析成文件、再决定要不要提醒你」是一张要靠手写符号索引活着的路由表。

本条只做那件事里不需要索引的一小半：

- **认得的名字只有一种来源：受控文件的路径本身**（`git ls-files`）。完整路径都认；按 `/` 切出来的尾段里，只属于一个文件、又带扩展名的也认（`mutate.ts` 认成 `scripts/check/mutate.ts`）。`README.md` 这种不止一份的，只认完整路径。没有一张手写的表，加文件、删文件、改名都自动跟着走。
- **不解析代码标识符、需求编号、计划步骤。** ADR-86 第二节那三处实测（符号名不出现在自己的 diff 里、`ADR-70:351` 真响了而词一次没出现、条件是析取）照旧成立，本条不碰。
- **不判响没响，不拦合入。** 点了名不等于条件成立（「下一条碰 `mutate.ts` 判定或汇总那一段的 PR」，改别的段也会被列出来）；所以它是提醒，替代不了每条 PR 合入前对欠条的清点，只是让清点从一份短单子开始。

ADR-86 第四节那句「台账不判这次改动踩到了谁」说的是台账（`debt-rule.ts`），对台账照旧成立：本条没改台账，判定另放一个模块。

照 ADR-87 那把尺子（替代跑的建、替代读的不建）：它替代的不是「读条件、判响没响」，那一半照旧是读；它替的是读之前那一步「从几百条里找出跟这次改动有关的」，也就是 `process/README.md` 许的「抽出来、列清楚、指过去」。ADR-64 第 173 行当年提的「由检查链对着本次 diff 报你踩到了 N 条欠条」被 ADR-86、ADR-87 判掉，判掉的是「踩到了」这个判断；本条报的是「点了名」，汇总每次写明不判响没响。

## 二、认得到多少，认不到哪些

主干 `5f68c8b` 上：台账 627 条；已还／已重挂／收尾行（ADR-167 第四节第 1 小节的写法）指到其中 228 条，剩 399 条没有状态行（这里叫「开着」，其实含散文标过已还的，见下面多列那一条）；这 399 条里，欠条正文（条目在 `⚠️ 欠条` 块里时是整个块，否则是条目那一行）逐字写了至少一个受控文件的是 196 条。点名最多的几个文件：`scripts/test.ts`、`process/6-INTEGRATE.md` 各 23 条，`scripts/check/mutate.ts` 20 条，`scripts/check/selfcheck.ts` 14 条。

**漏网情形**（报告每次都说一句）：

- 欠条没写文件路径，只写了模块名、代码标识符、需求编号、计划步骤或「某类改动」—— 例如 ADR-180 第 32 行「下次改动给报告加展示字段时」。开着的 399 条里有 203 条是这样，这一半仍靠人读台账判。
- 只写了目录（`scripts/check/`）：目录不认，认了的话改目录里任何一个文件都列一串。
- 文件名不止一份时只写了裸文件名。
- 条件是析取，另一条腿不是文件（「或落地 4 开工」「或定期清点」）：文件那条腿认得到，另一条腿认不到。
- 「改到的文件」只算受控文件：没 `git add` 的新文件不算。
- 欠条写的是改名或删除之前的旧路径（例如 ADR-70 第 3027、3031、4249 行点的 `packet/lifecycle319/…`、`dist/cli.mjs`）：名字表从今天的受控文件来，旧路径已不在里面，除非这次改动恰好删的就是它。
- 路径前面带 `./` 或别的前缀、或写成通配（`*.md`）。
- 状态行指的行号不是一条台账条目时（`5f68c8b` 上有 2 行这样的），那张欠条照旧算开着、照旧列出 —— 多列一条读的人排除得掉，少列一条没人会发现（ADR-86 第六节「不判已还」那条的理由）。

**多列的一种：** 只用散文标过已还、没有状态行的，照旧当开着列出来 —— 本条 PR 自己就被列到 ADR-75 第 117 行、ADR-20 第 14 行、ADR-88 第 157 行、ADR-90 第 135、137 行这几张。ADR-167 第 108–111 行要在台账读状态行之前给这批补一行，补了之后它们自然不再列。

## 三、在哪看得到

- **PR 上**：CI 的 check 那一跑里「欠条点名提醒（只提醒）」那一步。汇总那一句打成一条 notice（没命中时也带一句「只认逐字写着的文件路径」，免得读成「这次没碰任何欠条」），PR 的 Checks 页和那一跑的总览页上都看得到；全文（每条欠条的文件、行号、点到的文件、截短的正文）写进那一跑的 Summary。检查红了也照跑。
- **本地**：`npm run debt-touch`。改到的文件与体量闸门同一个起点（分支上是与主干的共同祖先，主干上是上一版），量到工作区为止，所以提交前跑也算正改着的文件。
- 两处都**恒以 0 退出**；取不到改动清单（浅克隆、不是仓库、找不到主干）时说「无从比较」加原因。它不在 `npm run check` 里，CI 那一步另有 `continue-on-error` 兜底。

入口没进自检的工具表，写进了自检的 `EXEMPT`：它在玩具 git 仓库上的真起由需求测试组 `h-iou-file-reminder` 做（改被点名的文件列出那条、改别的不列、改名后旧路径照样列、在 CI 里写 notice 与 Summary、主干上只有根提交或不是仓库时无从比较，每次都以 0 退出），自检再起一遍是重复。

## 四、负片

`M-H196-a`–`u`，`req` 都是 `harness`，`by` 都是 `test`，各自只红 `kills` 点名的那几条（逐条手跑过）：文件名不止一份时也认（a）、不带扩展名的尾段也认（b）、名字两头连着路径字符也算（c、d）、只看条件那一行不看整张欠条（e）、围栏示例里的路径也算（f）、已关的照样列（g）、围栏里演示的状态行也算（h）、不认收尾（i）、不管改没改到就列（j）、汇总不说「只提醒、不判响没响」（k）、不说漏网情形（l）、入口只算已提交的改动（m）、块外条目不拿那一行找（n）、连字符不算路径字符（o）、只看名字第一次出现（p）、删掉的文件不认（q）、正文不截短（r）、CI 里不打 notice（s）、不写 Summary（t）、改名只记新路径（u）。

没配变异的：入口最外层兜底那一句（出了意外也以 0 退出、说无从比较）与 Summary 写不进那一句 —— 两处都要造出 git 或文件系统的意外才走得到，手跑核过行为，没有断言。
