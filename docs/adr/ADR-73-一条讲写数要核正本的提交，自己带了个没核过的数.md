### 第一轮的修本身是错的：我比的不是同口径

第一轮评审说那个 104「只写了 grep，没给命令」—— 对。我于是补了命令，
却顺手写下「**今天重跑同口径给的是 105**（命令见下）—— 用来举例「数错了」的那个数，
自己又是另一个对不上的数」（`01bf7b5` 逐字）。**那句话是假的。**

同口径量一遍 —— 同一条命令，只换树：

```
git -c core.quotePath=false grep -c '⚠️.*欠条' 090e0ee -- 'docs/adr/ADR-*.md' \
  | awk -F: '{s+=$NF} END{print s}'      → 104
```

**104 本来就是对的。** 我那个 105 是在一棵**已经装了本记录**的树上量的，
拿去跟主干上的 104 比 —— 换了树，却当成换了口径。#115 第二轮评审指出。

⚠️ **这条命令上面那个版本是错的，而且错法正是本记录的主题。** 头一版写的是
`git grep … -- 'docs/adr/ADR-*.md'`，**没有那个 `090e0ee`** —— 不钉树的 `git grep`
搜的是当前 checkout，产不出它旁边那个「→ 104」。
**一条主旨是「数旁边要带上产出它的命令」的记录，给的命令产不出那个数。**
（#115 第四轮评审指出。钉了树之后字段数从两段变三段，求和要从 `$2` 改成 `$NF`。
这里不写那次跑出来的具体值 —— 它同样是个没钉树的、会随 checkout 变的数，
第五轮评审指出。稳的那一点只有一句：不钉树就复现不出主干那个值。）

### 写下那条命令，把它要数的那个数加了一

上面**故意只给主干那个数**。注意那条命令**写死了 `090e0ee`** —— 在本分支上照原样跑它，
搜的仍然是主干那棵树，仍然得 104。会把**本记录自己**算进去的，是**换掉那个树参数**：
其余一字不动，取本 PR 早期几次提交为例（**抽样，不是全部** —— 本 PR 的提交数还会涨，
不在这里写它）：

```
090e0ee（主干，没有本记录）→ 104
666de45（本记录第一版）    → 105
01bf7b5（第一轮的修）      → 107
9ea2175（第二轮的修）      → 106
```

**换一棵树就换一个数** —— 而每一行都钉在不会再动的树上，值本身不会漂。
而漂的机制不是我头一版说的那个 —— 那句话也错了，第五轮评审指出：

**那个「→ 104」的输出行根本不匹配那个模式，所以改那个数不会改变计数。**
本文件里匹配上的是**前后那两条命令**（一条在上面，一条紧跟在下面），加上末尾那些欠条 ——
命令里必须原样写出它要找的东西，于是它自己就撞上了它自己。挑几次提交量本文件贡献的匹配行数
（**只列与这段论证有关的几次，不是全部**）：

```
for c in 666de45 01bf7b5 9ea2175 0004fbb f400a1b; do
  echo "$c $(git -c core.quotePath=false grep -c '⚠️.*欠条' $c -- 'docs/adr/ADR-73-*' \
            | awk -F: '{s+=$NF} END{print s+0}')"
done
→ 666de45 1 / 01bf7b5 3 / 9ea2175 2 / 0004fbb 2 / f400a1b 5
```

所以准确的说法是：**写下那条命令这件事本身，把它要数的那个数加了一。**
这比我原来那句更窄，也更锋利 —— 漂的不是「每改一次」，是「每增删一处匹配的文字」，
而写下命令正好是其中一处。

### 解释这件事的那两句话，自己也是它的实例

上面那段的**头一版**（`f400a1b`）说「本文件里真正匹配的只有两行」。**那也是假的：当时是五行。**
多出来的三行里有两行，正是我用来解释这件事的那两句 —— 它们**引用了那个模式**，
于是自己也被数了进去（#115 第六轮评审指出）。

**所以这一层的修法是结构性的：叙述里不再原样写出那个模式。** 和本文后面「不写指向本文
自己的行号」那一处是同一条路 —— 逐个更新数字永远追不上，**把会自指的那一类写法去掉，
回路才关得上**。改完之后剩下的匹配行都是**必须原样写出来的东西**（那两条命令、末尾的欠条），
不是叙述；**具体几行不写在这里** —— 末尾那张欠条的重启条件会招来下一条欠条 PR 往本文再追加
一块，那个数是本文自己安排着要漂的。

**靠不住的是没钉树的数，不是自指的数。**（上一段那条结构性修法，说的是**叙述里**那种既没钉树、
又随本文变化的自计数；钉死了树的数不在此列。）上面那张表自己就是反证：`666de45 → 105`
把本记录算了进去，可它钉在一棵不会再动的树上 —— 今天跑、明年跑都还是 105。
真正会漂的只有两种：**没钉树**（搜的是当前 checkout），或者钉了树、但**被搜的文字
还在变**（本节上一版正是这么错的）。所以要么钉一棵不会再动的树，要么只写命令、不写输出。

所以这一条要从「一个数错了」改写成两件事：

- **104 这个数没问题**，它缺的只是来源；来源补在上面。
- **它仍然不是「还欠着几条」** —— 这条口径把已还的块和只是**引用**别条欠条的块
  一起算了进去，只能证明「这么数是错的」，不能当余额。真正能数出余额的办法还没有。

更值得记的是这一层本身：**一条更正，可以自己就是下一个要更正的东西。**
本记录**每一版都被评审逐出过同形状的错** —— 第一版如此，其后每一轮的修也如此，连上面
用来解释自指的那两句话自己都是实例。**逐轮的条数不写在这里**：那是一棵还在动的树，抄进
记录就开始过期（正是本文自己立的规矩），正本是 #115 各轮评审正文里的 `Suppressed comments`
清单。我自己另找到一处没人提的：第一轮的修把一个表格行写成了**跨两个物理行**，markdown
表格会在那里断掉 —— 而这些的形状，跟本记录要记的那件事一模一样。

## 为什么已有的规矩没拦住

这一轮中途给自己定过一条：「记录里出现的每个**数**，旁边必须带上产出它的那条命令」。
它没拦住上面第四条和第五条 —— **「采纳还是驳回」看着不像一个数，「32 行之上」看着像个修饰语**。

规矩定在「数」上，漏掉的是**形状**。形状在上面那张表底下已经写过：**每一条都有一份正本躺在
够得着的地方，每一条都没去够。** 可这个形状当不了钩子 —— 落纸的判据得能一眼认出来。
所以钩子往窄里挂一层：凡是列举（清单、枚举、「A 还是 B」、「N 处／N 种／N 类」、
一个指向别处的行号），都是清单；凡是清单，就得回去数那份正本。
**这一层比形状窄**，抓不到表里第一行那种泛化断言；那一格靠的是下面那句 ——
判据落纸那一刻，先拿它量一遍这条记录自己。

## 教训

**一条讲判据的记录，最容易在自己身上破那条判据** —— 因为写它的时候，注意力全在被讲的那件事上。
所以判据落纸那一刻，要拿它先量一遍**这条记录自己**。

本条就是这么被逮到的：#114 合入后的清点拿「凡是列举就回去数正本」去量这一轮的产出，
第一个撞上的是写这条规矩的那条提交。
