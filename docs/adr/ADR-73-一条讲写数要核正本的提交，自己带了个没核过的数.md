## 难看的地方不在偏了 17 行

### 第一轮的修本身是错的：我比的不是同口径

第一轮评审说那个 104「只写了 grep，没给命令」—— 对。我于是补了命令，
却顺手写下「重跑同口径给的是 105，那个数自己也对不上」。**那句话是假的。**

同口径量一遍 —— 同一条命令，只换树：

```
git -c core.quotePath=false grep -c '⚠️.*欠条' 090e0ee -- 'docs/adr/ADR-*.md' \
  | awk -F: '{s+=$NF} END{print s}'      → 104
```

**104 本来就是对的。** 我那个 105 是在一棵**已经装了本记录**的树上量的，
拿去跟主干上的 104 比 —— 换了树，却当成换了口径。#115 第二轮评审指出。

⚠️ **这条命令上面那个版本是错的，而且错法正是本记录的主题。** 头一版写的是
`git grep … -- 'docs/adr/ADR-*.md'`，**没有那个 `090e0ee`** —— 不钉树的 `git grep`
搜的是当前 checkout，在本分支上跑出来是 109，跟它旁边那个「→ 104」对不上。
**一条主旨是「数旁边要带上产出它的命令」的记录，给的命令产不出那个数。**
（#115 第四轮评审指出。钉了树之后字段数从两段变三段，求和要从 `$2` 改成 `$NF`。）

### 自指的数不能写进文件

上面**故意只给主干那个数**。在本分支上跑同一条命令，得到的数把**本记录自己**也算了进去，
于是每改一次本文它就变一次。同一条命令钉在本 PR 各次提交上量：

```
090e0ee（主干，没有本记录）→ 104
666de45（本记录第一版）    → 105
01bf7b5（第一轮的修）      → 107
9ea2175（第二轮的修）      → 106
```

**三次编辑，三个数**，而每一次编辑改的都是这一节自己。（头一版这里直接写着「107、106」
却没说是在哪棵树上量的 —— #115 第三轮评审指出，已钉上提交。那一轮顺带把当前树
估成了 105，实测是 106：本记录在 `9ea2175` 上占 2 行，不是 1 行。）

**一个把自己也算进去的数，写进那份文件就永远对不了。** 要么钉在一个不含它的树上量
（像上面那样写明 `090e0ee`），要么只写命令、不写输出。

所以这一条要从「一个数错了」改写成两件事：

- **104 这个数没问题**，它缺的只是来源；来源补在上面。
- **它仍然不是「还欠着几条」** —— 这条口径把已还的块和只是**引用**别条欠条的块
  一起算了进去，只能证明「这么数是错的」，不能当余额。真正能数出余额的办法还没有。

更值得记的是这一层本身：**一条更正，可以自己就是下一个要更正的东西。**
本记录第一版被评审逐出五条（#115 第一轮汇总里 `Suppressed comments (5)`），
第一轮的修又被逐出两条（第二轮 `Suppressed comments (2)`），我自己还另找到一处
（第一轮修把一个表格行写成了跨两个物理行，markdown 表格会在那里断掉）——
而这些的形状，跟本记录要记的那件事一模一样。

### 这一条最值得记：我自己把我引的东西挪了位置

`adr-rule.ts:49-51` 这个指针，写下来那一刻是对的：

```
for r in 5174a47 985ab2b c30e9fd b0d533d 3f52fda 090e0ee; do
  echo "$r $(git show $r:scripts/check/adr-rule.ts | grep -n 'export const slugify' | cut -d: -f1)"
done
→ 5174a47 46 / 985ab2b 49 / c30e9fd 49 / b0d533d 49 / 3f52fda 50 / 090e0ee 50
```

`985ab2b` 上它在 49，我照着写了「49-51」。**`3f52fda` 是我自己在同一条 PR 的第二轮**
**往文件头上那段注释里加了一行，把它推到了 50** —— 然后此后整轮都在复述 49-51，
一次没回头核。

这正是 `ADR-69:113` 那条：「**判据该落在那句话上** —— 拿「撞车／抢号／静默交错」扫全仓，
而不是落在那几个行号上」。

（头一版把它同时记在 ADR-64 名下 —— 那句话不在 ADR-64 里。**原始出处只有 `ADR-69:113`**；
说「全仓只有那一处」在写下它的那一刻就已经不成立了，因为本记录上面第 118 行也复述了它
—— 又一次自指（#115 第三轮指出挂错，第四轮指出这句「全仓只有」也站不住）。
一条讲「引用要核」的记录，自己把引文挂错了记录。）
行号会漂，而**推它漂的人往往就是引用它的那个人**，于是没有任何一刻会觉得「该重核了」。

## 为什么已有的规矩没拦住

这一轮中途给自己定过一条：「记录里出现的每个**数**，旁边必须带上产出它的那条命令」。
它没拦住上面第四条和第五条 —— **「采纳还是驳回」看着不像一个数，「32 行之上」看着像个修饰语**。

规矩定在「数」上，漏掉的是**形状**：凡是列举（清单、枚举、「A 还是 B」、「N 处／N 种／N 类」、
一个指向别处的行号），都是清单；凡是清单，就得回去数那份正本。

## 教训

**一条讲判据的记录，最容易在自己身上破那条判据** —— 因为写它的时候，注意力全在被讲的那件事上。
所以判据落纸那一刻，要拿它先量一遍**这条记录自己**。

本条就是这么被逮到的：#114 合入后的清点拿「凡是列举就回去数正本」去量这一轮的产出，
第一个撞上的是写这条规矩的那条提交。
