## 一、为什么改

ADR-210 管的是「信里写博主的话」，机器先得认出哪句在写博主。认法只能看字面：句子里有没有 you、your，有没有他的名字，是不是问候。这是猜，而且猜不完：用 he、she 指他的、省略主语的描述句（「Clearly the most honest fitness creator around.」）、两个字母的名字都认不出；普通词会被当成名字误列。ADR-210 第四节第 1 条已经写明这些是漏的。需求所有者要的是不靠猜的检查（2026-11-16：「猜太可笑了」）。

换一个问法就不用猜：**每一句都登记来处，机器只看信里有没有字没被登记盖住。** 这是确定的问题；哪句在写博主不用机器判断，由登记的来处说明。

## 二、决定

1. **每一句都登记，来处只认三种。** 博主自己的资料（`bio` 简介、`post` 作品文案、`nickname` 昵称）、任务里已证实的产品事实（`product`，即 `brand_calibration` 里 `kind=verified_product_fact` 的条目原文）、发件人自己的话（`self`：问候、提议、感受、约时间、联系方式、落款）。主题行、问候、落款也要登记。
2. **列不列只看有没有字没被盖住。** 覆盖照 ADR-210 第四节第 3 条按整封信的字算，每条登记在信里出现的每一处都算；信里有字（只剩空白与标点的不算，剩表情、符号、占位符的算）没被任何登记盖住，它所在的那一行就列出。ADR-210 里认 you、认名字、认问候的整套口径删掉。报告按行分组，不切句（第九节）。
3. **产品事实怎么对。** 登记成 `product` 的 `quote` 要在任一条已证实产品事实原文里逐字出现（比对前的统一写法同博主资料）；任务里一条都没有时一律「原文对不上：任务里已证实的产品事实没有这段」。品牌偏好不算。数字与承诺词照旧由 P2.c 兜底，两边各管各的：`product` 登记对得上，不等于这句里的数字也对得上。
4. **那一行改名「逐行出处」**（2026-11-18 由「逐句出处」改，第九节），三段照旧（要看、对得上、发件人自己的话），「发件人自己的话」那一段的提示改成「确认没有借它给博主安新说法，也没有夹带产品说法」。
5. **字段改名。** 评审正本里的 `creator_sources` 改叫 `draft_sources`，模块 `creator-sources.ts` 改叫 `draft-sources.ts`：它现在管整封信，旧名字会让读的人以为只管写博主的话。旧字段 ADR-210 合入（2026-11-17）到本条之间只有一天；万一真实任务里存着旧名字，评审这一层不拒不认得的键，读不到登记，那封信每句都会被列成「没登记出处」—— 看得见，不会悄悄漏。

## 三、登记成发件人自己的话里的数字

1. **移到哪。** 一条说法整段落在登记成 `self` 的字里（登记在信里出现的任一处都算，按字算，空白不计），而且是下面「能移的」那几类，就不列在「出处对不上」，另起一行「只在发件人自己的话里：…（确认是约时间、联系方式这类，不是产品说法）」。不是放过：人照样看得到，只是不和产品说法混在一起。
2. **能移的，只列这三类**：日期（`11/20/2026`、`Nov 20`）、钟点（`3:30pm`、`3pm EST`）、电话这类连着的至少九位数字（`415 555 0199`）。需求所有者 11-16 的原话是「约时间、电话」，就照这三类。这三类的写法后面紧跟单位的（`10/20/30 oz`、`1:30 hours`）是规格或时长，不挪（CodeRabbit 首轮指出）。按「能移的」列，不按「不能移的」列：清单外的种类，包括以后 P2.c 新加的种类，默认都留在「出处对不上」。
3. **所以登记成自己的话也照列在「出处对不上」的**：带不带单位的普通数字（`15-minute`、`12 blades`、`5000mAh`、`2x`、`29.99`）、价钱、百分比、承诺词（保修、退款、包邮……）、认证那一整句、数量写法（half off、double……）、型号串（IPX7）、尺寸串（`1920x1080`）。这几类是编造产品信息最常见、代价最大的，一句登记不能让它们离开那一行。
4. **按位置，不按写法。** 同一个 `415 555 0199` 一处落在登记成自己的话里、另一处没登记，没登记的那一处照列在「出处对不上」。半个日期被登记盖住（登记停在 `11/20` 上）不算落在里面。
5. **只认 `self`。** 登记成博主资料或产品事实的句子里的数字照旧由 P2.c 判。
6. **同时够两行时归这一行。** 一条日期、钟点或电话既够「只在发件人自己的话里」、又在博主作品文字里找得到，只列在「只在发件人自己的话里」，不再列进「只在博主作品里有」；不够格挪到这一行的（没落在 `self` 登记里、或后面紧跟单位），仍照 P2.c 原口径判，作品文字里有就进「只在博主作品里有」。
7. **单位可以跨行读（待需求所有者在卡上定）。** 日期、钟点、电话后面的单位和普通数字一样，下一行开头的字也算：换行写的 `1:30` / `hours` 照列在「出处对不上」。代价是行末的约时间后面紧跟落款（`3pm EST` 换行 `Best,`）时，落款的 Best 被当成单位，那条时间也留在「出处对不上」—— 多列一条，运营看得出；写信说明要求约时间那句以句号或问号收尾。不列「哪些词是落款」的词表：那是猜（第三轮驳回 `3pm tomorrow` 时同一理由）。CodeRabbit 第五轮挑「落款被当成单位」、第六轮挑「只读到行尾漏了换行写的单位」，同一处连着两轮，照规矩改设计、请需求所有者定。提示里的前后文只取这一行，行的认法与逐行出处一致。

为什么按登记、不按长相：需求所有者 2026-11-16 的卡上写着，之前四轮审查都发现按长相遮会误遮真的产品规格和价格。登记是 Agent 写下的明确说法，按位置移，不猜。

## 四、实现者替需求所有者选的默认

合入即认；想改，合入前说一句即可。

1. **能移的几类按 P2.c 已有的分类划，不另做判断，只取日期、钟点、电话三类。** 初版连普通数字也移，独立复核指出这样 `40-hour`、`5000mAh`、`12 blades`、`2x` 这类产品规格登记成自己的话就离开「出处对不上」，挡下了；改成只移需求所有者点名的约时间、电话。代价：信里约「15-minute chat」「a 2-week trial」这类自己的安排照列在「出处对不上」，运营多看一眼。重启条件：真实草稿里这类约定数字多到运营反映看不过来。
2. **没写年份的斜杠日期不认作日期。** `11/20` 也可能是 `9/10` 这样的评分，按 P2.c 原口径当两个数，登记成自己的话也照列；写信说明里让 Agent 写成 `Nov 20` 或带年份。没分钟的整点要带 am、pm 才认作钟点（`3pm`、`3 p.m. EST`）：这是本条给 P2.c 的钟点写法补的一种，`£10 pm` 这类币符后面的照旧不认。重启条件：真实草稿里因此多列的约时间被运营反映。
3. **比对前的统一写法改成逐字做。** ADR-210 是整串一次 NFKC 再整串转小写；现在一个字一个字地做（字母、数字、符号连同它后面的附加符号算一个字，见第九节第 3 条），这样能把「哪些字被登记盖住」换回草稿原文的位置交给数字扫描。两边（草稿、登记、原文）走同一个函数，口径一致；和整串做的差别只在韩文拆开的字母、希腊文词尾 sigma 这类，偏安全（对不上就列出来）。
4. **只有标点、破折号的一段不要求登记。** 只剩空白与标点的不算没登记的字；表情、符号、`{…}` 占位符算，要登记。`%`、`#`、`&`、`@`、`/` 单独剩下也算标点，带它们的数字照旧由 P2.c 列出。编号列表的 `1.`、`2)` 是字，要连同那一行一起登记，写信说明里写明。
5. **「要看」那一段空着时这一行以「要看：无」开头**，运营不用从「对得上：」开头推断没问题。全登记的干净信这一行仍会把整封信并排原文重印一遍，长；先这样，重启条件：运营反映干净信那一行太长看不过来。

## 五、按改需求逐条评定

- 红线：P2 收紧 —— 从「提到博主的句子要登记」扩到「每一句要登记」。P2.c 的扫描口径只多认一种钟点（没有分钟、带 am/pm 的整点，如 `3pm`、`3 p.m. EST`；币符或币种后隔一个空白的归价格），另外把登记成自己的话里的几类数字挪到另一行，挪的条件是 Agent 明确的登记，挪出去的照样印在报告里；价钱、承诺词这几类不挪。P1、P3、P4、P5 不碰。
- 缩范围还是降标准：P2.c 那一行列的东西变少了，但只是挪到相邻的另一行、条件确定；不是降标准。P2.f 删掉认「提到博主」的口径，换成更严的「每句都要登记」。
- 覆盖还是可信：可信上升 —— 删掉一套会漏的猜测规则，换成确定的覆盖检查。
- 可逆：可逆。正本字段可选，HTML 多一行、改一行的名字，不改表格、不改退出码。

## 九、按行对账，不切句

需求所有者 2026-11-18 在卡上选「改成按行对账」。

1. **为什么。** 报告原先把信切成句子再一句一句列。切句要猜句子边界：缩写（Dr.、a.m.）、收尾引号、列表编号 `1.`、句号后不带空格、只认 `\n` 不认别的换行写法……CodeRabbit 连着三轮在切句上挑出新的漏洞，每轮补一条规则又引出下一条。这和需求所有者定的规矩冲突：同一处连着两轮被挑就改设计，不靠猜（「猜太可笑了」）。换行是信里写死的，不用猜。
2. **怎么分行。** 回车换行、回车、换行、U+2028、U+2029 都算换行；只有空白的行不列；第一个非空行以 `Subject:` 开头时去掉这个标签再核，标签本身不用登记（同 U13.a），后面的行以 `Subject:` 开头照正文核，标签也要登记。
3. **列不列不变。** 覆盖照旧按整封信的字算（第二节第 2 条），登记跨不跨行都一样；一行里有字没被盖住，整行印在「要看」里，盖住一部分的列出没登记的部分（要不要列按统一写法后的字判，全角花括号 `｛…｝` 也算占位符；印的是草稿原文的写法）。附加符号只跟在字母、数字、符号后面并成一个字（合字只发生在这几类上）；跟在空白、标点、换行后面或打头的附加符号自成一个字，所以紧跟换行或「Subject:」字样的附加符号也要登记。列表编号 `1.` 是字，要登记。
4. **同一行出现几处就列几处。** 原先「同一句只列一次」的去重删掉：去重又要再加「前一处登记了、后一处没盖住」的例外，按行一处一处列就不用。
5. **代价。** 一行里写了好几句时整行印出，比按句长；写信说明照旧要求一项登记一整句、两种来处别混在一句里，报告只是按行把没盖住的字指出来。重启条件：运营反映一行太长、看不出是哪一句没登记。

## 十、表格文件那条检查逐张表全等比对

「真起 render 之后 XLSX 里没有出处列」这条测试连着两轮被 CodeRabbit 挑出毛病（第四轮：只看了第一张表；第五轮：表清单改从关系表读之后，仍是把几张表的字拼起来找词，某一张缺了关系或读不出表头时，别的表里的词会顶替它）。照「同一处连着两轮被挑就改设计」，不再一条条补。需求所有者 2026-11-18 在卡上选「就在这条 PR 里改」。

1. **新做法。** 不在拼起来的字里找词，改成对整份工作簿做全等比对：按工作簿自己的表清单（表名和关系号）逐张找到那张表的文件，读它第一行的表头；期望是三层各一张（空层也有，名字里带人数），每张的表头和 kol.csv 的表头逐格相同，而 kol.csv 的表头另外断言了有草稿列、没有出处列。任一张缺、关系对不上、读不出表头，结果都与期望不等。
2. **为什么不引第三方读表库。** 本仓库的开发依赖里没有读表格文件的库；工作簿是本仓库自己的写出器写的、结构固定，逐张全等比对已经能给出确切答案，不用再加一个依赖。重启条件：写出器改用共享字符串表或别的结构，这条比对读不出表头。
3. **守着它的变异。** M-P2-s72（只有 B 层多一列出处列）、M-P2-s73（第二张表的关系指到不存在的文件），两条在旧做法下都不会红。
