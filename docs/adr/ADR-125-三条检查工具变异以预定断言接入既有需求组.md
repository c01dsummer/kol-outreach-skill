# ADR-125 三条检查工具变异以预定断言接入既有需求组

- 日期：2026-09-28
- 类型：发现更优解
- 起点：main `5cd18a090c680c11df2b240fedb2d68d343d8d8e`，PR225 已合入；变异集合保留。
- 结论：只迁移 M-H9-u、M-H23-h、M-H40-g，复用既有需求组；先公开属性与边界，再提交断言和路由。
- 依据：`process/README.md` 的三态总纲、`process/4-VERIFY.md` 的断言来源与选组资格、
  `process/6-INTEGRATE.md` 的可比证据；具体基线、进程及认领边界沿 `docs/ARCHITECTURE.md`。

## 对应关系与本次范围

| 变异 | 公开合同与应失败属性 | 预先确定的固定断言 | 既有组 |
|---|---|---|---|
| M-H9-u | 合法非浅历史仍无法取得共同祖先时，不能将无法判断压成不适用 | 起点第 4 步：merge-base 答不上来（HEAD 与主干没有共同祖先）→ 无从判断 | h-check-rules |
| M-H23-h | 文件级真实豁免来源调用在普通函数体内仍存在；文本字样不能作语法调用 | 函数体中的真实豁免来源调用必须被识别 | h-mutate |
| M-H40-g | 全部验证者组先于坏标识诊断，诊断先于最终目录删除；不能漏组或以空计划通过 | 硬停止计划先列全部验证者组再列诊断最后清理目录 | h-jobs |

H9 复用原有固定断言。H23 的合法自造源文本包含函数体内真实调用，期望来自公开 presence 合同；
H40 使用两个合法组标识夹着一个现存坏标识的纯输入，独立核目标存在、数量及偏序。
两条新断言的属性、自然输入及 expected 在独立上下文先冻结，之后才接入并运行；
该作者未读目标函数体、旧断言或施变正文，披露了公开文档的历史描述暴露，不声称零污染。
保留全部旧断言和控制，不从偶然红的输出选择名字或改 expected。

三个组的声明、依赖和执行顺序不变；实际路由由 kills 的静态归组推导，不手写 only。
每次检查同一正常配置先完整成功一次再施变；既有隔离 worker、具名归因及全量认领保护继续生效。
这三条均由独立需求测试验证，不改成自身 selfcheck；基础设施隔离限制不变。

## 声明边界与仍全跑的候选

H9 只证明公开 Git adapter 判定，不声称真实浅克隆或 size 入口已经另验。
H23 只证明语法调用 presence，不声称报告实际打印正确；H40 只证明纯计划，
不以它替代真实硬停止、目录回收或完整进程树证据。fixture adapter 遇到未声明路径直接抛错，不能代领目标红。

M-H9-p 继续全跑：预定浅克隆断言在施变后仍绿，其他断言红不能替代；不回填目标。
业务候选、动态名字、实际页面交互及其它检查工具分别核证后再迁移，本次不混入。
正常代码绿、预定名字确实红及无其它故障的证据都成立后才接入；失败和未完成尝试保留为失败。
