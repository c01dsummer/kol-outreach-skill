# ADR-106 搜索任务展示保留原列表身份

- 日期：2026-09-23
- 类型：需求有歧义（补充）与事实证伪
- 冲击的需求：U8；保留 U3、P5.i、D6、F9 的既有语义
- 结论：采纳
- 理由：同词同平台可有不同维度或完全重复的任务，原下标已用于断点与归人数；展示却丢掉这个身份。当前 TikHub 搜索实现不读取 as_hashtag，自动加 # 或 (hashtag) 不能证明实际执行了话题搜索。
- 连带改动：需求登记表与 SPEC、架构、任务标签与关键词输出、试探/采集入口、输出与策略参考文档、独立测试及负片。

## 契约与范围

机器结果使用原 tasks 数组零起始下标 task_index；人读序号为下标加一。
标签格式为「任务 3 · scenario · instagram · 关键词「selfcare」」，原关键词原样展示。
同一目录的任务列表不重排；本次不增加迁移或跨目录身份。过滤仅决定哪些项被展示，
不重新赋予身份。已有 done、offsets、source_tasks 及关键词归人数算法不改。

meta.json 的关键词行与 probe 的成功/普通错误结果各带 task_index。预算中止原来不建的
结果行仍不建；不增加请求或改变退出码。HTML 在关键词表加任务序号列，使用行上的身份，
不拿行位置代替。有效下标限定为非负安全整数且加一仍为安全整数；缺失、null、负数、小数、
字符串和超界数都显示「无从确认」，不抹掉该行已有查询状态与真实计数。

as_hashtag 继续作为既有配置元数据保留，不切换端点；展示不根据它加 # 或路径承诺。
关键词本身带 # 时原样显示。记录每位创作者实际发现路径是另一项独立工作，本次不制造该记录。

## 结构与证据

新增 lib/task-label.ts 只负责显式下标到可读序号与标签；入口、管线与 HTML 依赖它，
它只依赖类型，不能反向依赖管线或发请求。列表筛选之前保留原下标。

测试先依据 U8 与对外契约在未修实现上看到具体错值，再改实现；检查逐行身份、筛选后身份、
旧行未知、原关键词以及入口输出。各项可独立破坏，入口认领配入口负片。
原有提示文本断言需要同步新标签时，只改格式期望，保留它们原来验证的筛选集合与成本含义；
这是新增 U8 明定的展示契约，不以变绿为理由降低旧断言。

本次不连接翻页、不改媒体绩效口径、不修生产预算计价，也不改变名单成员、得分或请求次序。

## 设计复核澄清（实现前）

U8.b 中的续跑身份约束落在关键词标签列表，成本提示仍只消费其长度，不增加列举输出。
原“续跑提示只列”的措辞会多承诺一项输出，已在实现前澄清；既有判定集合不变。

## 独立测试与实现核对

测试上下文只读需求、类型、对外文档与测试脚手架，没有读取产品实现或变异原文。
未修实现上，需求测试完整结束并出现 17 项断言失败；更正后的 probe 假网夹具有 4 项
具体身份断言失败，collect 完成、meta 和两种页数上限提示也已先见红。probe 首版夹具
把 402 放在中间，却期望执行后续任务；按既有 402 终止契约将错误任务移到末尾，
没有修改产品终止行为。最终红证据来自更正后的夹具。

实现后需求测试、类型检查、相关五组入口自检通过；完整检查另由提交后的检查记录证明。

其旧理由曾把配置标记说成实际话题路径，本次改正理由，不删除原负片。
