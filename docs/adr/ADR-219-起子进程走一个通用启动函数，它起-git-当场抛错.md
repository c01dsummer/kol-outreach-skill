- 日期 · 2026-11-18
- 类型：检查（运行时拒绝）加挪文件，是「调 git 只走一个入口」的第二片

- 结论：采纳。人批痕迹：需求所有者合入本条那条 PR
- 理由：「禁用接口」的另一半 —— 口外不许直接碰，口里要有个能用的口。真要起进程的那一刻，程序名是确切的值，判它是不是 git 不用猜；经 shell 起时起什么要读懂命令串，所以干脆不让经 shell。写法只认一种、别的当场报错，不替调用方改写：改写就得照 Node 每个函数各自怎么分参数去模仿，前一版这样做，评审连着两轮挑出模仿不全的地方（独立评审一轮、自动评审两轮都挑在同一处），按「同一处反复出问题就改设计」改成了报错

## 一、要用到的事实，各找谁要（`process/3-BUILD.md` 第 8 条）

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 这一次要起的是不是 git | 调用时传进来的程序名，取路径末段（`/` 与 `\` 都切），是 `git` 或 `git.exe` | 机器（真值，闭集） |
| 这一次经不经 shell | 选项里的 `shell` 是不是真值（Node 自己也照真值判）；是就当场抛错 | 机器（真值） |
| 参数是哪种形状 | 不认别的形状，只看是不是那一种：第二个位置是数组、第三个位置没有或是对象、没有第四个；不是就当场抛错。程序名不是字符串的原样交给 Node，由它报参数类型错 | 机器（真值） |
| 计数预加载、观察器预加载还拦不拦得到 | 通用启动函数在调用时才从模块对象上取函数，预加载换掉的就是这个对象上的函数；启动数摘要逐配置比对，经它起的进程照样记数 | 机器 |
| 一个文件挪干净了没有 | ADR-217 的闸门：文件里不再写出模块名，「待挪」里那一行就得删 | 机器 |

## 二、通用启动函数做什么

包 `spawn`、`spawnSync`、`execFileSync` 三个，只认（程序, 参数数组, 选项?）一种写法。下面几种当场抛错、不起进程，过了的参数原样交给 Node，一个字不改：

1. 程序名末段是 `git`、`git.exe`：当场抛错，不起进程。认法与启动数计数不算 git 的那一句是同一个函数（`launch-count.ts` 的 `isGitProgram`），不另写一份。
2. 选项里的 `shell` 是真值（写 `true` 或写一个 shell 的路径）。
3. 写法不是那一种：参数数组省了（没有参数就写 `[]`）、选项挪到第二个位置、参数数组的位置写空值、选项不是对象、多出第四个参数。挪过来的 10 个文件本来就是这种写法。
4. 子进程对象等几个类型从这里再导出，挪过来的文件不用为了类型再去碰那个模块。

`exec`、`execSync` 只能经 shell，`fork`、`execFile` 这批文件用不到，都不包；要用时再加，加的时候照样拦 git、不许经 shell。

## 三、这一片挪了哪些

「待挪」里自己的进程不起 git 的 10 个：CI 墙钟两份、预编译三份、实际路径、懒加载 TypeScript、记忆复核、工人输出清理与守护的契约测试。它们原来只用 `spawn`、`spawnSync`，导入改指通用启动函数就挪完了。几份文件里写在字符串里的模块名（运行时落成文件再跑的代码）不是「模块名这个字面量」，闸门不记。

没挪、留在「待挪」的 17 个：

- 15 个自己直接起 git，等 git 入口那一片。
- 观察器运行器（`observer-run.ts`）自己不起 git，但它是零请求观察器认证过的设施文件，SHA256 记在 ADR-186「第二片」那张表里，改一个字节认证就失效（ADR-204 撤回过同一种改动）。它跟认证一起挪：挪的那条改动同时把通用启动函数加进设施文件清单、在干净克隆里重跑冻结认证。
- 工人输出契约测试（`worker-output-contract-test.ts`）自己只起 `ps`、`lsof`、`node`，但文件里另有两处被闸门记成「进程内部的口」（回执对象的 `binding` 字段那一类，ADR-217 第二节），只改导入删不掉这一行，等给字段改名时一起挪。

## 四、拦不住的

- 还在「待挪」里的 17 个文件直接碰模块，不经通用启动函数，它们起 git 这里管不到。
- 「登记」里的文件直接碰模块，不经通用启动函数（计数与观察器两份预加载、预编译父进程、闸门判定），靠评审读理由。
- 写在字符串里、运行时落成文件再跑的代码：它自己导入模块起进程，闸门不记（ADR-217 第三节），通用启动函数也拦不到。已挪的 CI 墙钟契约测试里，冻结的运行器每跑一次都这样起 git；这一类在「待挪」清空以后照样存在。
- 经别的程序转一手：起 `sh`、`env`、`npx`、`bwrap` 再由它起 git。通用启动函数只看本进程直接起的那个程序；列一张「会转手的程序」名单是替代读的手写表，不建。
- ADR-217 第三节说的软链或改了名的 git、`git-upload-pack` 这类 git 自带程序、大小写不敏感文件系统上写成 `GIT`：只看名字，认不出。Windows 上还有几种同类的：`C:git.exe`（盘符后不带斜杠）、`git.EXE`、`git.cmd`、末尾多一个点或空格的 `git.`；本仓库不在 Windows 上跑，不另认。
- 选项里的 `shell` 写成一个每读一次给不同值的取值函数（或代理对象）：这里读到假值放行，Node 再读时读到真值，就经了 shell。要堵得把选项抄一份再交给 Node，那就不是「原样」了；没有调用方这样写，不堵。
- 类型照 Node 的签名写：省掉参数数组、选项挪到第二个位置的写法编译时不报，跑到那一句才抛。挪过来的 10 个文件都是那一种写法；以后挪的文件，没跑到的分支要靠评审看写法。

## 五、它替代什么、什么时候撤

**替代的是「跑」**（`process/README.md` 第二层「一道闸门该不该建」）：判的是调用时的真值，`git` 与 `git.exe` 是闭集，没有一张会随仓库变旧的名单。

> **什么条件下撤**：没有机器看得见的撤法 —— 这一句抛错只在写代码的人本机跑的时候出现，改掉就不留痕迹，数不出「多久没抛过」。所以不按次数撤，由人判：git 入口建成、「待挪」清空以后，需求所有者读一遍第四节，看拦 git 的活是不是已经全由「只有 git 入口碰得到」接住；接住了才删这一句，没接住（比如第四节第三条那类夹具还在）就留着。
