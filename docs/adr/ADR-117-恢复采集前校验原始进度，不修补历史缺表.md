# ADR-117 恢复采集前校验原始进度，不修补历史缺表

- 日期 · 2026-09-25 · 处理 ADR-115 第五节登记的断点字段缺陷
- 类型：既有缺陷；不改变任务、费用或分页的正常语义
- 冲击的需求：新增 D19；D6、D13、D14、D16、D17 与 P1/P3 原有承诺不变
- 结论：采集恢复先验校验 `done` 与四张进度表，坏输入退出 2，修正原文件后才可续跑

`TaskState` 的静态类型不约束从 `task.json` 读入的值。以前只验配置与任务列表：`done:null`
可能在进度行才抛，其他坏表可能到分页或保存时才抛；带 `--budget` 时还可能先写入新上限。
这会把输入错误报成运行错误，并改变一份无法继续的断点。纯判定先于预算构造和第一次进度读取，
以有效任务列表的长度解释下标；任务列表本身坏时沿用 D16 的拒绝，不从坏列表推算范围。

`done` 是必备的完成任务索引数组，元素原始 JSON 数字精确等于不重复的非负安全整数且小于任务数。
`offsets`、`answered`、`found`、`pages` 可以整表缺席；缺表是历史未知，不能补成 `{}`。
存在的表必须是非数组对象，键只收 `0` 或没有前导零的十进制正整数，且在任务范围内。
值的原始 JSON 数字须精确等于非负安全整数，仅 `found` 的单项允许 `null`，表示已经无法得到完整累计条数。
数值可写作 `1.0`、`1e0`，但不把 `0.99999999999999999` 舍入成 1，或把 `1e-325` 下溢成 0 后放行；
超大指数也按原 token 判定。原文通过 `JSON.parse` 的 source context 读取，费用数字的精确保留机制不变。
不设 `pages <= 4`：过去某次运行可以在不同规则下已抓更多页；也不以其他表或 `done`
推算缺失值。额外跨表一致性没有可靠证据，本次不加。

纯函数返回各字段问题，不修改输入。collect 对已有任务在原值配置、任务列表、路线校验之后调用，
进度行、改额、任何保存与费用预留、请求都在其后。坏输入向 stderr 给出 `task.json` 路径与全部
进度字段问题，非法数字展示原 token（包括溢出后的 `1e400`），以退出码 2 结束；
任务文件原字节保留，用户修正断点后再重试。
这一边界不意味着脚本能修复损坏断点，也不推断已经付费但未保存的业务进度。

单元反例覆盖非法值、重复、越界、键格式、缺表和历史页数；假网络进程分别覆盖普通恢复与改额恢复，
观测预算预留方法和 HTTP 尝试并比对任务文件字节。所有测试在本地假网络运行，不向供应商发请求，
不在仓库提交运行原件。
