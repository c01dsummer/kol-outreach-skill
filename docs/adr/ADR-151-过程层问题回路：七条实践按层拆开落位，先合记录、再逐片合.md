1. **P1、P2、P6、P7 不是闸门**，按 ADR-85 不设死亡条件：永不判红，只报数或只递原料。P1 的撤除：`process/6-INTEGRATE.md`「改验证成本时」的「前后实跑」义务被删时，同一条改动删掉 `check.yml` 那一步。
2. 例程永不改 `process/`、`scripts/`、`docs/requirements.json`、`.github/workflows/check.yml`；不写「采纳」、不标欠条已还、不判死亡条件（ADR-80、ADR-86）。
3. 没有一条按秒数判红（P3 判的是启动次数）。
4. P4 / P5 共用两条，八周从第 7 片合入那天 2026-10-15 起算，最早 2026-12-10 才判得了。第一条只认改到块标题那一行的提交（10-16 选「改」：往台账追加欠条块、补填人判都不算例程还在）；`git log -G` 恒按扩展正则，`{4}` 不转义：

> **什么条件下整个撤掉（P4 / P5）**：非浅克隆下 `git log --since=8.weeks -G '^## [0-9]{4}-[0-9]{2}-[0-9]{2} · 本跑 ' -- 'docs/adr/ADR-*-回访台账*.md'` 为空 —— 例程停了。

> **什么条件下停候选表、只留心跳行**：八周内台账里没有一块写着「上周结果：已合入」。

5. P3 的死亡条件在 ADR-145。
6. 这套东西不看缺口数降没降，看三个数：（一）台账里 `已合入` 的块数（ADR-152 第三节那条 grep）；（二）「同类」行条数、「同类第 N 次」欠条条数、另一种晚到的同类欠条条数，任一个动都算动；（三）「process/ 里没有这句通用话」欠条的已还条数。八周从第 11 片合入那天 2026-10-17 起算。ADR-154 的已还块头故意是另一种形状，不进第三个数。命令只放围栏里（写进 `>` 块会被「同类」的 grep 认到）：

```
grep -h '^- 同类：' docs/adr/ADR-*.md | wc -l
grep -hE '^>.*欠条(「.*」)?：同类第' docs/adr/ADR-*.md | wc -l
grep -hE '^>.*欠条(「.*」)?：同类（' docs/adr/ADR-*.md | wc -l
grep -hE '^> ⚠️ 上文那张「process/ 里没有这句通用话」欠条已还：' docs/adr/ADR-*.md | wc -l
```

> **什么条件下整个撤掉**：上面三个数八周都不动。

## 七、墙钟对比那一行（P1）

`check.yml` 检查链之后一步「墙钟对比（只报数）」，打一行到 notice 与 step summary：`本跑 X:XX · 主干前 5 次中位 Y:YY · ×1.NN · CPU：<型号> · 变异 <N> 条（<±d>） · 摊到每条 <X> 秒`。

- 时长 = 开跑到最后更新；只取主干上 push 触发、成功的 check 跑；「前」= 创建早于本跑、这时已跑完的最近 5 次，第 3 个是中位。拆 job 以后（ADR-197）「本跑」是整个 run 的墙钟，型号是这一步那台机器的
- 型号取 `lscpu` 的 `Model name`，只留 ASCII 字母数字、空格与 `()@.,_+/-`，截到 80 字；N 是本提交 `mutations.json` 的变异条数，±d 比对照提交（PR 上是合并提交的第一个父提交，推主干时是推送前的主干头）；X = 本跑秒数 ÷ N，是整跑摊到每条。三样只报，不判哪一样让这一跑慢
- 永不红：检查红了不跑，每条路只打一行、以 0 退出，`continue-on-error` 与两分钟上限兜底；取不到打「墙钟：无从比较（原因）」或各段「读不到」
- 只在 Checks 页与摘要页，不进 PR 对话页：10-14 定了保持只读、不为它加写权限，合并前点 Details 看
- 2026-10-25 起需求测试有 `h-ci-wallclock-*` 几组，从 YAML 原样抽出这一步对假接口跑（#384，ADR-158 第十九、二十节）
