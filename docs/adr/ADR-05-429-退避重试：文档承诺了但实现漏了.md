# ADR-05 429 退避重试：文档承诺了但实现漏了

- 2026-08-25 · 脚本自检首次跑通时
- 类型：**事实证伪**
- 触发它的事实：假 fetch 在第 7 次调用注入 429，collect 直接抛错退出。
  查 `skill/references/providers/tikhub.md`，里面明确写着「429 → 退避后重试，
  把间隔从 150ms 调到 300ms」—— **文档写了，代码没实现。**
- 冲击的需求：无（这是实现缺陷，不是需求变更）
- 结论：**采纳**（补实现）
- 理由：事实赢。文档是对外承诺，实现必须跟上。
  实现时多做了一步：撞到 429 后**永久调慢后续间隔**（翻倍，上限 1s），
  而不只是本次退避 —— 撞过一次说明整体节奏太快，只退避当次会立刻再撞。
- 连带改动：`scripts/providers/tikhub.ts`
- 教训：**这个缺陷是自检抓出来的，不是测试抓出来的。**
  单测不会构造 429，因为写测试的人和写实现的人有同一个盲区。
  假 fetch 的价值不在断言正确性，在于**逼着每条错误分支真的被执行一次** ——
  凡是「只在特定条件下才走到」的代码，都该被这样喂一遍。
