# ADR-130 评审与人工反馈分离，名单以采用优先级排序

- 日期 · 2026-09-25 · KOL 筛选优化
- 类型：产品取舍；需求所有者已在本次任务中明确选择
- 冲击的需求：现行 U1、U6（替换尚未生效）；P1、P4、P5、F4、F6、U3、U5、U8（保留）；评审、人工反馈、展示及统计新增需求待逐项登记
- 结论：采纳。硬指标权重维持，Agent 判断、人工反馈和采集原件分开，名单先按实际采用优先级再按原分层和分数排序

原流程用 `fit` 的一句理由承载内容合格、品牌可用和发信优先级。高分账号在没有可说明的自然植入场景时仍可能被强推荐；`creators.json` 又在续跑时重建，Agent 写入的字段可能丢失。人工复核若直接覆盖 Agent 字段，就无法知道双方在哪些账号上分歧。团队原始人工表尚未找到，现有附件只是初筛候选，不能替代采用答案。

任务中的可选 `brand_calibration` 区分品牌偏好与已证实产品事实，Agent 在小样方向确认中展示，不新增固定问卷。Adiaro 的 journaling、self-reflection、具体 daily reset/self-care 为项目初始偏好，不变成对其他品牌的通用淘汰条件。Agent 分别记录实际内容及作品证据、自然植入、最大风险或未核问题，并分别给出合格性和采用建议；缺具体植入场景时不得建议优先联系。旧 `fit` 与草稿兼容输出保留。

评审正本为任务级 `agent-review.json`，采集原件仍只装采集证据。人工反馈另存 `manual-feedback.csv`；模板默认只在不存在时生成，新增轮次须显式追加，旧人工内容原字节保留。一个账号的平台身份、关联平台映射和审核轮次均显式保存。每轮候选池及来源冻结，新账号进入新轮，不追溯改写上一轮的分母。非法、重复、冲突或无法关联的人工行先报文件与行号，任何交付文件或 memory 写入都在其后。人工判断投影成有效展示优先级，但不改 Agent 的原判断。

旧 CSV 按 A/B/C 优先、HTML 默认一个分层，与本次用户选择冲突，因此保留旧编号并退役，由新的展示需求接替。有效优先级顺序是优先联系、备选、待核实、暂不采用；层级和分数只在同优先级内排序。人工 adopted=yes 排首，adopted=no 或 eligible=no 为本次暂不采用，adopted=unknown 为待核实，未评沿用 Agent 建议；`eligible=no` 与 `adopted=yes` 是错误输入。HTML 默认全部，支持双维筛选；XLSX 仍保留三层工作表。旧列位置不动，新列追加。

关键词统计继续以原任务下标作为行身份，一人多任务归到每个实际来源；返回条目、入围人数、人工审核人数独立。人工 yes/no 的比率只用对应字段的明确结论作分母，未评和 unknown 分开。报告重导出前复核 memory 的 contacted/blocked；本任务自己已记录的推荐仍豁免，人工采用不解除已联系或屏蔽状态。本次不将人工“不采用”写入全局 memory，不改变 contacted/replied，也不建共享 CRM。

本次业务效果的核验必须以团队原始人工复核表为基准。若原表缺失，只交付离线证据与技术验证，不声称误推率或采用率改善，也不宣称历史采用率有已证实基线。需求所有者选择以未来 3–5 轮真实人工审核作为复盘门槛；这是产品决策参数，不是已测得的效果。到时再考虑修改硬评分或长期反馈记忆。
