## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 每种配置一次正常基线几秒、一条变异几秒 | 主干上一跑各份变异日志里的 `MUTATION_COST_JSON` 那一行（`mutate.ts` 打的成本报告），由 `scripts/check/main-costs.sh` 摘、`mainCostWeights` 认 | 机器 |
| 取自哪一跑 | 那份文件的第一行；闸门报数行与各份变异开头那一行都打出 run 编号与提交 | 机器、人 |
| 取不到时为什么 | 同一份文件第一行的 `unavailable`；取数那一步另打一条 GitHub 警告 | 人 |

## 一、怎么取：一个 job 挑一次，各份读同一个文件

工作流第一个 job「取主干上一跑的变异实测」跑 `scripts/check/main-costs.sh`：

1. 用 `gh api` 列主干上 push 触发、已经跑完的 check.yml 运行记录，从新到旧最多看 20 跑；跳过这一跑自己。
2. 取第一跑「名字以『变异（第』起头、结论是 success 的 job 恰好 3 个」的（份数由工作流照 `SHARD_COUNT` 传进去）。主干上一跑有一份红了、被取消了，就往更旧的找。
3. 从那 3 个 job 的日志里摘出带 `MUTATION_COST_JSON ` 的行，原样写进文件；第一行写一行 JSON，说取自哪一跑、哪个提交。
4. 挑中之后，哪一份日志取不下来或摘不出那一行，就写「取不到」与为什么，不改挑更旧的一跑：那种情况多半是日志格式或权限出了事，换一跑只会把它盖住。

产出作为这一跑的构件上传，检查链与各份变异都等这个 job、下载同一个文件，`MUTATION_MAIN_COSTS` 指着它。**只挑一次是必须的**：各份要是各自去挑，主干上恰好有一跑在它们之间跑完，几份就会按不同的数分，有的变异哪一份都不跑、有的跑两次 —— 前者是悄悄漏验。

这个 job 只装了仓库、不装依赖，本地实测约 3 秒（取 3 份日志，每份约 450 KB）；CI 上加上起机器约十几秒，排在检查链与变异前面，整跑的墙钟跟着多这么多。

## 二、认什么：`mainCostWeights`

摘出来的行只收 `kind` 为 summary 的那几段，要：恰好 3 份（每份变异一份）；每份的 `identity.headSha` 是第一行说的那个提交、`identity.state` 是 succeeded、成本观测齐；同一种带子集的配置只出现在一份里。

「成本观测齐」是 `complete` 为 true，或只缺整跑那几行的正常基线：整跑的变异（路由没有子集）不另起正常基线，成本报告给这种行无条件记一条「全量正常基线在本命令外」，`complete` 因此是 false；别的缺漏都会再多记一条，所以「报告本身没记问题、带子集的行都没记、整跑的行各恰好记一条」就是只缺这一样。整跑的变异各自成摞、散在几份里，键都一样，所以不算重叠。今天清单里整跑的是 0 条；不放这一样的话，加进第一条整跑的变异之后每跑都取不到（评审指出的）。都对上了交给 ADR-203 原来那个 `weightsFromReports` 算（一跑的中位数就是它自己）；算出来每种配置都是 0 秒也算取不到（计时坏了，第六节）；只要有一种不是 0 秒就收 —— 计时坏了一半时估的分钟数偏小，「最重一份超 14 分钟」那道线跟着变松（第四节）。哪一样对不上都交回「取不到」与为什么，不拿残缺的数顶上。

主干上一跑里没有的配置（新加或改了名的组）照旧按验证者取默认值，默认值也取自同一跑；闸门报数行后面照旧报有几条落在默认值上。合入一次、主干跑一次，它们就有了实测。

## 三、取不到、本地

- **CI 上取不到**：各份变异按条数分（`shardPlan` 原来那个按条数称的分支），每一条照样有一份跑它，只是分得不平；各份读的是同一个文件，要退一起退。闸门在 PR 上红（「取不到主干上一跑的实测（为什么），三道线没法判，不当成没越线」），主干上只报数 —— 同 ADR-203「读不到就红、主干上只报数」。取数那一步本身照样绿：它只摘，不判。多半是暂时连不上，要**重跑全部 job**：只重跑失败的 job 时，取数那一步已经绿了、不重跑，下游拿回的还是原来那份「取不到」。
- **要分份却没设那个变量**：接线错了，变异一步以 1 退出、一条不施（原来读不出秒数文件时也是这样）。
- **本地**（`npm run check`，没设那个变量）：变异一步本来就不分份；闸门只核接线，三道线不判、不红，报一行说「三道线只在 CI 上判」。原来本地也能判，现在要等 CI 上检查链跑到第三步（推上去约两分钟）。本地拿不到主干上的运行记录（私有仓库要令牌），不为本地另造一份数。

## 三之二、CPU 时间与墙钟并列报（还 ADR-203 第 157 行）

需求所有者 2026-11-28 12:36（UTC）在选择卡上选「本条一起还：另记 CPU 时间」：判线仍用实际耗时（墙钟估的分钟数），CPU 时间并列报出来。

CI 上检查链那一串与每份变异都经 `scripts/check/cpu-time.sh` 跑（`never-red.yml` 的变异也是）。跑完打一行 GitHub 提示（同一行写进 Summary）：「CPU 时间：变异：CPU N 秒（用户 a · 系统 b，含子进程） · 墙钟 M 秒 · 退出码 k」，以那条命令的退出码退出，不判红。CPU 时间取自 shell 内建的 `times` 第二行：这个 shell 等过的所有子进程、连同它们等过的子孙，用户加系统时间之和。虚拟机里排队等核时进程不在跑，CPU 时间不涨，墙钟照涨，所以它受抢占的影响比墙钟小得多；但换了慢一些的 CPU 型号、同一个核上超线程争用时，CPU 时间一样会涨，宿主机那一层的抢占客户机里也不一定看得见。两个并列看，能大致分出「活多了」还是「被挤了」，分不干净。

卡片上写的是「每个测试进程另记」，做成了按每份、每个 job 记：Node 拿不到子进程各自的 CPU 时间，逐个记就得改变异一步起进程那段最细的代码；按 job 记用 shell 自己的计数，算得准、不碰那段代码，ADR-203 那张欠条要的也正是「变异一步与检查链的 CPU 时间」。没被等过的进程不算在里面：自己脱离出去的，或连着父进程一起被杀、改由系统收的。变异一步「见齐就停」整组杀掉验证者时，那一刻正在跑的子进程树就是这样（复核时复现过：同样的活自然结束报 1.5 秒，整组杀掉报 0.0 秒），所以 `check.yml` 里开着提前停的三份报的 CPU 偏小，漏的是每条提前停的变异开枪那一刻在飞的那些；`never-red.yml`（不提前停）与检查链不受影响。漏多少没量。拿不到临时文件时少打这一行、照样以那条命令的退出码退出。

守着的：需求测试 `h-cpu-time-entry` 真起它（孙进程空转那段算进去、总数是用户加系统、原样交回退出码、写进 Summary、用法错以 2 退出），5 条（`M-H254-zj` 到 `M-H254-zn`）逐条施变，点名的那条红；接线由 `WORKFLOW_PIN` 钉着。没守的：GitHub 上真打出来的样子由本条 PR 自己那一跑看（第六节）。

## 四、代价

- **同一棵树换个时候跑，数会变。** ADR-203 第二节特意不用这一跑的秒数，理由是同一份代码在不同 runner 上差到 ×1.6，判红就可能换结论。现在用的是主干上一跑的，同一个 PR 在主干动过之后重跑，取到的是另一跑的数。三道线里「一次涨幅」两边用同一份数，不受影响；「三份不均」按这份数分、按这份数量，几乎不会越线；只有「最重一份预计超 14 分钟」会随主干上一跑落在什么机器上浮动。这是需求所有者选的代价，换来的是数永远是新的。
- **一跑的数带着那一跑的机器。** 三份落在三种 CPU 上（ADR-203 第六、九节），某一份落在慢机器上，它那几种配置下一跑就称重一点。只取一跑，不取几跑的中位数，是照所选的「上一跑」。
- **每周不提前停的整跑（`never-red.yml`）也读这份数。** 那是见齐就停时的秒数，比不提前停的整跑轻，三份之间的比例大致仍在；取不到时按条数分。
- **主干连着 20 跑都没有三份变异全绿时，每条 PR 的闸门都红**，修主干的那条也红（它要的是主干上一跑的数，自己绿了也没用）。那时只能看着红合入那条修主干的 PR；今天主干上没有连着红过这么多跑。
- **计时坏了一半看不出来。** 只有每种配置都是 0 秒才算取不到；坏了一部分时那几种配置称轻了，估的分钟数偏小。
- **整跑的墙钟多了取数那个 job。** 墙钟对比那一步（ADR-158）比的是整个 run 的墙钟，合入后头几跑与合入前的主干跑比，会因为多出的那十几秒与一次排队显得略慢。
- **依赖日志的样子。** 摘的是日志里的一行；GitHub 只留 90 天日志，主干 90 天没跑过就取不到（会红，看得见）。`mutate.ts` 打那一行的格式改了，`mainCostWeights` 认不出就是取不到，也看得见。

## 五、守着的与没守的

- `mainCostWeights` 与闸门的新分支：需求测试 `h-shard-load` 逐条断言（第一行写着取不到、schema、run、提交、份数多一份少一份、不是 summary 的不算、别的提交、没跑完、跑失败、整跑的行只缺正常基线照样收而多缺一样不收、带子集的行记了问题不收、报告本身记了问题不收、同一种配置在两份里、整跑的散在两份里不算重叠、算不出、全是 0、只有一种不是 0），25 条（`M-H254-a` 到 `M-H254-r`、`M-H254-za` 到 `M-H254-zg`）逐条在本地施变、跑 `h-shard-load`，各自点名的那条红。
- `main-costs.sh`：需求测试 `h-main-costs-entry` 拿一个假的 `gh`（答案取自玩具目录里的文件，`--jq` 交给真的 jq 算）在玩具目录里真起它：跳过这一跑自己与只有两份绿的那一跑、只摘那几行、挑中后不再问更旧的、只问主干上跑完的、有一份摘不出或日志取不下来就写取不到且不改挑、某一跑的 job 列表读不出来就写取不到且不跳过、日志里夹着 NUL 字节也照文本摘、凑不齐写取不到、列不出写取不到、少了份数以 2 退出。10 条（`M-H254-s` 到 `M-H254-z`、`M-H254-zh`、`M-H254-zi`）逐条施变，点名的那条红。假 `gh` 不验 GitHub 真的这样答 —— 那一半由本条 PR 自己的 CI 那一跑验（第六节）。
- 两个入口（`shard-load.ts`、`mutate.ts`）新加的读文件、没设变量、取不到按条数分：自检组 `shard-load-entry`、`mutate-shard` 在玩具树里真起入口守着（PR 上取不到红、文件不在、主干上只报数、本地不判但核接线、按主干实测分时说出取自哪一跑、没设变量以 1 退出一条不施、取不到按条数分照样只跑这一份、验证者环境里不带那个变量）。没有变异指着入口这几行：两个入口在自检的验证基础设施闭包里，指名自检的变异被「自己验自己」拦下，同 ADR-203 第七节说的 `mutate.ts` 分份那几行；指名需求测试的也不行，今天的需求测试不起这两个入口，要负片得另加一组真起入口的需求测试，本条不加。
- 验证者的环境里带着编译缓存的目录（ADR-72 第 708 行那张的验证者一半）：`mutate-shard` 起变异一步时不给这个变量，玩具验证者记下自己环境里的值，要等于变异一步补的默认目录；把起验证者那处 env 里的编译缓存去掉，这条红（本地手施过一次，同上不进变异清单）。起 worker 那一处看不出来：worker 没拿到也会自己补同一个默认值。
- 分份时称一摞用的是不是实测秒数（ADR-203 第 108 行那张欠条说只有读代码守）：变异一步现在把分法与每份重量出自同一次 `shardPlan`，按实测分时打一行「这一份约 N 验证者秒（各份 a / b）」。`mutate-shard` 的玩具实测里需求测试两种配置基线 3 秒、4 秒，整跑的一条按 7 秒称，每份两条该打 14 / 14；把称法换回按条数，打出来是 2 / 2，那条断言红（本地手施过一次，同上不进变异清单）。四条整跑的落点两种称法仍相同 —— 守的是称出来的重量，不是落点。这一行也让 CI 上每份变异开头就看得到它分到多重，可与这一份的实际墙钟对着读。

## 六、实测

（待补：本条 PR 自己那一跑的取数结果、各份墙钟与闸门报数。）

**计时与记账有断言了**（还 ADR-203 第 137 行，见第七节）：本地把 `mutate.ts` 里验证者计时那一行改成 0、再把记账时交进去的毫秒改成 0，各跑一次自检组 `mutation-cost-entry`，两次都是「成本入口正常与施变计时分别落在独立启动结束范围」那条红（那条断言按观察器记下的验证者起止时刻核报告里的毫秒）。这两处在 `mutate.ts` 里，指名自检的变异会被「自己验自己」拦下，所以没进变异清单，只有这两次手施。那条断言自 #224 就在，本条没有改它：ADR-203 那张欠条说「没有断言」时其实已经有了，这里是核实它守得住，不是新补。下游另有一道：报告里每种配置都是 0 秒时 `mainCostWeights` 交回取不到，PR 上闸门红（`M-H254-zb` 守着），不再是 ADR-203 那张欠条说的「报 0 / 0 / 0，看得见但不红」。

没盖住的：收尾那张「按验证者记账」的账单（每个验证者一共花了多久）记账时交的毫秒改成 0，`mutation-cost-entry` 照样全绿（清点时实测）。闸门与分份不读那张账单，所以 ADR-203 第 137 行按字面（闸门派生自哪份账）算还清；它承接的 ADR-99 第 443 行说的是账单本身，这一半另记一张欠条（第七节）。

独立复核（另起的评审，只给代码不给结论）找出两条要改的，都在本条改了：变异清单里一条的「为什么」夹带了实现原文，变异一步一条不施就红；整跑的变异会让主干实测永远取不到（第二节）。另有几处顺手改了：日志按文本摘（`grep -a`）、取数入口补两条路的断言、残留的「秒数文件」旧说法、取数 job 加了 5 分钟的超时。
