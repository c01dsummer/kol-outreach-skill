# ADR-190 草稿拿去就能放进邮箱：主题单列，发件人可选，只存不发

- 日期 · 2026-11-09 · 「Zoho 发开发信」那条线：运营方要用自己的 Zoho 邮箱发开发信，需求所有者问一个具体的邮件平台该怎么放进这个通用 Skill
- 类型：产品取舍（四件事都不违反需求，选哪种决定用户看到什么），需求所有者 2026-11-09 14:19Z 在决策卡上选「全按推荐」
- 触发它的事实：评审 CSV/XLSX/HTML 里开发信草稿是一整格，第一行是 `Subject: …`（`skill/references/outreach-draft.md` 的模板），主题和正文混在一起，放进任何邮箱工具或邮件合并之前都要人手拆；模板署名处有 `{name}`（同一文件的「我是谁」那一行与结尾署名），而流程里没有任何一项输入能填它，它只能原样留在草稿里
- 冲击的需求：S1（解释，不改字面）、U9.d（退役，由 U9 下一个新字母接替）；主题列、发件人姓名各新增一条需求，编号在实现那一片登记时定
- 结论：采纳。人批痕迹：需求所有者合入本条那条 PR；依据是他 2026-11-09 在项目线程决策卡上的选择。本条第三节那三处细节是实现者替他选的默认，合入即认
- 理由：草稿拿去要能直接放进任何邮箱工具，又不能让这个通用 Skill 绑上某一家邮箱、碰上发信。主题从草稿首行导出时拆，正本不多一份会漂的真相；发件人姓名是用户给的输入，放在任务根上，不碰品牌校准的版本。每一件的细节见第一、二节
- 连带改动：本条只有决策记录与索引一行；实现分三片串行，见第四节

## 一、决定

**1. 把审好的信放进用户自己邮箱的草稿箱，算 S1 说的「只产出草稿」。** 条件是只能经用户自己接上的邮箱工具，并且是本次对话里用户自己明说要放；Skill 自己的代码不调用任何邮箱接口，S1.a「代码中不存在任何 SMTP / 邮件发送 API 调用」字面不变。Agent 只调用「建草稿」一类的工具，绝不调用「发送」；发不发由人在邮箱里点。

**2. 具体邮件平台的代码不进本仓库。** 本仓库是发布给别人用、零配置的通用 Skill（`docs/business-requirements.md` 的「零配置可跑」与「发布给别人用」两条约束）；只有某一家邮箱的用户用得上的代码，对别人是死代码，凭据还会进 Agent 读得到的环境。连某一家邮箱的那一小段放在仓库外：先试该平台官方的 MCP、只挑「存草稿」那一个工具；没有，再另开一个小仓库做。`.agents/skills/`、`.claude/skills/` 里照旧只放那一条软链（`docs/ARCHITECTURE.md`「新东西落在哪个目录」）。

**3. 主题单独成一列（新增一条 U 类需求，退役 U9.d 换新字母）。** 导出时从草稿首个非空行的 `Subject:` 拆出来，不在 `agent-review.json` 里加字段：正本只留一份真相，字段里的主题和草稿首行不会各自漂。原来那格 `outreach_draft` 一个字节都不改，下游可能已经在读它。主题里的 `{…}` 照原样保留（P2.b）。

**4. 发件人姓名作可选输入（新增一条 D 类需求）。** 存进 `task.json` 根上的新字段 `sender_name`，由 collect 原样透传；不加第四个必问项，不进 `brand_calibration` —— 后者按内容算出版本号，一改并重算版本，所有已评账号都变成「待重评」。Agent 写草稿时拿它署名；脚本没有任何一处拿它去填 `{name}`。缺席就是用户没给：不读作默认值，脚本不补，草稿照旧留 `{name}`。

**5. 不导出 `.eml`。** 零凭据、不联网，但各邮件客户端把它打开成草稿的行为不统一，以后再看。

## 二、按改需求逐条评定

- 红线：P1–P5 都不碰。四片都不发请求、不花钱（P3 不受影响）；主题列里的占位符原样输出（P2.b）；「拆不出主题」和「没有草稿」写得不一样（P1：不同含义不共用一个空白）。
- 缩范围还是降标准：都不是。S1 的意思收窄成一条明确的边界（只经用户自己的工具、只存草稿），原先它对「放进草稿箱」没表态。
- 覆盖还是可信：覆盖上升 —— 草稿拿去就能放进邮箱，不用人手拆。
- 可逆：可逆。新列只追加在末尾，旧列与列序不变；`sender_name` 缺席照旧能跑。

## 三、实现者替需求所有者选的三处默认

合入即认；想改，合入前说一句即可。

1. **不另加「去掉主题行的正文」一列，接受为已知缺口。** 用邮件合并时主题会在正文里重复一次。重启条件：用户反馈主题在正文里重复，或接入某个邮箱工具时它要求正文单独给。
2. **拆不出主题时那一格写字面 `拆不出主题`，不留空。** 没有草稿时才留空。提醒：主题本身多半是英文，这一格若被邮件合并原样当主题发出去，收件人会看到这四个中文字；发之前要人看一眼。
3. **U9.d 照方案退役，换一个新字母。** U9.d 逐个点名评审表追加的列，加一列就是改它的字面；字母不回收。
