# ADR-46 写入侧能写出读取侧拒绝的东西；以及同一个 bug 我写了两遍

- 日期 · 2026-08-28 · PR #5 拆分后第十一轮自动评审，两条都成立
- 类型：**事实证伪**
- 冲击的需求：D4
- 结论：**采纳**，并把原子写入合并成**唯一一份**

### 一、一次写回就能毒掉整份记忆

任务配置里 `product` 是空白时：

```
写回报告: {"written":true}
盘上存的 product = ""
下次读:   记忆文件 ... 不可用：结构不对 —— tiktok:alice 的第 1 条推荐记录的 product 不是非空字符串
```

**这是我自己造的循环。** ADR-37 加了读取侧的「product 必须非空」，写入侧没跟着加 ——
于是一次正常的写回就把一份好好的记忆变成读不出来的，此后每一次采集
都被挡在门外，直到有人手工去修。

判据是**读取侧实际会拒绝什么**，不是「这个值看起来合不合理」。
写入侧现在拒收并报 `written:false`，另外 `collect` 在**花钱之前**就检查配置 ——
空产品名走不到最后，早说比晚说好。

### 二、同一个权限位的 bug，我在两个文件里各写了一遍

上一轮（ADR-45）我给任务目录写了个新的 `writeAtomic`。两轮前（ADR-40 · ADR-42）
刚在 `memory.ts` 里修好的权限位处理，**新写的这份一个字都没带过来** ——
`saveTask` 又是 600 进、644 出。

根因不是我粗心，是**这段例程有两份副本**。所以这次不是「把第二份也修好」，
是抽成 `lib/atomic.ts` 里**唯一一份**，两边共用。

合并的直接好处当场就看见了：原先守这两份的四条变异，合并后有两条
指向了同一行 —— 说明它们本来就在重复地守同一件事，只是分散在两处看不出来。

**留在调用方的**：孤儿临时文件清不清。记忆文件要清（长期存在、孤儿是一份
完整的联系历史副本），一次性的任务目录不用。这一条按各自处境不同，
不该合进公共函数。

### 教训

**「我刚修过这个」是最不该信的一句话。**

我修过 `memory.ts` 的权限位，两轮之后写一个新函数时，那次修复没有以任何形式
出现在我脑子里 —— 因为它属于**另一个文件**。

真正的问题从来不是「记不记得」，是**同一段逻辑有几份副本**。
一份副本的时候不需要记得，两份的时候记性就成了唯一的保障，而它不可靠。
