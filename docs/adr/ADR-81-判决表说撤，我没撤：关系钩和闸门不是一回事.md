# ADR-81 判决表说撤，我没撤：关系钩和闸门不是一回事

- 2026-09-18 · 按 Bitter Lesson 原则重整检查链，逐道评定里的第七道
- 类型：**驳回一条已定的判决**（只改结论，不改代码）
- 冲击的需求：无
- 结论：**「减 harness 变异」那一半已经做完了；另两半不撤，理由在下面。**
  这是一次对已定判决的偏离，所以要单独留一条记录，不能埋在别的提交里

## 判决表原话与它当时的前提

> selfcheck 留一半：假 fetch 跑**产品入口**那一半留；测 lint/mutate/arch **入口接线**那一半
> （`runTool`、`SELFCHECK_TOOLS`）随闸门收缩去掉。
> audit 收窄：「判定模块必须有变异」（ADR-62）那段随闸门收缩一起减。
> mutate：226 条 harness 变异随闸门收缩一起减。

**「随闸门收缩」这四个字是前提，不是修辞。** 而收缩已经自己发生了 ——
判决表写下的时候还有三个工具、11 步链；今天是一个工具、8 步链。

## 第一半：已经做完了，不是"待办"

撤 age / lint / arch / adr 的 git 机器 / size 的过期机器时，守它们的变异跟着文件一起走了：

| 随谁一起走 | 变异 |

**剩下的 229 条按文件摊开，没有一条守已撤的闸门** —— 全部落在活着的判定模块上
（`spec-rule` / `mutate-rule` / `jobs-rule` / `mutate-restore` / `audit-rule` / `claims` …）。
**「还能随闸门收缩再减」的那一摞是空的。**

命令：`node -e '…mutations.filter(m => m.req === "harness")…'` 按 `file` 分组打印。

## 第二半与第三半：不撤

### 它们不是闸门，是关系钩

判决表的斜率判据管的是**闸门**：一道会拦路、有豁免通道、要人维护的东西。
而这两样是另一种形状 —— **两个东西之间的机械关系**，近乎零维护、近乎不误报：

- **ADR-62 那条**：`scripts/check/` 下每个判定模块，和指向它的变异之间的关系。
  今天管 14 个模块，14 个全覆盖，零豁免
- **selfcheck 那 13 处 `runTool`**：`mutate.ts` 这个入口，和"它真的调了判定并以 1 退出"
  之间的关系

三问过一遍：

| | ADR-62 那条 | selfcheck 那 13 处 |
|---|---|---|
| 它守的失败是响的还是哑的？ | **哑** —— 一个判定模块丢了变异覆盖，没有任何信号 | **哑** —— 入口接线断了，检查链照样全绿 |
| 模型再强一档会不会自动对？ | 不会。这是**关系**，不是判断 | 不会。单元与变异**够不到入口**（`process/4-VERIFY.md`） |
| 发生过没有？ | 发生过 —— ADR-62 就是为它开的 | 发生过 —— 入口接线缺口是 ADR-70 立 `by` 机制的起因 |

**哑 ＋ 模型代替不了 ＋ 发生过 → 留。**

### 撤掉的具体代价

`mutate.ts` 的入口接线有五处只有自检够得着：派工、隔离目录、崩溃现场跟着结论过进程边界、
见齐点名就停、`--brief` 的豁免行。撤掉那 13 处之后，**这五处没有任何东西跑过** ——
而 `mutate` 是整条链收缩之后剩下的地基：它塌了，330 条变异一条都不算数。

### 反方，写清楚

判决表不是凭空写的。audit 那道闸门在 63 条记录里的账是**真阳性 1 / 自身 bug 7** ——
它的机器确实出过不少毛病，"收窄"这个方向没错。

但这一条具体的规矩（判定模块必须有变异）**简单、当前干净、且已经自己缩了**：
三个工具缩到一个，模块数随闸门撤掉从 16 缩到 14。
**判决表要的收缩已经发生，再撤就不是收缩，是拆掉一根还在承重的东西。**

## 这是一次偏离，记在明处

判决表标的是「已定，按此执行」。**我没执行，而且这是第二次**
（第一次是 ADR-76：判决说改 `6-INTEGRATE.md` 的「作者不许合」，我没改，
理由是原则 2 点名「验证者独立于生成者」不做减法）。

两次的形状一样：**斜率判据管的是"闸门该不该留"，而这两样东西不是闸门。**
把它们塞进同一把尺子量，量出来的是错的答案。

## 死亡条件

> **ADR-62 那条**：`scripts/check/` 下的判定模块降到 5 个以下、或者连续 20 次
> 完整 `npm run check` 里这条规矩从没报过缺口且没有新模块加入时 —— 退成只报数不硬失败。

> **selfcheck 那 13 处**：`mutate.ts` 的入口不再装任何接线（派工、隔离、判定调用
> 全部挪进判定模块，入口只剩打印与退出码）时 —— 那时单元和变异够得到它们，这 13 处就是重复。

**谁去数**：没有机器在数，同 ADR-80 那张欠条。两条都挂在「欠条台账可机读」那道闸门上。

> ⚠️ 欠条：**本条驳回了一条已定的判决，而这个仓库没有"驳回判决"的路径。**
> 五档路由（本改动/扩范围/既有缺陷/登记/驳回）管的是**评审发现**，
> 不管"上游定好的评定结论被下游执行者推翻"。这次的做法是单开一条记录讲清楚，
> 但那是我自己选的形状，不是仓库规定的。
