# ADR-107 费用金额与请求次数分开记账

- 日期：2026-09-23
- 类型：事实证伪与需求补充
- 触发事实：现有 Budget 按请求总数乘 $0.001；固定公开价目中 Instagram V2 Reels、账号名搜索与主页作品各为 $0.002，而 TikTok 三条路径与 IG 两个 profile 路径为 $0.001。
- 冲击的需求：新增 D12；金额依据涉及 P1、P3、P5，生产预算接线另行落实 P3、D6、F7。
- 结论：采纳
- 连带改动：固定价目摘录、纯金额与费用账、需求与架构、独立测试及负片。

## 决定

请求次数与金额分别保存。金额以整数微美元计算，一美元为一百万微美元；原始十进制
输入不能先经浮点舍入，超出精度或安全范围明确拒绝。展示由整数生成十进制文本，
不把 $0.005 显示成 $0.01。本次仅定义原始文本转换，入口 JSON/CLI 读取另行接线。

固定价目只包含八条已核生产端点，依据随仓库保存；价目版本不改写。未来更新新增版本，
历史记录仍与其原版本逐项核对。端点、版本或单价对不上时明确报错，不能挑一项继续算。
公开基础价不计优惠，属于估算依据，不是账户账单，也不保证供应商未来不调价。

费用账区分 HTTP 200 留存次数、未取得 HTTP 状态的保守留存次数，以及最多一条未结
预留。净请求数不包含未结项，占用金额包含它。同一次结算只移动状态、不重复扣钱。
非 200 只撤销这次预留；200 后的正文失败不退款；无状态不推断为免费。
一份凭据只归属一个账且只消费一次，拒绝时不留下部分改动。

新建费用账是显式操作；恢复缺失记录表示未知，不能靠旧 requests=0、空名单或游标
缺失补出零。合法未知与损坏记录分别诊断；它们不能用于新的费用预留，已有数据的
只读操作不因此被当成一次新任务。恢复的未结预留保留占用并阻止下一次预留。

## 范围与接线顺序

这次只交付纯金额模型与固定价目，**现有付费入口尚未使用它，生产预算尚未修复**。
不改变当前端点、重试、搜索数量、任务目录、评分或输出，不发真实 API 请求。
下一项将现有各付费入口、断点及费用出口完整接线；再以独立的硬中断证据落实请求前
持久预留。纯模块中保存未结状态不等于请求前已经写盘，不能借模型测试作那项保证。

JSON 数值先经 JSON.parse 可能丢失原始十进制含义；接线时必须在丢失前保留预算 token，
保存与恢复也以精确金额为准，不能再通过 Number 转回有损数值后把它当授权上限。
当前不新增历史迁移、增量预算命令、自动查价、账户对账或多写者锁。

> ⚠️ 欠条：生产入口仍使用统一单价，尚未消费本记录定义的费用账。纯模块不能保障真实请求的逐端点预算。· 重启条件：本记录所在改动合入后，立即完整接线现有付费入口与费用出口。

> ⚠️ 欠条：现有请求发出与断点保存之间存在硬中断窗口；逐端点金额接线本身不能消除它，也不保证已付费业务响应可恢复。· 重启条件：逐端点费用接线合入后，以请求前持久预留及硬中断注入单独验收；单写者范围沿用 D4 的断电与并发边界。

## 验证边界

独立测试只依据 D12、固定价目摘录、类型与对外签名，不读金额或适配器函数体。
新模块尚不存在时的导入失败只能表明缺实现，不能冒充行为断言；实现后必须用金额、
未知态、退款归属、恢复及精度的负片证明断言有效。旧生产入口的测试继续按现行契约执行，
不把它们改绿来宣称尚未完成的接线已完成。

## 供独立测试使用的接口契约

`cost-ledger.ts` 导出 `parseUsdMicros(string): number` 与 `formatUsd(number): string`；
十进制科学记数和无影响尾随零可用，非法类型、负非零、非整数微美元及超安全整数拒绝。
`FixedPriceCatalog` 是版本 → 完整端点 → 微美元单价的只读映射。`FrozenPrice` 为
`{endpoint, price_version, unit_micro_usd}`，历史单价须精确匹配该版本表。传入的表与账目均隔离引用。

账目 `CostLedgerV1` 为 `{schema:1, currency:'USD', unit:'micro_usd', scope:'task'|'process',
limit_micro_usd, next_attempt_id, entries, pending?}`。`entries` 每项为 FrozenPrice 加
`http_200_count/unknown_result_count`；pending 为 FrozenPrice 加 `attempt_id`。
新账 entries 为空、next_attempt_id=1；尝试序号正安全整数递增。聚合键不能重复。
快照 `CostSnapshot` 为 `{cost_ledger, requests}`，输出均为隔离副本。

- `createCostBudget(limit, scope, catalog): CostBudget` 显式新建。
- `inspectExistingCostLedger(rawLedger, rawRequests, catalog): ExistingCost` 不因普通坏账抛出。
  返回 known（含 snapshot/summary/problems:[]）、unknown-history（字段缺席）、unavailable-evidence
  （无法识别的 schema/价目版本）、invalid-ledger（损坏/不一致）之一；后三态只带 problems，不能带假金额。
- `restoreCostBudget(rawLedger, rawRequests, catalog): CostBudget` 重新校验原输入；非 known 抛
  `CostLedgerUnavailable`，其中 status/problems 与检查结果一致。
- `CostBudget.snapshot()/summary()` 读取；`reserve(FrozenPrice)` 返回本账本次专属凭据；
  `settle(receipt, {kind:'http',status}|{kind:'no_http_status'})` 结算，HTTP 状态必须为整数 100–599。
  有 pending 时不能继续 reserve；恢复 pending 没有可消费的原进程凭据。
- 错误以 `CostError.code` 区分 invalid-money、unknown-price、pending-attempt、invalid-receipt、
  invalid-outcome、budget-exceeded；账目不可用用上面的专门异常，不能全部冒充超预算。

summary 为 `limit_micro_usd/occupied_micro_usd/remaining_micro_usd/http_200_micro_usd/
unknown_result_micro_usd/pending_micro_usd/requests/http_200_count/unknown_result_count/pending_count`。
remaining 是上限减占用，可为负；pending_count 为 0 或 1。计数、乘积及合计必须在安全整数范围，
拒绝不会改变任何计数、序号或金额；非法结算不消费凭据。零价格允许，未知路径仍拒绝。

`tikhub-pricing.ts` 导出 `TIKHUB_PRICE_VERSION`、深冻结的 `TIKHUB_PRICE_CATALOG`、
`TIKHUB_PRICE_BASIS`（固定公开基础价、不计优惠、非账单、非未来价格上界），
以及 `quoteTikHub(endpoint)` 与 `resolveTikHubPrice(version, endpoint)`；报价是隔离副本。
当前版本及八项价格以 `docs/evidence/tikhub-pricing-20260923.json` 为依据，实验端点未加入。

## 实现前的独立设计复核

D12.l/n/o 分别把新建与历史缺失、旧价保留与未知版本、读入引用与输出引用及失败原子性
合在一起。这些路径可以独立坏，原编号与文字保留并退役，分别由 D12.q/r、s/t、u/v/w 接替。
语义不放宽；独立测试改认领拆开的判据，不从实现复制预期。固定价目事实同步到数据源调研正本。
