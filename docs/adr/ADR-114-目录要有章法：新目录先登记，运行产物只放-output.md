# ADR-114 目录要有章法：新目录先登记，运行产物只放 output

2026-09-24。

## 起因

- 2026-09-23，两条改动为了给决策记录留原始证据，各自在 `docs/` 下新建了一个 `docs/evidence/`：
  一次放资源夹具在 macOS / Node 24 上的诊断快照（`4897fdc`，ADR-104 引用），一次放 TikHub 价目快照（`02c4a8b`，ADR-107 引用）。
  需求所有者要求不再提交这类文件，#150 与 #154 删掉了它，#154 在 `.gitignore` 里加了 `evidence/`。
- 2026-09-24，需求所有者要求保证以后不会再传上去。我先提议在审计里加一道闸门：
  被跟踪的文件里，路径有一段叫 `evidence`、或者 `.gitignore` 说该忽略却已被跟踪的，一律硬失败。
  需求所有者反问：这个目录为什么会被造出来？新建目录总要有个章法；往 `audit-rule.ts` 里加补丁代码也不好。
- 核下来，根子在这里：**仓库里没有任何一处写着有哪些目录、各装什么、本机产物放哪。**
  `AGENTS.md` 只讲 `skill/` 与 `scripts/` 两种代码；`ARCHITECTURE.md` 的锚点表只管 `scripts/` 下的模块；
  `docs/SYNC.md` 的文档地图只管 `docs/` 里的文件。每个会话碰到「要存点东西」时只能自己起名建目录。
  同一天 ADIARO 那批样本放在 `output/adiaro-discovery/` 是放对了（ADR-101 第十五节），但那也是碰巧。

## 决定

- `docs/ARCHITECTURE.md` 加「新东西落在哪个目录」一节：一张目录表（进不进仓库、装什么）与三条规矩 ——
  不新建顶层目录、也不在 `docs/` 下新建子目录，真需要就在同一条改动里登记；运行产物一律放 `output/<名字>/`，
  决策记录只引用本机路径与 SHA256；这张表没有机器核，靠 `docs/SYNC.md` 提醒。
- `docs/SYNC.md` 触发表加一行（改目录结构 → 回来改那张表与 `.gitignore`）；`AGENTS.md` 的路由表加一行指过去。
- `.gitignore` 的 `evidence/` 一行保留，注释改成指向那张表。
- 旧记录里对 `docs/evidence/` 的 7 处引用（ADR-104、107、108、109、110）按只追加的约定原样保留，那是当时的事实。

## 驳回：在审计里加一道闸门

- `.gitignore` 已经挡住平常的 `git add`；`git add -f` 是有意为之，防它的代价是一段新的判定、测试与变异。
- 它治的是症状：换个目录名提交同类文件，它照样拦不住；真正缺的是「东西该放哪」这句话。
- 它会让 `audit-rule.ts` 多一块与它本职（检查链自己算不算数、报告上的数怎么数）无关的东西。

## 什么条件下重开这个讨论

- 这张表登记之后，又有一个没登记的新目录进了主干 —— 说明靠人记不住，再议要不要让检查去核目录清单。
