# ADR-122 CI优化的历史证据不能由文档迁移追认

- 日期：2026-09-27 · 复核 CI 提速与长期维护改动时
- 类型：事实证伪
- 触发它的事实：用户指出 PR208、215、217、218 改动了通用规则；仅将本仓库协议移到项目文档，不能证明这些改动此前的需求、测试与集成先后全部符合约定。
- 冲击的需求：不改变产品需求登记、P1–P5 或 CI 提速目标；成本生产接线仍暂停。
- 结论：采纳
- 理由：提交树能证明版本之间包含哪些文件，成功 CI 能证明该版本执行了哪些检查；它们不能还原测试作者读过什么，也不能替代未公开的旧代码运行证据。
- 连带改动：本记录及生成索引；不修改 `process/`、代码、检查链、变异或测试。

## 复核的依据与范围

公开来源为四条 PR 的正文、提交树、评审和成功 GitHub CI，不使用本地历史日志证明公开合规。
复核起点分别为 PR208 的 `30938d6`、PR215 的 `ec0b21e`、PR217 的 `4741eb5`、PR218 的 `0b429d4`。
这些起点已有 `process/README.md` 的向下依赖、`3-BUILD.md` 的上游来源、
`4-VERIFY.md` 的独立测试与先红要求、`5-DESIGN.md` 的架构先于代码，
以及 `6-INTEGRATE.md` 的新检查最后接入原则；它们不因本次新增文档才成立。

本次区分三种证据：提交树上的先后、作者在 PR/ADR 中报告的操作、GitHub CI 实际可见的执行。
未找到公开旧代码红日志，不等于当时没有运行；有测试先行提交，也不等于独立上下文已经得到证明。
当前结果不能改写为过去已经做到。

## 分别查到了什么

### PR208：给已有入口补独立负测试

[PR208](https://github.com/c01dsummer/kol-outreach-skill/pull/208) 的严格入口实现已在其起点存在。
`3528913` 补测试、M-H42-j 和文档，`06d6bf5` 追加验收记录；不是 PR208 先写新入口再验收。
更早的 PR199 中，`167625b` 的真实入口测试在 `b740650` 的严格解析修正之前。
ADR118/119 也已分别随 PR205/206 进入主干，记录了先前假红与修订，不能用后来的通过覆盖它们。

[成功 CI 36242567388](https://github.com/c01dsummer/kol-outreach-skill/actions/runs/36242567388)
对应 `06d6bf5`，可核正常断言、子集正常基线、M-H42-j 与完整 720 条变异，以及独立自检和审计通过。
PR 中的 Darwin 故障注入、认领逐字比较和作者读物隔离是作者报告，公开 CI 不提供这些旧操作的原始记录。

这里确有纠正通用陈述的依据：旧文档称需求测试够不到入口，但已有需求测试的独立实际入口验证。
“内部单测不能替代实际入口验证”可以跨项目复用；本仓库的自检认领、`by`/`kills` 和豁免资格属于项目协议。
后者的文档落点由 PR219 修正，不据此声称此前全部符合约定。

### PR215：文档和测试先提交，但新检查未分开接入

[PR215](https://github.com/c01dsummer/kol-outreach-skill/pull/215) 的公开树为
`5ff0d78`/`9160e98` 文档 → `4cc53da`/`9301cf8` 测试 → `669afd2` 判定与入口。
公开验收当时引用 `process/4-VERIFY.md`；其中 `full_run` 字段、六项核心字段、GitHub 事件来源与历史兼容是本仓库协议，放置不当。
树顺序成立；作者报告的未读实现、旧代码具名失败仍不能仅从这些提交证明。

`669afd2` 同时加入维护纯判定、14 条负片和实际入口的维护拒绝。
这新增了拒绝运行的条件，虽然复用既有命令、未增加检查阶段，仍属于新检查接入；
没有按当时已有的 `6-INTEGRATE.md` 先合判定、测试和变异，再另 PR 接入口。
已经合入的历史顺序无法事后补成合规；本次不撤掉已经验证的维护检查。

[最终成功 CI 36287458525](https://github.com/c01dsummer/kol-outreach-skill/actions/runs/36287458525)
对应 `4618990`：734 个 ID 与该提交清单精确相等、各 caught 一次，67 种子集基线各一次且全在首条变异结果前；
八步检查执行，真实入口的拒绝前零验证者启动、零改写等断言通过。
这证明最终版本的检查结果，不证明此前的上下文隔离或补回独立接入顺序。

### PR217：纯统计交付，仍需核对每项断言的上游

[PR217](https://github.com/c01dsummer/kol-outreach-skill/pull/217) 先交纯统计与呈现，未接成本入口，不能把它当作新检查已接链。
公开提交中有文档、类型、测试（作者报告为独立）先于纯实现的顺序；但并非每项验收细节都已先发布：
`1079389` 的初版测试已包含重复记录、跨组合关联须明确诊断的断言，`2860b15` 才追加对应公开判据。
这是具体的公开规格先后缺口，不足以认定断言来自实现输出，也不能概括为所有验收均先于测试。
运行环境中的 Node 等项目细节曾写进通用验证文档，由 PR219 修正落点。

[成功 CI 36293025709](https://github.com/c01dsummer/kol-outreach-skill/actions/runs/36293025709)
对应 `d2f8c2`：757 条变异各 caught 一次（含 23 条新守卫），68 种子集正常基线各一次且全在结果前，八步检查通过。
旧代码自然红与测试作者读物隔离仍属于 PR 中的作者报告，不能由最终全绿追认。

### PR218：既有 worker 协议扩展，尚未证明实际启动取数

[PR218](https://github.com/c01dsummer/kol-outreach-skill/pull/218) 的公开树为
`89b9dc9` 文档 → `61b63a0` 类型 → `645a389` 测试 → `0a326b9` 解析与 8 条守卫 → `3ab9a36` 既有耗时变异锚点适配。
显式 `started` 必须为布尔、坏值使整行无效，是本仓库 worker 协议，不应写进通用验证文档。
这里只扩展既有协议，未接成本观察或新检查入口；不以新检查分开接入要求判它违规。

[最终成功 CI 36295301607](https://github.com/c01dsummer/kol-outreach-skill/actions/runs/36295301607)
对应 `3ab9a36`：765 条变异各 caught 一次（含 8 条新守卫），69 种正常子集基线各一次且全在结果前，八步检查通过。
PR 报告的 7 条旧解析器具名失败未见公开原始红运行；不据此推断没跑，也不声称已公开证明。
协议测试通过不表示已从真实 spawn 取数，实际成本输出仍未接入。

## 当前更正与剩余工作

[PR219](https://github.com/c01dsummer/kol-outreach-skill/pull/219) 仅修正文档分层；本记录与它独立，不把迁移当作历史验收。
本记录不新增通用纪律，也不补造业务需求编号。检查工具自身不在产品红线登记表的边界，原 `4-VERIFY.md` 已明确；
其公开验收、具名断言和负片仍须能逐项对应，不能以“未改业务需求”替代这个核对。

恢复成本入口前，按 PR219 最终项目对外协议复核尚未发布的独立案例及其断言来源；
缺的验收先澄清，再验证旧入口具名失败、实际启动、基线关联、收尾与完整认领保护。
新时间取得的验证只作为新接线的证据；未公开的历史上下文和旧运行保留为证据限制，不补写成已发生。
实际报告接线与 ADR120 呈现欠条仍按 ADR121 单独验收；本记录不声称已兑现。

截至 PR218 的 `3ab9a36` 及其成功 CI，685 条选跑、80 条全跑，后者没有在本次迁移；完整 CI 15 分钟目标也没有达成。
本次只核证据和记录结论，不增加成功性能样本，不提交原始日志或 evidence 目录。
