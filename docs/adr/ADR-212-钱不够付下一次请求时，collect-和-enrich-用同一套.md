# ADR-212 钱不够付下一次请求时，collect 和 enrich 用同一套三行白话收尾

- 日期：2026-11-16 · 在 P3 红线测试隔离重写（ADR-208）里发现
- 类型：需求补全（给判据补上「说在哪、怎么说」）
- 触发它的事实：ADR-208 第四节 H1 —— P3.d 只说「断点保存成功才以 3 退出并声明已保存」，没说这句话说在哪、怎么说。
  没看过代码的那个会话不肯替判据选措辞，只断了退出码；现行的「断点已保存」四个字只有自检按字面钉着。
  两个入口原先各说各的：collect 说「余额不足以支付下一请求 … —— 断点已保存」再给一行命令，
  enrich 说「… —— enrichment.json 已保存，可提高总预算后续跑」、不给命令；「断点」「enrichment.json」都是内部词。
- 冲击的需求：D13（新增 D13.x）；P3.d 含义不变，它的「声明已保存」现在落到 D13.x 的第二行
- 结论：采纳。需求方 2026-11-15 在几种写法里选了「同一套三行」；2026-11-16 又定了前两行的准确说法（见第一节末）
- 连带改动：`scripts/lib/budget.ts`、`scripts/collect.ts`、`scripts/enrich.ts`、`scripts/lib/exit-codes.ts` 的注释、
  `skill/SKILL.md` 退出码表里 3 那一行、`docs/requirements.json`、自检、`scripts/test.ts`、变异目录

## 一、三行说什么

collect、enrich 因剩下的钱不够付下一次请求而停下、进度都存好之后，stderr 最后打这三行，两边同一套说法：

```text
⛔ 剩下的钱不够付下一次请求了（已花 $1.998 / 上限 $2），已停下。
✅ 进度已存好：已找到 7 位达人，已经拿到的搜索结果和已补完资料的达人下次不会再花钱重抓。
👉 想继续：npm run collect -- --resume output/x --budget <新总上限>
```

- 第一行的两个金额取汇总 JSON 里同一份费用（估算占用、总上限）。费用无从确认时不编金额，说出原因。
- 第二行说存了多少：collect 是名单里几位达人（记忆里标了已联系的不算，与汇总 JSON 的 `collected` 同数）；enrich 是已查好几个达人账号（含以前查过、存在缓存里的）、共几个要查（enrich 按平台账号查，一个人可能有两个账号，所以不说「位」）。
- enrich 带 `--refresh` 时缓存照样重查，刷新接不上上次的进度：照抄带 `--refresh` 的命令会从头重查。所以这一路第二行说「这次刷新了几个（共几个要刷新），刷新接不上上次的进度，再刷会从头重查」，第三行带上 `--refresh`。原先带了 `--ignore-memory` 的 collect，命令里也带上它，不然照抄会撞读不出记忆的 7。
- 第三行照抄就能续跑，必须带 `--budget` —— 光续跑会立刻再撞一次 3。占位写成 `<新总上限>`，与 Skill 里续跑那段同一个写法，提醒这是总上限、不是再加多少。

需求方最初选的前两行是「钱花到上限了」和「下次接着跑不会重复花钱」。复核指出两处说得比实际满，需求方 2026-11-16 改用现在的说法：

- 停下时常常还没花满（上例 $1.998 / $2）。F7.d 写明要提示「余额不足以支付下一请求」、没占满时不得说成用满 —— 第一行就是这句话的白话。
- 发出去却没拿到结果的请求，钱照算（D13.o），续跑时还会再试、再花一次。所以第二行只说「已经拿到的不会再花钱重抓」。ADR-22 批评过的正是把「已抓到的不重抓」说成「续跑免费」；续跑还要花多少，仍由紧挨在上面的 `resumeCostLine` 那句按实际剩余量说。

拼法只有一份：`budgetStopLines`，两个入口都调它；第二行冒号后面那半句（存了多少、续跑会不会重抓）由入口自己给，因为 enrich 的 `--refresh` 那一路说的是另一回事。它不收「没存上」的参数 —— 保存失败那一路以 6 退出、走不到调用点，第二行就只在真存好时出现。它的「花了多少无从确认」那一支两个入口今天都走不到（以额度不足停下，账必定先是可核的），留作防御，由单测守着。

collect 的三行上面紧挨着 `resumeCostLine` 那句「续跑还要不要花钱」，Skill 的退出码表让 Agent 把它们一起转述 —— 只转述三行，用户会把「不会再花钱重抓」读成「续跑不花钱」。enrich 没有这一句，Skill 只让它转述三行。

#498 上 CodeRabbit 第一轮又指出三处说满了或照抄续不上，都改了：

- collect 第二行原写「已经拿到的不会再花钱重抓」。补 profile 时资料没补完的人（`needsProfile`：没有简介或外链为空），续跑还会再查一次 profile、再花钱。现在写成「已经拿到的搜索结果和已补完资料的达人下次不会再花钱重抓」，「补完」与上面那句数「profile 没跑完」用的是同一个判定。第二轮 CodeRabbit 指出先改成的「补好外链的达人资料」还漏了有外链、没简介的人（同样会再查），改成现在这样，不再拿外链单说。
- enrich 第二行的「已查好」原先数的是 `enrichment.json` 里所有在名单上的账号。没有样本的旧条目续跑照样会查（只有带样本的才跳过），现在只数有样本的。
- 续跑命令里的目录原样拼进去。目录名由产品名拼成，产品名可以带空格和引号（D29 只挡 `/`、`\`、NUL），照抄进 shell 会被拆成几段。现在经 `shellArg` 包成一个参数：普通目录原样，带空格或引号的用单引号包住。collect 读不出记忆（退 7）那条修复命令也一样处理；那一路没有测试真把它跑出来（见第五节那张续挂的欠条），这一处只由同一个函数的单测守着。

collect 读不出记忆文件那一路（退 7，ADR-193）原先也有一句「本轮余额不足以支付下一请求」，改成「本轮剩下的钱也不够付下一次请求了，续跑时要用 --budget 给新的总上限」；它的修复命令占位也从 `<新额度>` 改成 `<新总上限>`，与三行一致。

## 二、为什么记在 D13 而不改 P3.d

判据「不改含义、不回收复用」（`process/1-REQUIREMENTS.md`）。给 P3.d 补上措辞会改它的字面，下游按它认领的检查就指向了别的东西。
三行说什么是费用输出的事，与 D13.w（新建任务缺预算时怎么告知默认 $2）同类，所以新开 D13.x，P3.d 原文不动。

D13.x 一条里写了三行加「保存失败时不打」，没拆：三行出自同一个函数的同一次调用，保存失败那一路走不到它，不会被不同的代码路径各自满足或各自弄坏（拆分判据见 `process/1-REQUIREMENTS.md`）。

## 三、退出改成自然结束

两个入口在 3（钱不够）和 1、2、5（运行中出错）这几支，原先打完 stdout 上的汇总 JSON 就调 `process.exit`；stdout 是管道时可能被截断（ADR-193「打完汇总仍调 process.exit」那张欠条）。本条改的正是这几行，顺手改成设 `process.exitCode`、自然结束，与达标（4）那一支、probe 一样。enrich 一侧新加变异 `M-P3-h`（去掉设 3 的那一行，就以 0 退出）守着。collect 一侧试过同样的变异：自检里好几处跑按「必须退 3」起，变异先撞上它们，判成「跑不起来」而不是被断言抓到，所以没登记 —— ADR-70 记的「退出码 3 拿不到负片」在 collect 一侧仍成立。

## 四、谁守着

- 自检 `cost-resume` 组：两个入口各真跑一次额度用尽，比对退出码 3 与 stderr 最后三行，金额与人数取 stdout 汇总 JSON 里的数（「钱不够付下一次请求停下：stderr 末尾三行…」那条断言），认领 D13.x。那几跑里几个数恰好相等，分不出取错了数，所以另有三跑的期望写成由夹具推出的字面数：collect 累加器 4 人、记忆里 1 人已联系，应报 3 位；enrich 4 个账号里 1 个有缓存、额度只够再查 1 个，应报已查好 2 个；同一夹具带 `--refresh`，应报这次刷新了 1 个、命令带 `--refresh`。enrich 夹具里另有一条没有样本的旧条目，不得算进「已查好」；collect 那一跑的目录名带空格和单引号，续跑命令交给 shell 拆出来须还是那个目录。
- `scripts/test.ts` 的 `p3-budget-token` 组：拼法单测（已花与上限各取各的数，费用无从确认时不写 `$null`）；`shellArg` 单测（普通目录原样，带空格、单引号的包成一个参数）。
- 变异 `M-D13-aj`…`M-D13-au` 与 `M-P3-h`：去掉第二行、已花写成上限、无从确认时照已知拼、collect 命令丢 `--budget`、enrich 把总数说成已查数、collect 报累加器人数、enrich 报本跑新查数、`--refresh` 时命令丢 `--refresh`、`--refresh` 时照常说已查好、enrich 把没有样本的旧条目算进已查好、collect 命令里的目录不包引号、单引号不转义、enrich 以 0 退出。逐个手改验过，都红。没有变异单独盖的：⛔、👉 两行本身（自检整行比对正面守着）、enrich 命令丢 `--budget`、命令里带 `--ignore-memory` 那一支、退 7 那一路的新措辞（那一路的自检夹具没撞上限，这句今天没有测试执行到，记在下面续挂的那张欠条里）。
- 保存失败那几路原先只查「已保存」「断点已保存」不出现；新说法是「已存好」「重抓」「不够付下一次」，这几条反面断言都补上了新字样，不然换了措辞它们就形同虚设。「运行中费用错误不伪装成余额不足」那条原先靠旧字样里的「余额不足」，也补上了新字样。
