## 二、git 入口做什么

1. **只答表里的那几问。** 表是 `git-entry.ts` 里的 `QUESTIONS`，每一行是一串参数的形状，旁边写着是谁要问。不在表里的当场抛错、不起 git，错里说出原样的参数并指到这张表。空位不许以 `-` 开头，调用方就没法借一个「修订」的位置塞进 `--output=` 这类开关。
2. **每次都带固定配置。** `GIT_CONFIG` 照旧放在 `size-rule.ts`（它是体量闸门的判定），由 git 入口统一带上；挪过来的文件不再各自拼。
3. **三种答法，外加一个简写。** `runGit` 原样交回退出码、输出字节与标准错误（要自己判退出码的用，例如 `git grep` 退 1 是「一处都没有」）；`gitText` 以 0 退出交回输出、否则交回空值；`gitOrThrow` 以 0 退出交回输出、否则抛错，错里带退出码与 git 的原话。`askGit` 是 `gitText` 去掉首尾空白，给 `resolveBaseline` 这类「问一句、答一行」的判定直接用。前三个可以给仓库目录、环境、标准输入；不给标准输入就不接。
4. **不解析输出。** 设计稿原想「按问题给函数、读不懂的输出一律抛错」。动手时看到：怎么切输出（`-z` 拆开、`--porcelain` 读哪几列）该在各判定模块里，大多已经在、各有测试与变异（`parseNumstat`、`changedFiles`、`grepOutput`……）；搬进 git 入口等于把判定挪出判定模块，违背 `docs/CONVENTIONS.md` 第 10 条。还留在入口里的一处（变异锚点拆 `cat-file --batch` 回话）本条挪进了判定模块，见第三节；另有几处入口自己切 `\0` 的（Skill 结构、起子进程接口闸门），切法只是按分隔符拆开，照旧留着。所以 git 入口管「能问什么、怎么起」，判定模块管「问哪一问、怎么读答案」。判定模块换了问法，表里没有就当场抛错，不会悄悄问成别的。

起子进程接口闸门入口这次改到了，ADR-217 那张「入口里几处出错的分支没有变异」响了，一起还：入口那组测试加两条（列文件那一问答不上来时说无从判断、以 1 结束；HEAD 就在主干上时待挪多了只报不判、以 0 退出），各配一条变异（`M-H220-p`、`M-H220-q`）。主干只有一个提交（`not-applicable`）那一支入口那组还没走到。

变异锚点（`anchors.ts`）这次改到了 `catBatch`，ADR-70 那张「anchors.ts 拆 cat-file 回话那几行留在入口」也响了，一起还：拆回话的那几行挪进 `mutate-rule.ts` 的 `batchBlobs`，拿手写的回话直接测，配四条变异（`M-H220-s`～`v`）。挪的时候改了一处：回话在半截断了的，原先会从头再读、错位，现在这一样和后面的都交 `undefined`。

没挪、留在「待挪」的 6 个：

## 四、拦不住的

- 还在「待挪」里的 6 个文件直接碰模块，起 git 这里管不到；写在字符串里、运行时落成文件再跑的代码也管不到（ADR-219 第四节）。
- 表里一行「能不能问」由评审判：新加一行要写的子命令、读给人看的输出，这里只有「子命令是不是只读的那几个」一条测试守着，开关是不是给机器读的那种靠评审读。
- `status` 会顺手刷新索引里的时间戳缓存（不改内容）。表里留着它，是打包准入读物要核「有没有没提交的改动」；严格说它不是纯读，这里如实写下。
- 空位只看「不以 `-` 开头」：`show` 的修订空位里填一个合法却不是调用方本意的修订、路径空位里填一个仓库外的路径，git 入口认不出，这是调用方自己的值。
- 形状比的是参数串，不是 git 怎么理解它：`rev-parse <修订>` 这一行也认 `rev-parse HEAD`，两行答法一样，不算洞。

## 五、它替代什么、什么时候撤

**替代的是「跑」**（`process/README.md` 第二层「一道闸门该不该建」）：判的是调用时的真值，表是闭集，不在表里的当场抛错，没有一张会随仓库悄悄变旧的名单 —— 判定模块换了问法而表里没有，下一次跑就抛。

> **什么条件下撤**：同 ADR-219 第五节，没有机器看得见的撤法（抛错只在写代码的人本机出现）。由人判：「待挪」清空以后，需求所有者读一遍第四节，看拦 git 的活是不是已经全由「只有 git 入口碰得到」接住；接住了，这张表可以只留「起 git 的统一入口」、不再逐串比形状；没接住就留着。
