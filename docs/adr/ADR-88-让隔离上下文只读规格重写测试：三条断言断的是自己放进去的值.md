# ADR-88 让隔离上下文只读规格重写测试：三条断言断的是自己放进去的值

## 起点：ADR-04 的重启条件，一直没兑现

ADR-04 把「测试与实现由同一上下文写成」登记为已知缺口，并写下重启条件：

> 由一个**清空上下文的新会话**只读 `docs/SPEC.md` 的验收标准重写测试，
> 与现有测试比对差异。**差异点就是污染的具体位置。**

从 2026-08-25 记下到 2026-09-19，这件事一次没做过。本条做了一次，对象是 **P1**（三态红线）。

## 先说一个改判据的发现：对人不可观测，对留痕的上下文可观测

`process/README.md` 第三层那张表写着「写测试时不许读实现 | **无法观测它读了什么**」。

**对人是真的。对一个会留下工具调用记录的执行者是假的** —— 它每读一个文件、跑一条命令，
都留在记录里，事后逐条翻得出来。

但这条不能写成「所以它可机器检查了」。**记录在仓库之外**，
`npm run check` 够不着它。诚实的三态说法是：

| | |
|---|---|
| 人 | 无法观测 |
| 留痕的上下文 | **可观测**，但要事后人去翻 |
| `npm run check` | 够不着 —— 记录不在仓库里 |

## 墙怎么砌的

不是「查它有没有偷看」（那是「读」那一侧，ADR-87 说不要建），
是**让它手里根本没有实现**：

1. 把准入读物拼成一个包，**放在仓库外面**。包里四份，就是 `4-VERIFY.md` 那张清单说的：
   需求条目与验收判据、类型声明（**函数体剥掉，只留签名**）、对外契约、
   变异集的「违反了什么」那一栏。
2. 扫一遍包，确认里面没有实现。
3. 告诉那个上下文：只读这个目录，**不要碰仓库，也不要听项目说明里那条「先读仓库文档」的路由**。
4. 事后翻它的工具调用记录核。

**核验结果 —— 那次运行的全部工具调用，原样抄在这里：**

```text
Read  …/scratchpad/pack/01-需求-P1.md
Read  …/scratchpad/pack/02-类型声明.ts
Bash  cat "…/scratchpad/pack/03-对外契约-输出格式.md"
Bash  cat "…/scratchpad/pack/04-变异集-违反了什么.md"
SubagentHandback  <最终回答>
```

上面这一段是**转录**，不是可审计的工件。它是从那次运行的会话记录里提出来的
（做法：逐行读 JSONL，取 `message.content` 里 `type` 为 `tool_use` 的项，打印
`name` 与 `input`），而**那份记录在仓库之外，不随提交走**。

所以这里能说的**只有这一句**：作者核过，并把核到的东西原样转录在上面；
**转录的完整性与真实性，提交树验不了。** 上面那张表的第三行说的就是这件事 ——
可观测、要人事后翻、`npm run check` 够不着。

**「作者核过」不等于「读者可以依赖」。** 前者是我的报告，后者要工件。
这正是这个仓库的总纲在防的那件事换了个位置出现：把「我查过、没发现」
说成「没有」。所以这条记录不写「墙挡住了，所以下面的结果算数」。

### 那下面的结果凭什么算数

**不凭这堵墙。** 下面每一条发现都是我事后**在树上逐条核出来的**，读者拿同样的
命令复核得了：

| 发现 | 读者怎么核 |
|---|---|
| 三条空断言 | 读 `scripts/test.ts` 的那三行和 `:175` 的夹具构造器 |
| `bio` 的空串不是一个态 | 读 `scripts/lib/types.ts:236` 与它上面那段文档 |
| 排序方向没有判据 | 读 `ADR-71:122` 那张欠条和 `scripts/test.ts:2456` |
| 四处真空白 | 在 `scripts/test.ts` 里搜那几样，搜不到 |

**隔离上下文的作用是提出假设，不是证明它们。** 墙挡没挡住，影响的是
「这些假设有多大概率是从一个没被污染的视角提出来的」——
不影响「它们是不是真的」。后者已经在树上核过了。

## 一、三条空断言 —— 最硬的那个发现

`scripts/test.ts` 的 P1 第一个 suite 里：

| 行 | 断言 |
|---|---|
| 218 | `ok('bio 未取到时为 undefined', notFetched.bio === undefined)` |
| 219 | `ok('bio 取到但为空时为空串', fetchedEmpty.bio === '')` |
| 225 | `ok('未知与 0 在类型上可区分', unknown.followers === undefined && zero.followers === 0)` |

这三条断的是**它自己上一行刚放进去的值**。夹具构造器 `mk`（`scripts/test.ts:175`）
是个纯展开，不做任何变换 —— **这三条无论实现怎么写都绿。**

隔离上下文为同一批判据写的断言，全部跑过真函数（补全映射、`needsProfile`、
渲染、粉丝闸门），期望值逐条指回判据原文，并且它主动标出了哪几条指不回去。

**这就是同源污染的形状**：写的人知道那个值是自己放进去的，
所以没觉得需要让它过一遍实现 —— 而一个不知道实现长什么样的上下文，
根本没有「把值放进去再断言它还在」这个选项。

## 二、一处契约与测试对不上

`scripts/lib/types.ts:236` 写着 `bio?: string | null`，三态是
undefined（没查过）／null（查过、对方没写）／有内容的字符串，
并且文档明写「`signature`／`biography` 是空只说明对方没写」。

而测试断言的是「bio 取到但为空时**为空串**」，`mk` 的默认值也是 `bio: ''`。
**`''` 在那份契约里不是一个态。**

隔离上下文读的是同一份契约，它写的是 `strictEqual(P0.bio, null)`。

**是测试错了还是契约错了，本条不定** —— 那要需求所有者拍。

## 三、它独立撞到了一张还欠着的欠条

隔离上下文说 P1.f 只写了「不得共用同一个排序键」，**没说哪个在前**，
于是它拒绝替判据选一个方向，只断言「先后确定且不相等」
（手法是同一对输入正序逆序各排一次 —— 比较器若返回 0，稳定排序会跟着输入顺序走，当场露馅）。

而 `ADR-71:122` 那张欠条说的正是这件事，重启条件是「需求所有者确认（写进 `U1` 的判据）」——
**还欠着**。现有测试 `scripts/test.ts:2456` 断言了一个具体方向。

**一个从规格出发的干净上下文，独立走到了污染上下文早就登记过的同一个缺口。**
这比任何论证都更能说明那张欠条是真的。

## 四、四处真空白

逐条核过，现有测试确实没有：

- **持久化往返**：`undefined` 与 `null` 过一趟 JSON 还分不分得开。
  续跑读的是 `creators.raw.json`，正确性直接压在这个往返上。
- **能力计数的恒等式** `total = measured + unavailable + unqueried`。
  `unqueried` 一旦并进 `unavailable`，报表上再也分不出「没查」和「查了测不出」，而总数看不出来。
- **评分侧**：未查询的输入维度不得折算成任何具体值。
  隔离上下文建议把这条补成判据 —— 而现有 `scripts/test.ts:224` **恰恰断言
  「未知」与「0」得分相同**，两者的方向是反的。
- **采集侧的响应解析**：P1 的 a–g 七条一条都没管到它。

## 五、它提的有几条已经有了

`asMemoryStatus` 的白名单测试有（`scripts/test.ts:1472`），
合并时未知不得静默相加有（`:232`），
松断言的风险在这个仓库结构上不存在（`eq` 走 `JSON.stringify`，实测分得开 undefined 与 null）。

**这三条说明它不是在瞎提** —— 它提的东西有真有假，而真假是核得出来的。

## 包本身缺一样

隔离上下文反复说同一句话：**写得出断言，写不出测试骨架。**
包里只有三个导出函数的签名，而判据和契约里点到名的函数（补全、`needsProfile`、
跨平台合并、粉丝闸门、评分、各渲染器）都没有签名。

缺的是一份**导出清单**：函数名加签名，不含函数体。这不是判据的问题，是包的问题。

## 没做的

本条只做测量与记录，一条测试都没改。

- ⚠️ 欠条：**那三条空断言还在。**
  重启条件：下一条要动 `scripts/test.ts` 里 P1 第一个 suite 的改动，或者本条合入后的第一条改动。
  ⚠️ 这张欠条已还：三条都换掉了，改成过一趟采集累加器（`saveRawCreators`／`loadRawCreators`），
  由 ADR-90 还上。换的不是断言的写法，是让它们真的走一条实现路径。
- ⚠️ 欠条：**`bio` 的空串那一态与类型契约对不上，没有裁决。**
  重启条件：需求所有者确认（写进 `P1.a` 的判据），或下一条要动 profile 补全映射的改动。
  ⚠️ 这张欠条已还：需求所有者 2026-09-19 裁决 —— **`''` 不是一个态**，夹具默认值改成 `null`，
  由 ADR-91 还上。**结案条件就是这两件：裁决 ＋ 夹具跟上。**
  括号里那半句「写进 `P1.a` 的判据」**取消了，不再是结案条件** —— `P1.a` 讲的是 email，
  往里塞 bio 会改掉那个编号的含义，而编号不许改含义。理由写在 ADR-91 第三节。
- ⚠️ 欠条：**评分侧与采集解析侧没有判据**（隔离上下文建议补两条）。
  那是需求变更，走评定，不在本条范围。
  重启条件：下一次要动 `docs/requirements.json` 里 P1 的改动。
- ⚠️ 欠条：**四处真空白一条测试都没补。**
  重启条件：本条合入之后的下一条改动，或者其中任一处真的坏了一次时。
  ⚠️ 这张欠条**还了三处**：持久化往返、能力计数、采集解析，由 ADR-90 还上。
  **评分侧那一处仍然欠着** —— 它和 `scripts/test.ts` 里「未知与 0 得分相同」那条方向相反，
  补哪一边都等于替需求所有者拍板。重启条件跟着上面那张「评分侧没有判据」的欠条走。
- ⚠️ 欠条：**包还是手工拼的，没有做成命令，也没有导出清单。**
  重启条件：下一次要对第二条需求做同样的事时 —— 手工拼第二遍就该做成工具了。
- **`process/README.md` 第三层那张表还写着「无法观测它读了什么」。**
  上面第二节已经说明那句话对留痕的上下文不成立，但本条没有动那份流程档 ——
  一条记录只做一件事，而且改流程档是跨项目的改动，该单独评定。
  ⚠️ 欠条：**流程档里那条理由已经不完整，还没改。**
  重启条件：下一条要动 `process/README.md` 第三层那张表的改动，或者本条合入之后的第一条改动。
  ⚠️ 这张欠条已还：那一行的理由换成了「证据在提交树之外，但后果削弱得了」，由 ADR-89 还上。
  顺带接回了 `ADR-04:12` 早就写下、而流程档丢掉的那半句 —— 变异测试是他评不是自评，
  但变异集也出自同一上下文，所以是削弱不是消除。
- **只做了 P1 一条需求。** 其余红线与口径类需求没走这一遍。
  ⚠️ 欠条：**其余需求没做过隔离重写。**
  重启条件：包做成命令之后，或者下一次有红线需求变更时。
