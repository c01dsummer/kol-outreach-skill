# ADR-73 验证者那几百个进程共用一份 V8 编译缓存

- 2026-09-09 · 接着 ADR-72 往下量，同一次「check 太慢」的请求
- 类型：扩范围（新跑法）—— 不改任何一条判定
- 冲击的需求：无
- 结论：**采用**。指一个绝对路径给 Node 自己的编译缓存，让几百次验证者跑共用一份

## 为什么它不是「用过期结果」

这是采用一份缓存时唯一要回答的问题，先答它。

缓存里装的是 **V8 把一段源文本编译出来的字节码**，条目由 Node 按
「源文本 ＋ Node 版本 ＋ V8 参数」自校验，对不上当场重编。里面**没有任何
「上一次的结论」** —— 不是「这条变异上次被抓到了」，是「这段字节码是这段源码编出来的」。

于是那个最要紧的问题（「一条变异改过的文件，会不会命中未改之前的缓存」）答案是不会：
源文本变了，键就变了。**实测**：一次完整跑（302 条变异）在冷缓存上全部被抓到，
之后每一轮都在热缓存上跑，仍然全部被抓到 —— 缓存要是替旧源码作了证，
那些变异会集体「存活」，而那是响的。

隔离机制：路径指的是主仓库的 `.check-cache/compile-cache`（gitignored）。
跑在隔离目录里的那几个 worker 各有各的 cwd，**所以必须是绝对路径** ——
不指绝对路径就成了几份互不相通的缓存，白建。已经有人在外面指了一份的，用人家那份。

## 收益与代价

同一台机器、同样的口径（各预热 1 次再量 3 次，见 ADR-72 的「收益」一节）：

| | mutate 均值 | check 均值 |
|---|---|---|
| 只有派工（ADR-72） | 227.823s | 273.062s |
| 加上本条 | **205.538s** | **251.468s** |

mutate 再省 22.3 秒（1.11 倍），check 再省 21.6 秒。相对基线合起来是 mutate 3.13 倍、
check 2.74 倍，一次 check 省 437.7 秒（−63.5%）。

**墙钟与 CPU 分开看**：派工那一条没省 CPU（每条变异 +1.2%），它换的是墙钟；
本条是真的少干了活 —— 每条变异的 CPU（user＋sys）2.539s → 2.262s，**−10.9%**。

⚠️ 秒数只在这台机器上成立。

代价是磁盘：本仓库这批源码，一次完整跑之后缓存约 16 MiB。它只增不减 ——
Node 不替我们收，删掉 `.check-cache/compile-cache` 就重新长出来。

## 没验过的边界

- `NODE_COMPILE_CACHE` 是 Node 22.1 起才认的环境变量。更老的 Node 会**当它不存在**，
  于是这一条静默地什么也不做 —— 不是坏，是没有收益。本仓库钉的是 v22
- 只在 Linux 上量过
