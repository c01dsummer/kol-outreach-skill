# ADR-204 旧记录里的工单号对照，其余各处撤掉工单号

- 日期 · 2026-11-15
- 类型：一次清理。不动任何需求的含义、判据的条件、断言逻辑或产品行为；`docs/requirements.json` 里改的只是括号里的出处写法
- 触发它的事实：需求所有者丸子 2026-11-15 06:21Z 在项目线程里说「KOL ticket下可以有相应的ADR，但ADR是我们repo内独有的，不该和某个外部工具有关联」，06:46Z 又说「linear可以用adr的号 反过来不行」。调研时主干 `d153df5` 上共有 392 处外部任务工具的工单号（23 个不同的号）：决策记录里 313 处，`scripts/` 里 66 处，需求登记表 5 处与照它生成的 `docs/SPEC.md` 5 处，`docs/ARCHITECTURE.md` 2 处，工作流文件 1 处；`skill/` 里没有
- 决定人与时间：需求所有者 06:47Z 在决策卡「仓库里现有的 392 处卡号怎么处理？」上选「可改的改，旧 ADR 加对照」，06:48Z 补一句「旧adr也要防止它们后续继续追加卡号」，06:58Z「改吧」
- 结论：采纳。本条做三件：可改的地方撤掉工单号（第一节）；旧决策记录正文不改，在本条列出每个号在仓库里指的是什么（第二节）；以工单号写重启条件的十张欠条，在本条换成仓库里能核的说法（第三节）。规则本身与防回流的检查是下一条记录、下一条 PR 的事 —— 那条改 `process/`，按 `process/2-CHANGE.md`「文档同步规则」不与本条的代码注释改动混在一条 PR 里；它的检查按文件记数、只许减不许加，本条第二节这张对照表的号就随本条合入算进它的起点。人批痕迹：需求所有者合入本条那条 PR
- 理由：工单号只在开 Linear 时才说得出意思，而且号的意思会漂：仓库里写「KOL-21」的那 39 个文件说的是独立黑盒测试包、零请求观察器那一大串工作，那张卡在 Linear 上的标题却还是建卡时的「自检夹具与工具清单：wiring 接线」。决策记录追加不删改（`docs/adr/README.md` 前言），旧文里的号只能留着，于是在仓库里给它们一张对照表，读旧文的人不开 Linear 也知道说的是哪件事
