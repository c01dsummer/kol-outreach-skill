# ADR-133 成本入口夹具把只剩一个线程的僵尸算作已结束

- 日期：2026-10-07 · #266 合入后的复核提出（ADR-132 第九节「复核发现六」），本条是它的裁决
- 类型：既有缺陷（响的误红）。`mutation-cost-entry` 夹具把已经不会再执行的僵尸算成活着，在回收孤儿慢的环境里判红；CI 上是绿的。为什么不走 `process/6-INTEGRATE.md`「主干红了」，见第二节
- 触发它的事实：现象 ADR-131「本机完整检查」一节早已记下 —— tsx 起的 `esbuild` 子进程成了孤儿，以 `Z` 态、父进程为 1 留在进程表里，夹具用 `kill(pid, 0)` 判活，僵尸也算活。本条新增五件事（第一节）：容器的 1 号进程回收孤儿有延迟；套上及时回收的包装再加负载也红过，留下的仍是僵尸；判红那一下在 close 当刻立即算，没有容忍窗口；ADR-132 第七节对 CI 的推论前提不成立（变异那一步执行这一组的路由是 0 条）；`/proc/<pid>/stat` 写着 `Z` 不等于整个进程不再执行
- 冲击的需求：无。该组不认领业务判据（`docs/ARCHITECTURE.md`「成本入口组」一段）；两条具名断言的标签不变
- 结论：**采纳。** 新增判定 `processEnded`，放进 `scripts/check/jobs-rule.ts`：0 号信号得到 `ESRCH`，或者 `/proc/<pid>/stat` 写着状态 `Z` **且线程数为 1**，才算已结束；读不到、认不出一律不算结束。判定连同测试与变异是下一条 PR，`mutation-cost-entry` 夹具的接线是再下一条 PR；本条只放裁决（第四节）
- 理由：夹具要守的是「删夹具目录之前，没有自有进程还会执行、还会写盘」，而 0 号信号送达只说明进程表里还有这一项。两者在僵尸上分叉：只剩一个线程的僵尸不会再执行任何代码，却被判活。改环境（套包装）只缩短僵尸停留的时间，负载下照样撞上；改判定才对准断言本身
- 连带改动：ADR-132、ADR-131 末尾各追加一块更正，ADR-121 末尾追加一行指针，`docs/adr/README.md` 索引回写。其后两条 PR 各要改哪些文件，见第四节。`docs/SYNC.md`「查到新事实」那一行的另两项：`docs/data-source-strategy.md` 与 `docs/SPEC.md`「尚未确定的」一节都与检查链夹具无关，不适用
- 教训：用一个代理量判一件事（这里是「0 号信号送达」代「还会执行」），先核两者在边界态上会不会分叉；拿另一步的绿给这一组作证之前，先核那一步到底跑没跑这一组

本条的实测都在同一类容器里：Linux 6.18 x86_64、4 核、Node 22.22.0、root、1 号进程是 `process_api`，可能有别的会话同时在跑。代码树是 `5e4e43c`，其中 `scripts/check/selfcheck.ts` 与本条所在 PR 的父提交 `5a2000d` 逐字相同。裁决之前的设计与两份审查是同一个工作流里的几个上下文做的，不是独立复核；下面凡是本条作者没有复跑的，都注明了。每个场景只跑了几次到十几次，给的是次数，不是比率。

## 一、事实与证据

**1. 不套包装单跑这一组，每次都红。** `npx tsx scripts/check/selfcheck.ts --only=mutation-cost-entry`：设计阶段在 `5e4e43c` 上跑了 7 次加 1 次，本条作者在 `5a2000d` 上又跑 1 次，全红。红的是两条具名断言「成本入口独立夹具资格」与「成本入口自有进程全部结束后才删除夹具」，失败详情里 `unexpected` 为 `true`、`living` 剩一个 pid。设计阶段插桩的 3 次都看到留下的是 `esbuild`、`Z` 态、父进程为 1；本条作者那一次没有核那个 pid 是谁。

**2. 1 号进程回收孤儿有延迟。** 设计阶段测了 8 个孤儿，以僵尸停留 1.67–1.81 秒（墙钟）才被回收；本条作者没有复跑。这组读数没有对应的 CPU 时间可报 —— 量的是僵尸等 1 号进程来收的那段空档，僵尸自己在这段时间里不执行；墙钟随机器和负载变（`REVIEW.md`），所以本条只拿它说明「有延迟」，不拿区间的大小推任何结论。这解释了第 1 条为什么是每次都红而不是偶发 —— 判红不等这段时间（第 4 条）。

**3. 套上及时回收的包装再加负载，也红过。** 包装与 ADR-131「本机完整检查」用的是同一种：Python 的 `prctl(PR_SET_CHILD_SUBREAPER)` 加一个 `waitpid` 循环。空闲时套包装 3 次都绿；加负载时原树 17 次里红 2 次，两次 close 当刻留下的都是 `esbuild` 僵尸，其中一次核实了它的父进程就是包装，另一次没核。这 17 遍的日志里一共记了 98 次 driver close，没见到 `S` 或 `R` 态的残留，但不能排除。以上都是设计阶段的实测，本条作者没有复跑。负载拖慢的是回收的时刻，误红的机制仍是僵尸。

**4. 判红那一下没有容忍窗口。** `scripts/check/selfcheck.ts` 第 6678 行（树 `5e4e43c`）在被测入口 close 的那一刻就算 `unexpected=living.length>0`；紧接着那段「杀掉、每 20 ms 再看一次、最多 50 次」的循环，只决定写进结果的 `living`，不决定 `unexpected`；第 6681 行两者任一成立都以 86 退出，外层第 6757 行据此判「独立夹具资格」红。所以约 1 秒是杀掉之后等进程消失的上限，不是判红前的宽限。ADR-132 第 35 行（「等子进程退出约 1 秒」）与第 112 行（「等子进程退出的约 1 秒窗口」）把这一秒写成判红前的等待，与代码不符。

**5. 变异那一步不执行这一组。** ADR-132 第 286 行的推论是「CI 上变异那一步本来就在另外三个 worker 满负载时跑这一组的基线，近几次都是绿的」。用 `executionRoutes` 逐条算真实 `mutations.json` 的路由，执行 `mutation-cost-entry` 的路由在 `557b3e5` 与 `5e4e43c` 上都是 0 条（两树的总路由数依次是 987、1007）。复跑命令只留一份，在 ADR-132 末尾「复核发现六」更正块的第二条。

`docs/ARCHITECTURE.md`「成本入口组」一段也写着「现有变异的选组闭包不依赖它」。所以 CI 上变异那一步的绿，对这一组在负载下的表现什么也没说明；每次 CI 运行里，这一组只在完整自检里跑一遍。

**6. 状态 `Z` 不等于整个进程不再执行。** 审查给出反例，设计阶段复现过：线程组的头线程用 `pthread_exit` 退出、另一个线程接着写盘时，`/proc/<pid>/stat` 的状态是 `Z`、第 20 段（线程数）是 2，0 号信号照样送达；进程处于 `Z` 期间日志从 5 行涨到 20 行，最后写满 30 行（本条作者没有复跑）。真僵尸的线程数是 1：一个运行时有 7 个线程的 node 整体退出、还没被回收时，是 `Z`、线程数 1。所以「僵尸不执行，算结束不会放过任何东西」只在加上「线程数为 1」之后才成立。

**7. 没排除的。** close 当刻 `esbuild` 真的还在跑（`S`／`R`）的那种竞争没有排除；审计原本报的场景（非 root、不套包装的整跑）没有复跑；GitHub runner 上孤儿被谁收养、多久回收，没有实测。

## 二、档、路由与为什么改夹具

**档：既有缺陷。** ADR-131 第 104 行记着，拆进程之前的 `8df080a` 上单跑这一组已能原样复现，不是 #266 引入的；按 `6-INTEGRATE.md`，合入之后才到的意见没有「本改动」档。

**不走「主干红了」。** `6-INTEGRATE.md` 既有缺陷那一行说「会让检查说假话或让主干不可发布的，走『主干红了』」。这一条两样都不是：CI 上是绿的，主干可发布；它错在响的一侧 —— 把一个其实收干净了的入口判红，不会让一个坏改动混过检查。后果是在回收慢的容器里本机完整检查停在 selfcheck、审计跑不到，人得知道去套包装。按同一份文件的排序，会让检查静默给出错误结论的排在前面，这一条不在那一类里。

**按 `2-CHANGE.md` 的两个判别问题。**
- 用户拿到的信息变少、变模糊了吗？没有。改前在回收慢的容器里这一组每次都红；设计阶段的原型不套包装单跑这一组 3 次都绿（第五节）。改后完整检查能不能跑完没有核：审查以 root、不套包装跑过原型的完整自检，拆进程与 `SELFCHECK_JOBS=1` 各一次，这一组都绿，仍红在 root 下已知必红的「模板入口-保存屏障合法阳性」（ADR-131 第 74 行）；跑的是原型哪一版、有没有同条件的基线整跑对照，设计材料没写明，本条作者没有复跑；非 root 的整跑没有跑。两条具名断言的标签不变；失败详情从只打 pid，变成带每个观察进程读到的 stat 原文或读失败的原因（接线那条 PR）。唯一的收窄是第六节欠条三那种情形，如实登记。
- 如果这件事很容易做，还会提吗？会。容易的那条路是改环境（包装、`tini`），而第一节第 3 条说明回收及时时负载下也红过：问题在夹具用的代理与断言要守的东西不一致，不在环境。

**按 `4-VERIFY.md`「测试失败时」：为什么改的是夹具。** 改夹具默认驳回，所以理由写在这里：改的不是任何断言的期望，是夹具判活所用的代理，把「活着」收窄成「还会执行代码」。负片照旧红 —— 设计阶段的原型往被测的玩具验证者里临时注入一个 `detached`、长睡的 node 子进程，仍红出「成本入口独立夹具资格」，那条记录的状态是 `S`（本条作者没有复跑）；头线程退出、别的线程还在跑的情形，要由判定那条 PR 的单元断言与变异守住。

## 四、裁决与交付顺序

1. **本条**：只含文档，先合，编号由此固定。
2. **判定那条 PR**：`scripts/check/jobs-rule.ts` 紧接 `ownGroup` 之后新增 `ProcessProbe` 与 `processEnded`。规则是：0 号信号得到 `ESRCH` 算结束；有 stat 正文时，从**最后一个** `)` 之后切段，第一段是 `Z`、第 18 段（stat 的第 20 段，线程数）是 `1` 才算结束；没有正文、没有 `)`、段数不够，一律不算结束。放在这里，是因为它与 `ownGroup` 读同一种正文、用同一种切法（ADR-74），而 `selfcheck.ts` 在验证基础设施闭包里，判定只有住在规则模块里才有变异守着（`docs/CONVENTIONS.md` 第 10 条）。期望值手推，先对着只看 `ESRCH` 的桩看红，再看绿，再逐条施加新变异。`docs/ARCHITECTURE.md` 锚点行写明「判定已就位，接线另开」，免得接线合入之前主干上有一句假话。预计改的文件：`scripts/check/jobs-rule.ts`、`scripts/test.ts`、`scripts/check/mutations.json`、`docs/ARCHITECTURE.md` 锚点表 `jobs-rule.ts` 那一行。
3. **接线那条 PR**（最后一块砖）：`mutation-cost-entry` 的外层、driver、收尾三处都改成先读 `/proc/<pid>/stat`、后发 0 号信号 —— 反过来的话，信号送达之后、读状态之前僵尸恰好被回收，就读不到正文、判成「不算结束」，又是一次误红。driver 只记下 close 当刻与杀完之后两组读数，判定在外层用 `processEnded` 做；两条具名断言的标签一字不改。证据按 `6-INTEGRATE.md`「改验证成本时」给可比实跑：本类容器里不套包装，基线红、改后绿；套包装时基线与改后交替各跑三次以上，同口径列墙钟与 CPU，比不成的写「无从比较」；负片（注入一个还会执行的进程）照旧红；完整检查在 CI 上跑通。合入时在本条末尾追加落地块，在 ADR-132 末尾追加「复核发现六」的已还块，并把锚点行改成接线的说法。预计改的文件：`scripts/check/selfcheck.ts`、同一锚点行、本条末尾的落地块。
4. 接线合入之前，本类容器里跑本机完整检查仍要套 ADR-131 那种包装。

## 五、已知代价与边界

- **等待会等满。** 接线之后，回收慢的容器里，僵尸对 0 号信号不会给 `ESRCH`，driver 杀完之后那段「最多 50 次、每次 20 ms」的等待每跑一次都等满，墙钟变长。以下计时都是设计阶段测的，本条作者没有复跑。原型在这类容器里不套包装跑了三次：墙钟 21.3–22.4 秒，CPU 17.1–18.3 秒（外层 `getrusage(RUSAGE_CHILDREN)`，不含被 1 号进程收走的孤儿）；基线这时是红的、提前退出，无从比较。套包装时基线与原型交替各三次：墙钟 17.7–18.7 秒对 17.5–29.6 秒（29.6 那次离群没定位），CPU 17.1–17.7 秒对 16.8–18.6 秒，看不出差异。数随负载漂，不写成这次改动的固定代价。去掉这段等待要把等待条件复制进 driver 字符串，同样没有变异守着，这次不做。
- **接线不会有变异守着。** 它会落在 `selfcheck.ts` 里，属于验证基础设施闭包。有人把读数改回只发 0 号信号、或对调读状态与发信号的先后，单元断言与变异都不会红，只有在回收慢的容器或负载下实跑才看得见。
- **只在 Linux 上把僵尸算结束**（欠条二）；**一处收窄**（欠条三）。
- **另一种来源不在本条范围。** close 当刻进程真的还在跑的那种竞争（第一节第 7 条）本条救不了，所以 ADR-132 第 288 行那张时间窗口欠条对两组照旧有效，本条不还它。
- **独立性。** ADR-121 第 101 行记着这个夹具原由独立作者只读公开合同、事前冻结。判定与接线将以设计阶段的原型为底，与它出自同一个工作流，预计不是独立作者；新测试与实现实际由谁写，在各自的落地块里如实记（`process/4-VERIFY.md`「标出干净的那些」）。这一组不认领业务判据，不触发红线改动必须独立复核那条；ADR-121 末尾追加了指向本节的指针。

## 六、欠条

「复核发现六」本身的欠条在 ADR-132 第九节，本条不另登一张同题的，免得两处各挂一份（ADR-131「复核发现三」记过同一组欠条重复登记的问题）。下面三张是这条裁决新带出来的。

> ⚠️ 欠条：`claims-restoration-entry` 的两处判活（`scripts/check/selfcheck.ts` 第 6251 行的 `ended`、第 6449 行控制器串里的 `gone`，树 `5e4e43c`）仍只看 0 号信号，僵尸算活着；设计阶段在本类容器里裸跑过这一组一次，是通过的，没有它的误红证据 · 重启条件：该组在任何机器上出现「自有进程没结束」一类的判红时，先读留下进程的 `/proc/<pid>/stat`，是只剩一个线程的僵尸就改用 `processEnded`

> ⚠️ 欠条：接线合入后，僵尸算结束也只在读得到 `/proc/<pid>/stat` 的 Linux 上成立，其余平台照旧只看 0 号信号 · 重启条件：非 Linux 机器上 `mutation-cost-entry` 出现「进程树没收完」一类的误红时

> ⚠️ 欠条：僵尸的父进程还活着、但不在观察集合里时（例如被测入口经 shell 起 node），接线合入后不再报；在那之前它是被「僵尸算活着」顺带报出来的 · 重启条件：被测入口改为经 shell 或其他非 node 进程起 node 子进程时，或观察记录里出现父进程既不在观察集合里、也不是 driver 的进程时

## 七、落地（2026-10-07）

本节随接线那条 PR 合入，第四节第 2、3 步到此都落了地。

- **判定**（#271）：`scripts/check/jobs-rule.ts` 的 `ProcessProbe` 与 `processEnded`，`scripts/test.ts` 的 `h-jobs` 组一条 harness 下 12 条断言，变异 `M-H40-q` 至 `M-H40-x`。先对着只看 `ESRCH` 的桩看红（红的正是三条该算结束的僵尸），换回实现后绿；八条变异逐条施加，`kills` 点名的断言都红。
- **接线**（本节所在 PR）：`mutation-cost-entry` 的外层、driver、收尾三处改成先读 `/proc/<pid>/stat`、后发 0 号信号；driver 只记 close 当刻（`atClose`）与杀完之后（`afterKill`）两组读数，判在外层用 `processEnded` 做。两条具名断言的标签一字未改；失败详情从只列 pid 变成带每个观察进程的 stat 原文或读失败的 errno。`docs/ARCHITECTURE.md` 锚点表 `jobs-rule.ts` 那一行改成接线的说法。
- **谁写的**（第五节「独立性」）：判定、断言、变异与接线都以设计阶段的原型为底，与本条出自同一个工作流，不是独立作者。本条作者按第四节拆成两条 PR，在下面的树上重跑了证据；第五节里原型阶段的数没有拿来充当这里的证据。
- **实跑证据**（`process/6-INTEGRATE.md`「改验证成本时」）：同类容器（Linux 6.18 x86_64、4 核、Node 22.22.0、root，1 号进程 `process_api`），跑的过程中 1 分钟负载均值从 0.54 升到 0.95。基线是 #271 的头提交 `a0b6c50`（判定已在、夹具未接；树与 #271 合入后的主干 `03d07ff` 逐字相同），改后是它加本 PR 的 `selfcheck.ts`。命令都是 `npx tsx scripts/check/selfcheck.ts --only=mutation-cost-entry`；墙钟与 CPU 由外层 Python 计，CPU 取 `getrusage(RUSAGE_CHILDREN)`，不含被 1 号进程收走的孤儿。
  - 不套包装，基线与改后交替各 3 次：基线 3/3 红，两条具名断言都红，各留下一个 pid；改后 3/3 绿，墙钟 19.17–20.80 秒，CPU 14.91–16.74 秒。基线在 close 当刻就判红、提前退出（墙钟 3.60–4.09 秒），无从比较。
  - 套 ADR-131 那种包装，基线与改后交替各 3 次，全绿：墙钟 15.09–15.46 秒对 15.35–15.62 秒，CPU 14.26–14.63 秒对 14.37–14.74 秒，看不出差异。改后不套包装比套包装多出的几秒，第五节归给「等待会等满」；这次没有逐段计时核实。
  - 负片：往玩具验证者里临时注入一个 detached、睡 4 秒的 node 子进程，改后的树不套包装、套包装各跑 1 次，都红出「成本入口独立夹具资格」。close 当刻那组读数里，注入的 node 是 `S` 态，判为没结束；不套包装那次还读到一个 `esbuild` 僵尸（`Z`、父进程 1），判为已结束。第二条具名断言两次都绿（driver 杀掉了注入的进程，夹具目录已删）。注入已还原，不在本 PR 里。
