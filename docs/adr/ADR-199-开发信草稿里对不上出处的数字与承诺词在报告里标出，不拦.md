## 一、三个候选

1. **导出时标出，不拦（选了这个）。** 底本是任务里已证实的产品事实；render 扫每封草稿里像产品事实的说法，对不上的列在评审 HTML 那封信旁边；存进邮箱前的确认也带上这一行。
2. **同样比对，对不上就拦。** 那一封不能存进邮箱，导出里标「待查」，改成占位符或补出处才放行。驳回理由：日常数字（two weeks、one post）难免被抓，误报会挡路。
3. **Agent 写信时逐条登记出处，脚本核对，再加扫描补漏。** 驳回理由：评审正本格式要改、旧评审要迁，Agent 写信更慢，登记本身也会写错；改动最大。

## 二、决定

1. **底本用现成的 `brand_calibration.sources` 里 `kind=verified_product_fact` 的条目，不另加字段。** 这一格本来就定义成「商品页或产品资料实际证实的产品事实」，`outreach-draft.md` 原来也要求产品说法「须能指回 `kind=verified_product_fact` 或商品页原文」。改的是 `product-intake.md`：读了商品页，就把卖点、规格、价格、保修这些原文逐条写成这一类条目，不再只在「用户给了官网、附件或品牌偏好」时才写校准。
2. **扫什么。** 草稿去掉 `{…}` 占位符之后：带数字的说法（数字、数字加单位、价格、IPX7 这类字母数字串；千分位只认三位一组，`.5` 也算数；拼写出来的数字从 one 到 ninety-nine 加 hundred、thousand，只在后面跟单位时才算，「ten seconds」算、「one post」不算），和一张固定词表里的承诺词（warranty、guarantee、refund、money-back、free shipping、certified、patented、FDA、BPA-free、organic、waterproof、#1 等）。
3. **对什么。** 已证实产品事实的原文，加上这位博主自己作品的文字（第一句引用他作品里的数字不是产品事实）。数字按值和单位比：`400 mL` 与 `400ml`、`10 seconds` 与 `ten seconds`、`29.99 USD` 与 `$29.99` 都算对得上；有一边没写单位时同数即可，两边单位不同（400ml 对 400 g）不算。价格对价格或不带单位的同数，币种不比。型号串整串对，不按子串（H1 对不上 H13）。承诺词按词干比。品牌偏好（`brand_preference`）不算出处。
4. **出在哪。** 只在评审模式 HTML、有草稿的卡片的草稿块里单列一行「出处对不上：…」，按出现先后、同一写法只列一次；都对得上写「无」；任务里一条已证实的产品事实都没有时（扫没扫到都一样），前面写明「任务里没有已证实的产品事实可对」，不让人把「全都对不上」读成比对过的结果。没有草稿或草稿只有空白不出这一行，默认模式不出（U9.a）。
5. **只标不拦。** 草稿一个字节都不改（P2.b），render 照常以 0 结束。

## 三、实现者替需求所有者选的默认

合入即认；想改，合入前说一句即可。

1. **评审 CSV/XLSX 不加列。** 加一列要改 U9.k 逐个点名的表头字面（像 ADR-190 那样退役一条换新字母），本条只在 HTML 里出。重启条件：运营要在表格里按这一项筛，或邮箱那一步只能从表格取。
2. **改了已证实的产品事实，所有已评账号变成待重评。** 这是校准按内容算版本号带来的（D20）；待重评的账号基础分层是 B（D21.q），A 级草稿要重评后才回来。放在校准里换来的是不加新字段、不加新命令；`outreach-draft.md` 写明开写草稿前先确认产品事实记齐了。重启条件：用户反馈补一条产品事实就要整批重评太重。
3. **词表固定写在代码里，不让用户配。** 重启条件：某个品类的常见承诺词（比如护肤的「fragrance-free」）屡次漏扫。

## 四、按改需求逐条评定

- 红线：P2 收紧了「看得见」的那一半，不放松任何一句；P1、P3、P4、P5 不碰（不发请求、不碰记忆、不改费用，只读任务与名单里已有的文字）。
- 缩范围还是降标准：都不是。P2.a 原文要的「找不到出处的必须留占位符」照旧靠 Agent；新加的是一层给人看的提示。
- 覆盖还是可信：可信上升 —— 编出来的参数、保修有一部分现在会被指出来。
- 可逆：可逆。只多一行 HTML，不改正本、不改表格、不改退出码。

## 五、机器保证到哪

- **保证的**：草稿里带数字的说法和词表里的承诺词，对不上已证实产品事实（或博主作品文字）的会被列出来。
- **不保证的**：不带数字、又不在词表里的换说法编造（「dishwasher safe」）；数字对得上但意思歪了（底本说「最长 10 小时」，信里写「整整 10 小时不用充」）；已证实产品事实本身写错了。这几样仍靠人看，P2.a 的豁免保留，范围收窄成这几样。

## 八、独立复核

一次独立复核（Fable），钉在 `d01f80c`：阻塞 2 条、非阻塞 11 条。两条阻塞与非阻塞里的实现问题（逗号、`.5`、型号串子串、缺断言的分支、文档没跟上的几处、连带改动不全、测试里多余的类型断言）在本 PR 修掉，见第六节。登记不改的：嵌套占位符只剥一层（`{a {b}}` 外层的字会被扫；P2.c 没定义嵌套）、币种不比（`€29` 对得上 `$29`）。复核认为按判据就是这样、不改的：博主作品文字能给产品承诺当出处、否定句（「No warranty」）也算出处。第一版两万个互异数字的草稿比对是平方级（29 秒），修后出处改用按值建的表，同一输入 70 ms。HTML 安全、默认模式字节不变、M-U9-v 与 M-U10-j 改 `find` 后语义不变，复核都核过。

第二轮复核（Fable）钉在 `9435fad`：阻塞 0 条，上一轮两条已消；随机对拍 20000 份剩 7 份分歧，全属下面第 2 条。顺手补了两处没被断言咬住的分支（`120k` 整串、不写单位的数对价格，M-P2-c19、c20），断言数改正。登记不改的两条：

1. 拼写数字用空格连写（`twenty five minutes`）或带 hundred（`two hundred hours`）仍取错值，前者误报、后者可能漏报；连字符写法对。
2. `BPA-free return policy` 这类「…-free」紧挨着 return 时，被 free returns 那一项吃成一个草稿里没有的说法「free return」并标出；两个词各自有出处也一样。方向是多标，不会漏。


CodeRabbit 第一轮（钉在 `55b5233`）报三条，都修在本 PR（M-P2-c21…c23，比对口径表多四行）：

1. 数字开头的型号串被拆出前面的数：`1080p` 记成 1080，出处里任何一个 1080 都把它对上。现在数（或数加单位）后面紧跟字母数字时不算数，整串留给型号串那一步整串对；`2nd` 这类序数词也因此整串列出，方向是多标。
2. 负号丢掉：信里 `-20`、出处 `20` 对上了。现在负号前面不是字母、数字、点时算数的一部分；`3-5 years`、`COVID-19` 里的连字符不算。
3. `free shipping`、`free trial` 这几个共用一组词干，出处里有其中一个就把别的都对上。现在拆成各自一项、各对各的词干，`returns policy`、`returns window` 同样拆开。
