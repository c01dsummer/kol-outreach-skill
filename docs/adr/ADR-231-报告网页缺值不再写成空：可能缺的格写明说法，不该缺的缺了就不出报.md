# ADR-231 报告网页缺值不再写成空：可能缺的格写明说法，不该缺的缺了就不出报告

- 日期 · 2026-11-21
- 类型：需求冲突（一侧是红线），连同落实已有原则（结构改造）；收场由需求所有者拍板

## 一、决定

红线 P1（缺的数据不许用默认值填）对上 U12.d（缺值写成空）：一侧是红线，红线赢，不用问人（`process/2-CHANGE.md`「需求冲突」）。赢完之后怎么收场是产品取舍，问了需求所有者，他选：

1. **可能缺的格，各自写明缺了显示什么。** 例如粉丝数没查写「未查询」、供应商给了怪值写「未知」、费用依据没有写「无从确认」、人工没填写「未填写」。这些说法原来大多已经有，本条补齐了缺的几处（第四节）。
2. **本该总有的格缺了，整份报告不出。** render 退出 2，stderr 写「报告里这一格没有值，报告没有生成……」，后面跟着那一格前后写死的文字（缺的位置用 ▯ 标出），或者调用处写明的格名（如「卡片上的分层（账号 abc）」）。meta.json 与 report.html 都不写，上一份原样留着。
3. **这件事由拼页面那一步统一把关，不靠逐处手写。** `html` 模板与 `joinHtml` 收到缺值时直接拒绝（抛 `MissingValueError`）。类型上插值只收不含 undefined、null 的类型：可能缺的取值不先写明说法，类型检查当场红；`meta` 这种没标类型的取值类型拦不住，靠运行时那一抛。以后新加一格忘了处理缺值，结果是报告不出、点名那一格，而不是悄悄空白。

这是业界模板引擎的通行做法：Jinja 的 `StrictUndefined`、Handlebars 的 strict 模式、Rust 的 askama 都是「模板里引用了没有的值就报错」，而不是印成空串。本条只是把它用在报告这一个页面上。

为什么不选「缺了一律显示未知」：那也是一个默认值，分不出是没查还是文件坏了，以后新加的格也会悄悄套上它。和需求所有者 2026-11-20 定的「供应商给的怪值显示未知、手改坏的文件拒收」是同一个思路（ADR-227）。

## 二、怎么落地

- `safe-html.ts`：`escapeText`、`html`、`joinHtml` 收到 undefined、null 时抛 `MissingValueError`，报错里点名那一格；新加 `need(取值, 格名)`，给类型上可选、实际由上游保证有的取值用。
- `report.ts`：
  - 原先十三处 `String(…)`（ADR-180 说的 escRaw 那几处）全部去掉，逐格定下缺了怎么办，见第四节表一。
  - 原先绕开 `html` 拼文字的地方（不带 `html` 的模板字符串、`+` 连字、`.join(…)`）全部改成 `html`／`joinHtml`，这样它们里面的取值也过那一道拒绝。
  - `meta.tiers?.[t] ?? 0`（选默认标签页时把缺的人数当 0）、`meta.keywords ?? []`、`meta.platforms ?? []` 改成 `need(…)`。
  - 邮箱、简介分清「没查过」和「查过为空」（P1.o，第四节表二）。
- `render.ts`：报告先拼好再写文件。拼的时候抛了缺值，打出报错、退 2，meta.json 与 report.html 都不动。别的错照旧往外抛。
- **语法树核**（U12.e 后半句）：`u12-safe-html` 组有一条断言读 `report.ts` 的语法树，查有没有这几样会让缺值绕过拒绝的写法：不带 `html` 的模板字符串（`need` 的格名除外，那是报错用的白话，不进页面）、`String(…)`、`+` 连字、`.join(…)`、`?? 0`、`?? ''`、`|| 0`、`|| ''`。它扫这个文件的每一个语法节点，不是一张字段清单；管的范围就是这一个文件，不认领别处（第六节）。

## 三、按改需求逐条评定

- **P1.n（新）**：报告每一处取值缺了时，要么写明说法，要么整份不出；本该总有的是哪些，写在判据里（render 自己算的交付信息、产品名、目标市场、卡片上的分层、平台、账号、昵称、主页链接）。这是「冲突收场」那一半，需求所有者定的。
- **P1.o（新）**：邮箱、简介在卡片上三态可分辨。这一条不要人定：P1 原文「未查询与查询结果为空必须是两个可区分的值」，P1.a、P1.e 早就这么要求交付表，报告卡片原先把没查过的邮箱写成「无邮箱」、没查过的简介和查过为空的一样不出那一行，是既有缺陷。
- **U12.d 退役、U12.e 接替**：U12.d 原文是「报告页面用同一种拼页面的写法拼成：插进去的取值不论是不是字符串都默认转义一次，缺值（undefined、null）写成空；只有这种写法自己拼出来的页面片段原样插入、不再转义；别的东西哪怕长得像片段，也照样当文字转义。」其中「缺值写成空」与红线冲突。判据不改含义、不回收复用（ADR-67），所以退役、用下一个字母。U12.e 保留转义那一半一字不改，缺值改成拒绝，另加「代码里拼文字一律走这种写法」。
- **交点 U12 × P1**：原裁决（ADR-180）只管两项统计（公开指标已测账号数、高风险人数缺了显示未知、真 0 保留 0），照旧；补一句别的取值按 P1.n、U12.e 办。
- 用户拿到的信息变少了吗：没有。原先缺值时是空白或 `undefined`，现在是写明的说法，或者一句点名哪一格缺了的报错。报告不出的那种情形，生产上只有输入文件被手写或手改坏时才会碰上：名单、任务文件，以及 Agent 手写合作报价的增强结果（第九节）。第四节表一「本该总有」那几格都是 render 自己算或排序后才有的。

**表三：整行有值才出、没值就不出的那几处（不是插值，是条件）**

这几处缺了时整行不出，不算「缺值写成空」，但也分不出「没查」和「查了没有」。逐个判过：

- 私密号标记：`is_private` 只有 Instagram 补资料时写，TikTok 没有这个概念；没写时不出标记。分不出「不是私密号」和「不知道」——登记为欠条，见第六节。
- 分层调整、曾推荐、开发信草稿、默认视图的契合理由：没有就是没有，这几样不是「查询」得来的，不存在「没查」那一态。
- 双平台标记、关联账号的公开指标：只在有关联时出；没有关联不是缺值。

## 六、没做的

> ⚠️ 欠条「报告引用的别处拼好的文字不在语法树核里」：发现来源（`discovery.ts` 的 `formatDiscoverySources`）、样本范围（`rows.ts` 的 `sampleScopeText`）、任务序号（`task-label.ts`）、开发信逐行出处与对不上的那几行（`draft-sources.ts`、`draft-claims.ts`）是别的文件拼好的文字，报告只把结果插进来。它们里面用不带 `html` 的模板字符串拼，取值缺了会印出 `undefined`；语法树核只读 `report.ts`。这几个函数还给交付表用，改成 `html` 要连交付表一起看 · 档：登记 · 重启条件：下一条改这几个函数的改动，或报告新引用别处拼好的文字时

> ⚠️ 欠条「报告不出时表格与记忆已经写了」：render 先写名单表格（CSV、XLSX）、写回跨任务记忆，再拼报告；报告因缺值不出时，表格与记忆已经是新的，meta.json 与报告还是旧的。独立复核实测，这时 `creators.json`、`task.json` 与评审正本也已经写了。没挪：报告要写明记忆写回的结果，得先写回；可以先拿占位的写回结果试拼一遍、再真写，但那要改 render 写交付物的整段先后，不在本条。碰得上的是名单、任务文件、增强结果被手写或手改坏、又躲过了读入检查的那几格；增强结果在读入时整份校验另开一条做（第九节） · 档：登记 · 重启条件：下一条改 render 写交付物先后的改动，或真的有人碰上一次时

> ⚠️ 欠条「私密号标记分不出不知道」：卡片上的私密号标记只在 `is_private` 为真时出，没写（TikTok 一律没写、Instagram 没补资料时没写）与「不是私密号」长得一样 · 档：登记 · 重启条件：下一条改私密号的读入或显示的改动

P1.b 的「任何位置」：本条只核了报告网页这一个文件（语法树核），不认领全仓库；`mutations.json` 豁免表里 P1.b 那一条照旧，在它的缓解说明里补一句本条的范围。ADR-77 撤掉的是「自称全量扫描、实现是一张手写字段表」的纪律 lint；本条的核读的是一个文件的完整语法树，不靠字段表，范围写在判据里（只管 `report.ts`），两者不是一回事。

> ⚠️ 欠条「语法树核是一张禁用写法的名单」：独立复核实测它放过 `?? (0)`、`??= 0`、`?? []`、三元式兜底成空串或 0、默认参数写 0、`.concat(…)`、`.toString()`、`Number(…)`、在本文件里另起一个叫 `html` 或 `need` 的函数；也误拦数字相加、`map.get(k) ?? 0`、`path.join(…)`（今天报告里没有这几种）。真正把关的是拼页面那一步运行时的拒绝，这一条只挡常见写法，U12.e 后半句不认领「写法已守全」 · 档：登记 · 重启条件：有人在报告里用上面任一种写法让缺值绕过了拒绝，或这一条误拦了一处正当写法时

同类：「要守的是一整类，落地成一张逐项手写的清单」，这一回是「缺值的处理逐格手写、忘了一格就空白」，改成在拼页面那一步统一拒绝。计数见第八节。

CodeRabbit 在新做法的第一个 head 上挑出读表还有两处会放过：把整份文档切开再解析，代码块里的示例会被当成那张表；
往后一直找，下一节的表也会被认。本条改成整份文档交给 marked 解析，在它给的顶层块里认锚点（代码块不算），
