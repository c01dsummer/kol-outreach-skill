# ADR-129 CI 选组迁移在五十条全跑处收束

- 日期：2026-09-29
- 类型：发现更优解
- 触发它的事实：PR #229 合入后，771 条变异中 721 条选组、50 条全跑；继续逐条迁移所需的独立具名断言与实测收益不再能由“全跑”两个字推定。
- 冲击的需求：不改产品需求、变异清单、检查强度或 `npm run check` 的步骤；只决定这轮 CI 提速何时收束。
- 结论：驳回以 50 条全跑清零作为本轮完成条件。保留它们的完整验证；有可预定且实际失败的独立断言，并能测出值得承担分组维护成本的收益时，再逐批迁移。性能回退先查真实耗时来源。
- 理由：当前同一代码树的两次自然成功 CI 中位数达到建议目标，但样本少且有波动；检查工具自身的隔离约束和业务测试的具名/分组边界不能为了减少全跑数字而放宽。这个决定不碰红线、不减覆盖、可按新证据重审。
- 连带改动：只新增本记录及生成索引；不改 `process/`、产品规格、代码、测试或变异路由。

未验证对应关系前继续完整需求测试，保留现有负片与成功判定。

## 以后什么时候重审

新增全跑、选跑退回全跑或旧全跑核心正文改变时，现有维护检查要求
`full_run.reason` 与 `full_run.recheck_when`，并列出实际执行配置、依赖和顺序变化；
历史未改的全跑项按可信旧内容兼容。这些检查让变化可审查，**不设自动秒数闸门**。

如果相同代码树、同类 runner、相同 worker 与变异集合的有限成功运行再次显示
中位数未达到 15 分钟，或新变异显著增加关键路径，先从完整日志分清变异步骤、
独立 `selfcheck` 与其它步骤，再选实测收益最大的候选。尤其不能把逐条时间相加
当作 job 可节省量；也不能未经组间状态、顺序和清理验证就并行化独立自检。
后续出现已由需求确定的固定断言时，也可单独验证正常基线、施变后的指定失败与
全跑/选跑对照，再决定是否迁移，不必等这 50 条一起处理。
