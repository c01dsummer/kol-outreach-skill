# ADR-129 CI 选组迁移在五十条全跑处收束

- 日期：2026-09-29
- 类型：发现更优解
- 触发它的事实：PR #229 合入后，771 条变异中 721 条选组、50 条全跑；继续逐条迁移所需的独立具名断言与实测收益不再能由“全跑”两个字推定。
- 冲击的需求：不改产品需求、变异清单、检查强度或 `npm run check` 的步骤；只决定这轮 CI 提速何时收束。
- 结论：驳回以 50 条全跑清零作为本轮完成条件。保留它们的完整验证；有可预定且实际失败的独立断言，并能测出值得承担分组维护成本的收益时，再逐批迁移。性能回退先查真实耗时来源。
- 理由：当前同一代码树的两次自然成功 CI 中位数达到建议目标，但样本少且有波动；检查工具自身的隔离约束和业务测试的具名/分组边界不能为了减少全跑数字而放宽。这个决定不碰红线、不减覆盖、可按新证据重审。
- 连带改动：只新增本记录及生成索引；不改 `process/`、产品规格、代码、测试或变异路由。

## 以后什么时候重审

新增全跑、选跑退回全跑或旧全跑核心正文改变时，现有维护检查要求
`full_run.reason` 与 `full_run.recheck_when`，并列出实际执行配置、依赖和顺序变化；
历史未改的全跑项按可信旧内容兼容。这些检查让变化可审查，**不设自动秒数闸门**。

如果相同代码树、同类 runner、相同 worker 与变异集合的有限成功运行再次显示
中位数未达到 15 分钟，或新变异显著增加关键路径，先从完整日志分清变异步骤、
独立 `selfcheck` 与其它步骤，再选实测收益最大的候选。尤其不能把逐条时间相加
当作 job 可节省量；也不能未经组间状态、顺序和清理验证就并行化独立自检。
后续出现已由需求确定的固定断言时，也可单独验证正常基线、施变后的指定失败与
全跑/选跑对照，再决定是否迁移，不必等这 50 条一起处理。

## 2026-09-29：用户重启剩余五十条的改造

> ⚠️ 更正：上文「在五十条全跑处收束」是当时的范围裁决。用户现明确要求继续处理全部五十条；此前的测量与验证边界仍是历史事实。

这次工作逐条处理现有五十条全跑变异，不因已经达到十五分钟的建议中位目标而停止。
每条先依据需求或检查契约确定应失败的固定断言，再核对正常源码及其组依赖能通过、
隔离施变后该断言确实失败；其它断言失败、进程崩溃、超时或夹具故障均不能代领。
检查工具仍须使用独立于被变异文件的验证路径，不能让自检验证自己的判定基础设施。

能够证成的条目接入选组，并以同一源码树、变异集合、Node 版本和 worker 数比较全跑与选跑；
完整需求测试、独立自检、审计及全部变异继续执行。尚无可靠固定断言、无法安全归组
或缺少特殊验证边界证据的条目，先保留全跑并逐条写明缺口，不能为凑齐五十条而放宽判定。
全部选组及整条 CI 的新增收益都是待验结果，须由自然成功的完整检查证实。

## 2026-09-29：逐项核对后的路由边界

PR #232 以 main `ba5c8c6` 为起点逐条核对这五十条。可由固定断言证成的四十八条
接入需求测试选组，其中检查工具三十五条、业务模块十三条；变异总数仍为 771，
实际路由由 721 条选组／50 条全跑变为 769 条选组／2 条全跑，
实际子集配置由 71 种变为 81 种。四十八条只增加 `by`／`kills`，
原变异文件、施变正文、需求编号与断言清单没有删除或放宽。
最终提交 `9c72853` 在 Darwin arm64、Node 22.23.2、十个 worker 下完整执行
`npm run check`，771 条全被抓到；81 种实际子集在施变前各通过一次正常代码基线，
完整需求测试、独立自检与审计也自然成功。本机完整经过时间为 480.85 秒，
`time` 归属的 user 1024.07 秒、sys 224.54 秒；它不是 Linux CI 的 job 耗时或 CPU。
该提交与合入 main 的 `4a0bd81` 在 `scripts/`、workflow、依赖锁文件和需求登记表上无差异。

这四十八条另在最终提交的两份临时副本中成对对照：两侧源码、变异集合、
Node 22.23.2、Darwin arm64 和单 worker 相同，仅以未提交的选择开关切换
全跑／选跑。完整需求测试及涉及的十八种正常子集基线先通过，预热不计时；
三对正式运行均为 48／48 `caught`，源码还原，选跑侧的全量测试认领文件
字节、inode 和修改时间均未变化。

局部墙钟中位数少 125.31 秒（77.8%），user+sys 中位数少 63.98 秒
（68.7%）；此表不包括整条检查及 CI 排队，不可直接外推为 job 提速。

留下的 `M-F5-b` 和 `M-F5-c` 继续全跑，并在本次完整检查中被抓到。
前者守的是无语义判断时使用刚算出的分数，后者守的是 B 级的 40 分门槛；
F5 的现行正文只要求缺增强层时照常完成主流程；无语义判断也不等于缺增强层，
两件事都没有对应验收判据。
ADR-71 已登记这一编号与守护点错位。重审条件：需求所有者确定无语义判断时
分数分层的规则与门槛、写入需求及下游契约；随后事前固定具名断言、核正常基线与
隔离施变后的指定失败，再比较同一源码与变异集合的全跑／选跑。
在这之前保持完整验证，不把现实现中的 30／45／60 样本反推成产品标准。
