- 日期：2026-10-24 · 读 Anthropic 那篇形式化验证文章时，照它「一条通用性质套到全部入口」的思路，在仓库外把报告渲染扫了一遍；需求所有者 2026-10-24 在项目线程里选了「两条都开」，本条是其中补转义的那条

## 一、测试怎么判

夹具是三个创作者加一份交付 meta，当作盘上读进来的 JSON 写在测试里：有报价、已测的受众风险（含依据）、人工评审与多平台人工作答、待重评的关联平台 Agent 判断、没有样本的关联账号、不可用的样本、每项都不可用的指标（显示的是原因）、没查询的简介、费用账问题、记忆没写回。

- **U12.a**：夹具里每个取值（字符串、数、布尔、`null`）逐个换成金丝雀 `x"y'z<q-u12>&w`，字符串另试一次末尾追加；每一份都用公共单层视图和生产用的双筛选视图各渲染一次。报告里出现金丝雀里任何一段原字符（`x"y`、`y'z`、`<q-u12`、`q-u12>`、`&w`）就记一处漏；报告会把有的取值改成大写再显示（受众风险等级），所以先转小写再比。渲染被拒（抛出）不算漏：没有报告，也就没有被改写的标记。
- **U12.b**：同一遍替换里，报告里出现金丝雀转义两次或更多次后的任何一段就记一处（查的几段是 `amp;quot;y`、`amp;#39;z`、`amp;lt;q-u12`、`q-u12&amp;`、`amp;amp;w`，不带金丝雀的前导字符，转义三次也认得出；也是先转小写）。
- **U12.c**：账号、昵称、简介、开发信草稿、产品名、关键词这六项换成金丝雀，两种视图里都要出现手写的「转义一次」写法。

U12.b 与 U12.c 挡的是把取值删掉、截断或转义多次也能让 U12.a 变绿的那几种写法；删掉与截断只对这六项判。两条各自能坏：把别的字段转义两次只红 U12.b，把昵称截断只红 U12.c，所以拆成两条（`process/1-REQUIREMENTS.md`「拆到多细」）。

什么能在事实不成立时也让它通过：渲染全被拒，U12.a 就是空的绿，所以先断言原夹具两种视图都照常渲染，U12.c 也要求那六个字段真的渲染出来；只转义尖括号、不转义引号，金丝雀里带着两种引号；只漏大于号，查的那几段里有 `q-u12>`；取值改成大写再显示时漏了，比对前先转小写；数值指标已测时显示的是格式化后的数，不可用时显示原因，夹具里每项都有不可用的一份。后面这三处初版（`19c8f73` 的测试）都没有，单漏 `>`、只在已测时不转义风险等级、去掉某项指标显示的转义，初版照样绿：前一处是欠条清点实测出来的，后两处与「转义两次只查六项」是独立复核实测出来的，补上后分别由 M-U12-e、M-U12-g、M-U12-f、M-U12-h 守着（这四条在初版测试上都不红，在本条合入的那一版上都红）。转义三次：第二版（`6e7ae44` 的测试）查的几段带着金丝雀的前导字符，转义三次就对不上，第二轮独立复核实测出来，补上后由 M-U12-i 守着（它在第二版上不红）。夹具里没有的字段扫不到，见第二节第三张欠条。

十条负片都只跑这一组：M-U12-a 去掉平台样式类的转义（属性里）、M-U12-b 去掉粉丝数的转义（正文里）、M-U12-c 去掉副标题平台列表的转义（交付 meta）、M-U12-d 把账号转义两次、M-U12-e 让原先直接插值的那些取值只放过大于号、M-U12-f 去掉播粉比的转义（不可用的原因）、M-U12-g 受众风险已测时不转义等级（大写显示）、M-U12-h 把契合理由转义两次、M-U12-i 把邮箱转义三次、M-U12-j 把昵称截到前八个字。M-U12-d 落在主页链接那一行，守的只是账号的写法，不守链接的协议（第二节第二张欠条）。

## 三、同类

本条与 ADR-71、ADR-77 是同一种错法：要守的是一整类，落地的是一张逐项手写的清单，清单外的那一项漏了，检查照样报绿 —— ADR-71 是敏感字段表漏了 `score`，ADR-77 是纪律 lint 自称全量扫描、实现是一张白名单，本条是报告里逐个字段手写的转义漏了十几处。不同在判据：那两条的判据写着「任何位置」，落地成了清单；本条在主干上连判据也是清单（D15.h、U9.i、U11.j 各管几类字段，没有一条管全部取值，见头部「类型」），所以补了 U12 这条管全部取值的判据。本条在每一处插值上补了转义（仍是逐处写 `esc(` 与 `escRaw(`，没有结构上的默认转义），再用逐个取值换金丝雀的测试去扫，测试那一头仍只扫夹具里有的字段（第二节第三张欠条）。独立复核另提过 ADR-95（闸门比较的两边是外部输入，没人查是不是数），驳回：它的错法是「比较的两边是谁没人问过」（ADR-95「教训」），不是「要守的是一整类、落地成手写清单」。两条都引了 `process/4-VERIFY.md` 里「反序列化进来的就是外部输入」那一行，那是同一个前提，不是同一种错法。

验证这一半 `process/4-VERIFY.md` 已经有了：「属性优先于例子」（第 35–41 行），和「这地方我已经修过了 = 这地方修好了」那一行（第 152 行：判据要落在那个类上）。落地这一半没有：要守的是一整类时，实现不做成逐项手写的清单，新加一处时默认就在里面。`process/README.md` 里「替代读的不建」那段讲的是闸门别做成手写的表，管不到产品代码。下面这张欠条说的是落地这一半。

> ⚠️ 欠条：同类第 3 次（ADR-71、ADR-77、ADR-180），通用句未进 process/ · 重启条件：需求所有者定了要搬，或下一条同类合入
