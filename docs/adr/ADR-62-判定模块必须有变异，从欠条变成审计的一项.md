# ADR-62 判定模块必须有变异，从欠条变成审计的一项

- 2026-09-02 · 还 ADR-59 的欠条
- 类型：不属于反向输入的五类 —— 改的是检查链自己，不触及需求登记表
- 冲击的需求：无
- 结论：**采纳**

## 触发它的事实

PR #7 那套分支寿命的判定，测试只写到两拍，第三拍（配变异、看它红）是评审看见的，
不是检查看见的。原因是结构性的：`npm run audit` 只对产品红线强制「有测试 + 有变异」，
闸门自己的需求不在 `docs/requirements.json` 里。ADR-59 把它写成欠条。

写这条记录时清点：`size-rule.ts`、`adr-rule.ts`、`trailer.ts`、`quoted.ts` 四个判定模块
一个变异都没有 —— 前一条分支补上了 20 个，这一条把「必须有」接进审计。

## 判据

**`scripts/check/` 下不带 shebang 的 `.ts`，每一个都必须有至少一个变异指向它**，豁免要写理由
（`audit-rule.ts` 的 `JUDGMENT_EXEMPT`，目前只有 `fake-fetch.ts`：它是假响应，不是判定）。

三个取舍：

- **按 shebang 分，不按 `*-rule.ts` 后缀分。** `trailer.ts`、`quoted.ts` 都是判定，不叫 rule；
  一条靠命名成立的检查，换个名字就绕过去了。带 shebang 的是入口，按 `docs/CONVENTIONS.md`
  第 10 条不该装判定，也就没有可变异的东西
- **只要求「有变异」，不另查「有测试」。** `npm run mutate` 要求每个变异被抓到，而「抓到」
  只算断言红了 —— 评审指出原先的判据是「测试进程非零退出」，一处语法错、一个空指针也算，
  那不是任何一条断言的功劳，「有变异被抓到就有测试」这句话在那个判据下不成立。所以 `mutate`
  的判定抽成 `mutate-rule.ts`，三态：抓到 / 跑不起来 / 存活，跑不起来不算抓到（M-H14-a 守着）。
  反过来「有测试」自己证明不了什么（`4-VERIFY.md`：绿不证明这条测试还能失败）
- **硬失败，不是待办。** 审计里的「·」是完成度缺口，可以长期显式留着；这一条不是缺口，
  是「这道闸门没被证明过」，和红线没变异同一级

判定自己也在名单上：`audit-rule.ts` 由 M-H13-a/b 守着 —— 少了这一步，这条检查就是它自己
要拦的那种东西。

## 一起想的那件：第 10 条能不能变成 lint

`docs/CONVENTIONS.md` 第 10 条「入口脚本里放决策逻辑，它就永远测不到」踩过六次，纪律 lint
里没有查它的规则。想过三条判据，都不成立：

| 判据 | 为什么不行 |
|---|---|
| 入口里不许有 `if` / 三元 / `switch` | 入口本来就要判「参数给了没有」「git 跑失败没有」—— 满屏假阳性，而被忽略的检查比没有检查更糟 |
| 入口里不许定义函数 | `git()`、`tryGit()`、`cannotAnswer()` 全是 IO 包装，也是函数 |
| 入口不许 `export` | 六次里没有一次是靠 export 泄漏的；判定就地写在入口里，什么都不 export |

判据的原话是「这段代码的顺序错了会不会出错」—— 那是语义，不是形状。**它留在第三层。**
这条记录能给的只是它的下游：判定一旦抽出来，就有东西看着它有没有变异；抽不抽，靠人。
