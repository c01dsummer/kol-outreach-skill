## 一、为什么做成命令，为什么是这个样子

ADR-88 那一次是手工拼的：四份读物放在仓库外的一个目录里，拼完人扫一遍，确认里面没有实现。它记下的毛病有两处：

- **手工拼不可复核。** 包里到底放了什么、少了什么，只在那次会话里，读者没法照着再拼一个一样的。做成命令，同一棵树上谁跑都是同一个包，清单写着它出自哪个提交。
- **包里缺一份导出清单。** 那个上下文「写得出断言，写不出测试骨架」：包里只有三个导出函数的签名，判据和契约里点到名的函数（补全、跨平台合并、粉丝闸门、评分、各渲染器）都没有签名（ADR-88「包本身缺一样」）。

所以包要多一份：产品代码每个模块的签名，函数体剥掉。剥函数体交给类型检查器的声明产出（同 `tsc --declaration` 的产物）：它的产物本来就只有签名与类型，**没有函数体是结构上做到的，不是靠扫出来的**。命令再把产物扫一遍（第三节），挡的是将来有人把产出方式换掉（比如换成直接抄源码）而没人发现。

这不是一道闸门：它不拦任何改动、不在 `npm run check` 里、没有豁免通道。所以不写死亡条件（第八节）。

## 二、包里装什么：四份读物与一份清单

`process/4-VERIFY.md`「给测试上下文一张准入读物清单」说的是：需求登记表、验收标准、对应的对外文档、类型定义，就这些；变异集里「违反了什么」那一栏也可以给。包照这张单子出，一份对一样：

```
<包目录>/
  00-清单.md
  01-需求-<编号>.md
  02-签名/scripts/lib/<模块>.d.ts …
  02-签名/scripts/providers/<模块>.d.ts …
  03-对外文档/skill/SKILL.md
  03-对外文档/skill/references/… （skill/ 下全部 .md，子目录照搬）
  04-变异集-违反了什么.md
```

### 第 1 份：需求单（`01-需求-<编号>.md`，本片的 `requirementSheet` 出）

输入是 `docs/requirements.json` 的 `requirements` 数组与一个编号。

1. 编号要与某条需求的 `id` 一字不差（区分大小写）。登记表里没有 → 不出包，理由是 `需求登记表里没有 <编号>`；那条需求带 `deprecated` → 不出包，理由是 `<编号> 已作废`。判据编号（如 `P2.a`）不是需求编号，按「没有」处理：一个包对一条需求。
2. 版式（行与行之间一个换行，整份以一个换行结尾）：

   ```
   # <编号>

   <需求原文>

   ## 验收标准

   - **<判据编号>** <判据原文>
   …

   ## 交点

   - **<声明它的那条> × <with>**：<ruling>
   …

   ## 点到名的需求

   只走一跳：下面这些是上面的原文里点到名的，它们自己点到的不再往下收。

   ### <编号>

   <需求原文>

   - **<判据编号>** <判据原文>
   …
   ```

   判据照登记表里的先后。一节里一项都没有时，那一节标题下面只有一行 `没有。`（「点到名的需求」那一节这时也不写「只走一跳」那一句）；点到名的那条没有判据时，它那一块的判据列表同样换成一行 `没有。`。点到名的每一块前面空一行：「只走一跳」那一句与第一块的 `###` 之间、上一块最后一行与下一块的 `###` 之间，都是一个空行。交点的 `adr` 不写进去：包里没有决策记录。
3. **交点**：按登记表的先后逐条需求（作废的也算）、每条需求按它 `tension` 里的先后，收「声明它的是这条」或「`with` 是这条」的那些。交点是两条需求一起的事，只收一边会把另一边声明的漏掉（P4 自己一条交点都没声明，D1 × P4、D4 × P4 都声明在对面）。
4. **点到名的需求**：从这几处找需求编号 —— 这条需求的原文、它每条判据的原文、收进来的每条交点的两边编号与 ruling。认法：大写的 `P`、`S`、`D`、`F`、`U` 之一紧跟一串数字；它前面不是 ASCII 字母、数字或下划线（或者它在开头），数字串后面不是数字。汉字不算字母：`与P4冲突` 认出 `P4`；数字串后面接字母照样认（`P1a` 认成 `P1`）。`P1.e` 认成 `P1`；`ADR-15`、`Phase 01` 都不认。认出来的编号要在登记表里（作废的也算），去掉这条需求自己，按登记表的先后排，每条只出一次。作废的那条标题写成 `### <编号>（已作废）`，原文与判据照常写。**只走一跳**：收进来的需求自己点到的编号不再往下收。

### 第 2 份：签名（`02-签名/`，第二片的入口出，本片的 `declarationFindings` 扫）

`scripts/lib/` 与 `scripts/providers/` 下（含子目录）全部 `.ts`，各出一份声明文件，路径照搬、扩展名换成 `.d.ts`。只收这两处：它们是产品逻辑与数据源适配（`docs/ARCHITECTURE.md`「新东西落在哪个目录」）。入口（`scripts/*.ts`）的对外契约是命令行参数、产出文件与退出码，写在第 3 份里；`scripts/check/` 是检查链自己，不是被测的产品。签名上的文档注释原样留着：类型层本来就是需求的一部分（`process/4-VERIFY.md`「契约面和实现体分开」），`bio` 的三态那段说明就写在类型的注释里（ADR-88 第二节）。

### 第 3 份：对外文档（`03-对外文档/`，第二片的入口出）

`skill/` 下（含子目录）全部 `.md`，逐字节照搬。它们是 Agent 读了照做的东西，命令、参数、产出文件、退出码的契约都在这里。不按「提到这条需求的编号」去挑：P3 的预算契约写在 `skill/SKILL.md` 里，可 `skill/` 下没有一份文档写着 `P3`。

### 第 4 份：变异说明（`04-变异集-违反了什么.md`，本片的 `briefSheet` 出）

输入是 `scripts/check/mutations.json` 的 `mutations` 与 `exemptions` 两个数组与一个编号。

1. 收「`req` 等于这个编号，或以这个编号加一个 `.` 开头」的变异与豁免。`D1` 的包不收 `D10` 名下的。
2. 版式：

   ```
   # 变异集 · <编号>

   <编号> 与 <编号>.x 名下的变异「违反了什么」，与 `npm run mutate -- --brief` 同一栏；变异改哪个文件、改成什么不在这里。

     <变异编号>  [<req>]  <why>
     ⊘     [<req>]  <名下有负片／名下无变异>（<scope>）：<why>

   共 <N> 个变异、<M> 处显式豁免。
   ```

   变异在前、豁免在后，各按原数组的先后。每一行的写法与 `mutate --brief` 逐字相同：豁免行前面那三个字由 `mutate-rule.ts` 的 `exemptionLead`、`exemptionCovered` 给，按全部变异算（有一条变异的 `req` 与这条豁免的 `req` 一字不差就是「名下有负片」，`F5.a` 名下的变异不算 `F5` 的）；只有 `scope` 缺着（`undefined`）时没有括号那一段，写成空串照样有一对空括号，与 `--brief` 相同。一条都没有时，中间那一块只有一行 `没有。`（不缩进），末行照写 `共 0 个变异、0 处显式豁免。` 整份以一个换行结尾。
3. 收进来的每条 `why` 过一遍 `why-rule.ts` 的 `implementationLeak`。认出夹带的，连同变异编号（豁免写成 `⊘ [<req>]`）与认出的那一段一起交出来，先变异、后豁免，各按原数组的先后；入口见了就不出包（第三节）。`mutate` 开跑前也拦这件事，但包不该靠别的步骤先跑过。

### 第 0 份：清单（`00-清单.md`，第二片的入口出）

出自哪个提交、工作区干不干净（读不到 git 时写「无从确认」，不写成干净）；每个文件的路径与 SHA256；包里不装什么（函数体、测试、决策记录、变异的代码原文）；机器核过的与没核的（第三节）；读法：只读这个目录，不要读仓库，也不要照项目说明里「先读仓库文档」的路由去读。

## 三、扫什么，不扫什么

`declarationFindings` 读一份声明文件的正文，交回一张单子，每一条是 `第 <行> 行：<哪一种>`，行号从 1 起，取那个节点自己起头的那一行（不算它前面的注释）：`函数体` 取那个函数（不是它的函数体那个块），`不是声明的语句` 取那条语句，`初始值不是字面量` 取带初始值的那一项自己（那一个变量、那一个类属性、那一个枚举成员；不是整条变量语句，也不是初始值）。三种：

- `函数体`：函数声明、方法、构造器、取值器、存值器、函数表达式、箭头函数，带着函数体的；箭头函数的函数体是一个表达式也算。报了一处就不再往它里面找：函数体里的任何东西（套的函数、语句、初始值）都不另报。
- `不是声明的语句`：文件顶层、以及每一个命名空间／模块块里（带不带 `declare`、套几层、`declare global` 都算），不是这几种的语句 —— 导入、导入赋值（`import x = require(…)`）、导出、导出赋值、接口、类型别名、类、函数、变量语句、枚举、命名空间／模块声明。报了一条照样往这条语句里面找。
- `初始值不是字面量`：变量、类属性、枚举成员带着初始值，而初始值不是这几种字面量 —— 数字、字符串、没有插值的模板串、BigInt、`true`、`false`，以及前面带一个负号的数字或 BigInt。这张单子是全的：`null`、正则、`+1`、`-x` 都报。报了一条照样往初始值里面找：`declare const f = () => {}` 报两条，先 `初始值不是字面量`（在 `f`），后 `函数体`（在箭头函数）。

单子按在文件里的先后排（同一处起头的，`不是声明的语句` 在前）；什么也没找到交空单子。入口对每份签名都扫：有一份不空就不出包，以 1 退出，逐条打印「文件：第几行：哪一种」。

**不扫的，写进清单：** 签名上的注释与第 3 份对外文档原样带进来，里面有没有实现原文，没有机器核。注释里引一段代码表达式、文档里贴一段实现，都会原样进包。把 `implementationLeak` 套到注释上会把对外契约里的字段名一并拦下（它的界线本来就只在 `why` 那种短句上成立）。这一半靠写注释的人自觉，事后翻那个上下文的工具调用记录时能看到它读了什么，看不到它从注释里得到了什么。

## 四、墙：包放在仓库外面

ADR-88 的墙是「让它手里根本没有实现」：包放在仓库外，告诉那个上下文只读这个目录，事后翻它的工具调用记录核。命令能守的只有头一半：

- **包目录不能在仓库里。** `insideRoot` 判一个目录在不在另一个目录之下（含就是它本身）：两个都是绝对路径，按 `path.relative` 的结果判 —— 结果是空串，或者既不是 `..`、也不以 `..` 加路径分隔符开头、也不是绝对路径，就算在里面。名字以 `..` 开头的子目录（如 `..cache`）在里面。入口拿仓库根（当前目录）与解析后的包目录问它，在里面就不出包，以 2 退出。
- **包目录已存在而且不空，不出包**，以 2 退出。往一个旧包上覆盖，旧包里多出来的文件会留着，而清单不列它们。

后两半（告诉它只读这个目录、事后翻记录）不是命令的事，记在用这个命令的那几条记录里（ADR-163 起）。

## 五、接口

```ts
import type { Req } from './spec-rule.js'

/** 第 1 份。不出包时交理由 */
export function requirementSheet(reqs: readonly Req[], id: string):
  { ok: true; text: string } | { ok: false; reason: string }

/** 第 4 份。leaks 不空时入口不出包 */
export function briefSheet(id: string,
  mutations: readonly { id: string; req: string; why: string }[],
  exemptions: readonly { req: string; why: string; scope?: string }[]):
  { text: string; leaks: { id: string; leak: string }[] }

/** 第三节。空单子 = 没找到 */
export function declarationFindings(text: string): string[]

/** 第四节。两个参数都是绝对路径 */
export function insideRoot(root: string, dir: string): boolean
```

四个都是纯函数：不读文件、不起进程。`declarationFindings` 用 `typescript` 的解析器读正文（`devDependencies` 里本来就有）。

## 七、测试怎么写

断言先写，写的上下文不读实现（`process/4-VERIFY.md`「新功能」那一条：先于实现，没东西可读）。

- **需求测试组 `h-admission`**（进程内，0 次启动），`needs: []`，排在 `h-skill-rule` 之后。只调第五节那四个函数，不读文件、不起进程；期望值从第二到第四节手推，不跑实现抄输出。
- 至少覆盖：需求单的三种结局（出、没有、已作废）与判据编号当需求编号；版式逐字（含三节各自「没有。」的写法）；交点两个方向都收、按登记表先后；点到名的认法（前后边界、`P1.e`、`ADR-15`、`Phase 01`、不在登记表里的、作废的、自己）与只走一跳；变异说明的归属（`D1` 不收 `D10`、`P2` 收 `P2.a`）、两种行的写法、一条都没有、夹带实现原文交出来（变异与豁免各一）；声明扫描的三种各自成立与不成立、一处函数体只报一条、行号、先后；`insideRoot` 的本身、子目录、兄弟目录、名字以根目录名开头的兄弟（`/a/repo-x` 对 `/a/repo`）、名字以 `..` 开头的子目录、上级目录。
- 断言写成 `eq('…', 实际, 期望)` 或 `ok('…', …)`，首参是字面量、各不相同：变异点名用的清册只认这两个函数的字面量首参（ADR-145 第 242 行）。经一层护着调被测函数：抛错时交回哨兵，每条断言各自红、整组不崩（ADR-156 第七节的先例）。
- **变异**全部 `by: test`、`req: "harness"`，编号 M-H62，落在 `admission-rule.ts` 上，由 `h-admission` 的断言点名抓。判定里每个判断分支至少一条。

## 八、不设死亡条件

`process/README.md`「往上撤」那一节的尺子只量闸门 —— 会拦路、有豁免通道、要人维护的东西。这个命令不拦任何改动，不在检查链里，不跑就没有任何后果，不在那把尺子的量程里。哪天 `process/4-VERIFY.md` 不再要准入读物清单，它就没人用了；那时删它是一条普通改动。

## 九、验收（本片）

```ts
import { readFileSync, readdirSync } from 'node:fs'
import { createRequire } from 'node:module'
import { relative, resolve } from 'node:path'
import { briefSheet, declarationFindings, requirementSheet } from './scripts/check/admission-rule.ts'
const ts = createRequire(resolve('node_modules/typescript/package.json'))('typescript')
const reqs = JSON.parse(readFileSync('docs/requirements.json', 'utf8')).requirements
const corpus = JSON.parse(readFileSync('scripts/check/mutations.json', 'utf8'))
for (const id of ['P1', 'P2', 'P3', 'P4', 'P5']) {
  const s = requirementSheet(reqs, id)
  const b = briefSheet(id, corpus.mutations, corpus.exemptions)
  const heads = s.ok ? [...s.text.matchAll(/^### (.+)$/gm)].map(m => m[1]) : []
  const tens = s.ok ? s.text.split('## 交点')[1].split('## 点到名')[0].split('\n').filter(l => l.startsWith('- ')).length : 0
  console.log(`${id}: 需求单 ${s.ok ? `${s.text.split('\n').length} 行 · 交点 ${tens} · 点到名 ${heads.join('、') || '无'}` : s.reason} · 变异说明「${b.text.match(/^共 .*$/m)?.[0]}」夹带 ${b.leaks.length}`)
}
const walk = (d: string): string[] => readdirSync(d, { withFileTypes: true }).flatMap(e => e.isDirectory() ? walk(`${d}/${e.name}`) : [`${d}/${e.name}`])
const files = ['scripts/lib', 'scripts/providers'].flatMap(walk).filter(f => f.endsWith('.ts')).sort()
const program = ts.createProgram(files, { target: ts.ScriptTarget.ES2022, module: ts.ModuleKind.ESNext, moduleResolution: ts.ModuleResolutionKind.Bundler, strict: true, skipLibCheck: true, declaration: true, emitDeclarationOnly: true, types: ['node'] })
const out = new Map<string, string>()
program.emit(undefined, (n: string, t: string) => out.set(relative(process.cwd(), resolve(n)), t))
let found = 0
for (const [f, t] of out) { const x = declarationFindings(t); found += x.length; if (x.length) console.log(f, x) }
console.log(`声明 ${out.size} 份（源 ${files.length} 份），扫出 ${found} 处`)
let src = 0
for (const f of files) src += declarationFindings(readFileSync(f, 'utf8')).length
console.log(`阴性对照：直接扫 ${files.length} 份源码，扫出 ${src} 处`)
```
