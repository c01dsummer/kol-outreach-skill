# ADR-234 本仓库所有改动都在提议档：开 PR、独立复核、需求所有者合

## 要用到的事实，各找谁要

不列：这一条不写代码，只记需求所有者定的档。

## 一、决定

本仓库**每一条改动都在提议档**：执行者可以改、可以开 PR，合并之前要有独立复核，复核记进 PR；合入由需求所有者做。欠条 PR（只加欠条块或状态行）、改文案、补测试、「主干红了」的修补都一样，没有执行者自己合的改动。

`process/README.md`「什么时候不走流程」把改文案、补测试这类列在自动档，读作「通用流程允许它们最多走到自动档」；本仓库收得更紧，把它们也放进提议档。收紧只多一道复核、多一个人合，不会让哪类改动少受检查，所以不需要改通用流程。

「主干红了」那一节说的「立刻合」，在本仓库读作：立刻开、复核一过就请需求所有者合，排在别的 PR 前面。

## 二、为什么

需求所有者今天就是每条亲自合的；写下来是把实际做法变成明文，免得流程里几处「直接合」被读成执行者可以自己合。

## 三、证不了的

谁合的，GitHub 记得；但「这一类改动本来该在哪一档」没有检查守，靠合并者读。
