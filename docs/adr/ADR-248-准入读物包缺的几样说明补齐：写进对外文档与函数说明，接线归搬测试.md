## 一、怎么分：对外该写清的写进文档，接线的事写明归谁

欠条一路攒下来的二十多样分两类：

- **对外本该写清的行为**：用户和 Agent 看得到的输出、命令、文件形状。写测试的人缺它们，用户读文档时也缺。补进 `skill/` 下的对外文档或签名上的函数说明，两边一起受益。
- **测试接线**：断言函数从哪来、怎么替换请求层、怎么开一本测试用的账、怎么起入口子进程。这些本来就不该由需求说清，由把测试搬进仓库的人接。以前包里没说这一点，隔离会话只好当成「判据没写清」交回，或者自己猜一个。现在清单里写明：自备一份最小的、标出来，搬入时换掉；能照着写的说明在哪几处，清单里点了名。

## 三、谁守着

- 清单那一段：自检 `admission-entry` 组多一条断言「admission 清单写明包外的接线自己备、去哪找说明」，起真入口看出的清单里有这一段。入口 `admission.ts` 是自检自己要用的东西，落在它上面的变异不能由自检来验（变异集会拒收「自己验自己」），于是测试里另起一组 `h-admission-manifest-wiring`，读入口源码核那三句关键的话还在；变异 `M-H202-bv` 删掉那一段的开头，这一组即红，验过。
- 对外文档与函数说明是文字，没有机器核它们与代码一致；本条写的每一句逐条对着代码读过。以后改了这些行为，对外文档要跟着改，这和其余对外文档一样靠改的人与评审。
