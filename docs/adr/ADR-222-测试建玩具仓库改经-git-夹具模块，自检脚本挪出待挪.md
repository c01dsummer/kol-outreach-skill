## 一、要用到的事实，各找谁要（`process/3-BUILD.md` 第 8 条）

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 一个文件挪干净了没有 | ADR-217 的闸门 | 机器 |
| 夹具起的 git 落在临时目录里、不在本仓库里 | 起之前问文件系统：`cwd` 的真实路径在系统临时目录的真实路径底下、不在本仓库根底下；再让 git 自己往上找仓库时停在系统临时目录（`GIT_CEILING_DIRECTORIES`） | 机器（文件系统与 git 自己的规则） |
| 夹具只被测试用 | ADR-217 闸门同一遍语法树：字符串里带着夹具模块名字的文件，要在登记表「测试文件」一节里；那一节逐行由评审看 | 机器（清单内容靠评审） |

## 二、做了什么

1. **git 夹具模块（`git-fixture.ts`，登记）。** `fixtureGit(参数, { cwd, env?, input? })` 起一次 git，交回退出码、标准输出、标准错误、起不来时的错误；`fixtureGitOrThrow` 以 0 退出交回去掉首尾空白的输出，否则抛错、带 git 的原话。起之前查三样，不合就抛错、不起 git：
   - **在哪起。** `cwd` 必填；真实路径要在系统临时目录底下（不能就是它本身），且不在本仓库里、也不是本仓库的上级目录。本仓库根由模块自己的位置算出。
   - **起什么。** 子命令只许 `add`、`checkout`、`commit`、`config`、`init`、`rev-parse`、`switch`、`update-ref`（自检里用到的全部）；子命令前只许 `-c 键=值`，键只许 `commit.gpgsign`、`core.quotePath`、`user.email`、`user.name`；`init` 不带目录参数（`-b` 后面的分支名不算）。
   - **带什么环境。** 从本进程的环境起，去掉全部 `GIT_` 开头的；调用方经 `env` 只许给提交身份与日期、往上找仓库的天花板（`ENV_KEYS`），值为 `undefined` 的当没给。再设 `GIT_CONFIG_NOSYSTEM=1`、`GIT_CONFIG_SYSTEM` 与 `GIT_CONFIG_GLOBAL` 指向 `/dev/null`，天花板加上系统临时目录。
   故意不带 git 入口钉死的那组配置：夹具有时要造出与入口相反的配置，去验被测的入口自己带没带。起 git 的函数调用时从模块上取：自检记当前目录、计数预加载换掉模块上的函数后照样记得到、数得到。原先各组自己删的继承变量是六项或九项、有的组一项不删，现在一律全删。
2. **自检记当前目录那一处（`selfcheck-spawn-notes.ts`，登记）。** 原先写在自检开头的那段包装原样挪出来：`noteSpawns(onLaunch)` 换掉七个起进程的函数，名字照旧、`exec`/`execFile` 自带的 promisify 版本一并带过来，交回原函数的返回值。记哪一笔（在不在某一组里、目录在不在自检的临时目录底下）仍在自检里判。
3. **自检脚本。** 十三处建玩具仓库改经 git 夹具；一处问本仓库的提交号（观察器认证入口那一组核汇总里记的提交）改经 git 入口；起 node、sh、bwrap、mkfifo 改经通用启动函数。两组原先自己从模块上取起进程的函数（`createRequire` 与 `getBuiltinModule`），也改了。写在字符串里、运行时落盘再跑的代码原样留着（ADR-219 第四节第三条）。
4. **闸门认「只给测试用的模块」。** 名字在 `TEST_ONLY_MODULES`：`git-fixture`、`selfcheck-spawn-notes`。任何字符串字面量、模板串的任何一段里带着这几个名字（导入说明符就是字符串），就算提到了；提到了的文件不在「测试文件」里，红。「测试文件」现在三行：两份测试与闸门判定自己（它把名字写在常量里）。这一节和「待挪」一样按字典序、不重复；比基线多出的行不红、列给评审看；列了却不在仓库里的红；基线上还没有这一节时当空。

## 三、白名单为什么是这几样

收的是自检里现有调用用到的，不预留。`config` 能设任意键（例如 `core.worktree`），放在白名单里是因为好几组要写提交身份；`-c` 那一层只放四个键，挡的是手一滑把危险的配置写进一次调用。环境只放提交身份、日期与天花板：别的 `GIT_` 变量多半是在指别处的仓库、索引、对象库，或往配置里注入键值。需求测试挪过来时（下一份），要用到的子命令、键加进这几张表，由评审逐个看。

## 四、拦不住的

- 夹具模块防的是误伤，不是存心绕：直接用文件接口改玩具仓库的 `.git/config`、把 `.git` 写成指向别处的文件、经白名单里的 `config` 写 `core.worktree`，都绕得过「只在临时目录里」这一条。
- 本仓库若整个克隆在系统临时目录底下，「不在本仓库里」那一条照样拦得住；但另一份克隆（不是本仓库这一份）在临时目录底下时，夹具能往那份里写。
- 闸门按名字认：把模块名拆开拼、经别的模块转手引出来的，认不出。只给测试用的模块不止这两个时（下一份的换替身模块），名字要加进 `TEST_ONLY_MODULES`。
- 记当前目录那一处的 `syncBuiltinESMExports` 没有变异守着：自检本身已经不按名字导入那个模块，这一句只管别的模块里按名字导入的绑定，测试里看不出差别。
