# ADR-182 「整类落成手写清单」还没有通用句

- 日期 · 2026-10-28 · 回访例程照 `docs/REVISIT.md`「候选句」起草
- 类型：接受为已知缺口
- 触发它的事实：ADR-180 第 48 行那张「同类第 3 次」欠条
- 冲击的需求：无
- 结论：接受为已知缺口；搬不搬进 `process/` 由需求所有者定；人批痕迹是需求所有者合入本条那条 PR
- 理由：这一类犯到了第 3 次；那张欠条的作者读过 `process/`，判通用句还没进去
- 连带改动：索引一行
- 候选句来源：ADR-180 第 48 行 · 同类第 3 次 · 这一类：ADR-71、ADR-77、ADR-180

## 给 process/ 的候选句

```
要守的是一整类东西时，不把实现做成一张逐项手写的清单：清单外的那一项漏了，检查照样报绿，而且漏得没有声音。
让新加的那一项默认就落在守护里面（从同一个来源派生，或默认全守、逐项放行）；做不到的，判据只许写清单真实覆盖到的那几项，不写「任何位置」「全部」。
```

拟放在：`process/3-BUILD.md`「通用纪律」。这三条都是落地时把「一整类」写成了逐项清单，管的是怎么写实现，放写代码那一份的通用纪律最近。

来源：
- ADR-71 第 88 行：敏感字段表是人手维护的，漏了 `score`，红线那条「任何位置」在两处静默失效；测试守的是表上的名字会不会被判出来，不是该在表上的名字在不在表上。
- ADR-77 第 6 行：纪律 lint 的判据写着「任何位置」「全量扫描」，实现是一张手写的敏感字段表，真实覆盖只是表上那几十个名字。
- ADR-180 第 7 行：报告里逐个字段手写转义，漏了十几处，判据本身也是几条各管几类字段的清单。

git log --first-parent --date=short --format='%h %ad %s' -E --grep='ADR-0*(71|77|180)([^0-9]|$)' origin/main -- process/

## 要搬、要拒

- 要搬：需求所有者另开一条 PR 改 `process/`，同一条 PR 在本条末尾追加一块，头一行写成
  `> ⚠️ 上文那张「process/ 里没有这句通用话」欠条已还：搬进了 process/<文件>「<节>」，批准它的是 #<号>`。
- 要拒：在本条末尾追加一块，头一行以 `> ⚠️ 驳回：` 开头（「驳回」后面直接接冒号，不加括注），写为什么（比如 `process/` 哪一句已经说了），
  不写重启条件；也可以在这条 PR 上直接追加，再合。关掉 PR 不合不算驳回，下一跑照样为这一类起草。驳回以后，欠条括号里出现这条记录「这一类」
  以外的编号之前（那张欠条写在驳回前还是驳回后都算），例程不再为它起草；是不是驳回以后才添的，起草时写进「驳回过」，由需求所有者判。

> ⚠️ 欠条：process/ 里没有这句通用话 · 重启条件：需求所有者定了要搬，或同类再添一例
