## 一、取值

| 数 | 意思 | 调用方该做什么 |
|---|---|---|
| 0 | 该干的都干完了：collect 关键词跑完、enrich 与 probe 跑完、render 成功 | 读 stdout |
| 1 | 其他运行中错误或意外崩溃 | 读 stderr；有汇总时断点已保存，可以续跑 |
| 2 | 输入问题：开跑前查出的；跑到一半才查出的缺 key、费用账问题；collect 收尾时评审文件有问题 | 把具体哪里不对报给用户 |
| 3 | 预算不足以支付下一请求：collect、enrich 断点已保存；probe 已出部分结果 | 用户确认新总上限后续跑，或用已有数据收尾 |
| 4 | collect 达标停下 | 读 stdout；照常转述 `pending_keywords` |
| 5 | 供应商返回 402（余额不足） | 告诉用户去充值，不要原样重试 |
| 6 | 保存失败：断点、费用、名单、交付物或评审正本 | 不得声称已保存 |
| 7 | 跨任务记忆 `memory/creators.json` 读不出来 | 停下，请用户修那个文件 |

逐个入口：

- **collect**：跑完 0（F9.e 那种一个词都不搜也算）、达标 4、预算不足且断点存好 3、402 为 5（搜索与 profile 补全两个阶段都是）、运行中才查出的预算或费用输入问题 2、其余运行中出错 1 —— 这几种都出汇总 JSON。保存失败 6（运行中任一次保存失败也算：不再出汇总，先尽力再存一次业务状态，然后结束）、开跑前输入问题 2、收尾时评审文件有问题 2、读不出记忆 7、其余意外异常 1 —— 这几种都不出汇总。保存失败之后又读不出记忆仍是 6；402 之后某步本地收尾失败时按失败的那一种取值
- **enrich**：跑完 0、预算不足 3、402 为 5、运行中预算或费用输入问题 2、其余运行中出错 1，都出汇总；开跑前输入问题 2、保存失败 6、其余意外异常 1，都不出汇总
- **probe**：全部任务跑完 0（单个任务的普通错误记在那一行、接着跑）、预算不足中途停下 3、402 中途停下 5，三种都照出结果 JSON，顶层新增 `stopped`：`done`、`budget` 或 `provider_402`；输入问题 2、其余意外异常 1
- **render**：成功 0、输入问题 2、读不出记忆 7、名单／交付物／评审正本保存失败 6、其余意外异常 1。记忆**写回**失败照旧不中断交付、退 0，由 meta 的 `memory_written`、`memory_write_error` 写明（D4.n）—— 这一路不是「保存失败」：交付物已经写好，没写回的是下一轮去重用的记录

除了退出码，行为只变三处：collect、enrich 运行中保存失败一律不出汇总 JSON（以前有一种是先出汇总再退 1；尽力再存一次也失败时，stderr 先打「收尾保存也失败：…」再打第一次的错误）；collect「⚠️ N 人补全失败」那一行在补全循环被 402、费用错误或预算参数错误打断时也照打（KOL-108 第 1 条）；probe 多一个 `stopped` 字段。stdout、stderr 的其余文字，汇总字段，请求次数与落盘内容都不变。

## 二、实现

`scripts/lib/exit-codes.ts` 给八个数起名（`EXIT.done` 到 `EXIT.memory`），四个入口每一次退出都用名字。保存失败怎么从别的错误里认出来：`saving(fn)` 跑一段保存，它抛的错误原样抛出，只多打一个不可枚举的记号，入口的 catch 用 `isSaveFailure(e)` 认。不换成新的错误对象 —— 换了，`console.error(e)` 打出来的类名会变、错误上的 `code` 会丢，stderr 上就多出东西来（第一版这么写过，自检照出来了）。

- collect：`persist()` 包进 `saving`，原来的函数体改名 `persistNow` 原样不动；收尾的 `reviews.save` 与 `persistListAndStatus` 也包进去。`main` 的 catch 把 `isSaveFailure` 与费用的 `persistence-failed` 同样处理（尽力再存一次、照原样抛出），`main().catch` 里按 `ReviewInputError` → 2、保存失败 → 6、其余 → 1 分。补 profile 的循环外面套 `try … finally`，「N 人补全失败」那一行挪进 `finally`（KOL-108 第 1 条）。收尾那一路（冻结候选、投影、保存评审正本、写名单）抛出时照旧不出汇总，退出码按上面三种分（KOL-108 第 2 条）
- enrich：同样的 `persist` 包装与 catch；402 在 catch 里单独认成 5
- probe：循环里记下停的原因，结果 JSON 带 `stopped`，打完再按原因退 3 或 5
- render：读不出记忆退 7；评审正本保存失败退 6；名单、CSV、XLSX、meta 与报告每一处写盘外面一个 `try`，失败原样打出错误、退 6。`try` 里那一行连着写盘的实参一起（`buildSheets(...)`、`renderHtml(...)` 这几处），实参算的时候抛出也会退 6 —— 没拆开，是因为变异 M-U9-u、M-U9-v 的 `find` 逐字钉着这两行；这几个函数只做纯计算，抛出的路径今天没有用例走得到
- probe：停下的原因用 `process.exitCode` 交出、自然退出，不调 `process.exit` —— 结果 JSON 可能比一个管道缓冲大，`process.exit` 会把 stdout 截断

开跑前那些 `process.exit(2)` 没换成 `EXIT.input`：变异目录里有几十条变异的 `find` 逐字钉着这一行，换了全部失配，意思又没变。
