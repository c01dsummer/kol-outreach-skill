# ADR-91 bio 空串不是一个态：需求所有者裁决，夹具默认值改 null

## 起点：欠条的重启条件是「需求所有者确认」，今天确认了

ADR-88 第二节记下 `bio` 的空串与类型契约对不上，挂了欠条，重启条件写着
「需求所有者确认」。ADR-90 把那条断言去掉了，但**没有裁决**，夹具的默认值照旧。
2026-09-19 需求所有者裁决：**`''` 不是一个态。**

三态就是契约里写的那三个：`undefined`（没查过）／`null`（查过、对方没写）／
有内容的字符串（查过、写了）。

## 一、裁决之前证据就已经齐了，缺的只是谁来拍

这几条都是在树上核得出来的，不是推断：

| | |
|---|---|
| `scripts/lib/types.ts` 的契约注释 | 明写三态是 undefined／null／有内容的字符串 |
| TikTok 的补全映射 | 查回来没写简介 → `null` |
| Instagram 的补全映射 | 同上 |
| `''` 的生产者 | **一个都没有** —— 实现里没有任何地方产出它 |
| `''` 的唯一来源 | `scripts/test.ts` 里夹具构造器的默认值 |

**一份在实现里没有生产者的取值，出现在测试夹具的默认值上** —— 那不是契约多了一态，
是夹具在说一件契约里没有的事。

## 二、改了什么

一行：夹具构造器的 `bio` 默认值从 `''` 改成 `null`。

## 三、没有新增判据，理由

欠条括号里写着「写进 `P1.a` 的判据」。**没照做。**

`P1.a` 讲的是 `email` 的三态。把 `bio` 塞进去会改掉那个编号的含义，
而 `process/1-REQUIREMENTS.md` 定的是**编号不改含义**。

而且这条规则**已经有测试守着**：两个平台的补全映射各有一条断言「查回来了但没写简介
→ 记『查过，没有』」，记在 `P1.c` 名下，各自配着负片。裁决没有引入新行为，
它确认的正是那两条测试已经在守的东西。缺的只是夹具跟上。

## 四、这一行改完，什么都没红 —— 这件事本身要说清楚

改之前改之后，测试全绿，变异一条不剩全被抓到。

**也就是说这个改动没有被任何检查守着。** 它修的不是一个会红的缺陷，
是「夹具在说一件契约里没有的事」。谁把它改回 `''`，今天也没有任何东西会喊。

这不是「所以不重要」。夹具的默认值是往后每一条用 `mk` 写的测试的起点 ——
起点是一个契约里不存在的态，下一条测试就可能围着那个态写断言，
而 ADR-88 那三条空断言正是这么长出来的。

## 五、没做的

- **没有给「`bio` 不得是 `''`」加检查。** 那是一条全称，而实现里没有生产者 ——
  要查它得扫写法，正是 ADR-77 撤掉纪律 lint 的形状。
  ⚠️ 欠条：**没有任何检查拦得住有人把夹具默认值改回 `''`。**
  重启条件：下一条要动那个夹具构造器的改动，或者下一次有人在实现里写出 `''` 这个态时。
- **另一件裁决（未查询的粉丝数排在确实是 0 的前面）不在本条。**
  那是改产品行为，要动需求登记表、判据、负片，单独走一条。
