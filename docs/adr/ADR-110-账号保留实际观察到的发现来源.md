# ADR-110 账号保留实际观察到的发现来源

- 日期：2026-09-23
- 类型：需求补充
- 触发事实：交接任务要求记录真实发现路径；当前 IG Reels 空结果后会调用账号名搜索，但账号只保留搜索词和任务下标，不能由这些字段识别实际返回它的端点。
- 冲击的需求：新增 D15；承接 D1、D3、U1、U3、U5、U8，P1/P5 交点见登记表。
- 结论：采纳
- 理由：在返回账号的适配边界记下来源，才能让后续合并与交付保留实际路径；配置标签和补全资料都不能证明发现路径。
- 连带改动：类型、纯来源并集与格式化、现有三路搜索适配、合页与同人合并、probe/表格/HTML，以及架构与 Skill 字段说明。

## 数据与公开接口

```ts
type DiscoveryEndpoint =
  | '/api/v1/tiktok/app/v3/fetch_video_search_result'
  | '/api/v1/instagram/v2/search_reels'
  | '/api/v1/instagram/v2/search_users'
interface DiscoverySource {
  platform: Platform
  handle: string
  keyword: string
  dimension: Dimension
  endpoint: DiscoveryEndpoint
}
// Creator 新增 discovery_sources?: DiscoverySource[]
// scripts/lib/discovery.ts 的纯接口：
mergeDiscoverySources(
  first?: readonly DiscoverySource[], next?: readonly DiscoverySource[]
): DiscoverySource[] | undefined
formatDiscoverySources(sources?: readonly DiscoverySource[]): string
```

五字段组成来源身份。platform/handle 按 D1 的大小写规则比较，但保留第一次原值；关键词不删井号、不变大小写、不 trim；维度和端点按原值比较。稳定并集不改变输入；只有两侧都缺席时返回 undefined，有任一数组而并集为空时返回 []。首次收页也去除来源重复。合页为旧记录在前、新页在后；跨平台合并为主记录在前、关联记录在后，不承诺全局发现时间顺序。

适配器只有实际返回账号时才填来源。来源是该条响应账号及搜索任务的快照；profile 不写它。IG Reels 无可用账号、users 返回账号时只给 users 来源；错误和零账号结果没有可附着来源的账号。沿用既有请求、fallback、页数、预算与异常行为，as_hashtag 继续只是配置元数据。端点常量由实际请求与来源填写共用，不能复制两套可漂移的路径。

旧记录没有来源不妨碍追加后来真实观察，也不把新的观察说成旧历史。这与 source_tasks 的完整归属口径不同：source_tasks 仍沿用原规则，来源集合独立保存，不从任务下标、首个来源词或当前任务列表反推。来源属于账号，不对应具体作品，不是请求历史，也不是费用依据。

## 保存与展示

来源跟随 Creator 在现有业务保存点落入 creators.raw.json 和 creators.json，恢复及 profile 补全保持已有值；不进入费用检查点，不改变评分与准入。probe 只透传 sample[].discovery_sources，不补空值或来源。CSV/XLSX 最末增加 discovery_sources，不移动原列；同一纯格式化函数用于表格和 HTML。

格式约定：每项为 `路线 · 平台:@账号 · 关键词 · 维度`，多项以 `；` 分隔。三条路线分别显示 `TikTok 视频搜索`、`Instagram Reels 搜索`、`Instagram 账号名搜索`。缺席及空数组显示 `来源未知`。HTML 在输出处转义整个格式化文本；标签为「已观察发现来源」，并说明「仅含已记录的账号发现来源，可能不含完整历史；不对应具体作品或请求次数」。CSV/XLSX 的字段含义在输出说明中同样限定。

## 验证与边界

先完成需求与本契约，再由未读待改生产函数体的测试上下文从公开接口、类型和假网络协议写测试。纯测试验证五元组差异、大小写、分隔符冲突、输入不变、首次去重、合页/跨平台并集、未知及展示。假网络入口验证三条实际路径、fallback/profile 边界、probe/采集保存与恢复、交付字段以及既有请求次数和费用不变。负片守住适配、两种合并、透传与展示接线；全链检查前不声称通过。

本项不切换发现策略、不新增端点或付费请求、不接 IG 游标翻页、不决定图文指标口径；这些各有独立问题。未知或空来源不证明“没搜过”，已知非空集合也不保证所有历史均已记录。用户要求不再提交 evidence，因此只提交需求、实现与可重跑的假网络测试，不新增证据归档。

## 验证追记

需求与设计先提交，独立单元和入口测试后提交，实现最后接线。实现前，入口假网络测试出现六项行为失败，实际进程与文件生成均可运行；实现后单元测试及 discovery 入口组通过。probe 的已知来源由三条真实适配路径验证；当前路径不会生产来源缺席或空数组的账号，因此不为这两态新增运行时注入或纯投影接口，透明传递由独立代码审查核对，不把不可构造样本宣称为入口实测。

新增负片 M-D15-a 至 M-D15-j 覆盖真实适配、五元组、首次收页、同人合并、已有账号业务保存、probe、表格与边界声明。既有 M-D6-t 只随私有搜索参数从关键词变为任务对象调整锚点，仍验证不能吞掉兜底预算异常。
