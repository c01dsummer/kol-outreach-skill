# ADR-105 搜索作品保留真实标识并稳定取并集

- 日期 · 2026-09-23（Asia/Shanghai）· 接续 ADR-102 作品证据欠条
- 类型：需求补充与事实证伪
- 触发它的事实：同一个人被不同关键词搜到时，现有累加器在两边都有作品的情况下丢弃后到证据；跨平台合并则直接拼接。此前缺少 IG 作品 id 的真实层级，2026-09-23 用户本地单请求输出已包含 `data.data.items[0].id`。
- 冲击的需求：D11（新增）；继续遵守 P1 的缺失与未查询边界。
- 结论：采纳。真实 id 可用时按平台内作品标识稳定去重；缺 id 的作品逐条保留。
- 理由：不能用猜测的空标识或文案把不同作品吞掉，也不能仅保留第一次搜索命中而丢弃后来的真实作品。
- 连带改动：需求登记表及生成 SPEC、作品类型与适配契约、作品并集模块、采集累加与同人合并、来源字段表、需求测试及变异；ADR-102 只追加新结论。

## 来源和状态边界

TikTok 使用已实测的 `aweme_info.aweme_id`（现有直接条目兼容路径继续读同一个 `aweme_id`）；
Instagram 只使用这次确认的 item 直接 `id`。不能用用户 id 或 caption id 替代，
不能从键路径报告推出所有作品都有 id 或值必非空。

`RecentPost.id?: string` 是带平台前缀的作品键，形如 `tiktok:<原始id>` 或
`instagram:<原始id>`。原始值只有非空白字符串或安全整数可用；字符串用 `trim()` 仅判是否空白，保存原值，
不擅自删除两侧空格；安全整数转十进制字符串。不接受对象、不安全数字或空白，缺失仍为缺失。平台前缀防止跨平台同号误合，并不参与创作者身份判定。
这是搜索证据字段，不更改公开绩效样本 `NormalizedPublicPost` 的现有契约。

## 合并契约先于代码

新模块 `scripts/lib/posts.ts` 提供 `searchPostId(platform, raw)` 和
`mergeRecentPosts(left?, right?)`。前者处理外部标识；后者不改输入，依次保留左边、
右边的首次同 id 作品，缺 id 或空白 id 的作品全部保留；非空白字符串键按原值比较，不做 trim。两边均无非空作品时返回缺失，
不从空数组创造「确认无作品」。同 id 后来文案或指标变化仍保留首次记录，
本次不引入更新或评分重算规则。

采集累加器首次收人、再次收页均调用同一作品并集函数，覆盖页内重复与跨关键词重复。
同人合并保持现有主记录选择，主记录作品在先、关联记录作品在后，并调用相同函数。
跨平台原始 id 相同仍是不同作品；未知 id 的旧样本没有可靠去重依据，允许重复保留。

D11 与 P1 的交点明确取 P1：缺少可靠标识时保留重复证据，不造假 id；无作品证据仍是
未查询，不把旧空数组改称确认无作品。旧的「两边都有则不合并」判断被 D11 替代，
已有作品不可被擦除的保证继续保留；既有补齐负片只更新锚点，不改变原失败含义。

本次不连接 IG 分页、不决定图文口径、不改变按账号名兜底或同人识别规则。
