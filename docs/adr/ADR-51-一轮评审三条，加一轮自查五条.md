# ADR-51 一轮评审三条，加一轮自查五条

- 日期 · 2026-08-28 · 评审第十五轮 + 用户要求「按五类完整自查一遍」
- 类型：**事实证伪**
- 冲击的需求：P4 · D4 · D1
- 结论：**采纳全部**

### 评审提的三条

1. **`.check-cache/test-claims.json` 被提交进了仓库。** 拆分时我判定
   `.gitignore` 里那行属于后一半，于是 `git add -A` 把这个产物带了进来 ——
   而这一半里**没有任何代码写它或读它**。已移除。
2. **写入侧生成的键不过校验**：名单里混进一个展示形态的用户名，
   就写下一条自己下次读不出来的记录。与 ADR-46 的产品名同一条规矩，
   这次轮到键 —— 把判断抽成 `keyProblem`，读写两侧共用。
3. **同一个任务目录跑两个采集，三步落盘会交错**：三步各自原子，
   合起来不是。用记忆那边同一个机制（改名前比对），只检测不串行化。

### 自查又找出五条

用户指出前十四轮的问题可归为五类，要求按类逐条自查全 PR。找出的：

| # | 类 | 事实 |
|---|---|---|
| 一 | 4 · 5 | `writeFileAtomic` 里 `catch { /* 新文件 */ }` 断言了单一原因 —— 读不到目标权限位时会当成新文件，把用户设过的权限换成 0600。方向与 ADR-40 相反，性质相同 |
| 二 | 5 | D4 写「下一次写回**必须**清掉临时文件」，而目录列不出来时代码直接跳过。措辞改成「列得出来时清掉」，并写明为什么跳过是对的 |
| 三 | 3 · 4 | **D1 说「两侧必须逐字一致」，而那是两个各自写出来的表达式。** 今天一致靠的是我把同一句话写对了两遍 |
| 四 | 3 | 「同一个人」在仓库里有**五处各写各的**，三套不同规则：记忆两个都小写、采集只小写用户名、跨平台识别都不小写 |
| 五 | 1 | 清临时文件时 `catch { continue }` 同样断言了单一原因（「刚被别人清掉」） |

三和四是同一件事的两面，一起修：身份键搬进 `types.ts` 的 `creatorKey`，
记忆与采集共用；D1 的措辞从「逐字一致」改成「**调用同一个规范化函数**」——
从一句要靠人守的话，变成一件结构上做到的事。

### 修的时候类型检查又抓出一个

把采集那处的键接进有类型的函数之后，`tsc` 当场指出 `p.platform` 可能是
undefined —— 而上一行只挡了 `handle`。原先的写法会静默生成一个
`undefined:名字` 的去重键：那个人此后既去不了重、记忆也查不到他。

**这条没人发现过。** 它藏了这么久，是因为手写的模板字符串**接受任何东西**；
一旦换成有签名的函数，类型检查就替我看见了。

### 教训

**「同一段逻辑有几份副本」不只是维护问题，它会让需求里的「必须」变成假话。**

D1 那句「两侧必须逐字一致」，写的时候是描述一个事实（当时确实一致），
读起来却像一个保证。区别在于：**事实靠人守，保证靠结构。**
把两份合成一份之后，那句话才第一次变成真的 —— 而且顺带把一个手写模板
换成了带签名的函数，类型检查立刻还了一个没人发现的 bug。
