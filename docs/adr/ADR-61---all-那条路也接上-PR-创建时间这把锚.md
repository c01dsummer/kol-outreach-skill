# ADR-61 --all 那条路也接上 PR 创建时间这把锚

- 2026-09-02 · PR #7 合并后复查分支寿命闸门时发现
- 类型:**事实证伪** —— ADR-59 把「`--all` 那条路上作者时间仍是唯一的钟」写成一处已知缺口;
  实测它不只是缺口,是**系统性报小**,而且一声不响
- 冲击的需求:无(闸门自己的判定)
- 结论:**采纳**

## 触发它的事实

同一条分支(PR #5 的 head),两条跑法给出两个数:

| 跑法 | 报出的分叉时长 |
|---|---|
| `npm run age -- --all` | 108.1 小时 |
| `npm run age -- --ref <同一个头> --since 2026-08-28T06:13:15Z`(PR #5 的创建时间) | 118.8 小时,并提示「历史被改写过」 |

差 10.7 小时。最早那个提交的作者时间是 08-28 16:52,而 PR 是 06:13 开的 ——
历史在 PR 开出来之后被改写过。`--ref` 那条路有锚,按锚算对了;`--all` 那条路没有锚,
报的是改写后的数。**同一条分支、同一天、两个数,小的那个还什么都没说。**

## 改了什么

- `--all` 加 `--prs <清单>`:`gh pr list --json number,headRefName,createdAt,isCrossRepository`
  的原样输出。每条分支若有**同仓库**开着的 PR,取其中最早那个的创建时间当锚 ——
  与 `--ref --since` 是同一把锚、同一个 `birthOf`(`age-rule.ts` 的 `anchorFor`)
- 只认同仓库的 PR:fork 来的 PR,那条分支在 fork 里,基仓的 `origin/<同名>` 要么不存在、
  要么是另一条分支 —— 把它的创建时间安上去是拿别人的锚量自己
- `age.yml` 的定时任务把清单落在 `$RUNNER_TEMP`,贴 PR 那一步和 `--all` 共用同一份
- **没有锚的那几条不再沉默**:每一行标 `[锚 #N]` / `[无 PR]` / `[无清单]`,汇总里说有几条
  没有锚、它们的数可能偏小。「没给清单」和「没有 PR」分开标 —— 前者是这次跑法的事,
  后者是这条分支的事,补法不一样。清单给了却读不懂则拒答:一份读错的清单会把所有分支
  静默标成「无 PR」

> ⚠️ 就地更正:「有 PR 但创建时间读不出来」这一态原先只打标签、照常用作者时间。PR #10
> 合并后的评审指出,这是在锚最该起作用的时候(历史被改写过)把它扔掉,退回去的正是用户
> 可控的那个钟,报告里还一个字不提。现改为**拒答**(进「量不了」);`--ref --since` 给了却
> 读不出来、或给了空串,同样拒答。「量不了」是 `birthOf` 给出的一个有名字的判定,入口只传
> 不判,M-H2-s/t 守着;一条分支的几个 PR 里有一个读不出来就算读不出来,M-H2-u 守着;
> 「读得出来」按 RFC 3339 的形状认,不按 `Date.parse` 肯不肯认(它连 `Jan 1 9999` 都认),M-H2-v 守着;
> 形状对了还要日历上存在(`04-31`、`24:00` 会被悄悄进位成下一天),M-H2-w 守着。

接上之后再量一次:同一条分支报 `118.9 小时 [锚 #5 ⚠ 按锚算]`,另两条没有 PR 的分支
标 `[无 PR]`,汇总说 `2 / 3 条在途分支没有锚`。

## 仍然量不到的

没有 PR 的分支还是只有作者时间。这条路上没有服务端的锚可借 —— 分支本身在服务端
没有创建时间。留在报告里,不假装它被守住了;要么开 PR,要么删掉分支。

## 教训

ADR-59 把这条写成「缺口」,用词是对的,但**没量过它有多大**。一处已知缺口若能当场量出来,
就该量出来写上数 —— 「10.7 小时」和「可能偏小」不是同一句话:前者会让人立刻去补,
后者会被当成一句免责声明读过去。
