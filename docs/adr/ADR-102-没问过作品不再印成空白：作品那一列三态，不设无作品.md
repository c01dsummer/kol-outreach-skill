# ADR-102 「没问过作品」不再印成空白：作品那一列三态，不设「无作品」

- 日期 · 2026-09-22 · 做 IG 召回（ADR-101）时读 IG 按账号名搜人那条兜底路径撞见的
- 类型：**既有缺陷**（P1 红线）；其中「这一列给几个值」是**产品取舍**，由需求所有者拍板
- 触发它的事实：兜底路径给搜到的每个人写 `recent_posts: []`，而那个响应里根本没有作品；
  交付表的 `best_post_desc` 把「字段缺席」「空数组」「作品没写文案」三件事都印成空白
- 冲击的需求：**P1.e**（判据原文一个字不改 —— 三态正好就是它）
- 结论：**采纳。** 这一列三个值 —— 没问过作品 →「未查询」、有作品但文案是空的 → 空白、
  有文案 → 文案。**不设「无作品」**：今天没有一样证据说得真这句话（第二节）

---

## 一、错在哪

`skill/references/providers/_interface.md` 和 `scripts/lib/types.ts` 都把 `recent_posts`
声明成**必填**。IG 按账号名搜人的那条兜底路径拿不到作品，就写一个空数组来满足类型 ——
**那个空数组是一句「问过了，他没作品」的假话**，而我们从没问过。

它落到两个地方：

1. **交付表。** `best_post_desc` 对这批人印空白，跟「作品本身没写文案」一模一样。
   运营只能读成后者。
2. **Phase 04 的语义判断。** 读 `creators.json` 的那一步看到空作品列表，
   按 `semantic-fit.md` 第 2 条（是不是真人创作者）可能直接判掉 —— 人没见过他的作品，
   却给了一个结论。

## 二、几个值：需求所有者的裁决

1. 第一轮选的是**四个**：未查询 / 无作品 / 空白 / 文案。
2. 第二轮改成「无作品」看主页作品样本 —— 搜索命中的作品是被关键词筛过的，
   证明不了他没发过帖。
3. 然后需求所有者指出：**IG 上图文和视频同时存在。** 而 IG 的主页样本只留视频
   （`recentInstagramPosts` 的过滤：「不拿图片帖与视频混算」）—— 样本里零个视频，
   只说明他不发视频，不说明他没发过帖。「无作品」这句话说不真，于是定为**三个值**。

⚠️ 裁决当时还说了一句「TikTok 就是纯视频」，**这句不成立** —— TikTok 也有纯图文帖。
它不改变本条的结论：TikTok 的人都是先见到一条作品才建记录的，走不到「没作品」那一支。
但它把欠账第 6 条变宽了（见那一条）。

## 三、盘上的旧空数组：读成「未查询」，不迁移

今天的代码里空数组**没有生产者**：两条搜索路径都是先见到一条作品才建人，
兜底路径改成不写这个键。所以盘上旧 `creators.raw.json`／`creators.json` 里的空数组，
**全是兜底路径以前写的，意思一律是没问过**。

于是读它的地方把空数组和缺席当成同一态。不去改写盘上的旧文件 ——
读的时候解释对了，旧目录不用升级也说真话。

## 四、同一个人被两个词搜到：补齐，不并集

`mergePage` 原先见到老熟人只追加来源任务，别的字段都不动。现在加一笔：
**先到的那次没带作品、这一页带来了，就补上** —— 不补的话，交付表对一个我们明明见过
作品的人说「未查询」。

- 判「没有」用长度，不用 `undefined` —— 盘上的空数组也是没问过（第三节）。
- **两边都有作品时不动。** `RecentPost` 还没有作品 id：同一条作品在两个词下各来一次，
  拼起来就成了两条，而「重复模板」在语义判断里是**非真人**的信号（`semantic-fit.md` 第 2 条）。
  并集等 id 落地再做（欠账第 5 条）。
- 跨平台合并（`identity.ts`）那一处原本就是并集，**不改**：跨平台必有一边是 TikTok，
  两边都没作品的情况走不到。万一走到，拼出来的空数组也按第三节读成「未查询」。

## 六、欠账

1. **`identity.ts` 那一支没有负片。** 走不到的分支，写负片只能靠手造一个现实里不存在的输入。
2. **`scripts/probe.ts` 的 `top_post` 还是两态** —— 没问过和没文案都印空串。它是核实工具，
   不进交付物；下次碰它时一起改。
3. **已经跑过 Phase 04 的旧任务不回头改判。** 兜底路径那批人当时可能因为「看起来没作品」
   被判掉了。重跑 Phase 04 才会按新规矩判 —— 本条不替用户重跑。
4. **挑播放最高那一条时，缺播放数的按 0 排。** 只决定展示哪一条、不写回数据，
   但它仍是一处「不知道当 0」，归在 P1.b 那条全称豁免底下（ADR-77）。
5. **作品 id 与并集。** 两条搜索路径的响应里都有作品 id（TikTok
   `search_item_list[].aweme_info.aweme_id`，IG `data.data.items[].id`）。给 `RecentPost`
   加上 id，`mergePage` 才能按 id 去重取并集。⚠️ 不许照抄主页样本那里「拿不到 id 就写空串」
   的写法 —— 缺 id 的作品会全部撞成同一条，去重把它们吞掉。
6. **「无作品」要一个把图文算进去的生产者。** 而两个平台对图文的口径今天不一致：
   IG 主页样本明确扔掉图文；TikTok 主页样本那一侧代码里**没有任何过滤** —— 那个端点
   会不会返回图文帖、图文帖带不带播放数，还没查权威文档，所以说不出它是「混着算」
   还是「本来就只有视频」。先把这两件事查清、定下两个平台统一的口径，再谈「无作品」。

## 教训

**类型把一个字段声明成必填，而某条路径拿不到它时，那条路径就会编一个「空」来满足类型 ——
那个空就是一句「查过，没有」的假话。** 一个字段只要在某条路径上拿不到，类型上就该是可选的；
必填只留给每条路径都真拿得到的字段。

**给需求所有者列选项之前，先查每个选项今天有没有生产者、证据说不说得真。**
实现者第一轮列的四个值里，「无作品」当时没有任何代码能真生产它 —— 需求所有者据此选了四个，
又在两轮之后被迫退回三个。选项表本身就是一次陈述，列出来的每一项都在暗示「这做得到」。

## 七、2026-09-23 合入后更正与欠条台账

> ⚠️ 更正：第六节第 2 条的「核实工具，不进交付物」不能成为推迟理由。`scripts/probe.ts` 是 F3 小样试探的入口，Agent 会读它判断方向；作品未查询被印为空串同样会误导。输出契约与修补见 ADR-103。

> ⚠️ 更正：第六节第 5 条关于 IG `data.data.items[].id` 的陈述未经真实响应核实。已有探针按 `id`、`pk`、`media.id`、`media.pk` 逐个尝试，不能用探针代码证明其中任何一个键已被观察到。TikTok `search_item_list[].aweme_info.aweme_id` 则有交接中的本地调用观察；两者证据状态不同。

> ⚠️ 更正：空文案不只可能来自作者未写。两条搜索适配路径也把未取到的文案转换为空串，所以本记录中「作品本身没写文案」的解释过强；当前空白仅表示所选作品的文案值为空。交付说明同步收窄，不把缺失状态已被保留说成事实。

> ⚠️ 编号消歧：第五节的 `M-P1-o`、`M-P1-p`、`M-P1-v` 曾在 ADR-77、ADR-81 中指已删除的纪律 lint 变异。本记录起它们分别指兜底空数组、删掉作品补齐、用后页覆盖作品。旧记录所指仍是当时的 lint 变异，不可按当前清单反解历史；新增编号不再复用。

以下把第六节的六项逐一纳入可检索台账，保留原文以记录当时判断。

> ⚠️ 欠条：跨平台合并中两侧都没有作品的路径没有负片，当前搜索生产者无法产生这种组合 · 重启条件：新的发现路径能让两平台都在没有作品时建立记录，或开始修改跨平台作品合并契约。

> ⚠️ 欠条：小样试探的 `top_post` 仍把作品未查询与空文案压成空串 · 重启条件：本次交接已点名此缺口，按 ADR-103 修复并以入口自检验证。

> ⚠️ 欠条：旧任务已经完成的语义判断可能把兜底账号误当成没有作品，现有修补不会回写旧判断 · 重启条件：用户要求重评旧任务，或该任务再次执行语义筛选。

> ⚠️ 欠条：选择展示作品时缺播放量仍按 0 排，与真实 0 并列且保留原顺序 · 重启条件：用户要求区分缺播放量与真实 0 的展示优先级，或修改最佳作品的选择规则。

> ⚠️ 欠条：搜索作品没有 id，同平台二次命中仅补齐、不取并集；IG id 的具体字段层级未验证，缺 id 不能写空串参与去重 · 重启条件：取得 IG 真实响应的字段证据后，按交接要求给作品加可选 id 并实现并集。

> ⚠️ 欠条：两平台图文口径未统一，TikTok 两个端点是否返回图文及图文播放量仍缺证据，也没有能支持「无作品」的完整生产者 · 重启条件：查清官方资料或取得本地实测结果，并由需求所有者决定图文是否计入样本。

> ⚠️ 欠条：`RecentPost.desc` 必填，适配层把文案字段缺失与空文案压成空串；本次只收窄输出说明，没有修复字段状态 · 重启条件：调整搜索作品文案契约时，将缺失与空串分开并同步生产者、消费者和验证。


## 八、2026-09-23 作品并集契约替代第四节（ADR-105）

> ⚠️ 更正：2026-09-23 用户本地单请求输出的键路径已包含 `data.data.items[0].id`，
> 首条没有 `media` 包层。第七节「IG 层级未验证」在这个首条观测范围内得到补充；
> 不据此声称值必非空、类型已核实或所有条目都有 id。

D11 与 ADR-105 接替第四节的「两边都有作品时不动」及第六节第 5 项：搜索作品标识
可用时按平台内 id 稳定取并集，同 id 保留先到记录，后到新作品按原顺序追加；缺 id
或空白 id 的作品逐条保留，不按文案折叠。首次收页也遵守此规则。跨平台同人合并
同样使用该契约，主记录在先、关联记录在后，原始 id 跨平台相同不能合成一条。

未查询由 D11.e/f 一并约束。这里只记录契约替代，不把尚未完成的实现或验证报为已还债。
原有「已取得作品不得被擦除」与空数组读作未查询的保证继续成立，不新增「无作品」状态。

## 九、2026-09-24 追记：第七节图文欠条的重启条件满足了

第七节那张「两平台图文口径未统一」的欠条，重启条件是「查清官方资料或取得本地实测结果，并由需求所有者决定图文是否计入样本」。

- 本地实测（零成本，需求所有者本机只读核对，见 ADR-101 第十五节）：
  - TikTok 视频搜索两个词首页 40 条，没确认到图文正例；`aweme_type` 有 0 与 55，55 那条是视频还是图文没有判定，
    不能用「不是 0」判图文。
    主页作品端点没有样本。
  - IG Reels 8 份首页 96 条全是视频；话题页 191 条里 97 条非视频，它们的 `play_count` 是 0（假零）、`like_count` 有的为 null、
    `taken_at` 是字符串（这 8 份话题页首页里视频条目也是字符串，所以字符串不能当图文标记）。IG 主页作品端点上图文条目带哪些字段，没有样本。
- 官方资料：固定规范核过的 IG 端点（ADR-101 第十三节：V2 Reels／users／general、V3 users、V1／V2 hashtag、V1／V2 id 转用户名），
  业务 `data` 都没有结构约束，不限定媒体类型；
  TikTok 两个端点与 IG 主页作品端点都没在固定快照里核过。和样本放在一起的报告 `photo-tt-search/report.md`（谁写的没有记录）
  核对了 docs.tikhub.io 的视频搜索与用户主页作品两页，那是在线文档；贴回的节选里没有这两页的日期与版本，
  通用响应模型也没有回答媒体类型。
- 需求所有者的决定（2026-09-24；原话「第一类，follow 你的建议」，采纳的是会话里逐条列出的建议）：
  - 主页样本计入图文；播放类指标（`median_views`、`view_rate`、`reach_consistency`、`engagement_rate_views`）只用视频，
    互动、发帖间隔与活跃度用全部作品，活跃标签随之看图文；
  - 搜索命中作品只给判为视频的条目写播放数，图文与轮播作为文案证据保留；
  - 维持第二节的三态，不设「无作品」。
- 施工另开 PR：改 D8 等需求文字要按 `process/2-CHANGE.md` 评定。IG 一侧有现成的视频判定，可以先做；
  TikTok 一侧要先查清靠哪个字段认图文、主页端点返不返回图文，在那之前照旧。

这张欠条随之重启，由后续施工 PR 还；还之前它照旧在台账上。

## 十、2026-09-25 搜索播放数落实第九节裁决

Reels 搜索适配原来直接把条目的播放字段写进搜索作品；话题搜索已按现有视频信号门控。
前者与第九节已定的「只给视频写播放数」不一致。D18.a–d 将两条搜索路线的正、负分支分别列为
验收边界：任一既有肯定视频信号成立才保留来源播放数，真实 0 保留；没有肯定信号的
图文、轮播及未知媒体保留作者和作品内容，播放数缺席。两路共用同一视频判定，
不凭端点名或来源播放字段是否出现来推断媒体类型。

该口径只作用于新解析的搜索命中作品。旧任务已保存的作品没有逐条媒体类型证据，
本次不追溯改写或证明其播放数字段；主页绩效样本与 TikTok Photo Mode 仍各按自身
尚未完成的证据边界处理。本节记录施工目标，不以此宣称检查或线上采样已通过。
