# ADR-98 体量闸门按内容量收费：只改行内空白的行不计，折扣走白名单

- 日期 · 2026-09-21 · 起因是 ADR-97 第六节那条主修（给 `selfcheck` 一个选跑入口）
  落地时撞上了这道闸门：把 `scripts/check/selfcheck.ts` 的小节包进回调要重排缩进，
  而闸门量的是不带 `-w` 的 `git diff --numstat`，纯重排也照数
- 类型：**既有缺陷**（这道闸门自己写下的原则没有落到实现上），外加一条**口径变更**。
  不触及需求登记表 —— 检查链的计量口径不是编号需求
- 触发它的事实：见第一节（实测，命令在那一节）
- 冲击的需求：无。冲击的是**这道闸门看得见多少改动**
- 结论：**① 计数改成「两遍 numstat 合并」：吃折扣的后缀取忽略行内空白那一遍，其余照实；
  ② 吃折扣的后缀走白名单（今天只有 `.ts`），不是黑名单；
  ③ 折掉的行数逐类打出来，为 0 也打；
  ④ 「量新增行带哪些 git 参数」从入口搬进判定模块，并由一个真 git 仓库的夹具钉住；
  ⑤ 不写死亡条件 —— 这道闸门早有一条，在 ADR-80**
- 理由：原则早就写在这道闸门自己的注释里（「按搬运量收费会惩罚重构」），
  只是它只为「整文件改名」开了口子，认不出重排缩进

## 一、量出来的事实（git 2.43.0，树钉在 `017a8e3`）

| 情形 | 照实 `--numstat` | 加 `-w` |
|---|---|---|
| 三行代码包进回调＋缩进 | 5 增 / 3 删 | **2 增 / 0 删** |
| 纯改缩进、零内容变化 | 照行数 | **文件整个从输出里消失** |
| 只加一个空行 | 1 增 | 1 增（不折价） |
| 折行重排（`call(a, b)` → 多行） | 5 增 / 1 删 | 5 增 / 1 删（不折价） |
| 纯改名（零内容变化） | `0\t0\t` ＋两个路径段 | 同 |
| 改名 ＋ 整体缩进 | 旧全删 ＋ 新全增 | **同（没折价）** |
| 二进制 | `-\t-\t` | 同 |
| 字符串字面量里加一个空格 | 1 增 / 1 删 | **文件整个消失** |

两条要记住的：

**`-b`（`--ignore-space-change`）不够，而且是被严格支配的。** 前导缩进是「插入」不是
「量的变化」，`-b` 认不出来 —— 上表第一行它读 4 增 / 2 删，和照实数一模一样。

**折价发生在行上，不在文件上。** 多数被折价的文件在 `-w` 输出里**并不消失**
（600 行包进回调 ＋ 两处真新增 → 照实 604，忽略空白 4，文件两边都在）。
所以那句交代要报**折掉的行数**，报文件数会在折价最大的那一类上报 0。

## 二、白名单，不是黑名单

吃折扣的后缀列在 `WHITESPACE_FREE`，今天只有 `.ts`。

写成白名单是因为**失败方向**：漏掉一种文件类型的后果是「照实全数」，也就是今天的行为。
反过来写成「这几类不折价」，下一种空白带语义的文件（Python、Makefile、`.rst`）进来时
会被静默折价，而没有任何东西提醒 —— ADR-77 撤掉的那张手写敏感字段表，错的正是这个方向。

这一条同时把三处缺口从「披露」变成「堵上」：全仓 `.md` 的四空格代码块、围栏缩进、
列表层级都带语义（实测一次零内容变化的全仓重排，照实数判红，一刀切 `-w` 会读 0/600 判绿），
`.yml` 与 `AGENTS.md.tpl` 同理 —— 它们一律照实数。

## 三、为什么不用 pathspec 分流

`-- ':(exclude)*.md'` 看着更直接，却会把一次**跨类改名**的两端切进不同调用，
改名检测就此失效：400 行零内容变化的 `挪走的.md → 挪来的.ts`，单次调用读 `0\t0\t`，
两次 pathspec 调用读成「文档侧删 400 ＋ 源码侧增 400」（实测）。
那正撞在 `parseNumstat` 那段承重注释上 —— **拿走改名折扣去换空白折扣，
是把这道闸门自己写下的原则换掉一条。** 所以两遍都**不带 pathspec**，按路径逐文件合并。

## 四、被否决的替代方案

- **`-b`** —— 见第一节，被 `-w` 严格支配。
- **把 `-M` / `--find-renames` 的相似度阈值调低**，好让「改名＋整体缩进」也折价 ——
  `-M`、`--find-renames=01%`、`-C`、`-B`、`--find-copies-harder` 全试过，救不回来。
  两个折扣**天然互斥**：忽略行内空白唯一宣称免费的那类编辑，恰好是唯一会把改名相似度
  打到零的那类。实测那组反差最能说明问题：挪个位置同时改 3 行真内容收 3 行；
  挪个位置、一行内容都不改、只整体缩进收满额 60 行 —— **真改内容反而便宜 20 倍。**
  这个反常写进了 `size-rule.ts` 的注释与闸门的运行时输出，不藏着。
- **自己写一个只忽略前导空白的比较器**（`textconv` 或逐行解析 `-U0`）—— 比 `-w` 准，
  它不会盖住字符串字面量里的空白。否掉的理由是它给这道闸门开了一条**静默读 0** 的路：
  一个自己写的行比较器出错时不会抛，只会少数几行，而「读错了还照常给数」正是
  `parseNumstat` 那句「比没有闸门更糟」说的情形。`-w` 的语义由 git 定义、可实测、
  出错方式是整个文件消失（看得见）。

## 五、这条改动自己不许吃这个折扣

一条「改计数口径」的改动如果靠新口径过线，理由与结果同源，任何复核都白做。
所以两条可核的披露：

- **本条自己的 diff 在照实计数下也要在线内，且不写 `size-ok:`。** 折掉的行数预期为 0 ——
  这条改动一行缩进都没重排。PR 描述里贴两组数。
- **以后吃到折扣的改动，把逐类折掉的行数写进提交信息。** 不是只写在 PR 描述里 ——
  ADR-69 记着「留在 PR 描述里的东西，接手的会话翻不到」，ADR-64 记着「PR 描述清单
  squash 之后会丢」。闸门每跑必打那几行，抄进提交信息是零成本。

顺带答一句 `process/2-CHANGE.md` 的自检（「如果这件事很容易做，你还会提这个建议吗」）：
会。理由指向 `size-rule.ts` 那段**主干上早就写着**的注释，不指向「我下一条要重排 1800 行」。

## 六、成本：夹具 46 毫秒，要乘 365

ADR-97 第二节那句通则在这里照样成立：**给任何一个验证者加一秒，都要乘以用它的变异条数。**

新加的那条夹具真起一个 git 仓库（8 个子进程）：20 次实测，最小 42 ms、**中位 46 ms**、
最大 60 ms。缺省验证者名下的变异是 365 条，而缺省那族没有 `kills`、没有「见齐就停」，
**每一条都跑完整个 `test.ts`** —— 所以夹具一次折扣都不打：

| | |
|---|---|
| 串行实付 | **+17 s**（占串行总量约 0.9%） |
| 4 worker 的 makespan | **+4 s** |
| 下一条改动要省下的 | 约 640 s 串行 · 约 170 s makespan |

也就是说这笔钱约是那笔节省的 2.5%。划得来，但要明码写出来。

⚠️ 顺手更正 ADR-97 第二节末那一行过期的数：写的是「乘 347 条」与「selfcheck ×18」，
在 `017a8e3` 上是 **365** 与 **19**。那一行不是锚了提交的测量值，是一句当期陈述。

⚠️ 还有一个不对称，ADR-97 没写：它那句「一条负片的价钱是它的夹具在文件里排第几」
**只对点了名的 `by` 负片成立**。缺省验证者这一族恰恰相反 —— 没有 `kills` 就没有
「见齐就停」，夹具排第几都要全额付。这比那 17 秒更耐用。

## 七、为什么没有死亡条件

ADR-85 逐道判过，`size` 那一行写的是「**早有**，ADR-80」。给同一道闸门再写一条平行的
死亡条件，就是两份会各自漂的副本。写下「判过、早有」，免得下一个人当成漏了去补一份。

**顺带还掉 ADR-80 派下来的那件活。** 它末节写着「下一个碰 `size-rule.ts` 的人顺手看一眼
`git log --all --format=%B | grep -c '^size-ok:'` 和 CI 上 `size` 的红史」——
本条正是那个人，所以去看了：

- 在 `017a8e3` 上，用**闸门自己的判据**（`scanMessage`）数出来是**真豁免 57 条、
  分布在 43 个提交**。那条 naive grep 读出 90，多出来的是正文与围栏里的示例。
  距「连续 20 次为 0」极远 —— **这道闸门没在空转。**
- 另一半（CI 上 `size` 的红史）**仍然核不了**：运行史落在仓库之外，ADR-85 已经记过。
  所以这件活只还得了一半，欠条照旧挂在 ADR-80 名下。

## 八、缺口，明写

- **`.ts` 的字符串与模板字面量里，空白也是内容。** `'已用'` → `'已 用'` 这类改动在这道
  闸门上读 0（实测文件整个消失）。挡它的是测试与变异，不是行数 —— 这道闸门守的是
  「一个 diff 读不读得完」，而一个空格的 diff 确实一眼就读完了。
- **行尾翻转（LF ↔ CRLF）在 `.ts` 上同样读 0。** 根因不是行尾，是上一条的同族。
  真正的修法是给仓库定行尾规范，那是独立的一件事。

  > ⚠️ 欠条：仓库没有 `.gitattributes`，而 `CLAUDE.md` 明写要在 Windows 上也 work ——
  > 一次行尾翻转在这道闸门上读 0 行 · 重启条件：下一条碰 `.gitattributes` 或行尾规范的改动

- **`GIT_CONFIG` 里的 `core.quotePath=false` 今天量不到。** `-z` 本身就关掉了路径转义
  （实测：注掉那一项，夹具里的中文路径断言照样绿）。它留着是给将来不走 `-z` 的调用方，
  所以那条断言的名字改成了「靠的是 `-z`，不是 quotePath」—— 不假装它被守住。
  同一组里另两项（`diff.renames=true`、两个 `NUMSTAT`）是真被钉住的：夹具把仓库本地的
  `diff.renames` 设成 `false`，钉不住就当场红。
- **`docs/CONVENTIONS.md` 第十节后半句**（「哪些提交算这条分支自己的」）描述的落点
  仍然不成立，已在那里就地登记成欠条。

## 九、给下一条铺的路 —— 以及下一条不是「纯重排」

ADR-97 第六节那条主修（`selfcheck --only=<标签>` ＋ 夹具成组）在这道闸门下的读数：
照实约 1830/350（判红），忽略空白后约 97/350（在线内）。

⚠️ **但它不是一次纯空白改动。** 实测 `tsc --noEmit` 报 82 条 TS2304：24 条是预期的
`group` 未定义，另 58 条是跨节绑定 —— 12 个名字被后面的小节用着。其中 10 个是无状态的
辅助函数与常量（约 48 行），外提到模块作用域即可；真正的跨组执行态只有两个
（`dir`、`rendered`），波及 4 个小节。

所以 ADR-97 第六节欠第五条落地前必办项：**`needs` 的语义是载重的**，那 4 个小节一跑就得
拖着前面那次真 collect，第六节「676.8 s → 约 20–40 s」的估算因此是乐观的，要重新推一遍。
指向那条，不在本条里改。

## 什么条件下重开这个讨论

- 有人往 `WHITESPACE_FREE` 里加第二种后缀 —— 那一刻要重新问一遍「这类文件的空白带语义吗」，
  而不是照着 `.ts` 类推
- 仓库开始收非 `.ts` 的代码文件（Python、Go、Rust）—— 白名单的漏项会从「保守」变成「常态」
- 有人给这道闸门加第三遍 diff —— 两遍已经是它全部的 git 成本，第三遍要先说清买到什么

## 2026-09-24 更正：上一节「不顺手做」的理由说重了

上一节写「把那段搬进判定模块、再配上测试，全量检查会多出一段串行的 git 夹具」。这句不成立，有两处：

- 算起点那段（先试哪个主干引用、取 `merge-base`、再列这条分支自己的提交）可以抽成一个纯函数，
  git 的应答由调用方传进来，测试喂假应答即可，用不着真起一个 git 仓库。
  代价是假应答只测得到「先试哪个、按什么顺序、答不上来时怎么说」，测不到 git 本身的行为。
- 真要测 git 本身的行为，`scripts/test.ts` 里已经有一个真 git 仓库的夹具（守着 `GIT_CONFIG` 与两个 `NUMSTAT`），
  加进去即可，不是「多出一段」。

> ⚠️ 更正：上一节不修的理由过重，并不需要新增一段串行的 git 夹具。
> 当时登记不修是需求所有者的裁决，不依赖这句理由；本条只更正理由，那张欠条与重启条件原样不动。
