# ADR-218 P5 红线测试隔离重写：去重那句排在最前现有测试没守住

- 日期：2026-11-17 · ADR-202「P2–P5 没做过隔离重写」那条欠条的 P5 那一截，也是最后一截（P2 是 ADR-206，P3 是 ADR-208，P4 是 ADR-214）
- 类型：测试补漏，外加报告措辞照判据改、对外文档补例子
- 触发它的事实：没看过实现的会话照 P5 的判据写了 75 条测试，搬到真代码上第一次跑就全过；拿十处手改去试，「本次没去重」那句不再排在报告数据边界最前面时，现有的需求测试和自检都不红
- 冲击的需求：无（判据不改）。需求测试多三条断言、两个变异；关键词表里入围与语义通过无从确认的那几格，从印「—」改成判据原文的「无从确认」（需求所有者在决定卡上选的）
- 结论：采纳
- 连带改动：`scripts/test.ts` 的 `p5-report`、`u3-keywords`、`u8-labels` 三组，变异目录加 `M-P5-p`、`q` 并改 `M-P5-u`、`v` 两条说明，`scripts/lib/report.ts` 一行，`scripts/lib/pipeline.ts` 三句注释，`skill/references/output-format.md`

P5 的判据八条：P5.b（算了公开指标也不得藏 P5.f、P5.g）、P5.c（公开信号另行声明不是假粉率、不代表带货效果）、
P5.d（去重状态是一条数据边界）、P5.f、P5.g（没配外部增强层时报告声明邮箱没验证、粉丝在不在目标市场无从确认）、

## 一、先补包：导出读哪几个文件，报告里那几句的原文

ADR-214「准入读物包与对外文档仍缺几样」那条欠条点名的几样里，P5 这一截要用的先补了（`595f48b1`），都写进 `output-format.md`：

- 导出（render）读哪几个文件：名单从任务目录的 `creators.json` 来，`creators.raw.json` 只用来认关联账号、不往名单里加人；判断从 `agent-review.json` 来，没有时把旧行里的判断迁成正本；`enrichment.json` 可以没有；记忆按 render 进程的当前目录找，文件不存在时 `memory_status` 是 `absent`、render 新建它。
- 一份能导出的最小任务目录（`task.json` 一份、`creators.json` 一行）：照抄起 render 以 0 结束，写出四个交付文件。
- 关键词表那一列从 `task.json` 的 `answered`、`found` 两张表怎么读出四态，一张表五行。
- HTML 报告数据边界那几句的原句、出现的条件和先后。这张表是照现行代码写的，判据没写到这一层（第五节第 4 条）。

`answered` 写成 `null` 的那一种（隔离会话说明第 3 条点了不知道算缺表还是算损坏），实测是算损坏、以 2 拒收、什么都不写，补进了同一段。

复核指出最小目录初稿里 `found` 写的是 0、却有一个人出自那个任务（「找到 0、入围 1」），合入前改成 `found` 为 1。

那张欠条里别的几样与 P5 无关（collect 续跑要什么样的目录、`knownRelations`、`persistListAndStatus`、enrich、probe、挡请求的注入点、入口那一份认的写法），这次没补，重挂在第七节。

## 五、补进现有测试的，和照判据改的

1. **P5.j 副标题**：`p5-report` 组加一条，名单里只有 TikTok 的人、`meta.platforms` 是 `['tiktok','instagram']`，报告副标题要有「目标市场 US · tiktok + instagram」。配变异 `M-P5-p`（副标题从交付名单反推）。自检那一组已经守着同一件事，这一条让变异在需求测试里就能被抓，不必起 render。
2. **「本次没去重」排在最前**：同一组加两条，七句里能同时出的都打开（没写回、邮箱、受众、公开指标几句），`memory_status` 分别是 `unreadable_ignored` 与 `unknown`，数据边界块的第一句必须是去重那一句。配变异 `M-P5-q`（邮箱、受众两句插到最前）；复核另试的三种改法（「不是假粉率」、「公开指标边界」插到最前，`unknown` 时倒序）也都红。
   出处照实说：判据 P5.d 只要求声明、没说先后；对外文档「收尾输出」一节写着 Agent 交付时那段话里「这句要排在最前面」，报告是同一份交付的另一个出口，照同一条排，`report.ts` 的注释也是这个意思。它和第 4 条不补的几处不同：那几处是单句的出现条件与样式，只出自本条照代码写的原句表；这一处是文档原有的一条规矩在报告上的延伸。所以 `M-P5-q` 的需求栏记 `P5`，不认领判据。
   两个变异逐个手施，点名的那几条红。
3. **入围与语义通过无从确认时印什么。** P5.i 原文：「它的入围与语义通过同样报『无从确认』」；U3.b 原文：「整张表的入围一律报『无从确认』」。报告一直印的是「—」（ADR-94 第十六节当时的取舍），现有测试与注释都把「—」当成「无从确认」，还标了「P5.i 逐字」。
   隔离会话说明第 1 条点了这处对不上，没替判据选。需求所有者在决定卡上选了「照需求原文印『无从确认』」。改法：`report.ts` 里这两格 `null` 时印「无从确认」，**没查过的行、状态无从确认的旧目录行、名单里有人来源无从确认时整张表**三种都照这一条；查过、数确知的格照印数。
   `u3-keywords` 里三条、`u8-labels` 里一条断言的期望从「—」改成「无从确认」，注释里「P5.i 逐字」的说法一并改对；`pipeline.ts` 两句还写着印「—」的注释、`M-P5-u`、`v` 两条变异说明也改了（`M-P5-v` 那句说明就是隔离会话说明第 2 条拿不准的来由）；对外文档同步。
4. **只出自原句表的那几处（H1、H4、H7、H10）不补。** 它们的条件是第一节照现行代码写进文档的，判据没写到那一层；补成测试等于把现行代码当成标准钉死。H4 归「需求不清」，登记在第七节；其余三处是措辞与样式，不登。
5. **`pipeline.ts` 里 `KeywordRow.found` 的注释**原写「`null` 只在 `status` 不是 `queried` 时出现」，与代码和文档都不符（问过、条数没记下时也是 `null`，报告印「未知」）。隔离会话说明第 4 条指出，改了注释。

隔离测试的其余部分不搬：现有测试都管，搬进来是重复。

## 六、隔离会话说写不出来或拿不准的地方

说明里列了 18 处。第 1 条是第五节第 3 条（已定、已改），第 2 条随第 3 条一起有了答案（旧目录那一行也印「无从确认」），第 3 条是 `answered: null`（第一节已补文档），第 4 条是注释（第五节第 5 条）。其余按性质归：

1. **判据没说死、现行做法由现有测试钉着：** P5.h 的 true 那一头（第 5 条，现有测试有一条不认领判据的断言守着，`M-P5-h`）；`taskOrdinal` 收到字符串算不算非法（第 16 条，`u8-labels` 有）。不替判据选，不登欠条。

4. **它的写法交代：** HTML 结构假设（第 13 条）、手拼的 meta（第 14 条）、「查过且没人入围给 0」从 U3.c 反推（第 15 条）、render 的当前目录（第 18 条）。第一次跑全过，这几处假设都成立。
