# ADR-120 变异全量解释与分组变化由真实基线核对

- 日期：2026-09-27 · 长期维护变异执行成本时
- 类型：发现更优解
- 触发它的事实：现有选组选取与正常基线复用已接入变异命令，但新增全量、选组回退和组配置变化尚缺统一的版本间说明；历史性能记录不能替每次改动证明当前成本。
- 冲击的需求：不改变业务需求；P1–P5 的既有测试与变异保障保持。
- 结论：采纳
- 理由：从真实 Git 版本抽出变化属于机械核对；为何需要全量、何时值得重审属于阅读判断。两者接在现有变异命令里，避免新建一份会漂的路由表或用解释降低验证资格。
- 连带改动：`process/4-VERIFY.md`、`process/6-INTEGRATE.md`、`docs/ARCHITECTURE.md`、`docs/SYNC.md`；既有变异命令与 CI 传入可信基线。

## 决定与边界

公开验收在 `process/4-VERIFY.md`「选组与全量执行的长期维护」，评审证据在
`process/6-INTEGRATE.md`「改验证成本时,评审要看到实际变化」。不改需求登记表或其渲染。

维护比较使用可信 Git 基线的变异目录与验证者实际配置，复用当前 `kills` 归组路径。
已有未解释全量变异只有核心正文未变时才自动兼容，兼容来自旧 Git 内容，不手写历史名单。
解释存在与否、形状是否完整由机器核；理由及重审条件是否成立由评审者读。
旧提交或旧配置读不出来时失败，不把未知记为没有变化。

本次维护输出列出路由与分组配置变化。实际组合复用数与经过时间报告决定为下一条独立交付，
在本次合入之后再接入；本次不声称已具备成本报告，不以同文件叠分支提前接入。
不建固定秒数闸门；高频验证工作改变时，评审核有限的可比成功证据。
本记录不声称已测得提速，也不以历史短集收益代替本次完整执行资格。

解释不改全量或选组的实际执行、正常源码基线、断言归因、错误记号、进程收尾或审计认领。
本次不新建目录、不提交原始响应或运行产物，不扩展采集能力。

## 死亡条件

若实际执行路径已取消全量回退，变异目录也从结构上拒绝所有无法具名归组的条目，
且可从可信版本比较和完整成功运行核实全量执行集合为空，重新评定并撤除 `full_run` 的形状闸门。
不能仅因全量变少、运行变快或解释太麻烦撤除。

组配置变化清单和另交付的实际复用、计时输出只提供原料，没有额外的性能通过判定；固定秒数闸门本次已判为不建。
