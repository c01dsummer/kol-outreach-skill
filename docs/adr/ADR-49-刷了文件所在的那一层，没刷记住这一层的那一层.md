# ADR-49 刷了文件所在的那一层，没刷记住这一层的那一层

- 日期 · 2026-08-28 · PR #5 拆分后第十四轮自动评审，成立
- 类型：**事实证伪**（同一条线上第三轮）
- 冲击的需求：D4
- 结论：**采纳**，并把五处建目录合并成一处

### 事实

`writeFileAtomic` 改名后刷 `dirname(file)` —— 那让**文件的目录项**落了盘。
但这些目录本身可能是刚建出来的，而**记录它们的是各自的上一层**，那几层没人刷。
断电之后整个目录可能不存在，而调用方已经被告知成功：第一次跑的断点、
或者第一份联系历史，就这么没了。

`mkdirSync` 的 recursive 会返回**第一个被新建的那一层**，所以确切知道要刷哪几层：
从那一层的父目录开始，逐层刷到目标的上一层。

### 顺带：五处建目录

改的时候发现 `mkdirSync(..., { recursive: true })` 在这两个文件里出现了**五次**。
按 ADR-46 的结论，合成 `mkdirDurable` 一处 —— 否则这条修复只会落在我改到的那几处，
下一个新调用方又从零开始。

### 这条线上的第三轮，值得停下来看一眼

| 轮次 | 加了什么 | 下一轮发现 |
|---|---|---|
| 十二 | 刷文件 + 刷目录 | 刷文件的失败被吞了 |
| 十三 | 拆成抛 / 吞两个 | 新建目录的上层没刷 |
| 十四 | 逐层刷新建的目录 | ？ |

**每一轮的发现都成立，每一轮的修法也都对。** 但这条线已经从「原子替换」
一路深进到 POSIX 崩溃持久性 —— 而这是个跑在运营机器上的本地命令行工具。

我没有自己叫停，理由是：**D4 现在写着「写了不等于落到盘上了」**，
既然写了就得做到，或者把话收回来（ADR-44 的规矩）。这一轮我选了做到，
同时把「刷目录受平台限制、这一半是尽力而为」写进了验收标准 ——
**不做到的部分，明写不做到。**

要不要继续往这个方向深挖，是产品判断，交给用户。

### 教训

**「我刷了目录」和「这个目录会在」是两件事。**

持久性是一条链：文件的目录项、目录自己的目录项、再上一层的……
刷了链上的一环不等于这条链在。而我每一轮都以为刚补的那一环是最后一环。
