## 一、判据原文

`P1.p`：搜索结果里供应商没给的粉丝数、作品数（字段没有，或者是空值），记成「未查询」，不记成 0。搜索接口对所有人一律回 0 的作品数只是占位，不当成真实的作品数，也记成「未查询」。

原文由执行者照现有做法起草，需求所有者在选择卡上照这句选定，一字未改。

## 二、怎么认领、谁守着

- 组 `p1-provider` 认领 `P1.p`。原有两条断言：搜索没给粉丝数时仍是未查询、占位的 0 作品数不成为真实的 0。新加四条：粉丝数给了空值、作品数没给、作品数给了空值，都仍是未查询；两条空值的还核了不进「给了怪值」那个记号（那是 `P1.m` 的「已查询但未取得有效值」，与「没给」是两个态）；再加一条反面：真给了粉丝数的照收，免得「一律记未查询」也过得去。
- 判据级负片：原有的 `M-P1-j`（没给的粉丝数记成 0）、`M-P1-k`（占位的 0 当真值）改记在 `P1.p` 名下；新加 `M-P1-bj`（空值当成给了怪值）、`M-P1-bk`（没给的作品数记成 0）。四条逐条验过都被抓到。
- Instagram 的三条搜索路径今天都不写粉丝数和作品数，留给补全那一步，判据对它们自然成立；它们不另配断言。
