# ADR-27 同一句承诺的第三份副本 —— 按记忆去搜，搜不到不等于没有

- 日期 · 2026-08-28 · PR #5 第九轮自动评审
- 类型：**事实证伪**（ADR-23 立的同步规矩，我自己执行时漏了一份）
- 冲击的需求：P3（预算相关的承诺）
- 结论：**采纳**

### 触发它的事实

ADR-23 发现「续跑不会重复花费」这句承诺在代码和两份文档里各有一份副本，
改了代码没改文档；于是我改了那两份，并**给同步表加了一行**：
「改给用户看的报错里的一句承诺，要改复述同一句话的每一份文档」。

这一轮发现还有**第三份**：`README.md` 里写着「修好后 `--resume` 不产生新请求」。

漏掉它的原因不是忘了规矩，是**执行规矩的方法不对**：我按自己记得的措辞去
grep（「不产生新的请求」），而 README 那份写的是「不产生新请求」——
**少一个字，搜不到。**

规矩是对的，方法是错的：

> **按记忆去搜副本，搜不到不等于没有。** 同一句话在不同文档里会被不同的人、
> 在不同的时候、用不同的措辞写下来，而搜索匹配的是字面。

修法：README 那句改成有条件的说法（与代码、`ARCHITECTURE`、`SKILL.md` 一致）；
两张同步表里那一行**从「每一份文档」改成点名的清单**，并写明
「点名逐个过，不要 grep」。清单是有限的，记忆不是。

### 连带改动

`README.md` · `docs/SYNC.md` · `process/2-CHANGE.md`

### 教训

**一条同步规矩要能被执行，就得给出「要看哪几份」，而不是「所有相关的」。**

「复述同一句话的每一份文档」听起来完整，实际执行时会退化成「我搜得到的那些」。
把它换成一串点名的路径，执行方式就从**回忆 + 搜索**变成**逐个打开**——
后者会漏的唯一情况是清单本身没更新，而那是新增文档时就该做的事，
比"每次都要想起所有副本"可靠得多。
