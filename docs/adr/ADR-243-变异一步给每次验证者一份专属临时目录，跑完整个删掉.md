# ADR-243 变异一步给每次验证者一份专属临时目录，跑完整个删掉

- 日期 · 2026-11-24
- 类型：不属于反向输入的五类 —— 改的是检查链自己（还 ADR-158 一张欠条）
- 触发它的事实：变异一步为了省时间，点名要红的那几条断言一亮齐就把验证者叫停（见齐就停）；被叫停的验证者来不及删它和它的子进程建的临时目录，这些目录留在系统临时目录里没人收（ADR-158「见齐就停的验证者留下的临时目录没人收」）。这张欠条响过、续挂过，交需求所有者定
- 冲击的需求：无
- 决定人与时间：需求所有者丸子 —— 2026-11-24 13:19（北京时间）在项目线程「整理四张到期欠条给你选」的选择卡「变异测试停掉后留下的临时文件夹，要不要修？（改了建议）」上选了「做：每次给专属临时目录」。第一版卡片建议不做，理由写的是「系统会定期清理」；需求所有者问「现在有这种东西吗」，那句是凭印象写的、没核过（GitHub 上的机器用完就扔是真的；本机 Linux 常见做法只在重启时清，Mac 在这边验证不了），收回后改了建议重新发卡
- 结论：采纳。人批痕迹：上面那张选择卡；需求所有者合入本条
- 理由：清不清不该指望系统；谁建的谁收，最确切的办法是开跑前给它一个只属于它的目录，跑完整个删
- 连带改动：`scripts/check/mutate-rule.ts`（`ownTmpEnv`、`tsxCacheName`）· `scripts/check/mutate.ts`（起验证者时建专属目录、放链接、结束时删）· `scripts/test.ts`（`h-mutate` 组四条断言）· `scripts/check/mutations.json`（M-H243-a 到 f）· `scripts/check/selfcheck.ts`（`stop-if-seen` 组三条断言）· `docs/ARCHITECTURE.md`（`mutate.ts` 那一行补一句）· ADR-158 那张欠条连同已还一行挪进它的历史文件 · `docs/adr/README.md` 索引 · `docs/adr/白话目录.md`
- 同类：无

## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 验证者和它的子进程把临时文件建在哪 | Node 的 `os.tmpdir()` 读 `TMPDIR`（Windows 上读 `TEMP`、`TMP`）；自检与需求测试里建临时目录都走它 | 人（读 Node 文档与代码） |
| tsx 的编译缓存放在哪 | tsx 4 的源码：`os.tmpdir()` 下 `tsx-<有效用户号>`，没有用户号的平台用用户名 | 人 |
| 被叫停的验证者建的目录收了没有、缓存是不是共用那份 | 自检组 `stop-if-seen`：假验证者每跑一次在它看到的临时目录里建一个目录、记下路径与它看到的 tsx 缓存解开后的真实路径；mutate 收尾后逐个核 | 机器 |
| 修了以后慢没慢 | 实跑：同一台机器上本条与 ADR-242 那条的完整检查，变异一步的墙钟与自检验证者累计用时（第五节） | 人 |

## 一、做了什么

1. **每次起验证者给一份专属临时目录。** 变异一步起验证者前在系统临时目录下建一个 `kv-` 开头的目录（前缀取短，理由见第六节），`TMPDIR`、`TMP`、`TEMP` 三个变量都指过去（`ownTmpEnv`）。验证者和它起的子进程都继承这份环境，建的临时文件都落在里面。
2. **跑完整个删掉。** 验证者那一组的输出关了（正常跑完、或见齐就停把整组叫停）以后，入口把这个目录整个删掉。删不掉（验证者那边又自成一组、还没停的子进程正往里写）不影响这一条的结论，只是那一次留着。被中断（Ctrl-C、信号、号作废不掉）时入口直接退出、等不到验证者那一组关，手上还没删的几份在进程退出时补删。建不成专属目录时照旧用系统临时目录跑，不判这条变异跑不起来。
3. **编译缓存不变冷。** tsx 按「临时目录/tsx-<用户号>」找编译缓存，换了临时目录就会冷。专属目录里放一个这个名字的链接，指回系统临时目录里共用的那一份（`tsxCacheName`）；删目录时只删链接，共用的缓存不动。Node 自己的编译缓存原本就由 `NODE_COMPILE_CACHE` 指到固定位置，不受影响。
4. **测试。** 需求测试 `h-mutate` 组四条断言守 `ownTmpEnv`、`tsxCacheName`（六条变异 M-H243-*）；入口那一半由自检组 `stop-if-seen` 守：被叫停的验证者建的目录收尾后一个都不在；它看到的临时目录不是系统那一个、在那里找到的 tsx 缓存解开后是共用那份；共用缓存里的东西删目录后还在。拿掉入口里的这一段，第一条当场红（实测过：撤掉本条对 `mutate.ts`、`mutate-rule.ts` 的改动，自检报「还在的：/tmp/kol-stop-left-…」）。

## 二、为什么是这个分法

想过的三种：

- **甲（本条）：开跑前给专属目录，跑完整个删。** 谁建的都在里面，删得确切；不用知道验证者建了什么。
- **乙：叫停前后对比系统临时目录，多出来的删掉。** 变异一步并行跑好几个验证者，多出来的分不清是谁的，会删到别人正在用的。
- **丙：让验证者自己收（收到停止信号时清理）。** 见齐就停杀的是整组，子进程各有各的临时目录，要每一处都装信号处理；漏一处就照旧留着，而且没有东西会提醒。

## 三、关上的欠条

## 五、量出来的成本

同一台机器（云端容器，以 nobody 跑完整检查），前后两跑：先跑 ADR-242 那条的树，紧接着跑本条的树。数字都是检查链自己打的，单跑一次，不是区间。

| | ADR-242 那一跑 | 本条这一跑 |
|---|---|---|
| 需求测试当验证者：逐条墙钟合计 | 3479 秒（2923 条，平均 1.2 秒） | 3519 秒（2889 条，平均 1.2 秒） |
| 脚本自检当验证者：逐条墙钟合计 | 2213 秒（352 条，平均 6.3 秒） | 2244 秒（352 条，平均 6.4 秒） |
| 跑完后系统临时目录里留下的 `kol-` 开头的目录 | 369 个（这一跑时间段里建的） | 0 个 |
| 留下的专属目录（`kv-` 开头） | — | 5 个 |

- 慢没慢：自检那一类平均每条多 0.1 秒、合计多 1.4%；需求测试那一类平均没变（两跑条数不同，合计不好直接比）。两跑之间同一台机器上没有别的重活，但单跑一次的差在这个量级上分不清是本条的成本还是起伏；按「每条多建一个目录、一个链接、删一次」的量，不该到秒级。没拿主干 CI 的墙钟判。
- 收没收住：上一跑留下 369 个，这一跑系统临时目录里一个 `kol-` 开头的都没留。留下的 5 个专属目录：3 个里面装着自检自己的临时目录，2 个只有那个链接；都是同一跑里起的，原因没逐个追 —— 第六节说的两种（被 `kill -9` 这类方式杀掉、退出补删那一道不跑；或验证者那边自成一组的子进程还在写）都对得上，没核到是哪一种。

## 六、证不了的

- 验证者那边又自成一组的子进程，见齐就停杀不到，它们还在往专属目录里写时删不干净，那一次照旧留着（同 ADR-74「收的只有一层」那张）。被 `kill -9` 这类不给进程收尾机会的方式杀掉时，退出时补删那一道也不跑。
- Mac 上没跑过：tsx 把通信用的 socket 开在「临时目录/tsx-<用户号>/<进程号>.pipe」，Mac 上这条路径过 104 字节就起不来（ADR-201 记过 Linux 上的同一个上限）。专属目录每套一层加 10 个字符，验证者里再起玩具 mutate 又套一层；Mac 的系统临时目录本来就长，前缀因此取了 `kv-`，够不够只在 Linux 上按长度推过，没在 Mac 上实跑。
- tsx 缓存名的取法（有效用户号，没有时用用户名）是对着 tsx 4.23.12 的源码核的；升级 tsx 时要重核，没有东西会提醒。
- Windows 上没跑过：那里 `os.tmpdir()` 读 `TEMP`、`TMP`，本条三个都设了，但链接与删除只在 Linux 上实测。
- 验证者里有谁不经 `os.tmpdir()`、把临时文件写死在 `/tmp` 下的，不归这个目录管，照旧没人收。
