# ADR-243 变异一步给每次验证者一份专属临时目录，跑完整个删掉

- 日期 · 2026-11-24
- 类型：不属于反向输入的五类 —— 改的是检查链自己（还 ADR-158 一张欠条）
- 触发它的事实：变异一步为了省时间，点名要红的那几条断言一亮齐就把验证者叫停（见齐就停）；被叫停的验证者来不及删它和它的子进程建的临时目录，这些目录留在系统临时目录里没人收（ADR-158「见齐就停的验证者留下的临时目录没人收」）。这张欠条响过、续挂过，交需求所有者定
- 冲击的需求：无
- 决定人与时间：需求所有者丸子 —— 2026-11-24 13:19（北京时间）在项目线程「整理四张到期欠条给你选」的选择卡「变异测试停掉后留下的临时文件夹，要不要修？（改了建议）」上选了「做：每次给专属临时目录」。第一版卡片建议不做，理由写的是「系统会定期清理」；需求所有者问「现在有这种东西吗」，那句是凭印象写的、没核过（GitHub 上的机器用完就扔是真的；本机 Linux 常见做法只在重启时清，Mac 在这边验证不了），收回后改了建议重新发卡
- 结论：采纳。人批痕迹：上面那张选择卡；需求所有者合入本条
- 理由：清不清不该指望系统；谁建的谁收，最确切的办法是开跑前给它一个只属于它的目录，跑完整个删

## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 验证者和它的子进程把临时文件建在哪 | Node 的 `os.tmpdir()` 读 `TMPDIR`（Windows 上读 `TEMP`、`TMP`）；自检与需求测试里建临时目录都走它 | 人（读 Node 文档与代码） |
| tsx 的编译缓存放在哪 | tsx 4 的源码：`os.tmpdir()` 下 `tsx-<有效用户号>`，没有用户号的平台用用户名 | 人 |
| 被叫停的验证者建的目录收了没有、缓存是不是共用那份 | 自检组 `stop-if-seen`：假验证者每跑一次在它看到的临时目录里建一个目录、记下路径与它看到的 tsx 缓存解开后的真实路径；mutate 收尾后逐个核 | 机器 |
| 修了以后慢没慢 | 实跑：同一台机器上本条与 ADR-242 那条的完整检查，变异一步的墙钟与自检验证者累计用时（第五节） | 人 |

## 一、做了什么

1. **每次起验证者给一份专属临时目录。** 变异一步起验证者前在系统临时目录下建一个 `kol-verifier-` 开头的目录，`TMPDIR`、`TMP`、`TEMP` 三个变量都指过去（`ownTmpEnv`）。验证者和它起的子进程都继承这份环境，建的临时文件都落在里面。
2. **跑完整个删掉。** 验证者那一组的输出关了（正常跑完、或见齐就停把整组叫停）以后，入口把这个目录整个删掉。删不掉（验证者那边又自成一组、还没停的子进程正往里写）不影响这一条的结论，只是那一次留着。建不成专属目录时照旧用系统临时目录跑，不判这条变异跑不起来。
3. **编译缓存不变冷。** tsx 按「临时目录/tsx-<用户号>」找编译缓存，换了临时目录就会冷。专属目录里放一个这个名字的链接，指回系统临时目录里共用的那一份（`tsxCacheName`）；删目录时只删链接，共用的缓存不动。Node 自己的编译缓存原本就由 `NODE_COMPILE_CACHE` 指到固定位置，不受影响。
4. **测试。** 需求测试 `h-mutate` 组四条断言守 `ownTmpEnv`、`tsxCacheName`（五条变异 M-H243-*）；入口那一半由自检组 `stop-if-seen` 守：被叫停的验证者建的目录收尾后一个都不在、它看到的 tsx 缓存是共用那份、共用缓存里的东西删目录后还在。拿掉入口里的这一段，第一条当场红（实测过：撤掉本条对 `mutate.ts`、`mutate-rule.ts` 的改动，自检报「还在的：/tmp/kol-stop-left-…」）。

## 二、为什么是这个分法

想过的三种：

- **甲（本条）：开跑前给专属目录，跑完整个删。** 谁建的都在里面，删得确切；不用知道验证者建了什么。
- **乙：叫停前后对比系统临时目录，多出来的删掉。** 变异一步并行跑好几个验证者，多出来的分不清是谁的，会删到别人正在用的。
- **丙：让验证者自己收（收到停止信号时清理）。** 见齐就停杀的是整组，子进程各有各的临时目录，要每一处都装信号处理；漏一处就照旧留着，而且没有东西会提醒。
