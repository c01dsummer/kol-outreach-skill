## 一、换一份登记表的参数

玩具仓库里没有登记表绑的那些真记录，用默认登记表起入口，只测得到「核不过以 1 退出」：算出越线、拿掉越线的那几步一步都走不到。
所以三个入口认一个参数 `--conditions <文件>`，文件里是一组登记表的行（JSON）；不写就用 `CONDITIONS`，与以前一样。

- **只给入口测试用。** 检查链（`npm run adr`）与每周回访（`npm run conditions`、`npm run due-list`）都不传它；`docs/REVISIT.md` 不提它。
  传了，入口先在标准错误打一句「用的是换过的登记表 <文件>（--conditions 只给入口测试用）」：哪一跑换过，看输出就知道，不会悄悄把检查链里那一道换成空表。
- **用参数，不用环境变量。** 环境变量会从外面悄悄带进来（CI、本机 shell），一跑用的是哪份登记表，看命令行就看得见。
- **形状核到每种判法、量法带齐了参数。** 读不出、不是 JSON、不是一组「`binds`、`name` 是字符串，`kind` 是欠条或死亡条件，`pin` 没写或是字符串，判法认得、带齐那种判法与量法要的参数（PR 号是数，等的那张是字符串、状态是已还，量法认得、路径或目录与后缀写了，比较符认得、线是数）」的行，入口说一句为什么、以 2 退出（参数写错那一档）。
  值对不对（PR 号是不是正整数、路径在不在、绑的条目在不在）和真登记表走同一道 `conditionFaults`。
  这一道顺手多核一处（评审提出的）：数份数的目录写成 `d/`、`./d`、`/d`、`.` 或空，目录在也报。份数按「路径以 `<目录>/` 开头」比 git 列出的路径，这几种写法一份都比不上、量出来总是 0；不替人改写成规范写法（改写要猜写的人想要哪个目录），报出来让人改。真登记表里现有的行没有这种写法。
- `adr-sync.ts` 写错时设退出码 2、自然退出，不硬退出（ADR-70「硬退出收口只到 mutate.ts」那张说的那种掐掉诊断的写法，这里不加）。`conditions.ts`、`revisit-due.ts` 本来就以 `process.exit(2)` 处理参数写错，新的一处照旧。

## 二、测了什么

三组，都经 git 夹具建玩具仓库（`withToyRepo`、`fixtureEnv`，ADR-239）。真起入口单独成组，因为入口每起一次，都会乘上这一组的全部变异（ADR-145）；条件探针那两个入口拆成两组，各乘各的。

**`h-adr-sync-entry`**：

1. 主干上 `--write` 钉住一份历史文件，打出回写了、以 0 退出；换一份登记表，一行绑了台账里没有的记法、量一个不在的文件，两句都报到标准错误、以 1 退出。
2. 换的登记表读不出，以 2 退出、什么都不比。
3. 切一条分支，删掉主干钉过的历史文件、本树的指纹表也删掉：本树比不出来，只有拿主干上那份比才红。入口以 1 退出，报的只有「比主干上的指纹表」那一句。**删掉交给 `adrSync` 的真 git 就绿了 —— ADR-220 那张欠条说的就是这一处。**

**`h-conditions-entry`** 与 **`h-revisit-conditions-entry`** 用同一个玩具仓库：三份决策记录、一个文件、一个标题带「(#5)」的提交，换的登记表里一条欠条等 PR #5 合入，一条死亡条件、一条续挂到 12 月 21 日的欠条量那个文件在不在，三条都越线。

1. 默认登记表：核不过的每一行（台账里没有、文件不在）都报、以 1 退出；日子写错以 2 退出。
2. `conditions.ts` 问 `--run` 给的提交（玩具仓库里那个提交只在一条分支上，主干上没有，问错了提交就算不出越线）、读树里的文件，越线的两条各打一行，续挂没到那天的那条打成「先不列」。
3. `revisit-due.ts --list` 拿掉越线的、只列没越线的那张；`--deaths` 轮到的那条越线了，这一周一条都不列。
4. 换的登记表里再加一行量不在的文件：核不过，`--list` 一张都不拿掉，标准错误说这一次不拿掉越线的。
5. 换的登记表不是一份登记表，两个入口都以 2 退出、什么都不打。

`registryArg` 本身另在 `h-conditions` 里直接调：没写参数用 `CONDITIONS`、写了原样交回，每一种用不了的写法各说一句，三种判法、五种量法、三种比较符带齐参数都认。

`M-H252-ca` 起的那一段变异，本地逐条施变全被抓到；起几次、乘上条数，见 `scripts/check/launches.json`。

## 三、清点

台账里开着的行分三份逐条读过（三个独立的清点各读一份），按条件原文判这条改动响没响：

- ADR-89 第 92 行（加变异时看一眼盖的是不是没人盖过的地方）：**核过** —— 主干 `5b44502c` 上 `adr-sync.ts` 一条变异都没有；`condition-rule.ts` 新加的全在 `registryArg` 与它的两个形状判定上；`conditions.ts`、`revisit-due.ts` 主干上原有的变异没有一条盖「用哪一份登记表」这一处接线。
- ADR-252「能算的条件落成手写登记表」（下一条同类合入就响）：**不算同类，没响。** `registryArg` 里认得的判法、量法是手写的，与类型里那几种重复；但漏了一种是「写对了的行被说成不是登记表、以 2 退出」，响的，不是「清单外的漏了没声音」；而且只在测试用的那一路上。
- ADR-70「硬退出收口只到 mutate.ts」：没响。它点名的入口里只有 `adr-sync.ts` 被改到，那里没有硬退出，新加的一处也是设退出码。
- ADR-129 第 149 行（检查链时长按完整日志重新分账）、ADR-145「回测与拆前数只能靠仓库外的交接文档复现」：都等启动数闸门报出超线或「不确定」；这条改动的完整检查里启动数闸门是绿的，没响。
- 其余行没有一条的条件原文被这条改动做成。
