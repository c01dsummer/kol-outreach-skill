# ADR-55 拆出来之后第一件事：三步协议的第二步没有比对

> ⚠️ 欠条：第二步的比对没有补上，其余三个无条件写入方也没进协议；
> `persistListAndStatus` 是拆分前分支上的名字，主干上尚无 · 重启条件：见 ADR-66 ——
> 五个写入方都进同一个协议、验收能逐个列出时，作为一条新需求另开改动

- 日期 · 2026-08-31 · 自查（拆分时按「谁在写」清点写入方发现）
- 类型：**事实证伪**
- 冲击的需求：D4 · P4
- 结论：**接受为已知缺口**；本条只记事实，修法不在本条

### 事实

`persistListAndStatus` 的注释写着「**每一步**改名前确认盘上还是上一步留下的
那份」。实际上第一步和第三步带了比对，**第二步 `saveCreators` 是无条件写**。

不需要任何外部写入方，两个 `persistListAndStatus` 就够：

```
A 第一步 → unknown          B 第一步 → unknown（比对通过）
                            B 第二步 → B 的名单
                            B 第三步 → ok（比对通过）
A 第二步 → A 的名单  ← 无比对，盖掉 B
A 第三步 → 比对失败，抛
```

实跑复现，盘上留下 `memory_status = ok` 配 `['未去重的人','已拉黑的人']`。
A 是响地失败了，**但抛出来并不修盘上的东西**，而报告对 `ok` 一个字都不说。

第二条同一个根：两个文件一共**五个写入方**，事务只管住两个。
`task.json` 还有 `collect` 的断点保存和 `enrich`，`creators.json` 还有 `render`，
它们都是无条件写。

### 教训（在动手修之前就先记下）

**「检测到了」不等于「挡住了」。** 比对能告诉你撞车了，不能把已经落盘的
东西收回去。一个只做检测的协议，它的保证上限是「**参与协议的那些写入方**
之间不会静默互相盖掉」—— 而这句话里的限定词，正是上一版漏掉的那半。

所以这一层的验收不能写成「并发安全」，得写成
**「以下 N 个写入方之间互不静默覆盖」，并把 N 个逐个列出来**。
列不出来的，就是还没被挡住的。

---

### 追记 · 「参与协议的写入方之间不会静默互相盖掉」这个上限本身也说大了

- 拆分评审

上面把只做检测的协议的保证上限写成「参与协议的那些写入方之间不会静默互相盖掉」。
这句也不成立。ADR-47 第二节自己写着：「比一次」到「改名生效」之间有一道缝。
两个都进了协议的写入方，各自读、各自比对、都发现盘上还是读到的那份、然后先后改名 ——
两次比对都通过，后一次改名照样静默盖掉前一次。比对把撞车从「永远不知道」
变成「多数时候能报出来」，给的是尽力检测，不是互不覆盖。

所以「验收得写成以下 N 个写入方之间互不静默覆盖」那句作废：列得出 N 个也写不出
那条保证。D4 里的承诺已在 ADR-66 整句撤回，改成明确不保证；要再立，
先把它变成一条需求，而那条需求需要的不只是比对。
