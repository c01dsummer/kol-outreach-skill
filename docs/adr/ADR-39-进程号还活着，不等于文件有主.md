# ADR-39 进程号还活着，不等于文件有主

- 日期 · 2026-08-28 · PR #5 拆分后第四轮自动评审，成立
- 类型：**事实证伪**
- 冲击的需求：D4（临时文件的清理）
- 结论：**采纳**，进程号之外再加一道文件年龄

### 事实

ADR-30 加的那道清理是：临时名带 pid，下次写回时清掉**已死进程**留下的，
不动还活着的（并发写保护）。

漏掉的是：**系统会回收进程号。** 孤儿文件活得够久，它名字里那个 pid 被分配给
一个毫不相干的长命进程之后，`alive(pid)` 就永远返回 true —— 这个孤儿再也清不掉，
一份完整的记忆副本永远躺在盘上。D4 明写着下次写回要清掉它，而它清不掉。

### 修法

进程号之外再加一道**文件年龄**：写的过程是一次 `writeFileSync` 加一次
`renameSync`，毫秒级；活过一小时的一定不是正在写的。一小时是荒谬地宽松，
为的是任何真正在写的文件都不可能被误判成孤儿。

两个条件都要满足才保留：**进程还活着 且 文件还年轻。**

顺带把 D4 的验收标准改成实话：进程号会被回收，所以「那个进程还在」
不足以判定文件有主。原先那句读起来像是 pid 就够了。

### 教训

**pid 是个会被复用的标识符，而我把它当成了身份。**

同一个形状在这个 PR 里出现过好几次：编号被回收复用会让历史记录指向错误的东西
（所以需求编号和判据编号都写死了「不回收复用」），而我在需求文档里写下这条规矩，
转头就在代码里拿一个**由系统回收复用**的数字当身份用。

「这个标识符会不会被复用」是个该在用它之前问的问题，不是该在评审里被问的问题。
