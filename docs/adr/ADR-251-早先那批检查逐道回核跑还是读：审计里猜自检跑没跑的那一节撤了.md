## 一、尺子

尺子本身不在这里重述，照 `process/README.md` 第三层「一道闸门该不该建」那一行与 ADR-87。

这一次逐道看的时候多问了一句：**检查里有没有手写的表，表漏了一项时往哪边错？** 漏了就红的，
是跑的检查里一份配置；漏了照样绿的，才是那张替代读的表。

| 架构锚点检查 | ADR-78 | 一半跑一半读：表和磁盘对不对得上是命令；它让人以为守住的说明列对不对是读，而它从没查过 | 撤得对 |

坏法在 diff 里一眼可见）都不在这把尺子上，所以这次回核不改它们的结论。

## 三、撤掉审计第 2 节

它问的是「`scripts/` 下非 `scripts/check/` 的可执行文件，每一个都被自检执行过吗」。
判法是：**在 `selfcheck.ts` 的源码里找那个文件名的调用写法**，找到就算执行过。

那是读源码去猜跑没跑。调用写在一段永远走不到的分支里，它照样判「执行过」，报绿。

而同一个问题，自检自己是**在跑的时候**答的：每走到取一个脚本路径的那一行就记下来，跑完对着 `scripts/` 下
**全部**带 shebang 的文件找孤儿 —— 范围比第 2 节大（连 `scripts/check/` 也算），
判据是这一跑真走到了那一行，不是源码里写了。第 2 节查得出的，孤儿检查都查得出，差别只有两处：自检那边可以写一条具名豁免放过它（豁免要写理由、在报告里逐条打出来，和审计这边原先那张豁免表同一个形状）；检查链那一串里点到的脚本也算有出处（第 2 节管的那些入口里只有需求测试那一个走这条路，第 2 节原先也豁免它）。
在 `npm run check` 里（本地与 CI 都是）自检总是在审计之前整跑一遍，第 2 节真该红的时候孤儿检查已经先红了；它唯一能独自红的，是自检按子目录路径取一个入口、它只认文件名对不上的那种误报。单独跑 `npm run audit` 从此不再报这一项，要看就跑自检。
`process/4-VERIFY.md` 里「审计要检查这一条：每个可执行文件……」说的「审计」是一个角色，在本仓库由自检承担，那句不用改。

照 ADR-87，替代读的那一份不该留；它又只是跑的那一份的弱副本，撤掉不丢任何覆盖。

改的是 `scripts/check/audit.ts`：那一节的判定、它的豁免表与报告里打印豁免的那一行删掉，
节号留一行注释占着，别处按「第 3 节」「第 4 节」引的仍对得上。这一节在入口文件里，
没有变异、没有测试点它的名。跟着改的几处指针：`docs/SYNC.md` 触发表「新增/删除 `scripts/` 下的模块」那一行
原先写着由审计守，改成由自检守；`audit-rule.ts` 与 `selfcheck.ts` 头注释里「死亡条件记在 ADR-85」补上本条。

ADR-85 给这一节写的死亡条件、给自检孤儿检查那一半写的死亡条件（「审计第 2 节把
`scripts/check/` 也纳入之后退成只报数」）都跟着失效 —— 后者等的那件事不会再发生了。
自检孤儿检查那一半的现行条件见第五节；ADR-85 末尾补一块指过来。

## 四、具名豁免的理由没人核

自检的 `EXEMPT` 现在七条，每条理由都点名一个需求测试组，说入口由它在玩具仓库上真起、或判定由它守着。
**这句话是读**：没有东西核那个组还在、还起这个入口。那个组被删了、或改成不起它了，
这个入口从此谁都没跑过，自检照样报「都有出处」。审计的 `JUDGMENT_EXEMPT` 一条（理由是「由自检自己的断言守着」）、
变异目录里验收判据的显式豁免（十一条，每条写着为什么这条判据没有负片）同样如此：理由说的那件事变了，表照样绿。

这一处要修就得让机器知道「这个入口在哪个测试组里真起过」，那是测试跑的时候才有的事实，
不是一张表能逼近的。本条不修，登记：

> ⚠️ 欠条「具名豁免的理由没人核」（档：登记）：自检具名豁免、审计「不算判定模块」那张表、变异目录里验收判据的显式豁免，每条理由里写的「由哪个测试组真起、由谁守着、为什么没有负片」都是写给人看的；理由说的那件事变了（组删了、改名了、不再起那个入口、判据有了写得出负片的办法），三张表照样绿 · 重启条件：下一条删掉或改名一个需求测试组的改动，或往这三张豁免表里加一条的改动

## 五、自检孤儿检查那一半的死亡条件

> **什么条件下退成只报数、不拦**：`scripts/` 下带 shebang 的可执行文件（不分在不在 `scripts/check/`）降到 2 个以下时 —— 那时「每个可执行文件都有出处」剩不下几个对象，一次人读就够。

这一条原是 ADR-85 写给审计第 2 节的，搬过来时把范围放大到孤儿检查实际查的那么大。
数法与自检同一条判据，只看第一行：

```bash
git ls-files -z 'scripts/*.ts' 'scripts/**/*.ts' | xargs -0 awk 'FNR==1 && /^#!/ {print FILENAME}' | wc -l
```

## 六、欠条

本条还上的：

- ADR-205「旧闸门逐道回核跑还是读」：还上，就是第二、三节；ADR-205 末尾补已还行。

本条新登记的：第四节那一张。

碰响了的，逐张处置（三份独立清点）：

- ADR-85 给自检孤儿检查那一半写的死亡条件：它的数法是「审计里那一行把 `scripts/check/` 排除在外的代码还在，条件就没成立」，那一行随第 2 节删了，照字面读成成立；实质没成立 —— 那一节是撤了，不是纳入了。ADR-85 末尾补了更正块指到第五节。台账不认更正块，周回访轮到 ADR-85 时那一条照旧会列出来，读的人看末尾的更正块。
- ADR-246「只给测试用的模块按名字认」（同类「要守的一整类落成手写清单」）：不响。本条没有落下新的手写清单，只回头看了旧的；第四节登记的是旧表的理由没人核，不是新添一例。
- ADR-193 重挂的「记录里同时写着机制和与机制矛盾的结论」：不响。评审指出本条初稿里孤儿检查的判据说过头了（写成「三半都是跑」「唯一的差别」），本条合入前已照代码改正，没有合入一份自相矛盾的记录。
