## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 现在有哪几份决策记录 | `docs/adr/` 目录：`adrSync` 读到的每份记录的编号（文件名与第一行一致的那一套） | 机器 |
| 每份记录定了什么、对用户有什么影响 | 记录原文开头几栏（结论、冲击的需求）与正文；写这一行的人读了再写 | 人 |
| 每份记录还欠什么 | 记录里的欠条块与「已还／已重挂／收尾」状态行；写这一行的人读了再判 | 人 |

## 一、决定

- 另起一个文件 `docs/adr/白话目录.md`，一张四列的表：编号、定了什么、对用户有什么影响、还欠什么。每份决策记录一行，原文一个字不动。
- 「对用户」指用这个 Skill 找博主、出名单的人。只改开发流程或检查的记录，写「无（只影响开发流程）」这一类，让读的人一眼跳过。
- 「还欠什么」挑要紧的写；欠条已挪到别的记录的，写「已挪到 ADR-xxx」。
- `npm run adr`（决策记录检查）多核一件事：目录里的编号与 `docs/adr/` 下的记录一一对应，四格都填了。新记录没补那一行、目录里多出没有记录的一行、同一个编号两行、空格子，都报红 —— 卡上关单标准第 2 条允许提醒或报红，取报红：只提醒的话，新记录漏补一行没有人会回头补。
- 不从原文自动生成：定了什么、对谁有什么影响要读懂了才写得出白话，生成出来的只能是标题的复写（第三节）。

## 二、这一版怎么写出来的

208 份记录逐份读了开头几栏（标题、结论、冲击的需求）、正文开头和全部欠条块与状态行，再写那一行。「还欠什么」按原文里的已还、已重挂、收尾记录判；老记录里按「第几行」互指的状态行，行号后来挪过，按内容对上了才算已还。

## 三、仍然按不住的

> ⚠️ 欠条「还欠什么那一栏没有机器跟着改」：「还欠什么」是 2026-11-22 读出来的快照。以后某张欠条还上或挪走，写状态行的人不一定记得回来改这一格，没有机器提醒；欠条台账（`npm run adr-ledger`）不判哪张已还，接不上 · 还法：台账认得出已还、已重挂、收尾之后（ADR-151「台账不判哪张欠条已还」），让这一栏由它生成或由它核 · 档：登记 · 重启条件：ADR-151「台账不判哪张欠条已还」还上时；或周回访第一次发现这一栏有一格与原文对不上

> ⚠️ 欠条「白话目录写得白不白只靠人读」：检查只核一一对应与格子不空，写得是不是白话、说得对不对，只靠写的人和评审读 · 还法：行话提示（检查时列出新冒出来的行话与编号，另一张卡）上线后，把这个文件也纳进去 · 档：登记 · 重启条件：行话提示那道检查合入时

- **定了什么一栏多半照标题改写**：多数记录的标题本来就是一句结论，这一栏是把它说白，不另做总结。

## 四、给后来者的提醒

新加决策记录时在同一条改动里补一行；改了某份记录的结论或还上它的欠条时，顺手改它那一行。
