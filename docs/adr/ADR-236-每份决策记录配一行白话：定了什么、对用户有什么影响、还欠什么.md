## 要用到的事实，各找谁要

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 现在有哪几份决策记录 | `docs/adr/` 目录：`adrSync` 读到的每份记录的编号（文件名与第一行一致的那一套） | 机器 |
| 每份记录定了什么、对用户有什么影响 | 记录原文开头几栏（结论、冲击的需求）与正文；写这一行的人读了再写 | 人 |
| 每份记录还欠什么 | 记录里的欠条块与「已还／已重挂／收尾」状态行；写这一行的人读了再判 | 人 |

## 一、决定

- 另起一个文件 `docs/adr/白话目录.md`，一张四列的表：编号、定了什么、对用户有什么影响、还欠什么。每份决策记录一行，原文一个字不动。
- 「对用户」指用这个 Skill 找博主、出名单的人。只改开发流程或检查的记录，写「无（只影响开发流程）」这一类，让读的人一眼跳过。
- 「还欠什么」挑要紧的写；欠条已挪到别的记录的，写「已挪到 ADR-xxx」。
- `npm run adr`（决策记录检查）多核一件事：目录里的编号与 `docs/adr/` 下的记录一一对应，四格都填了。新记录没补那一行、目录里多出没有记录的一行、同一个编号两行、空格子，都报红 —— 卡上关单标准第 2 条允许提醒或报红，取报红：只提醒的话，新记录漏补一行没有人会回头补。
- 不从原文自动生成：定了什么、对谁有什么影响要读懂了才写得出白话，生成出来的只能是标题的复写（第三节）。

## 二、这一版怎么写出来的

当时的每一份记录逐份读了开头几栏（标题、结论、冲击的需求）、正文开头和全部欠条块与状态行，再写那一行。「还欠什么」按原文里的已还、已重挂、收尾记录判；老记录里按「第几行」互指的状态行，行号后来挪过，按内容对上了才算已还。

开 PR 前合主干时，主干上已新加了 ADR-234（每条改动都在提议档）和 ADR-235（体量闸门只数叠分支自己的提交），这两行照同样读法补上；本记录因此由原定的 235 改号为 236。

## 三、仍然按不住的

> ⚠️ 欠条「还欠什么那一栏没有机器跟着改」：「还欠什么」是 2026-11-22 读出来的快照。以后某张欠条还上或挪走，写状态行的人不一定记得回来改这一格，没有机器提醒；欠条台账（`npm run adr-ledger`）不判哪张已还，接不上 · 还法：台账认得出已还、已重挂、收尾之后（ADR-151「台账不判哪张欠条已还」），让这一栏由它生成或由它核 · 档：登记 · 重启条件：ADR-151「台账不判哪张欠条已还」还上时；或周回访第一次发现这一栏有一格与原文对不上

> ⚠️ 续挂：ADR-236「还欠什么那一栏没有机器跟着改」 · 在台账认得状态行那一片（ADR-167）合入时响了，当时没写处置，到期清单那一片补上 · 到 2026-12-21 · 因为台账现在只认得出哪张开着、哪张关上，「还欠什么」那一格是挑要紧的白话，由台账生成还是只核个数要另行设计，不放进到期清单这一条

> ⚠️ 欠条「白话目录写得白不白只靠人读」：检查只核一一对应与格子不空，写得是不是白话、说得对不对，只靠写的人和评审读 · 还法：行话提示（检查时列出新冒出来的行话与编号，另一张卡）上线后，把这个文件也纳进去 · 档：登记 · 重启条件：行话提示那道检查合入时

> ⚠️ 已还：ADR-236「白话目录写得白不白只靠人读」 · 还在生词提示那条改动（ADR-237）：它看每份 Markdown 新加的行，白话目录在内；只提醒不拦，写得对不对仍靠人读

- **定了什么一栏多半照标题改写**：多数记录的标题本来就是一句结论，这一栏是把它说白，不另做总结。

## 四、给后来者的提醒

新加决策记录时在同一条改动里补一行；改了某份记录的结论或还上它的欠条时，顺手改它那一行。

## 五、欠条清点

三个独立上下文按台账分段判过（ADR-1–80、81–160、161–236），本条上响了或沾边的：

- ADR-89 第 92 行（加变异时看盖的是不是没人盖过）：核过，本条的变异全落在新写的目录核法与 `adrSync` 新接的那两处上，主干上没有变异盖它们。
- ADR-82 第 112 行（碰到 `docs/ARCHITECTURE.md` 时看可算的数量词）：字面响、实质不响。本条在那里加的一行只说目录的格式，没有可算的数词；原块点名的那几句在主干上已经找不到，是否标已还留给欠条台账那条线判，本条不动它。
- ADR-205「旧闸门逐道回核跑还是读」（下一条新建或撤一道闸门的改动）：拿不准，按窄读不响。本条没在检查链上新加一步，只在 `npm run adr` 这一步里多核一件事；它替代的是「读」—— 原先没人逐份对一一对应，现在机器对。
- ADR-211「过线的记录改到时先拆没有机器守」（改 `adr-rule.ts` 历史文件那段判定）：字面挨着、实质不响。本条只在 `adrSync` 跳过的文件名里加了一个、在历史文件那段之前加了一次调用，历史文件与指纹的判定一行没动，也没往过线的记录末尾加内容。
- ADR-99「往记录或注释里写算出来的数，没有东西会红」：评审指出本条初稿写了记录份数，与合主干后的份数对不上，已改成不写数。
- 同类：「还欠什么」一栏是又一份手工读的欠条状态，与 ADR-151「台账不判哪张欠条已还」、ADR-167「台账认不出状态行」同一处缺口；本条第三节那张欠条已挂在 ADR-151 那一张还上时。

独立复核另提的几处在本条里改了：几行白话与原文对不上（ADR-79、ADR-145、ADR-167）或不够白（ADR-151、ADR-205、ADR-235），照原文改写；核法补了四处会漏的 —— 行尾挂 HTML 注释的行会逃过核对（目录里不许写注释）、只写占位的格子当成填了、少了分隔行、表头之前的行也当目录行，各补测试与变异。

CodeRabbit 首轮又在同一个核法上挑出两处会漏的（表里第一格空着的行被悄悄跳过；表后隔了空行再写的行照样算数）。前一轮独立复核在这里补的也是「哪些行算目录行」，两轮落在同一处，所以不再逐条补，改了认法：目录表只认表头、分隔行和紧跟其后连续的表格行；表外任何以竖线开头的行都报红，不悄悄跳过；表里每一行第一格都得是 `ADR-<编号>`。漏的方向从「跳过」变成「多报红」。

CodeRabbit 第二轮还落在这个核法上：整张表缩进四格，页面上是代码块，核法却当成目录表核过。连着两轮都出在「自己认 Markdown」这件事上 —— 认法改得再细，每漏一种写法（缩进的代码块、引用块里套的表……）就多一个洞。需求所有者 2026-11-23 在项目线程的选择卡上定了「就在这条里改」：哪几行是目录表交给项目已装的 Markdown 解析器（`marked`，按 GFM 认），读的人在页面上看到的那张表就是检查核的那张表；表外以竖线开头的文字行、目录表以外的任何表（引用块、列表里套的也算）都报红；同样表头的第二张表不顶替第一张。只有「这一行几格」照原文按竖线切 —— 解析器会把多出的格子丢掉、少的补空，那样看不出来。原先「目录里不许写 HTML 注释」那条随之撤掉：行尾挂注释的行，解析器照样认成表里的一行，逃不过重复与格数的核对。测试与变异按新认法重写（M-H236 一组里落在这个核法上的那些）。

同一轮另两处是白话写得不准，照原文改了：ADR-03 那一行的「还欠什么」点出与它字面矛盾的是 ADR-184；ADR-49 那一行注明它的断电保证已被 ADR-50 收窄为尽力而为。
