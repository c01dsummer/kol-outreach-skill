# ADR-116 市场与目标人数校验原值，缺省只适用于新输入缺席

- 日期 · 2026-09-25 · 处理 ADR-115 第五节登记的 `market` / `target_count` 输入缺陷
- 类型：**既有缺陷**及**需求有歧义**（明确已有字段类型、缺席与显式非法值的边界）
- 触发它的事实：ADR-115 已登记非数 `target_count` 使 collect 不能正常判定达标、非字符串 `market` 仍进入 probe 付费请求；D16 入口接线已合入，重启条件已满足
- 冲击的需求：新增 D17；D16、D15.j、F3、F9 与 P1–P5 含义不变
- 结论：**采纳**。先交付原始字段纯判定，入口拒绝另交付；纯判定通过不代表用户入口已修复
- 理由：字段类型与新输入 US / 50 的既有缺省不能混为一件事；显式坏值不应被默认值掩盖，续跑缺必填字段时也不能推断原配置
- 连带改动：本次为 `docs/requirements.json`、生成的 `docs/SPEC.md`、本记录、ADR-115 末尾说明、`docs/ARCHITECTURE.md` 纯模块边界，以及纯判定的实现、单元测试和变异；不改变入口、README 或 Skill 的现行行为说明

## 一、字段边界

`TaskState` 已声明市场为必填字符串、人数为必填数值；产品理解说明已有新输入市场缺省 US（要说明）、人数缺省 50。
据此明确下面的取值边界，不增加国家白名单、ISO 格式、大小写或人数正数、整数、最大值限制。

| 原始字段 | new | resume（含改额续跑） | probe |
|---|---|---|---|
| `market` 缺席 | 判定允许；入口沿用 US 并说明 | 逐项报错 | 判定允许；入口沿用 US 并说明 |
| `market` 已出现 | 非空白字符串，保留原值 | 同左 | 同左 |
| `target_count` 缺席 | 判定允许；入口沿用 50 | 逐项报错 | 不使用，不校验 |
| `target_count` 已出现 | 有限 number，保留原值 | 同左 | 不使用，不校验 |

缺席只指自有字段不存在；显式 `null` 或自有字段值为 `undefined` 不是缺席。字符串人数、布尔、数组与对象不转换后接受。
`market` 的首尾空白和大小写不改；0、负数、小数不在这次禁止范围内，这不赋予它们新的业务含义。
有限数判定须拒绝 JSON 原文 `1e400` 解析后的 Infinity，不引入金额字段的原始十进制精度协议。

续跑缺字段单独按输入不完整处理：原市场或目标已不可知，不能用新配置缺省重建。原文件应保留，用户修正输入后才可再尝试续跑。
这项依据是必填配置不完整与不得推断原值，不声称 ADR-115 对旧 `tasks` 的用户裁决自动覆盖了其他字段。

## 二、纯判定的公开边界

新增 `scripts/lib/config-input.ts`：

```ts
export type ConfigInputRole = 'new' | 'resume' | 'probe'
export function configFieldProblems(
  raw: Readonly<{ market?: unknown; target_count?: unknown }>,
  role: ConfigInputRole,
): string[]
```

只读两个原始自有字段，按角色返回全部问题；空数组表示这两个字段在该角色下没有问题。
不读盘、不填默认值、不改输入、不预留、不请求；根对象形状与 JSON 读取仍由既有读取边界负责。
字段输入涵盖 JSON 读入值及直接调用的 `undefined`、非有限数、BigInt、Symbol、函数；后三类仍是错误类型，不限定其文本编码。
不新增循环引用、代理对象或访问器的处理语义。
不把任务列表或路线判定搬进这个模块，不扩成完整 TaskState schema，也不处理未知字段、拼错字段或 `as_hashtag`。
错误须让字段与原值可辨，缺席与实际 `null`、`undefined`、字符串“缺席”不同；非有限数不能只以 JSON 序列化后的 `null` 表示。
不规定固定句子、内部算法或问题先后顺序。

本次 D17.a–g 只认领上述纯判定。D17 × P1 只覆盖判定不把非法值或续跑缺席补成合规值；
入口若先默认化再调用，纯判定证据看不见。因此下述入口缺口仍单独登记，不能由本次交点认领声称已守住入口。

## 三、入口完整目标与本次边界

collect 保留既有文件及预算解析的先后边界，取得原始配置后汇总本项字段、任务列表与路线的全部问题。
字段检查在缺省应用之前；配置可读、CLI 预算与新建预算合规时，stderr 写输入路径及上述全部问题。
拒绝须退出 2，先于建任务目录、任何任务写入、预算预留和请求；新建不留目录，续跑原文件逐字不变，改额不落盘。
probe 只查实际使用的 market，与任务、路线问题一起报告后拒绝，先于开进程预算、预留和请求；退出 2，遵守 F3.c/d 的路径、问题与无内部类名/堆栈要求。
只有全部相关输入问题消除后，new / probe 才为缺席字段采用上表既有缺省。目标人数为 0 也不能绕过 F9 的第一页保证。

纯函数单元断言与实际入口的退出、零预留、零请求、文件不变是两种证据。按 `process/6-INTEGRATE.md` 分开交付：
本次只交纯判定及其反例；入口合入时再从 D17.h 起追加判据，将 collect / probe 的拒绝与诊断分别编号，并同步实际顺序与用户说明。
不改 D16 已合入判据的含义，不允许新字段错误遮住它已承诺报告的任务与路线问题。
