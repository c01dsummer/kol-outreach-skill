## 一、要用到的事实，各找谁要（`process/3-BUILD.md` 第 8 条）

| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |
|---|---|---|
| 有哪些决策记录、各是几号 | `docs/adr/` 的目录列表，加文件名 `ADR-<编号>-<标题>.md` 与第一行 `# ADR-<编号> <标题>`；两者对不对得上、撞没撞号，已由 `npm run adr` 那道检查校验 | 项目定格式、已有检查校验的标记 |
| 哪一份算「新的」 | 编号不小于 224（本条）。编号不复用，但允许空号：224 以下原有的空号抄成一张表，新记录写成这些号、或写成 0，一律报红。那张表对不对，权威是 `docs/adr/` 目录本身：测试每跑一次都拿目录实数重算 224 以下的空号、与表比（记录只加不删，这件事一直成立） | 同上；空号表由测试对着目录核 |
| 这一节在不在、表填没填 | 本条定的三样格式：节标题、表头一字不差、或一句「不列：理由」，由本检查校验 | 项目定格式、由本检查校验的标记（第 8 条说的「写给机器读的契约」） |
| 一行是不是在举例（围栏代码块、HTML 注释里的） | `quotedMask`（围栏照 CommonMark 的规则认，HTML 注释宁可多盖） | 机器；多盖的那一边在这里只会多报：表里有一行被盖住就报红 |
| 一行表格拆成几格、哪一行算分隔行、节到哪里结束 | 本条自己定的规则，取 GFM 表格的一个子集：按没转义的竖线拆；分隔行每格是横线（可带对齐冒号）；节到下一个 `#` 或 `##` 开头的标题为止（不认下划线式标题） | 项目定格式、由本检查校验；比 GFM 窄的地方只会多报 |
| 「找谁要」那一格填得对不对、「不列」的理由站不站得住 | 写代码前的独立复核（第 8 条），评审 | 人读 |

## 二、检查怎么判

编号不小于 224 的每一份决策记录，跳过引文以后：

1. 二级标题「要用到的事实，各找谁要」正好一个（前面可带「一、」这样的序号，后面可带括号补充）。没有、或有两个，红。
2. 这一节（到下一个一级或二级标题为止）第一个不空的行，要么是表头 `| 要用到的事实 | 找谁要 | 给机器读的还是给人看的 |`，要么以「不列：」开头、后面写了理由。都不是，红。第 8 条本来就说不用出计划的平凡改动不用列，「不列」就是给这种记录的；它站不站得住由评审读。
3. 是表头的：紧接着一行分隔行，再紧接着至少一行；每行按没转义的竖线拆成正好三格，三格都不空。缺分隔行、一行都没有、格数不对、有空格子，红。

224 以下原有的空号、或编号 0，新记录写成哪一个都红。表里有一行被当成引文（多半是格里写了 HTML 注释的开头）也红，不让它悄悄把表截断。认不出的写法一律报红：选多报那一边（第 8 条），多报当场红、有人看。

检查挂在 `npm run adr` 里（它本来就逐份读每一份记录），不另起入口。

## 三、拦不住的

- 填得对不对。「找谁要」写的是不是那件事真正的权威、第三格写「机器」是不是真的、「不列」的理由站不站得住，机器都判不出，仍靠写代码前的独立复核和评审。格子里只填一个横线、只填看不见的字符、「不列：无」，格式上都算填了。
- 表是不是在写代码之前列的。表和代码同一条 PR 进来，先后没有留痕；第 8 条要求的「写代码前过一次独立复核」也没有机器看着。
- 不写决策记录的改动。第 8 条说计划写进决策记录的表也写在那里；计划不写进决策记录的，没有地方可查。
- 拆分以后。主文件只放现行结论、过程挪去历史文件（ADR-211）；拆一份 224 以后的记录时，这一节要留在主文件里，留没留由本检查看着（它查的就是主文件）。

## 四、它替代什么、什么时候撤

**替代的是「跑」，不替代「读」**（`process/README.md` 第二层「一道闸门该不该建」）：它数的是固定格式在不在、格子空不空，同一份文件永远同一个结论。它不碰「找谁要」写得对不对，那一半是读，留在第三层。

> **什么条件下退成只报数**：连续二十份新决策记录没有一次因为本检查红过 —— 写这一节已经成了习惯，红的只会是格式笔误。
