## 一、决定

1. **照 D27 整份判。** 需求所有者在 ADR-142 那张卡上选的是「整份判」，配置文件同一个理由：读入只留最后一处，在哪个字段都是同一件事。配置里没被 collect 抄进新任务的键（如 `cost_ledger`）写重复也报 —— 用户写了两次，说明至少有一处不是他以为的那样；不报，就得先替他判断哪些键要紧。
2. **进度键在配置里不例外。** D19.k 那几处的例外是因为续跑另有一套判法（D19.l、D19.m）；配置不续跑，collect 新建时丢掉配置里的进度字段，probe 不读它们，所以照别的键一样报，不跳过。
3. **与原字段、任务列表、路线问题同一道。** 配置的原始问题本来就在一处汇总，在读预算 token、套缺省、建目录之前报（D17.h、D16.j、D20.e）。写重复的键并进这一道：同一份配置里的任务问题不被遮住，预算 token 的问题照旧排在这一道之后（与原先任务问题遮住它的方式相同）。collect 另起一句「里写重复的键」，与续跑同一种写法；probe 的输入问题本来就拼成一条「任务配置不合规」，写重复的键排在最前、同一条里，退出码与报错出口不变（F3.c、F3.d）。
4. **只管这两个命令读的配置。** 别的命令读的 JSON 见第四节。

## 二、逐条评定

1. **触碰红线吗？** 撞的是 P1（替用户挑一处：新建的 task.json 里只剩那一处，前几处从此不见）与 P3（`budget_usd` 按最后一处的上限开账）。拒绝不违反任何红线；两个交点都写了裁决。
2. **缩范围还是降标准？** 都不是。没有写重复的配置，两个命令的行为一字未改（D28.d）。
3. **可逆吗？** 可逆：两处调用删掉即回到原样。

## 三、测试与变异

1. **测试先于实现、由另一个上下文写成**：只读需求原文、本条草稿、D27 那一段测试的接法与夹具，不读 `collect.ts`、`probe.ts`、`cost-json.ts`、`duplicate-keys.ts` 的函数体。`scripts/test.ts` 新增 `d28-config-duplicates` 组（`needs` 为空），全走真入口：collect --config、collect --config --budget 2 与 probe，fake-fetch 逐次记请求，预加载在预算预留上记次数，观测文件放在入口的工作目录之外、工作目录整棵比。三种模式先各跑一遍只留最后一处的同一份配置当阳性对照，要照常以 0 结束、预留并请求。
2. **对着 `f0a86f0` 看红**：九条里五条红 —— collect 与 probe 各两条（以 2 拒绝、零预留零请求；stderr 写出路径、位置、次数与每一处原文），另有「与任务列表或市场问题一起时写出写重复的那一处」一条。观测值见文首「触发它的事实」。绿着的四条是两条夹具有效、「那一类问题不被写重复遮住」与 D28.d 不多拒 —— 断的是现状本来就对的那一半。接上实现（`6fb09b7`）后全绿。
3. **变异 M-D28-a 至 M-D28-m，十三条，都是 `by: test`**：
   - collect：新建时不判（回到只在续跑时判）、新建时照续跑跳过根上的进度键、写出了却不退出、退出推迟到建目录与预留之后、另有字段或任务问题时不写出写重复的键、见写重复的键就先退出（遮住字段与任务问题）、带 `--budget` 时不判；
   - probe：不判、跳过根上的进度键、只报写重复的键（遮住市场与任务问题）、另有市场或任务问题时不报写重复的键、只有写重复的键时先开预算并预留再拒；
   - 不多拒：同一个数组里的几个对象共用一份键表（与 M-D27-aa 同一处改动，点名本组那一条）。
   每条在副本里单独施变后只跑 `d28-config-duplicates`（非 root 用户）：点名的断言都红，没有别的断言跟着红。M-D27-l、M-D27-u 跟着改了 find，在副本里单独施变后跑自检 `resume-progress` 组，点名的断言照样红、没有夹具或进程记号。
4. **顺序契约表那一行点名七条**（M-D28-c、d、e、f、j、k、l）：它们施下去后，写重复的键照样被判出来，坏的是先后或汇总 —— 退出晚了、两类只报一类、先开账再拒。M-D28-a、b、g、h、i 是某种配置根本不判，后果是照常按最后一处开账请求，不是先后错了，不列在那一行。
5. **没写成变异的一条**：找不到读入时的原文判为无从核对（D28.a 末句）。两个入口读配置都经同一次读入，入口上造不出没有原文的配置；这一句由库层的 M-D27-k 守。

## 四、边界

- 只判这两个命令读的配置。别的命令读的 JSON：task.json 由 D27 判；`agent-review.json` 与跨任务记忆读入时各有一遍整份的重复键判定（`lib/review.ts`、`lib/memory.ts`）；`creators.json`、`creators.raw.json` 由脚本写出，本条没有核它们写重复时的读法。
- 读不出的配置（不是 JSON、根不是对象）照旧在读入那一步拒绝，到不了这里。
- `--budget` 是命令行实参，不是文件，不在此列；与配置里的 `budget_usd` 同时出现时照旧用实参，但配置里的 `budget_usd` 写重复照样拒绝 —— 那是用户写错的输入，实参盖过去不等于它没写错。
