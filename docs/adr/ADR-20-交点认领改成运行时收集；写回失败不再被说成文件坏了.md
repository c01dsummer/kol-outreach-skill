# ADR-20 交点认领改成运行时收集；写回失败不再被说成文件坏了

- 日期 · 2026-08-28 · PR #5 第三轮自动评审，两条都成立
- 类型：**事实证伪**（一条把我上一轮亲手立的规矩变成了空头承诺，一条是 ADR-19 的余波）
- 冲击的需求：**P4**（守它的机制失效）· D4 · P5
- 结论：**采纳**，两条都改

### 一、注释掉的认领照样算数 —— 硬失败被一句注释绕过去

ADR-17 立了一条规矩：**含红线的交点没有测试认领就是硬失败**。
审计的实现是按源码正则找 `tension('A', 'B')`。于是：

```ts
  // tension('P4', 'D4')   ← 测试删了，认领留在注释里
```

审计照样报 `✓ D4 × P4`、`交点 3 处 · 有测试认领 3`、全绿通过 ——
**红线交点一个测试都没有，而我上一轮承诺的硬失败一次都不会响。**

最难堪的是，这个坑仓库里有现成的记录，就在 `audit.ts` 同一个文件里：

> 只认 `S('xxx.ts')` 这个精确形式。早先还 or 了一个 `includes(base)` 兜底，
> 结果是 selfcheck.ts 里**任何地方**提到文件名（哪怕注释里）就算「执行过」——
> 前面那个精确判据变成死代码，整条检查形同虚设。

我在写着这段注释的文件里，又建了一个同样形状的检查。

修法不是把正则写得更聪明（注释挡住了，字符串、`if (false)` 里的调用还在），
而是**换一层**：

- `tension()` 在**运行时**把认领记进一个数组，测试结束时连同覆盖到的编号
  一起写进 `.check-cache/test-claims.json`
- 审计读这份记录，不再看源码。**没执行的就是没有**
- 记录带 `scripts/test.ts` 的指纹，审计重算并比对 —— 一份过期的记录
  不能替一段已经改掉的代码作证。记录不存在或对不上，审计当场说
  「先跑 `npm test`」，而不是默默放行

> ⚠️ 就地更正（#48）：指纹当时只算 `scripts/test.ts` 自己，挡不住「被 import 的实现
> 改坏、测试还没跑到第一行就崩掉」这一路 —— 静态 import 先于模块体求值，
> 而 `test.ts` 一个字没动，指纹照旧对得上，上一次的记录成了这一次的证据。
> 范围已放到整棵 `scripts/` 树：改坏实现就等于改了指纹，那份记录当场判过期。

顺带把 `suite()` / `covered.add()` 的覆盖统计也换成运行时记录 ——
它们是同一个形状，而 `covered` 这个集合本来就是运行时的，接过来几乎零成本。

### 二、写不进去被说成文件坏了

ADR-19 让 `written: false` 有了第二个原因（目录不可写、磁盘满），
而报告上的那句话是 ADR-15 写的，只考虑了第一个原因：

> 本次推荐未记入跨任务记忆（**记忆文件读不出来**，原文件未被覆盖）——
> 在**修好它**之前……

磁盘满的人会拿着这句话去修一份根本没坏的 JSON。

修法：`meta.json` 带上 `memory_write_error`（原因原文），报告改成
不预设原因的措辞并把原文带给用户。**两类原因要去修的地方完全不同** ——
读不出来去修 JSON，写不进去去看权限或磁盘。M-P5-e 守着。

### 教训

**要「某段代码跑过」的证据，就别去源码里搜它。**

搜出来的东西没有执行语义：注释、字符串、走不到的分支，全都算数。
这条已经写进 `process/4-VERIFY.md` 的「判据的失效方式」那张表 ——
那张表存在的全部意义就是记下这类形状，而这一条本来就该在上面。

更值得记的是**它发生在什么时候**：我在建立一条新纪律的同一次改动里，
用一个自己刚记过教训的手法去实现它。**新立的规矩最脆弱，因为立规矩的人
正忙着论证它为什么必要，没空问它能不能被绕过。**

所以立一条硬失败的规矩时，配套要问一句：**怎么在不触发它的情况下违反它？**
答得出来，那就是这条规矩的真实强度。
