# ADR-43 给一个值加了第二个来源，措辞还在描述第一个

- 日期 · 2026-08-28 · PR #5 拆分后第八轮自动评审，成立
- 类型：**事实证伪**（ADR-41 的余波）
- 冲击的需求：P5（交付物的声明）· D4
- 结论：**采纳**，措辞改成与来源无关

### 事实

ADR-41 给 `unknown` 加了第二个来源（名单与状态没能一起落成）。我改了
`requirements.json`、改了类型注释 —— **四份面向用户和 Agent 的措辞一份没改**：

| 副本 | 原话 |
|---|---|
| `scripts/lib/report.ts` | 「这批人由早期版本采集，当时记忆文件读不出来会被静默当成空记忆」 |
| `scripts/render.ts` 块注释 | 「缺失**只可能**来自 ADR-15 之前的 collect」 |
| `skill/references/memory.md` | 「（早期版本采集的任务目录）」 |
| `skill/references/output-format.md` | 「（早期版本采集的任务目录）」 |

于是：被打断的那种情况，用户会在报告上读到「这批人由早期版本采集」——
而它其实是**刚刚才产生的**。这不是措辞过时，是**给了用户一个编造的诊断**，
他会拿着它去查一个不存在的历史原因。

### 修法

措辞与来源无关：只说「无从确认」和「重跑一次采集即可得到确定答案」，
不解释为什么无从确认。两个来源事后本来就分不出，说不出来就别说。

这是 ADR-20 那条规矩的另一面：那次是**不许替下一步打包票**
（把「写不进去」说成「文件坏了」），这次是**不许替上一步编原因**。

### 教训

**加一个来源，和改一句话，我把它们当成了两件事。**

同步表里那条「改报错/提示里给用户的一句承诺」，列的是**改承诺**时要走的清单。
而我这次做的是**加一个来源** —— 承诺本身一个字没动，所以我根本没想到要走那张表。

漏掉的判据不是「有没有改措辞」，是**「有没有让某句已经写下的措辞变得不再为真」**。
第二个来源让「只可能来自早期采集」这句话当场变成假的，而我没改它一个字。

### 追记 · `output-format.md` 把 `unknown` 和 `unreadable_ignored` 合成了一句话

- 第十六轮评审

`report.ts` 与 `memory.md` 都写着「`unknown` 只说不知道，**不要替它编一个原因**」
（ADR-22 · 本条），而 Agent 照着输出格式那份说的时候，会告诉用户
「记忆文件读不出来，你让我跳过了」—— 一个编造的诊断。同一句话的第三份副本，
而它是唯一一份错的。

修法：`output-format.md` 的 `unknown` 那句不再自己发明措辞，改成写明
「措辞的规矩以 `memory.md` 为准」—— 三份副本降成两份，而剩下那两份
一份是代码、一份是它的说明。
