# ADR-97 检查链的时长：调度已经到顶，能砍的只有那段无关前缀

- 日期 · 2026-09-20 · 用户在 #139／#140 那两条改动之后提出「`npm run check` 时长又劣化了，
  我想我们需要有一种机制阻止这种情况，或者说这次的『劣化』是不是应该的」，
  并追加一条约束：**分析要 follow bitter lesson 的大原则**
- 类型：**既有缺陷**（检查链自身的成本结构），外加一条**不做**的登记。
  不触及需求登记表 —— 检查链的成本不是编号需求
- 触发它的事实：见第一节（串行实测，命令在那一节）
- 冲击的需求：无。冲击的是**检查链自己跑得起跑不起**
- 结论：**① 这次的劣化「工作量该付、乘数不该付」；② 明确不加时长／条数闸门，理由逐条在第四节；
  ③ 主修是给 `selfcheck` 一个选跑入口，不在本条里（重启条件在第六节）；
  ④ 本条只落 CI 那一刀 —— 每次 push 跑两遍整条链，砍掉一半**
- 理由：量出来之后，**调度已经在最优的 2.7% 以内**，并行没有红利可拿；能砍的只有总量，
  而总量里有 677 秒是「一条负片为了够到自己那条夹具，先把前面几十个无关子进程跑一遍」

## 二、一条 `by: "selfcheck"` 负片到底付多少 —— 我一开始说错了

头一版的说法是「每条负片都要**整跑一遍** selfcheck」。**错的。**
`scripts/check/mutate.ts` 的 `stopIfSeen`：输出里一见齐 `kills` 点名的那几条夹具，
就 `process.kill(-pid)` 把整个进程组停掉。所以一条负片付的是
**跑到它那条夹具为止的前缀**，不是整份。

按这个重新量（给 selfcheck 的每一行输出打上经过秒数，再按每条负片的 `kills` 取出现时刻）：

```
M-P3-f  5.6 · M-D6-n 11.2 · M-P3-b 11.2 · M-D6-m 11.7 · M-D6-o 23.9 · M-P1-l 24.4
M-D6-j 36.5 · M-F9-a 44.7 · M-F9-b 46.0 · M-F9-f 48.1 · M-F9-g 48.1
M-D6-p 48.7 · M-D6-v 48.7 · M-D6-r 50.9 · M-D6-w 51.5 · M-D6-u 53.0 · M-D6-q 56.0 · M-D6-t 56.7
```

**Σ 实付：308.9 s → 676.8 s。**

⚠️ **真正要记住的不是「夹具让 selfcheck 变慢了 9 秒」。**
老的 11 条负片前后几乎一模一样（5.5→5.6、47.7→48.1）—— 新夹具对它们只加了约 4 秒，
因为它们在走到新夹具之前就被停了。那 +368 秒**全部**来自
**7 条新负片各自为了够到自己那条夹具，先付了约 50 秒的无关前缀**。

所以：**一条负片的价钱是「它的夹具在文件里排第几」，不是它测什么。**
`M-D6-t` 付 56.7 秒去够一条自身约 1 秒的夹具。而新夹具默认追加在文件末尾，
新负片于是默认拿到最差的系数 —— **没有任何东西守着这件事。**

同一个形状还有一处：`test.ts` 慢了 0.6 秒，乘 347 条 → +208 秒。
**给任何一个验证者加一秒，都要乘以用它的变异条数。** selfcheck ×18，test.ts ×347。

## 三、调度已经到顶 —— 这一条封掉了所有「靠并行／排序解决」的路

拿上面那 18 个实测值加上 348 条默认变异各 ≈3.2 秒，模拟 4 个 worker 的贪心派工
（`jobsWanted` ＝ `min(cpus, total)`，本机 `availableParallelism()` = 4）：

| | makespan |
|---|---|
| 串行总量 | 1791 s |
| **理想下界（总量 ÷ 4）** | **448 s** |
| 当前清单序 | 460.3 s |
| LPT（长作业优先） | 448.3 s |

**当前派工离理想下界只差 2.7%**（460.3 ÷ 448）。 那 18 条贵的恰好落在清单位次 27–42、259–275 与 357–365，
第一批就派出去了；末尾 40 条里最贵的只有 24.4 秒。

**结论：LPT 那一行 sort 值 12 秒，不值一条 PR。** 并行、排序、派工这一族路全部封掉 ——
**能动的只有总量。**

## 四、为什么不加时长闸 —— 而这正是 bitter lesson 那条分界

用户追加的约束是「分析要 follow bitter lesson 的大原则」。那条原则在这里的分界是：
**让结构吃下这件事，还是把人的知识编进结构里。**

一道「一条改动允许让链慢多少秒／最多加几条自检负片」的闸门属于后者，而且本仓库
已经有四条现成的理由拒它：

- **ADR-75 已经预先判掉这个形状** —— 秒数只在那台机器上成立；而且链里**没有一步与时间有关**：
  把 `NODE_COMPILE_CACHE` 删掉、或把 `jobsWanted` 改成恒返回 1，全部变异、
  全部单测、整条 check **一条都不会红**
- **ADR-85**：核不了的死亡条件比没有更糟。「这条闸什么时候该撤」写不成一条跑得动的命令
- **体量闸门当不了先例**：它的判据是**行数**（数得出来、和机器无关），不是时长；
  而 ADR-64 记着它的 15 次豁免**全部由写代码的同一方自批**
- **它自身的成本是自相矛盾的乘性**：为了管住检查链变慢，先给检查链加一个判定模块、
  它的变异、很可能再加一条 `by: "selfcheck"` 负片 —— 而那正是最贵的那一族

**也不采纳「把夹具往前挪」。** Σ 是一个排序问题：把新夹具挪到前面，老的 11 条就得跟着
付它们的钱。而且顺序是人排的、没有任何东西守着 —— 同 ADR-77 撤掉的那张手写敏感字段表。
它可以在主修落地时顺手做，**不能当成解法**。

## 五、这次的劣化该不该

**分两件事，结论相反。**

**工作量该付。** 那 5 组夹具里 4 组是独立复核逼出来的，每组守着一条
「把实现改坏、整条检查链仍然全绿」的反例，其中两条是 blocking。
而且**不付只有两条路，两条都被仓库明文堵死**：不加夹具 ＝ 拿掉反例换速度
（`process/6-INTEGRATE.md` 逐字：跳过、禁用、隔离一个测试永远不是让检查变绿的办法）；
加夹具不加负片 ＝ `scripts/check/spec-rule.ts` 那道「只由自检认领的判据必须有一条
`by:"selfcheck"` 负片」当场硬失败 —— **那道闸正是这一族负片的生成器**，
11→18 是它的产物，不是谁不自觉。

**乘数不该付。** 一条负片要证的事情只有一件：**它点名的那 1–3 条夹具会红**。
为此它今天跑 43–57 秒，其中绝大部分与它要证的事无关。
多跑的那些**只买到一样东西**：`judgeRun` 的 `notAssertion` 一票否决
（「这条变异有没有顺手把别处弄崩」）。那是真保证 —— 但它的价钱是
**常数级的信息 × 线性增长的前缀**，而且系数由「夹具在文件里排第几」决定。

**所以这次的劣化不是「改动加太多夹具」，是「selfcheck 没有选跑入口」这个结构缺陷
在一次正常改动上露了头。** 处置是压单条负片的成本，不是给改动配额。

## 六、主修：给 `selfcheck` 一个选跑入口 —— 不在本条里

形状：`selfcheck --only=<标签>` ＋ 把夹具变成一等公民（`group(id, needs, fn)`）。
`mutate` 已经在 `kills` 里点了名，把它翻成参数即可（照 `MUTATING` 的先例走 env 或 argv）。
估算：Σ 676.8 s → 约 20–40 s，**降一个数量级**，而且把「新夹具默认拿最差系数」这个
二次增长源整个拿掉。

> ⚠️ **这个估算错了单位，也错了量级 —— 落地之后由 ADR-99 订正。**
> 单位：`676.8 s` 是**串行 Σ**，不是实付；真正付钱的是 4 核。量级：「约 20–40 s」
> 把依赖闭包当成了空集，也没算到有几节自己就很贵。实测（同机同条件、整条链）是
> **603 s → 432 s**，串行 Σ 是 737.4 s → 145.2 s。
> 二次增长源那一句仍然成立。

⚠️ **落地前必须逐条处理四处，其中两处是硬的：**

- **孤儿检查会把「存活」静默改报成「红错了地方」。** `selfcheck.ts` 里
  `failed += orphans.length` **不在** `if (failed)` 的 else 支里，任何跑都会执行；
  子集跑时 `covered`（由 `S()` 填）只装执行到的脚本 → 多出几十条孤儿 →
  一条本该 `survived` 的变异会变成 `elsewhere`，因为孤儿行不带记号、`notAssertion` 为假
- **一票否决的面会缩小。** 只跑点名的那几条，就再也看不见「这条变异顺手把别的夹具弄崩了」——
  那是 ADR-70／#139 两轮评审才补上的东西。处置照 ADR-77 的做法：
  **把缩了的那部分照实说出来**（报告里写明这一跑只覆盖了哪几组），不假装没缩
- `ENTRY_CLAIMS_PATH` 的删与写回：变异那条路安全（`MUTATING=1`），人手跑子集会先删掉
  入口认领、再用残缺的 `criteria` 重写它，而审计读的就是这份文件
- **「每个可执行文件都有出处」那句承诺在子集模式下不成立** —— 必须照 `noShell` 的先例
  显式打一句「本次没验」，不能静默跳过

另：`labelsOf` 不用动 —— 它按语法树扫**源码**，`kills` 点名校验仍由全量源码保证。

**重启条件：#140（`claude/report-honest-states`）合入主干之后 —— 已于 `3299d6f` 满足。**
当时它正压着 `selfcheck.ts` 八十行改动，先做主修就是再叠一次分支，
而本条工作流刚刚为「叠分支」付过一次代价（体量闸门读出 519/350，合并顺序才是真相）。

## 七、本条落地的那一刀：CI 每次 push 跑两遍

`.github/workflows/check.yml` 原本是 `on: push`（全分支）＋ `on: pull_request`，
于是**往 PR 分支推一次，同一个 head 上会起两个完全一样的 `check`**。
这不是推测 —— #140 上实测到过两个并发的 `check` 作业（`106112892980` 与 `106112885958`，
起跑时间差 1 秒，同一个 `head_sha`）。

改成 `push` 只管 `main`，并加 `concurrency` 让被顶替的跑自己取消：

- **PR 分支上的算力当场减半**，而覆盖一点没少 —— `pull_request` 那条跑的是同一条链
- 连推两次时，前一次自动取消（本条工作流里两条 PR 各发生过一次）
- `main` 上**不取消** —— 每个进主干的提交都要自己跑过一遍

⚠️ **代价明写**：既不在 `main`、也没有开 PR 的分支，推上去不再自动跑检查链。
那种分支本来也拿不到评审，`npm run check` 在本地是同一条链。

⚠️ **追记 · #141 评审一条 minor：说这件事的地方有两处，评审只抓到一处。**
`README.md` 与 `AGENTS.md` 都写着「CI 在每次 push 时执行同一条命令」，改完 `check.yml`
两处当场都成了假话。评审点的是 `README.md`，`AGENTS.md` 那份要自己回去数才看得见
（`grep -rn 'check.yml' --include=*.md`）。两处都改了。
**而 `README.md` 那一句的上半句正在解释「抄一份就是一份会漂的副本，而它已经漂过一次」**
—— 句尾跟着的就是刚漂掉的那一份。`docs/SYNC.md` 的同步表里没有「改 CI 触发条件」这一行。
