# ADR-22 身份规范化两侧必须一致；错误信息不许替下一步打包票

- 日期 · 2026-08-28 · PR #5 第五轮自动评审，三条都成立
- 类型：**事实证伪**（一条是 D1 从未被真正实现，两条是我这几轮改动的余角）
- 冲击的需求：**P4**（红线）· **D1** · D4 · 登记表的派生元数据
- 结论：**采纳**，三条都改。新登记一处交点 **D1 × P4**

### 一、键的大小写让 P4 整个失效

`D1` 写着：**创作者的唯一标识是 platform 与 handle 的组合，大小写不敏感。**

实现里，**查询侧**一直在小写化（`key()` 把 handle 转小写），**存储侧**没有。
于是一份手改出 `tiktok:Alice` 的记忆：

| 键 | 修之前 | 修之后 |
|---|---|---|
| `tiktok:alice` | 已联系的人被挡住 | 同左 |
| `tiktok:Alice` | `status: ok`，**已联系的人进名单** | 被挡住（键规范化） |
| `alice` | `status: ok`，**已联系的人进名单** | 拦下：不是 platform:handle 的形式 |

D1 的验收标准写的是「同一 handle 的不同大小写形式在**去重与记忆查询**中被视为
同一人」—— 它一直是假的，而 D1 有测试、测试也一直是绿的：**那条测试测的是
去重那一半，没测记忆查询那一半。**

修法：

- `key()` 平台也小写 —— 两侧的规则逐字一致，不留潜在分歧
- 读盘时规范化所有键；写回去的自然也是规范形式（手改出来的大小写就地纠正）
- 两类键不规范化，直接判读不出来：**形状不对**（少冒号、两边任一为空，
  它永远匹配不到任何人，是个静默黑洞）、**规范化后撞键**（两条记录说法可能相反，
  该信哪条无从判断，而**答不上来时不许猜**）

**新登记交点 D1 × P4**：身份规范化是 P4 的承重结构，规范化错了红线直接失效，
而两条需求各自的测试都看不见这件事。这正是 ADR-17 建那套交点机制要接住的东西 ——
这次它接住了（`tension('D1', 'P4')`）。

### 二、错误信息替下一步打了一张空头支票

ADR-15 在 collect 的中止分支里写了一句「采集结果都在 `{dir}`，**续跑不会重复花费**」。
它成立的前提是采集已经跑完 —— 而这个分支同样会在**采集失败**（网络错误）
或**预算用尽**时到达。那时：

- `stopped` 与 `errorMsg` 记着的采集失败**被这条错误盖掉**，用户根本不知道
- 还有关键词没跑完，续跑**要继续花钱**，而信息说的是不会

「已抓到的不会重抓」被写成了「续跑免费」。修法：把采集侧的失败一并报出来，
并按 `pendingKeywords` 的实际数量说话 —— 没跑完就明说「还有 N 个关键词，
续跑会继续花钱」。

### 三、分类表不进内容指纹

### 教训

**一条需求有测试，不等于它验收标准里的每一半都有测试。**

D1 的验收标准有两半：「去重中视为同一人」和「记忆查询中视为同一人」。
测试覆盖了前一半，审计据此报 `D1 测试✓`，而后一半从来没实现过 ——
**一条需求的覆盖是按编号计量的，而编号底下的连词「与」把两件事捆成了一件。**

所以验收标准里出现「与」「且」「同时」的地方，是覆盖率最容易虚报的地方：
它们在计量上是一条，在事实上是两条。

第二条的形状单独记：**错误信息里的每一句承诺，都要问一遍它在哪些路径上成立。**
「续跑不会重复花费」在写下它的那条路径上是真的，而那个分支还有另外两条进入方式。
错误信息不是散文，它是给人照着做的指令 —— 说错的代价和代码说错一样。
