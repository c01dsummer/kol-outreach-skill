# ADR-52 按五类把全 PR 自查一遍

- 日期 · 2026-08-28 · 用户要求：不要再出现那五类问题
- 类型：**事实证伪**（自查，不是评审提的）
- 冲击的需求：D1 · D4
- 结论：**采纳全部**

### 做法

前十四轮的问题归成五类之后，逐类拿 grep 去扫，**不靠回想**：

| 类 | 怎么扫 |
|---|---|
| 1 状态被压成一个 | 所有 `catch` 里返回/继续某个值的地方；所有 `??` `\|\|` 兜底 |
| 2 校验只做到一层 | 所有 `Array.isArray`、所有 `typeof === 'string'`；再对着「消费侧实际读哪些字段」核一遍 |
| 3 同一句话有 N 份副本 | 重复的字面量、重复的表达式、重复的正则 |
| 4 把保证范围记大了 | 代码注释里所有「保证 / 一定 / 永远 / 不可能」 |
| 5 文档替代码吹牛 | 需求与文档里所有「必须 / 绝不 / 任何情况下 / 一律」 |

### 查出来的

**第 1 类** —— 两处 `catch` 各自断言了单一原因（「新文件」「刚被别人清掉」），
而两处都还有别的原因。前者会把用户设过的权限换成默认值，后者跳过是安全的
那一边、只是注释说窄了。

**第 3 类 + 第 4 类（同一件事的两面）** —— D1 写着「两侧必须逐字一致」，
而那是**两个各自写出来的表达式**；再往外扫，「同一个人」在仓库里有
**五处各写各的、三套规则**：记忆两个都小写、采集只小写用户名、
跨平台识别都不小写。

修法不是把它们改成一样，是**只留一份**：身份键搬进 `types.ts` 的 `creatorKey`。
D1 的措辞也从「逐字一致」改成「**调用同一个规范化函数**」——
从一句要靠人守的话，变成一件结构上做到的事。

`'task.json'` 同样写了三遍，而 `saveTask` 与 `persistListAndStatus` 各自拼它 ——
改一处不改另一处，改名前的比对就会去比**另一个文件，而且比得通过**：
那道并发保护会静默失效。合成一个常量。

**第 4 类** —— 同一个文件里两句注释互相矛盾：一处写「任何真正在写的文件都
**不可能**被误判成孤儿」，另一处（ADR-44）明写着「代价是被长时间挂起的
写入方会被误判」。还有两处说「查询侧生成的键里永远不会有空白 / 别的字符」——
**查询侧其实照单全收**，拦住它的是读写两侧的校验，而根据是平台不允许。
其中一句是**用户可见的报错文本**。

**第 5 类** —— D4 写「下一次写回**必须**清掉临时文件」，而目录列不出来时
代码直接跳过。改成「列得出来时清掉」，并写明为什么跳过是对的
（多一份副本的代价小于丢掉这一轮记录）。

**第 2 类没查出问题**：`shapeProblem` 校验的字段与「消费侧真正据以做判断的
字段」正好对上；`nickname` / `followers` / `linked_to` 只是被携带、不参与任何
判断，不校验它们是对的。

### 顺带：类型检查还了一个没人发现的 bug

把采集那处的键接进有签名的函数之后，`tsc` 当场指出 `p.platform` 可能是
undefined —— 而上一行只挡了 `handle`。原先会静默生成一个 `undefined:名字`
的去重键：那个人此后既去不了重、记忆也查不到他。

### 教训

**手写的模板字符串接受任何东西，函数签名不接受。**

这个 bug 藏了很久，不是因为难，是因为 `` `${a}:${b}` `` 对 `a` 是什么毫无意见。
换成 `creatorKey(c)` 的那一刻，类型检查就替我看见了。

**「合并副本」的收益不只是少改一处** —— 它把一段没有约束的拼接，
换成了一个有约束的调用。
