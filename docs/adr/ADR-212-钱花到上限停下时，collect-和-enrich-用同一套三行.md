# ADR-212 钱花到上限停下时，collect 和 enrich 用同一套三行白话收尾

- 日期：2026-11-16 · 在 P3 红线测试隔离重写（ADR-208）里发现
- 类型：需求补全（给判据补上「说在哪、怎么说」）
- 触发它的事实：ADR-208 第四节 H1 —— P3.d 只说「断点保存成功才以 3 退出并声明已保存」，没说这句话说在哪、怎么说。
  没看过代码的那个会话不肯替判据选措辞，只断了退出码；现行的「断点已保存」四个字只有自检按字面钉着。
  两个入口原先各说各的：collect 说「余额不足以支付下一请求 … —— 断点已保存」再给一行命令，
  enrich 说「… —— enrichment.json 已保存，可提高总预算后续跑」、不给命令；「断点」「enrichment.json」都是内部词。
- 冲击的需求：D13（新增 D13.x）；P3.d 含义不变，它的「声明已保存」现在落到 D13.x 的第二行
- 结论：采纳。需求方 2026-11-15 在几种写法里选了这一种（方案 A）
- 连带改动：`scripts/lib/budget.ts`、`scripts/collect.ts`、`scripts/enrich.ts`、`scripts/lib/exit-codes.ts` 的注释、
  `skill/SKILL.md` 退出码表里 3 那一行、`docs/requirements.json`、自检、`scripts/test.ts`、变异目录

## 一、三行说什么

collect、enrich 因额度不足停下、进度都存好之后，stderr 最后打这三行，两边同一套说法：

```text
⛔ 钱花到上限了（已花 $1.998 / 上限 $2），已停下。
✅ 进度已存好：已找到 7 位达人，下次接着跑不会重复花钱。
👉 想继续：npm run collect -- --resume output/x --budget <新总上限>
```

- 第一行的两个金额取汇总 JSON 里同一份费用（估算占用、总上限）。费用无从确认时不编金额，说出原因。
- 第二行说存了多少：collect 是名单里几位达人；enrich 是查好几个达人账号、共几个要查（enrich 按平台账号查，一个人可能有两个账号，所以不说「位」）。
- 第三行照抄就能续跑，必须带 `--budget` —— 光续跑会立刻再撞一次 3。占位写成 `<新总上限>`，与 Skill 里续跑那段同一个写法，提醒这是总上限、不是再加多少。

拼法只有一份：`budgetStopLines`，两个入口都调它。它不收「没存上」的参数 —— 保存失败那一路以 6 退出、走不到调用点，第二行就只在真存好时出现。

collect 读不出记忆文件那一路（退 7，ADR-193）原先也有一句「本轮余额不足以支付下一请求」，改成「本轮钱也花到上限了，续跑时要用 --budget 给新的总上限」，修复命令不变。

## 二、为什么记在 D13 而不改 P3.d

判据「不改含义、不回收复用」（`process/1-REQUIREMENTS.md`）。给 P3.d 补上措辞会改它的字面，下游按它认领的检查就指向了别的东西。
三行说什么是费用输出的事，与 D13.w（新建任务缺预算时怎么告知默认 $2）同类，所以新开 D13.x，P3.d 原文不动。

## 三、谁守着

- 自检 `cost-resume` 组：两个入口各真跑一次额度用尽，比对 stderr 最后三行与汇总 JSON 里的数（「钱花到上限停下：stderr 末尾三行…」那条断言），认领 D13.x。
- `scripts/test.ts`：拼法单测（已花与上限各取各的数，费用无从确认时不写 `$null`）。
- 变异 `M-D13-aj`…`M-D13-ao`：去掉第二行、已花写成上限、无从确认时照已知拼、collect 命令丢 `--budget`、enrich 把总数说成已查数、collect 把累加器人数当名单人数。逐个手改验过，都红。
- 保存失败那几路原先只查「已保存」「断点已保存」不出现；新说法是「已存好」「接着跑」「花到上限」，这几条反面断言都补上了新字样，不然换了措辞它们就形同虚设。
