# ADR-127 分组选跑规则九条变异由具名断言验证

- 日期：2026-09-29
- 类型：发现更优解
- 起点：PR 226 已合入的 main `31d25aaf56c13c8189f9b56fedf3262ec7042d90`；现有 771 条变异中 699 条选组、72 条全跑。
- 结论：将 M-H42-a…i 的九条分组选跑规则变异指向需求测试的 `h-group` 组及其预定断言；空组名的一条把既有循环断言中的同一输入改成固定名字，其余八条复用现有固定断言。
- 依据：`process/4-VERIFY.md` 的正常基线、具名失败及自己验证自己限制；`docs/ARCHITECTURE.md` 的静态组与依赖合同；`scripts/test.ts` 现有 `h-group` 断言。对应关系在读取目标模块实现体或施变输出之前确定。
- 连带改动：`scripts/test.ts` 一处断言命名、`scripts/check/mutations.json` 九条 `by`/`kills`、本索引；不改 `process/`、产品规格、组声明、依赖、执行顺序或检查步骤。

## 应失败的属性先于路由

| 变异 | 合同要求 | 应失败的固定断言 |
|---|---|---|
| M-H42-a | 选择组必须递归带上前置组 | 点一个，连它的 needs 递归拖进来 |
| M-H42-b | 未知组必须明确拒绝并指出名字 | 点了不存在的组，抛的那句话要点出是哪个名字 |
| M-H42-c | 不带选择参数仍表示完整运行 | 没写 --only → 交回 undefined，调用方据此全跑 |
| M-H42-d | 空选择不冒充无选择 | --only= 空着 → 空数组，不是 undefined |
| M-H42-e | 重名的登记不能放行 | 选跑判定拒绝重复登记 id |
| M-H42-f | 缺失依赖必须点出前后两端 | 选跑判定拒绝缺失依赖并点名两端 |
| M-H42-g | 拼错的命令行选项不得被忽略 | 需求测试拒绝拼错的参数并点名它 |
| M-H42-h | 空组名必须明确拒绝 | 需求测试拒绝空组名并点明非空要求 |
| M-H42-i | 同一组被重复点名必须拒绝 | 需求测试拒绝同一组重复点名 |

M-H42-h 的既有断言用循环中的动态名字，静态清册不能把这个名字归入某组。
将同一个 `--only=` 输入和同一个「诊断包含非空」预期改成一条字面名字断言；
其它坏参数仍留在循环，断言数与语义不减少。固定名字不从施变输出反推。

九条均由需求测试验证，不改指向自身自检；其余检查工具变异维持原路由。
每种实际子集先在正常源码上完整成功一次，才施加变异，并逐条确认该名字失败；
其它断言失败、崩溃、超时或夹具错误均不得代领。完整 `npm test` 仍只认领一次全量审计。

验收要用同一九条、同 Node 和 worker 对照全跑与选跑，分别记录正常基线及变异运行；
只用完整成功样本给中位数、范围与可取得的 CPU，逐次时间之和不冒充 CI job。
完整检查须保留 771 条全部被抓到、独立自检和审计；局部收益不声称十五分钟目标。
