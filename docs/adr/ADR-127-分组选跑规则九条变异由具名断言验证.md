# ADR-127 分组选跑规则九条变异由具名断言验证

- 日期：2026-09-29
- 类型：发现更优解
- 起点：PR 226 已合入的 main `31d25aaf56c13c8189f9b56fedf3262ec7042d90`；现有 771 条变异中 699 条选组、72 条全跑。
- 结论：将 M-H42-a…i 的九条分组选跑规则变异指向需求测试的 `h-group` 组及其预定断言；空组名的一条把既有循环断言中的同一输入改成固定名字，其余八条复用现有固定断言。
- 依据：`process/4-VERIFY.md` 的正常基线、具名失败及自己验证自己限制；`docs/ARCHITECTURE.md` 的静态组与依赖合同；`scripts/test.ts` 现有 `h-group` 断言。对应关系在读取目标模块实现体或施变输出之前确定。
- 连带改动：`scripts/test.ts` 一处断言命名、`scripts/check/mutations.json` 九条 `by`/`kills`、本索引；不改 `process/`、产品规格、组声明、依赖、执行顺序或检查步骤。

> ⚠️ 此处九条的结论后来收窄，见末尾「M-H42-c 预定断言未红」。

## 应失败的属性先于路由

| 变异 | 合同要求 | 应失败的固定断言 |
|---|---|---|
| M-H42-a | 选择组必须递归带上前置组 | 点一个，连它的 needs 递归拖进来 |
| M-H42-b | 未知组必须明确拒绝并指出名字 | 点了不存在的组，抛的那句话要点出是哪个名字 |
| M-H42-c | 不带选择参数仍表示完整运行 | 没写 --only → 交回 undefined，调用方据此全跑 |
| M-H42-d | 空选择不冒充无选择 | --only= 空着 → 空数组，不是 undefined |
| M-H42-e | 重名的登记不能放行 | 选跑判定拒绝重复登记 id |
| M-H42-f | 缺失依赖必须点出前后两端 | 选跑判定拒绝缺失依赖并点名两端 |
| M-H42-g | 拼错的命令行选项不得被忽略 | 需求测试拒绝拼错的参数并点名它 |
| M-H42-h | 空组名必须明确拒绝 | 需求测试拒绝空组名并点明非空要求 |
| M-H42-i | 同一组被重复点名必须拒绝 | 需求测试拒绝同一组重复点名 |

M-H42-h 的既有断言用循环中的动态名字，静态清册不能把这个名字归入某组。
将同一个 `--only=` 输入和同一个「诊断包含非空」预期改成一条字面名字断言；
其它坏参数仍留在循环，断言数与语义不减少。固定名字不从施变输出反推。

九条均由需求测试验证，不改指向自身自检；其余检查工具变异维持原路由。
每种实际子集先在正常源码上完整成功一次，才施加变异，并逐条确认该名字失败；
其它断言失败、崩溃、超时或夹具错误均不得代领。完整 `npm test` 仍只认领一次全量审计。

验收要用同一九条、同 Node 和 worker 对照全跑与选跑，分别记录正常基线及变异运行；
只用完整成功样本给中位数、范围与可取得的 CPU，逐次时间之和不冒充 CI job。
完整检查须保留 771 条全部被抓到、独立自检和审计；局部收益不声称十五分钟目标。

## M-H42-c 预定断言未红

正常源码上的 `h-group` 完整通过 32 条断言后，在隔离 worker 中按上表九个名字逐条施变。
M-H42-a、b、d…i 均被各自具名断言抓到；M-H42-c 却只得到 `elsewhere`，
即预定名字没有失败。未查看其它失败行并回填名字，也不把非零退出算作抓到。
故本次只接入另外八条，M-H42-c 保持原有全量需求测试，不改变它的施变正文。

重审条件：用独立于这次失败输出的上下文，先从「未给选择参数必须完整运行」的公开合同
确定固定断言与自然输入；正常代码通过、施变后那个名字确实失败，且没有夹具或进程故障，
才能另行切换。此处试验的失败不作性能成功样本，也不作为其它八条的具名证据。

## 八条的固定版本对照

当前私有实现提交 `7ef87dd9ce6781cadbf721503196fd0cf35d59a9` 从上述 main 独立开出。
目录仍有 771 条，实际路由为 707 条选组、64 条全跑；八条都只执行 `h-group`，
M-H42-c 是本批保持全跑的一条。`h-group` 无依赖，正常源码完整执行 32 条断言通过。
完整 `npm test` 也通过，仍覆盖 36 条需求。

两侧从同一提交归档，锁文件相同。全跑对照只从 `test.ts` 的字面 GROUPS 清单删掉
`h-group`，把其包裹换成原位 `if (fullRun)`，不删或重排内层任何断言；
因此同八条 `kills` 无法归组，验证者执行全量测试。全跑和选跑两侧的完整 `npm test`
各成功一次；选跑侧的 `h-group` 正常基线再完整成功一次，之后才施变。
这份临时对照不写回仓库，也不改生产版的组声明或执行顺序。

Node 22.23.2、Darwin arm64、worker 1；固定 tsx CLI 启动真实 `mutate.ts --worker`，
stdin 每次送同八个 ID 后 EOF。两侧各预热一次，不计收益。随后按全跑→选跑、
选跑→全跑、全跑→选跑交错三对。六次运行均自然收齐八份 `caught` 结论；
全跑验证者按现有具名满足机制主动停下，选跑验证者非零退出且打完失败汇总，
未以崩溃、超时或其它断言代领。每次施变源码、目录、锁文件与完整测试认领原件的
字节、inode、mtime 都恢复或保持原值。

> ⚠️ 欠条（档：登记）：`M-H42-f` 的 `why` 说「需求测试组声明了不存在的依赖仍放行，选跑可能跳过前置断言」，与 `M-H42-l`、`M-H42-m` 原先那两条是同一类说错（那两条在 ADR-132 末尾改了）。拿掉选跑里缺失依赖那道校验之后，依赖闭包里含那一组的选跑（点了它，或点了直接、间接需要它的组）沿依赖走到不存在的组，当场抛一个读不到属性的类型错误，只是不再说出是哪一组缺了哪个依赖；闭包碰不到它的选跑照常，没有哪条前置断言被跳过；整跑时选跑本来就不校验，需求测试自己的组登记另有一道「依赖尚未执行」的拦截。这是读代码、再把这条变异施加到 `group-rule.ts` 副本上直接调选跑核的（点到那一组时抛「Cannot read properties of undefined」，`test.ts` 记 `M-H42-b` 那段注释说的是同一个机制），没用真入口跑过。需求所有者这次只批了 `M-H42-l`、`M-H42-m` · 重启条件：下一条改 `M-H42-f`、或改 `group-rule.ts` 里选跑校验缺失依赖那一行的 PR

> ⚠️ 上一块那张欠条（`M-H42-f` 的 `why`）已还，需求所有者定为改。上一块按读代码说的是「当场抛类型错误、不再点名两端」；这次用真入口跑过，还多出上一块没写到的一半：碰不到那一组的子集跑，连组表坏了都不说。
>
> - **怎么核的。** 树 `9741cd7`，在副本里把需求测试组表 `h-why` 那一项的 `needs` 写成 `['h-spek']`（`h-spec` 拼错，它登记在 `h-why` 前面）。不施变与施加 `M-H42-f` 各跑四次：`npx tsx scripts/test.ts --only=h-why`、`--only=h-spec`、整跑 `npx tsx scripts/test.ts`，以及以 `a54d12c` 为基线的 `npx tsx scripts/check/mutate.ts`（它施变之前先算一遍路由，选跑那一段要过整张组表）。另跑一次不造毛病的整跑做基线，退出码 0。容器是 root，都套 `setpriv --bounding-set=-dac_override,-dac_read_search`。
> - **不施变时，碰没碰到那一组都拦。** 选跑校验整张组表：`--only=h-why` 与 `--only=h-spec` 都在开跑前抛「组 h-why 缺少依赖组 h-spek」，退出码 1；`mutate` 算路由时抛同一句，报「未施加任何变异」。
> - **施变之后：**
>   - `--only=h-why`（依赖闭包碰到那一组）：抛「Cannot read properties of undefined (reading 'needs')」，退出码 1，看不出缺的是什么。`mutate` 算路由时也只剩这一句。
>   - `--only=h-spec`（碰不到）：照常跑完，「全部通过」，退出码 0。上一块写的「闭包碰不到它的选跑照常」说的就是这一种：没有哪条前置断言被跳过，可组表写错也一声不吭。
>   - 整跑：施变与不施变一样，跑到 `h-why` 时需求测试自己的组登记抛「需求测试组 h-why 的依赖 h-spek 尚未执行」，退出码 1。整跑时选跑本来就不校验。
>   - 自检不受这条变异影响：族划分在入口开跑前先校验（ADR-132 第九节）。把自检组表里 `render` 的依赖拼成 `enrch`、施加 `M-H42-f` 跑 `--only=dup-ids`，停在族划分那一句「组 render 缺少依赖组 enrch」。
> - **`why` 改成什么。** 碰到那一组的选跑报一个看不出原因的类型错误；碰不到它的子集跑照常以退出码零结束，组表写错一声不吭；整跑时需求测试自己的组登记照样点名拦下。`req`、`file`、`find`、`replace`、`by`、`kills` 一字未动，依据同 ADR-132 第九节「改已发编号变异的 `why`」。
