# ADR-94 第一页保证排在达标判断之前：那句「每个维度都有产出」换了形状又回来

- 2026-09-19 · 用户按 `skill/SKILL.md` 真实跑建联任务时发现：Instagram 召回很少，甚至一个人都没有
- 类型：**三件事，分开标**。① 「轮转保证每个维度都有产出」不成立 —— **事实证伪**，需求必须改，不谈 trade-off；
  ② 两个平台各分多少人 —— **产品取舍**，`2-CHANGE.md` 说这一类默认要人拍板；
  ③ 「没查过」在交付物里看不出来 —— **红线判据缺口**（P5 名下没有这一条）
- 触发它的事实：见下面第一节（用假 fetch 按真实产量建模跑 `scripts/collect.ts`，命令在那一节；
  承诺句的位置由第四节那条钉树 grep 给出）
- 冲击的需求：**P5 加一条判据** · **U3 加一条判据** · **D6 退役一条、新增两条** ·
  **另新增一条流程需求**（第三节写它要什么；**编号还没分配** —— 登记表是编号的唯一真相来源，
  而本条一个字都没往它里面加）。登记表的条目为什么不在本条 PR 里，理由与实测在第五节
- 结论：**采纳**，分三件：
  ① 事实证伪那一半**本条就生效**：ADR-06 与另外四处的结果承诺当场撤回成事实（第四节）
  ② **F9（第一页保证）采纳**为要做的事，需求正文在第三节；它的登记表条目与测试跟着各自的实现走
  ③ 产品取舍那一半：用户 2026-09-19 指示把本条开出来，即**采纳「第一页保证」作底线**；
     平台交错调度与平台最低人数**登记不做**，「达标对 IG 偏乐观」取「接受并声明」，
     一次性升级边界**接受** —— 逐条在第六节，每条写了重启条件
- 理由：不是「降标准」，是它的反面 —— 用户拿到的信息**变多**（IG 真的被查了、没查到的会被告知），
  代价是每次任务多发「任务数」次搜索请求，而预算闸门一字不动。
  影响的是**可信**不只是覆盖：今天 IG 一次没查时，报告和「IG 查了没人」长得一模一样，
  运营据此得出「这个品类 IG 没人做」，下次就不投 IG 了 —— 那正是 P5 要防的代价。
  「把 IG 排前面」这种只靠 Agent 自觉的修法单独不够（第六节丁），它把一条保证放回散文，
  而本仓库为同一件事已经栽过一次（ADR-06 → 本条）
- 连带改动：本条 PR 只动措辞 —— `skill/SKILL.md`（两处）· `docs/business-requirements.md` ·
  `scripts/collect.ts`（函数头注释）· `docs/ARCHITECTURE.md`（锚点表 `collect.ts` 那一行）·
  `docs/adr/ADR-06`（末尾追记 ＋ 开头指针）· 本文件与 `docs/adr/README.md` 的索引
- 教训：**「达标即停」这个判断跑在什么之前，决定了它保护什么。** 跑在每次请求之前，它保护的是预算；
  跑在「每个任务都问过一遍」之后，它保护的才是策略。ADR-06 的教训是「凡是写 `if (x >= target)`
  都要问 x 和 target 是不是同一种东西」，本条在它后面补一句：**还要问这个判断跑在什么之前。**
  另一半与 ADR-66 同形：**一句描述保证的话，被一个形状不同的同类 bug 绕过之后，比代码更难发现自己在撒谎** ——
  因为它引用的那次修复是真的

## 一、事实：轮转保证的是「页」，不是「每个词被问过」

`scripts/collect.ts` 的 `run()`：

```
for round in 0..MAX_PAGES:
  for i in state.tasks（task.json 的顺序）:
    if exhausted(i): continue
    if qualified() >= target_count: stopped = 'target'; break   ← 每一次请求之前
    search(task[i], offset)
```

那句达标判断跑在**每一次**搜索请求之前，第一轮也不例外。所以轮转保证的是
「一个词不连翻四页」，**不是「每个词都被问过一遍」**：第一轮里排在前面的任务只要把目标填满，
内层 `break` 之后外层也 `break`，后面的任务一个请求都不发。而 `qualified()` 是一个**跨平台的总数**，
`TaskState` 里没有任何按平台或按维度的配额。

task.json 的顺序由 Agent 写，没有任何文档说它有意义 —— 而本仓库几处**任务清单形状**的样例
（`skill/references/keyword-strategy.md` 的试探结果样例、`scripts/check/selfcheck.ts` 的夹具）
都把 TikTok 排在前、Instagram 排在后。**于是最常见的受害者正是整个 IG。**

⚠️ **不写成「每一个例子」。** `skill/SKILL.md` 那段续跑对话里的「剩余关键词」把
`#travelessentials(IG)` 列在首位 —— 它展示的是剩余进度而不是任务清单，但一样能被抄，
所以这里不用全称（#128 第一轮评审指出，头一版写的是「每一个能抄的例子」，那句为假）。

两个把它放大的结构性事实（都已记在 `skill/references/providers/tikhub.md`，不是新发现）：
TikTok 视频搜索每页 20 条、有 `offset` 与 `has_more`，一个词最多四页；
**IG 的 Reels 搜索没有分页游标**，一个词只有一页（约 12 条，同一作者多条还会合并成一个人），
`offset > 0` 直接返回空。所以即便顺序公平，IG 的上限也只是「每词一页 × IG 词数」，
第二轮起只剩 TikTok 在跑。

## 二、四条把「少」推向「零」的连带成因

都用同一套夹具跑过。**它们各自独立**，第一页保证只修掉第一条与第二条的一半。

1. **达标停下之后 `--resume` 救不回 IG。** 续跑从第 0 轮第 0 个任务重来，那句判断在第一个请求之前
   就成立；`keywordsResumeWillRun` 返回空，于是收尾那句话说「续跑不产生新的请求」，
   而 stdout 的 `pending_keywords` 里明明还列着两个 IG 词。`collect` 只接受 `--budget`，
   **没有抬高 `target_count` 的参数**；手改 task.json 抬高之后，多出来的额度先被排在前面的
   TikTok 词翻第二、三页吃掉，IG 照样轮不到（实测目标 50→100 后续跑，TikTok 60→100，IG 仍 0）。
   而 `SKILL.md` 写着「人不够，再多找点」也走 `--resume` —— 这条路在达标停下时什么都不做
2. **预算续跑循环让 TikTok 越翻越深，IG 永远不再被看。** 页数上限是**每次运行**的轮数，
   计数只在内存里；预算中途用尽时翻满四页的 TikTok 词不会被标 `done`，续跑后从 `offsets`
   接着再翻四页。IG 词在第一页之后就进了 `done`，永远跳过。实测两个 TikTok ＋ 一个 IG、
   预算只够 8 次，用尽后续跑：一个 TikTok 词累计八页，IG 零次新请求。
   这同时违反 `SKILL.md` 写的「单关键词页数上限 4 页」
3. **IG 的人按「粉丝数未知」计入达标，补 profile 之后才被闸门筛掉 —— 那时循环早停了。**
   P1.g 要求入池时未知放行，这没错；但采集期的 `qualified()` 因此对 IG 偏乐观。
   实测 IG 排前面、目标 50、假 profile 让 IG 粉丝数落在下限之下：`stopped=target`，
   累加器里 IG 24 人，交付物里 IG 0 人，总数还低于目标。
   **今天 TikTok 在前的配置走不到这条**（IG 根本没被数进去）；**第一页保证落地之后它会真的发生** ——
   处置在第六节
4. **免费额度下 IG 端点返回 402，一个 402 让整轮以出错退出，而报错不点名平台。**
   `tikhub.md` 记着 IG 端点不吃 free credit；402 不重试直接抛，入口转成 `stopped='error'` 退 1。
   TikTok 在前时，第一轮 TikTok 跑完、第一个 IG 请求就把整轮打断：profile 一个没补、
   关键词一个没标完，而 stderr 只说「余额不足」。`probe` 遇 402 也直接 `break`，
   后面的 IG 词连一行试探结果都没有。**这条与调度无关，第一次用的人最容易撞上**

## 三、要新增的那条需求要什么（编号未分配，下面暂记为 F9）

**「F9」在本条里只是个代号。** 登记表是编号的唯一真相来源（`process/1-REQUIREMENTS.md`），
而本条没往登记表里加任何东西 —— 所以这个号**今天不属于任何人**，由落地它的那条 PR 正式分配，
到时按登记表里的实际下一个空号写。下面把「要什么」定死，编号的事留给那一刻。
⚠️ 跨分支抢号本仓库没有任何机器守着（同 `docs/adr/README.md` 记的那半个缺口），
所以分配的那一刻要去核一遍登记表里 F 那一族到了几号。

> **F9（暂记）** 规模采集的达标判断不得让任务列表里的任何一个关键词×平台连第一页都没抓到；
> 任务在 task.json 里的先后顺序不得改变哪些任务会被查询。
> **本条保证的是「问过」，不保证任何平台的人数。**

判据按「会不会被不同的代码路径独立满足、或者独立弄坏」拆，**五条**：

| | 要什么 | 谁认领得了 |
|---|---|---|
| **F9.a** | 以达标（`stopped=target`）收尾时，任务列表里的每一个关键词×平台都至少发出过一次搜索请求；把同一批任务换任何顺序，这一条都成立 | 入口的接线 → 自检端到端，**要配一条 `by: "selfcheck"` 的负片** |
| **F9.b** | 预算不够给每个任务抓第一页时，按 P3 停下（退 3、存断点），从未查询的任务如实列出，**不得为了抓齐第一页超出预算** | 同上 |
| **F9.c** | 续跑时，没抓过第一页的任务会被查询，即使当前已经达标；已抓过第一页的任务在达标后不再查询。**「续跑会去抓哪些」只此一份判定**，调度与「续跑要不要花钱」那句话共用它 | `lib` 的纯函数 → 单元断言 |
| **F9.d** | 第一页之后的分页仍按达标判断停止 | 同上 |
| **F9.e** | 任务目录里没有分页记录表时，读作「无从确认哪些任务查过」：不发请求，续跑那句话如实说明；**不得读作「都没查过」去发请求，也不得读作「都查过了」** | 入口 → 自检 ＋ 负片 |

F9.c 的后半句是结构要求，同 `needsProfile` 的先例（ADR-25）：补全循环和账单各写一份表达式时，
**先改的那边不会报错**。F9.d 是范围边界，按 ADR-67 它必须可失败 ——
一条把 IG 也翻到第二页、或者达标后继续翻页的实现让它红。
F9.e 是三态在 `task.json` 上的落点：**「没有那个键」和「没有那张表」是两件事。**

### 与红线的交点，以及三条连带的判据

| 交点 | 裁决（红线在场，结论已定，只是写下来） |
|---|---|
| **F9 × P3**（不超预算） | P3 赢。第一页保证在**达标判断**之前生效，不在**预算**之前；预算不够时照旧退 3 存断点，没抓到的按 P5 如实列出 |
| **F9 × P1**（不填默认值） | 不设任何默认的平台配额。用户没说，就只有「每个任务一页」这条机械保证；IG 占多少由 Agent 出了几个 IG 词决定，那是判断层的事。同 `docs/CONVENTIONS.md` 第 7 条对预算的处理 |
| **F9 × D6** | 续跑会去抓的 ＝ 没抓过第一页的任务 ∪（未达标时）其余未完成的任务。**D6.c 据此退役** —— 它断言「达标提前停下时那些词一个都没碰过，续跑一个都不会去抓」，而 F9.c 让这句为假。判据不改含义、不回收复用（ADR-67 第二节连「改窄」都算改含义），所以退役、用下一个字母 |
| **F9 × F1**（只问三个问题） | 不新增必问项 |

三条连带的判据，与 F9 同一批但各自独立：

- **P5.i（红线）**：`meta.json` 与 HTML 报告必须列出任务里**从未发出过搜索请求**的关键词与平台；
  「未查询」「查了 0 命中」「命中 N 人」「无从确认」四态可分，从未查询的平台不得从「平台」那一行
  静默消失；未查询的行不得带出 `0%` 这类看起来像测量值的数（渲染口径同 P1.e）
- **U3.b**：关键词表按**关键词×平台**列出任务里的每一个，包括 0 命中的与从未查询的；
  「找到」按搜索命中数计，另列「入围」，两个数不得合并
- **D6.g / D6.h**：前者接替退役的 D6.c；后者是「单关键词页数上限跨运行有效」（第二节第 2 条）

**为什么 P5.i 落在 P5 而不是 U3**：U3 管「表里有什么」，P5 管「用户会不会据此做出错误决定」。
IG 从报告里消失，运营的结论是「这个品类 IG 没人」，下次预算就不投 —— 代价由用户承担且不可逆。
**为什么不并进 P1.e**：P1.e 说的是交付表里**人**的字段，落在 `rows.ts` 的 `cell` 上；
关键词表落在另一条路径上，会独立坏掉。这正是 ADR-77 末尾那张欠条说的「三条轴之外的压平点没人守」——
关键词表就是第四处，本条给它补一条轴，但登记在 P5 名下（它是「数据边界」，不是「字段取值」）。

## 四、五处结果承诺，本条当场撤回

按 `docs/CONVENTIONS.md` 第 11 条「描述保证的那句话，没有任何检查看着」，**搜关键词不搜整句、搜全仓不只搜文档**：

```bash
git -c core.quotePath=false grep -n \
  -e '整个 IG 一' -e '每个维度都保证有产出' -e '不让第一个关键词吃掉全部配额' -e '再多找点' \
  <要量的那棵树> -- skill docs scripts README.md
```

命中里有五处在说一句不成立的话，本条都改成事实：`skill/SKILL.md` 的 Phase 03 那条与续跑那段、
`docs/business-requirements.md` 的「采集必须轮转」那段、`scripts/collect.ts` 的 `run()` 函数头注释、
以及 ADR-06「理由」里那句（记录只追加，所以在**末尾**追一块、开头留一行指针）。
`docs/ARCHITECTURE.md` 锚点表里 `collect.ts` 那一行**本身成立**（第一个词确实每轮只拿一页），
漏说的是「排在后面的任务可能一次都不被查」—— 那一处是**补充**，不是撤回。

同一条命令还会命中 ADR-08 与自检里的「再多找点」，那两处说的是
「`--resume` 在 render 之后不会把已采集的人清掉」—— 那一半今天仍然成立，不在撤回范围里。

**先撤回、后重申，理由与 ADR-66 同**：撤回是响的（读的人知道这里没有保证），
挂着是静默的（读的人以为有）。落地之后再改成新的保证，而且**措辞只说请求、不说产出** ——
一页可以 0 个不同作者、可以被兜底成商家号、可以补完 profile 全被筛掉。
写「每个维度才真的有产出」又会是一句没人看着的承诺。

没有任何测试或变异守着那几句话：`git grep -e 轮转 -e 各抓一页` 在 `scripts/test.ts`、
`scripts/check/mutations.json`、`scripts/check/selfcheck.ts` 里**一行都不命中**；
变异集里唯一碰那句达标判断的是 `M-D6-e`，它守的是相反的那件事。

## 五、登记表的条目不在本条 PR 里 —— 实测它过不了审计

变更文档原先把「ADR ＋ 登记表 ＋ 撤回措辞」放在同一条 PR 里，理由是「先把编号固定下来」。

### 追记 · 第二轮评审：我修第三条的时候，又犯了第三条
