# ADR-13 缓存命中永远按当前口径重算，不引版本号

> ⚠️ **本条「边界」一节里「盘上的样本本身不会被重写」那一句已被 ADR-14 推翻。**
> 其余部分仍然有效。（追加不删改：原文留着，因为它错在哪本身是有用的信息。）

- 日期 · 2026-08-27 · 修 D8 窗口顺序时由 PR #4 的评审意见发现
- 类型：**事实证伪**（「旧样本可零请求补算」这句承诺，实现只覆盖了其中一种「旧」）
- 冲击的需求：D8 · D10 · F8（受众风险按指标算，指标旧则风险旧）
- 结论：**采纳**

### 触发它的事实

`enrich` 的缓存命中分支只在**活跃字段缺失**时才本地重算 —— 那个条件是当初为 D10
迁移写的（更早的样本没有 activity 字段）。于是一份在 D10 之后、D8 窗口修复之前生成的
`enrichment.json`，`hasActivity` 为真，整段被跳过：旧窗口算出来的中位数、发布间隔、
以及按它们算出来的受众风险全部留在交付物里，运营不额外付费 `--refresh` 就换不掉，
而**交付物上看不出任何区别**。

条件写对了它当时要解的那个问题，错在它把「旧」定义成了「缺那三个字段」。

### 为什么不引版本号

第一反应是给 metrics 盖一个 revision，版本不匹配才重算。驳回，两个理由：

1. **重算不花钱。** 它只读磁盘上已有的样本，零 API 请求。既然没有成本，
   「什么时候该重算」就不是一个需要答案的问题 —— 永远算，缓存里的数永远是
   当前代码对当前样本的输出。
2. **版本号把一次性的问题换成永久的问题。** 有了它，每次改口径都要记得递增；
   忘记递增不报错，而症状与今天这个 bug 一模一样。省下来的是一次纯函数调用，
   换来的是一条只能靠自觉维护的规则。

### 边界

- `locally_recomputed` 的含义随之变准：现在是「手上的数**换过**的账号数」，
  不再是「补过字段的账号数」。比较用键序无关的序列化 —— 磁盘上的键序由写下它的
  那一版代码决定，直接比较字符串会把键序差异误报成改动
- 重算不改 `observed_at`：它属于当初那次采样，不是这次跑的时间
- 判定放在 `lib/assessment.ts` 的 `recomputeCachedMetrics`，不留在入口脚本 ——
  变异测试只跑 `scripts/test.ts`，留在 `enrich.ts` 里的判定没有任何东西守得住。
  M-D10-a 守判定；入口的接线由自检的「旧口径缓存零请求就地纠正」守
- **仍然做不到的**：盘上的样本本身是旧的（提供方多返回、在截断之前写下的那些）
  不会被重写，只是算的时候按窗口截。要让样本也收窄，等于重写历史记录，
  且会丢掉当初真实抓到的东西 —— 不做

### 教训

**零成本的正确性不要加条件。**

一个条件判断的价值，是省下它守着的那份成本。成本是零的时候，条件本身就是纯负债：
它唯一的作用是提供一个出错的地方，而且出错时不报警。
