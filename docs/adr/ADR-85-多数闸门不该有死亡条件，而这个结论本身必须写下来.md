# ADR-85 多数闸门不该有死亡条件，而这个结论本身必须写下来

- 2026-09-18 · ADR-84 立完判据之后，逐道去补
- 类型：**不属于反向输入的五类** —— 它改的是 `process/` 与 `docs/adr/`，不触及需求登记表
- 冲击的需求：无
- 结论：**采纳** —— 三道补条件，四道写明为什么不该有，一道早有

## 起点，以及它没按预想走

ADR-84 的结论是「两个方向都该有机制，往上撤那个没有」，并指死亡条件是补那个缺口的前一半。
本条就是去补。**但逐道量完之后，账和「给八道各写一份」不一样。**

量的是两把现成的尺子，不是新发明的：

- **ADR-76 的斜率**：模型再强一档，它的边际价值涨、跌，还是不动？
  「涨的（验证、工具、规格）留；跌的（编排、步骤协议、路由表）标死亡条件；
  不动的（沙箱、权限、预算上限 —— 约束的是世界不是模型）永远留。」
  **「涨的」那一档的处置就是留，本来就不标死亡条件。**
- **ADR-81 的分类**：闸门会拦路、**有豁免通道**、要人维护；关系钩是两个东西之间的机械关系。

第二把尺子上有一个之前没人查过的硬事实：**八道里只有 `size` 有豁免通道。**

```bash
for k in size spec adr mutate audit selfcheck; do
  printf '%-10s ' "$k-ok:"
  git -c core.quotePath=false grep -c "${k}-ok" -- '*.ts' '*.md' | awk -F: '{s+=$2}END{print (s?s:0)}'
done
```

## 逐道的账

| 闸门 | ADR-81 的类别 | ADR-76 的斜率档 | 豁免通道 | 判决 |
|---|---|---|---|---|
| `size` | 闸门 | 跌的 | 有 | **早有**，ADR-80 |
| `spec` | 关系钩 | 涨的（规格） | 无 | **不该有** |
| `adr` | 关系钩 ＋ 一次性工具 | 不动的 | 无 | **补两条** |
| `typecheck` | 工具 | 涨的（工具） | 无 | **不该有** |
| `test` | 验证 | 涨的（验证） | 无 | **不该有** |
| `mutate` | 验证 ＋ 工具 | 涨的（验证） | 无 | **不该有** |
| `selfcheck` | 一身三半 | 两档 | 无 | **补一条**，另两半各有去向 |
| `audit` | 一身两半 | 两档 | 无 | **补两条**，另两节不该有 |

## 「不该有」这个结论必须写下来

这是本条最要紧的一句。

**一个从没被判过的闸门，和一个判过、结论是「不该有」的闸门，在文件里长得一模一样** ——
都是没有死亡条件。不写下来，下一个人会当成漏了，然后补一份。

而**一份不成立的死亡条件比没有更糟**：它给「已经想过了」发了张假证明。
下一个人读到它，不会再去重新问一遍；而它写的那个条件可能永远不会响，
也可能明天就响 —— 两种都是错的，且都比空白更难发现。

所以下面四道各记一句为什么不写，理由一律回到 ADR-76 那把尺子，不另立判据：

- **`spec`** —— 它是规格本身的机器。模型再强一档，需求写得更多、改得更快，
  `requirements.json` 与 `SPEC.md`、与 `content_hash`、与 `docs/adr/` 之间那几组关系
  只会更需要被机械拉住。而且给它写「退成只报数」等于把 `content_hash` 退回成
  当年那个从没递增过的 `version`，那条路的结局记在 ADR-17。
- **`typecheck`** —— 第三方工具，跑的是验证，两个词都在「涨」那一档里逐字列着。
  真要顺手看一眼，该看的不是它的红史，是**开关面有没有松**：`strict` 被关掉、
  或在 `skipLibCheck` 之外再添放宽项，才是它开始烂的信号。
- **`test`** —— 它就是「验证」。ADR-76 自己写着「模型越强，越会把自己的误解
  原样复制进它写的测试里」，所以一份独立跑的断言集边际价值只涨不跌。
- **`mutate`** —— 本体是验证（给测试做的测试），派工那一半是工具。
  标死亡条件那一档点的是编排、步骤协议、路由表，它一样都不沾。

## 补上的三处

### `adr`

**先解释一处尺子打架的地方。** 上面那张表把它的斜率档标成「不动的」，而 ADR-76 对
那一档的处置是**「永远留」** —— 照字面它不该有死亡条件。这里按 ADR-81 那把尺子写，
理由是**两把尺子量的是两种死法**：

- ADR-76 的斜率量的是**价值跌不跌**。「不动的」那一档（沙箱、权限、预算上限）
  永远留，因为它们约束的是世界，而世界不会停止需要被约束
- ADR-81 的分类量的是**关系还成不成立**。一条关系钩死于**对象没了**，不是死于价值跌了

`adr` 约束的不是世界，是**这个仓库自己的归档办法** —— 而归档办法是可以不存在的。
下面两条说的正是那种死法：不是「它不值了」，是「它守的那个关系没有对象了」。

> **什么条件下退成只报数、不拦**：`docs/adr/` 之外按 `ADR-NN` 引用记录的地方降到 0 时 ——
> 那时撞号与标题变更不再会让别处的引用静默指向另一件决策，这道钩子守的关系就没有对象了。

> **什么条件下整个撤掉**：它查的对手方全部消失时 —— `DECISIONS.md` 不再存在、
> `docs/adr/README.md` 里 `BEGIN:GENERATED` 标记数为 0、且 `docs/adr/` 下形如
> `ADR-<号>-<标题>.md` 的文件数为 0。

**诚实的补充**：这两条都可核，但**都几乎不会响**。写出来不是因为它们会响，
是因为它们是这道检查唯一真正的失效条件 —— 一条「几乎不会响但说得准」的条件，
和一条「听起来会响但核不了」的条件，前者才是死亡条件。

**谁去数**：没有机器在数。两条都可核，命令是

```bash
# 退成只报数那条：docs/adr/ 之外还有没有按号引用
# 用仓库级 pathspec 只排除 docs/adr/,**不要列扩展名** —— 见下面那段
git -c core.quotePath=false grep -ohE 'ADR-[0-9]+' -- . ':(exclude)docs/adr/*' | wc -l

# 整个撤掉那条：三个对手方还在不在
test -f DECISIONS.md && echo 有 || echo 无
grep -c 'BEGIN:GENERATED' docs/adr/README.md
git -c core.quotePath=false ls-files 'docs/adr/ADR-*.md' | wc -l
```

第一条有两处要当心。

**一、只在「等于 0」这个判定上可靠。** 怎么数「引用了几处」有好几种口径
（算不算行内多次出现、算不算 `.json` 里的字段值），不同写法给不同的数 ——
这正是 ADR-82 记的那个「一个复现不出来的数」。**而降没降到 0 不受口径影响**，
所以条件写成「降到 0」，不写成一个当前值。

**二、扫的范围必须是全仓，不能列扩展名。** 这一条的第一版写的是
`-- '*.md' '*.ts' '*.json'`，而这个仓库还跟踪 `.yml`／`.yaml`／`.tpl`／`.example`
这些文件。**判据写的是全称（「`docs/adr/` 之外」），实现却是一张手写白名单** ——
那正是 ADR-77 撤掉纪律 lint 的理由，而这一版是在一份引用着 ADR-77 的记录里犯的。
今天两种口径给的数恰好一样，**但那是运气，不是判据成立**：白名单之外的文件里
一旦出现引用，命令会照样报 0，而 0 正是这条死亡条件成立的意思。

### `selfcheck` 的孤儿检查那一半

这道检查一身三半，三把尺子答案不同，所以不能给整道发一份：

| 哪一半 | 去向 |
|---|---|
| 假 fetch 端到端 | **不该有** —— 验证，涨的一档。硬编一条「产品入口不再需要密钥或网络时」，那是句永远不成立的话 |
| `mutate` 入口的接线 | **早有**，ADR-81 已经写了 |
| 孤儿检查（可执行文件都被执行过） | **补一条**，见下 |

> **什么条件下退成只报数、不拦**：`audit.ts` 第 2 节把 `scripts/check/` 那一侧也纳入之后 ——
> 它今天明确把那一侧排除在外，只对产品入口硬失败；一旦纳入，`selfcheck` 末尾这段就与审计完全重复。

**谁去数**：`grep -n "startsWith('scripts/check/')" scripts/check/audit.ts` ——
这一行还在，条件就没成立。**一条命令，落在仓库内，不需要任何运行史。**

### `audit` 的关系钩那两节

第 1、4 节（红线有没有被证明过、待办报数）落在「涨的」一档，**不写**。撤掉它等于把
「每条红线有没有被证明过」退回自评，而那 30 项待办是有意留着的显式缺口，不是积压。

能写的只有关系钩那两节：

> **第 3 节（判定模块 ↔ 变异）退成只报数**：`scripts/check/` 下的判定模块降到 5 个以下时。
> 这条逐字沿用 ADR-81 给同一条规矩写的那半，本条只是把它记到 `audit` 名下 ——
> 它原先挂在一条讲「关系钩和闸门不是一回事」的记录里，不在闸门的账上。

> **第 2 节（可执行入口 ↔ 自检执行）退成只报数**：`scripts/` 下非 `scripts/check/` 的
> 带 shebang 入口降到 2 个以下时 —— 那时「每个入口都被自检执行过」这条关系
> 剩不下几个对象，一次人读就够。

**谁去数**：`npm run audit` 末尾第三行每跑一次就印一次判定模块的数，以及其中几个有变异守着。
入口数：`grep -rl '^#!' scripts --include=*.ts | grep -vc '^scripts/check/'`。
**两条都落在仓库内。**

## 两份现成的死亡条件，各有一半是装饰 —— 同一个原因

这是量的过程中撞见的，比上面几条更要紧。

ADR-80 给 `size` 写的：

> **什么条件下整个撤掉**：连续 20 次 CI 运行里，`size` 报红或报豁免的次数为 0

ADR-81 给「判定模块必须有变异」写的：

> ……或者连续 20 次完整 `npm run check` 里这条规矩从没报过缺口且没有新模块加入时

**两条的后一半今天都核不了，而且是同一个原因：这个仓库不留逐次运行的结果。**

| 可能留运行史的地方 | 实际 |
|---|---|
| `.check-cache/` | 被 `.gitignore` 排除 —— 它存的是**当前状态**，不是历史 |
| `audit` 自己 | 全文只有 `console.log` / `console.error` / `process.exit`，一个字不写盘 |
| `.github/workflows/check.yml` | 只有一行 `npm run check`，不回写、不传产物 |

GitHub 那边确实留着运行记录，但：**八道串在一句 `npm run check` 里，运行结论只有整条链的红绿**，
要知道是哪一道红的必须逐条拉 job 日志；而且那条路在**仓库之外** ——
`npm run check` 跑在本机，没有网络，它永远够不到。

**「报豁免」那一半倒是取得到**：

```bash
git rev-parse --is-shallow-repository   # 必须先问这一句
git log --all --format=%B | grep -c '^size-ok:'
```

**第一句不能省。** 浅克隆缺历史，而 `git log` 不会说它被截断 —— 它照样给一个
看起来有效的数，只是偏小，然后这个偏小的数会去支撑「次数为 0」那个判断
（`REVIEW.md` 的「四个坑」第二条说的就是它）。
两半一半可核一半不可核，恰好说明问题在哪：**可核的那半落在 git 里，不可核的那半落在运行史里。**

**为什么没人发现**：因为从来没有人真去核过它。ADR-84 说的就是这件事，
这是它的第一个实例 —— 而且实例出在**唯一一份写得最全的死亡条件**上。

> ⚠️ 欠条：**「连续 N 次运行里 X 没发生过」这一族条件，在这个仓库今天全是装饰。**
> 本条新写的三处一律避开了这个形状，全部落在仓库内可核的事实上；但 ADR-80 与 ADR-81
> 那两条既有的没有改（追加不删改），它们仍然半张空头。
> 真正的修法不是重写措辞，是**让检查链把每次的逐道结论留下来** —— 那时这一族条件
> 才第一次可核。
> · 重启条件：**欠条台账那道闸门落地时** —— 那道闸门要读的东西和这件事是同一份。

## 顺带撞见：一张欠条的实质自己成立了，而它的条件在等一件可能永不发生的事

ADR-79 收窄决策记录闸门时留了一张欠条，说 `npm run adr -- --split` 是给还装着整册
`DECISIONS.md` 的在途分支用的迁移工具，「但它今天还有没有用户没核过」。它的重启条件是：

> · 重启条件：**下一条碰 `adr-sync.ts` 的 PR**，顺手核一次还有没有在途分支需要它；
> 没有就连它一起撤。

**这个条件没有响** —— `adr-sync.ts` 最后一次被碰就是 ADR-79 自己那条提交：

```bash
test "$(git rev-parse --is-shallow-repository)" = false || { echo '需要完整历史' >&2; exit 1; }
git log --all -1 --format='%h %ad %s' --date=short -- scripts/check/adr-sync.ts
```

本条也没碰它。**这句话的范围要说清楚**：它成立的范围是**本地分支与远程分支可达的
历史**，不包括还没推上来、或已经关掉没合的 PR。第一版这里写的是 `git log -1`
（不带 `--all`），那只看当前分支 —— 结论侥幸还对，但那条命令支撑不了它。
**「我没查到」和「没有」不是一回事**，而把前者说成后者是这个仓库的头号事故。

**第一行那句守卫也不能省，而且它挡的失败比上面那处更坏。** 上面数豁免时，浅克隆给的是
一个偏小的数；这里**给的是一个完全不同、却看不出破绽的提交**。实测（`--depth 3` 克隆
本仓库，跑同一条命令）：完整克隆答 `3e85d0b`，浅克隆答另一个提交 —— 真的 hash、
真的日期、真的标题，没有任何迹象说它是错的。

这一处我原本推理成「浅克隆只会给空输出或正确答案」，**实验当场推翻了它**。
写死亡条件的人会想去推理命令的行为；这个仓库的办法是**跑一遍**。

**但它让人去核的那件事，今天已经是真的了**：

```bash
for r in $(git for-each-ref --format='%(refname)' refs/heads refs/remotes); do
  git show "$r:DECISIONS.md" 2>/dev/null | grep -cE '^#{1,2} ADR-[0-9]+ '
done
```

扫本地分支与远程分支（这个条件只跟分支有关，标签之类的 ref 不在范围内），
**没有一个还装着整册**。也就是说 `--split` 今天没有用户了。

**这两件事之间没有任何东西连着。** 条件在等一个事件（有人去碰那个文件），
而它要问的那个问题自己先有了答案 —— 而且是一个**用一条命令就能问出来**的答案。
没人去问，是因为没有触发器；触发器不来，是因为那个文件恰好没人需要改。

**这比「条件响了没人知道」更难办。** 响了至少还有个时刻可以被抓住；
这一种从头到尾没有任何时刻。**一条写成「下次有人碰 X」的重启条件，
天生看不见自己的实质已经成立了。**

本条**不还这张欠条** —— 撤 `--split` 是代码改动，本条是文档，串行规矩不许夹带。
记在这里是因为它给下一步添了一件活：欠条台账那道闸门要报的不只是
「你这次踩到了哪几条」，还有**「这几条的实质今天已经成立了，去看一眼」** ——
后者才够得着这一种。

## 一条给下一步的硬约束

欠条台账那道闸门跑在 `npm run check` 里，**没有网络**。所以：

**凡是写成「数 CI 运行」的死亡条件，它一律核不了。**

本条新写的三处全部避开了那个形状。下一个写死亡条件的人照办 ——
不是因为「仓库内可核」更优雅，是因为**只有仓库内可核的条件，机器才数得了**。

## 没做的

- **没有改 ADR-80 与 ADR-81 那两条既有的死亡条件** —— 追加不删改；它们半张空头这件事
  记在上面那张欠条里
- **没有撤 `adr --split`** —— 那是代码改动，另开一条
- **没有给任何死亡条件装机器** —— 那是下一条，也是这条线唯一有代码的一条
- **`typecheck` 没有判定模块可以挂指针** —— 它的配置在 `tsconfig.json`，本条只在这里记一句
