# ADR-93 第三层靠的是人问一句话：那就把那句话写下来

## 起点：一个被问出来的缺口

有人问了一句：**我们搞的这些东西，仓库里有不可跳过的闸门保证吗？**

核完之后的答案是「几乎没有」，而且没有那一半是判过的结论：

| | |
|---|---|
| CI 每次 push 与 PR 跑整条检查链，主干受分支保护 | 这一层跑不掉 |
| 沾边的硬闸门**只有一条** | `⚠️ 欠条` 块里没写重启条件当场红 |
| 那把尺子本身（「替代跑的建、替代读的不建」） | **一道闸门都没有，而且不该有** |

最后一行是 ADR-87 明写的：给「该不该建闸门」建一道闸门，
**会当场违反它自己说的话** —— 而且替代「读」的闸门坏起来是**报绿**，没人会发现。

## 一、真正的缺口不在「没有闸门」，在那句话没写下来

`process/README.md` 第三层的收尾本来就写着：

> **不要假装这一层是被保证的。** 它靠的是每次开工前真的把对应那份文档读进去，
> 以及一个会追问的人 —— 这两样都不是文件能提供的。

**「一个会追问的人」不可执行。** 读者拿到这句话，不知道该问什么。
而这一层被拦住的那几次，拦住它的**都是一句具体的话**，不是这份文档。

所以缺的不是判据，是**那句话本身没被写下来**。

## 二、写下去的是两句话，不是一条规矩

> **我们还在原则上吗？**
> **这一条违反原则吗？**

两句都不指名任何一条纪律，对着第三层表里任何一行都问得出口。

三条性质值得记：

- **问的人不必先看出哪里错了。** 它把「你自己说说看」交回给动手的那一方，
  而上下文全在那一方手里 —— 这正是「读那一侧会随执行者变强」的用法。
- **在代码写出来之前问最便宜。** 写完再问，撤掉的是已经写好的东西。
- **它不建任何闸门。** 所以不会多出一张替谁报绿的表 —— 这一层唯一便宜的干预。

## 三、表里补的那一行，比「该不该建」更早

ADR-87 搬进流程档的是「这道闸门**该不该**建」。两轮下来看清楚了：
**滑的位置比那一步更早。**

> 等你问得出「该不该建」，「**要建一道闸门**」这个框已经套上了。

真正发生的是：一个「这件事怎么核」的问题，被自动读成了「给它建什么闸门」。
那是一次联想，不是一次判断 —— 没有任何判据拦得住一次联想。

所以第三层补了一行，位置排在「该不该建」**前面**。

## 四、动了哪一处

`process/README.md` 第三层：表里加一行，收尾那段后面加一节。**没有动第二层。**

## 五、没做的

- **没有给这一层加任何检查。** 这是第一节那个结论的直接后果，不是省事。
- **两句话的措辞没有验证过。** 它们是从实际拦住过的那两次抄下来的，
  但「换个人问同样两句话，还拦不拦得住」没有证据 —— 这一层本来就不可观测。
  ⚠️ 欠条：**写下来的那两句话，有效性只有两个样本，且都来自同一个提问者。**
  重启条件：下一次有人照着这两句话问、并且记得下来结果时；
  或者下一条要动第三层那一节的改动。
- **没有回头看第三层别的行缺不缺同样的东西。** 本条只给「该不该建闸门」这一族
  补了可以照着问的话，表里其余几行仍然只写了「为什么机器查不了」，
  没写「那靠什么」。
  ⚠️ 欠条：**第三层其余各行没有对应的「那靠什么」。**
  重启条件：下一条要往第三层那张表加行或改行的改动。
