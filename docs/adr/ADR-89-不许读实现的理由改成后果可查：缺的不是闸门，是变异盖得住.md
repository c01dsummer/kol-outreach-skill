# ADR-89 「不许读实现」的理由改成后果可查：缺的不是闸门，是变异盖得住

## 起点：一张到期的欠条

ADR-88 在 `process/README.md` 第三层那张表上挂了一张欠条 —— 那一行的理由
「无法观测它读了什么」已经不完整，但那一条没动流程档。它的重启条件写着
「下一条要动那张表的改动，**或者本条合入之后的第一条改动**」。ADR-88 合入了，
条件成立，这是那一条。

## 一、原来那句话错在哪

它把「机器查不了」归因于**观测不到**。真因不是观测不到，是**证据不在提交树里**。
诚实的三态在 ADR-88 第二节：

| | |
|---|---|
| 人 | 无法观测 |
| 留痕的执行者 | 可观测，但要事后人去翻 |
| 提交树里的检查 | 够不着 —— 记录不在仓库里 |

## 二、但停在三态是不够的，它会把人推向错的一侧

「证据在提交树之外」这个写法留下一个很自然的下一步：**那就想办法把证据弄进提交树。**
本条真的沿着那个念头走了一遍。三条路，全判掉：

| 路 | 判 |
|---|---|
| 把工具调用记录导出进仓库，写检查读它 | 转录不是可审计工件 —— ADR-88 末节刚为同一件事重写过一次结论。而且判据还要「读懂它读的那些文件里有没有实现」，是双重的「读」 |
| 扫规格包、确认里面没有实现 | 「是不是实现」不可算，落地必然是一张手写的表，漏了**报绿**。**而且包若由一条命令从仓库生成，这道闸门是多余的** —— 生成器只放它放的那几样，检查它等于检查生成器有没有发疯 |
| 完整杀伤集，或把 `kills` 推广到全部变异 | 判据本身干净：静态清册交上实测红过的 label，不需要任何手写的表。但 `ADR-70:605` 对推广那一路明写「有一条出路，**本条不承诺**」，`:548` 说测量那一路与「见齐就停」互斥，`:67` 称那是「**一个真取舍，不是可以补的漏**」 |

规模不写在这里（ADR-82）。两条命令 —— 断言那一边用仓库自己的判定模块数，别另起一套正则：

```bash
node -e "const m=require('./scripts/check/mutations.json').mutations;console.log('变异',m.length,'带 kills',m.filter(x=>x.kills).length)"
npx tsx -e "import(process.cwd()+'/scripts/check/mutate-rule.ts').then(async m=>{const{readFileSync}=await import('node:fs');const i=m.labelsOf(readFileSync('scripts/test.ts','utf8'),m.VERIFIERS.test.declares);console.log('夹具',i.size,'调用',[...i.values()].reduce((a,b)=>a+b,0))})"
```

**第三条路值得单说，因为它差一点就成立。** 它不违反 ADR-87 的判据：判据写得成命令，
也只抽取不判断，是 ADR-86 那个形状。杀死它的是另一件事 —— 它产出的表偏宽（变异集本身
不全，大量正常断言也会进去），体量跟它要省的阅读量同一个数量级，**于是没有人会读**。
然后它会以「这件事有人管了」的样子挂在那儿。

**那正是 ADR-87 第四节说的报绿。** 一道闸门的成本不止在建它的时候，
还在它产出的东西有没有人接得住。ADR-86 给欠条台账的辩护是「一份百来条的索引比
2249 行便宜两个量级」—— 那个辩护在这里不成立，而我差点没去算它。

## 三、答案 2026-08-25 就写下来了，是流程档把它丢了

`ADR-04:12` 写着：

> 部分缓解来自变异测试：它是他评而非自评……**但变异集也是同一上下文写的，
> 同源污染没有被消除，只是被削弱了**。

`process/README.md` 那一行**把这两句都丢了**，只留下「无法观测它读了什么」。
于是一条本来有部分机器缓解、而且自带保留的纪律，在流程档里读起来像是毫无办法。
**而正是「毫无办法」这个读法，把人推去建闸门。**

这是 ADR-82 那类漂移的另一种形状：**不是数漂了，是理由漂了。**
一份记录里写着的缓解，在另一份档里成了没办法。数漂了至少还有检查会喊；
理由漂了没有任何东西会喊，而且它比数漂得更远 —— 数说错一个值，理由说错一个方向。

## 四、拦住它的又是一句人问的话

ADR-87 开头记着：那一轮差点建成一张路由表，**拦住它的是有人在代码写出来之前问了一句
「我们在 bitter lesson 的原则吗」**，不是 `process/`。

本条这一轮，拦住的是「违反 bitter lesson 了吗」。**两轮，流程档一次都没拦住。**

两次滑的位置还是同一个：**把一个「怎么核」的问题，自动读成了「建什么闸门」。**
ADR-87 搬进流程档的那一节回答的是「这道闸门**该不该**建」——
比这晚一步。等问到该不该建的时候，「要建一道闸门」这个框已经套上了。

本条不动流程档的那一节：一条 PR 一件事，而且那是跨项目的改动。记成欠条。

## 五、动了哪两处

- `process/README.md` 第三层那张表：换掉「写测试时不许读实现」那一行的理由栏。
  新理由说三件事：证据在提交树之外、**但后果削弱得了**、而且削弱不是消除。
  最后半句不是修辞 —— 没有它，这一行又会变成一句可以拿来收工的话。
- `docs/adr/ADR-88-…`：把那张欠条标成已还。

**全仓只有这一处副本。** `process/4-VERIFY.md:23` 只写那条纪律本身，不写它为什么进第三层，
本条没动它。

## 六、没做的

- **没有建任何东西去数「哪些行为没被变异盖住」。** 第二节第三行判掉的就是它。
  真正的缺口是变异盖不住全部行为，而补缺口的办法是多写变异（规格那一侧），
  不是给缺口装一块仪表盘。
  ⚠️ 欠条：**变异盖不住全部行为，而没有任何东西在数这件事。**
  重启条件：下一条要往 `scripts/check/mutations.json` 加变异的改动 ——
  那一刻顺手看一眼，它盖的是不是一处从来没人盖过的地方。
- **流程档里没有一句话拦「把『怎么核』读成『建什么闸门』」。** 两轮都是人拦的。
  那一步比「该不该建」更早，而 ADR-87 搬下去的只有后者。
  ⚠️ 欠条：**这个滑坡在流程档里没有判据。**
  重启条件：下一条要动 `process/README.md` 第二层或第三层那两节的改动。
- **没有核 `ADR-04:12` 那句「部分缓解」今天还有多强。** 本条把流程档的理由**压在了它身上**，
  而它写于 2026-08-25、当时说的是 14 个变异全被抓到。条数涨了不等于同源污染削弱得更多 ——
  今天的变异集是不是仍然出自同一个上下文，本条没查。
  ⚠️ 欠条：**流程档新引的那句缓解，强度从没被重新核过。**
  重启条件：下一次按 `ADR-04` 的重启条件做隔离重写时，或者下一条要改这一行理由的改动。

## 七、评审收紧的四处措辞

**一、「两条命令」原本只有一条能跑。** 第二条写成了一句 `labelsOf(…)` 表达式，
缺 import 与调用上下文，读者复制过去跑不起来。而 `REVIEW.md:18` 给的两条出路之一
正是**只写命令不写输出** —— 一句跑不起来的表达式不算兑现那条出路，
它和直接把数写进散文一样，读者复核不了。改成两条真的能跑的。

**二、「不约束实现的测试」这个说法有歧义。** 它可以读成「不受实现约束的测试」
（那是好事），而本条要说的是「对实现没形成任何约束」。

**三、改完第二条之后，机制还是写错了一档 —— 这一条最值得记。**
头一版改成了「一条对实现没形成任何约束的测试，只要有变异点着那处行为，
那条变异就会存活」。**那是按单条断言说的，而变异存活是套件级的事。**

评审指出得对：套件里别的测试照样可以把那条变异杀掉。而这不是抠字眼 ——
**它正是 ADR-88 那三条空断言当年没被变异测试抓到的原因。** 在本条的基线 `822adad` 上，
变异测试是全绿的 —— 那棵树不会再动 —— 而那三条空断言就在 `scripts/test.ts` 里放着：
**写空一条断言，在变异报告上是看不见的。** 按单条断言写，这一行等于在承诺一件
这台机器做不到的事。

`ADR-04:12` 原话本来就是准的 —— 它说的是「这些测试不是纯粹的实现镜子」，
**套件级，复数**。是我在搬过来的时候把它收窄成了单条。改回套件级，
并把「单条断言写空了看不出来」这一句明写进那一行：不写，下一个人会拿这台机器
去查它查不了的东西。

**四、上面那一段自己就违反了 ADR-82。** 头一版写的是「今天全仓的变异一条不剩全被抓到」——
**那是锚在流动的现在上**，明天加一条变异它就可能不为真，而且读者没法知道它什么时候失效。
改成钉在本条的基线 `822adad` 上（`REVIEW.md:18` 给的两条出路之一）。

这和 ADR-86 第五节那一笔是同一类：**一份讲某条判据的记录，躲不开被那条判据管到。**
