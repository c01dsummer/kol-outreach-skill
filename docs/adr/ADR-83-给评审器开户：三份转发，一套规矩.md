# ADR-83 给评审器开户：三份转发，一套规矩

- 2026-09-18 · 撤掉四道闸门之后，把转出去的责任真正交出去
- 类型：扩范围（新增文档，无代码改动）
- 冲击的需求：无
- 结论：新增 `REVIEW.md` 作正本，三个评审器各一份**只做转发**的适配器

## 为什么现在做

撤那四道闸门时，有两道的理由是**把责任转给评审**：

- 撤 adr 的 git 机器（ADR-79）：「它守的坏法在 diff 里是一行红字，评审第一眼就看见」
- 撤 arch 覆盖（ADR-78）：「关系问题，一个读得了仓库的上下文顺手就答了」

**而这个仓库对评审零配置** —— `.github/` 下只有一个 `check.yml`，根目录没有任何
给评审器看的东西。两个评审器今天跑的是出厂默认：它们在 #117 上抓到的四条真发现，
靠的是通用直觉，**不是读过 `6-INTEGRATE.md`**。

等于开了支票，收款方还没开户。这一条把户开上。

## 形状：照 `CLAUDE.md` → `AGENTS.md` 那一套

正本一份，适配器三份，**适配器一个字的规则都不装**：

| 文件 | 给谁 | 装什么 |
|---|---|---|
| `REVIEW.md`（根目录） | 正本 | **只有指针**，28 行 |
| `.github/copilot-instructions.md` | Copilot | 一句「先读 `REVIEW.md`」 |
| `.coderabbit.yaml` | CodeRabbit | `reviews.path_instructions` 指向 `REVIEW.md` |
| `AGENTS.md` 路由表加一行 | Claude | `CLAUDE.md` 已经转发到 `AGENTS.md`，落在那儿 |

**Claude 那一份为什么不建新文件**：`CLAUDE.md` 自己写着「永远不要往这里写内容」，
而 `AGENTS.md` 的职责就是路由 —— 加一行「评审别人的改动 → `REVIEW.md`」正好是它该干的事。

**改规矩时三份转发一个字都不用动。** 这是这个形状唯一的好处，也是全部的好处。

## 我核不出来的那件事，说在明处

**这三个文件名，我一个都没能在这个仓库里核实。** 它们来自我对这几个工具约定的记忆，
不是从代码或配置里读出来的 —— 三个文件今天都不存在，没有任何东西可比对。

**验证办法只有一个：下一轮评审的行为变没变。** 具体看两件事：
评审里出不出现「按 `6-INTEGRATE.md` 分档」这类本仓库专有的说法；
以及它会不会照那句要求，在看不见 diff 外的东西时说「我不知道」而不是补全。

**没验之前，不要把这一条当成「评审已经知道规矩了」。**

## 一处真实的风险

`.coderabbit.yaml` 是**配置文件**，不是文档 —— 写歪了的后果不是"没生效"，
可能是 CodeRabbit 整个不跑了，那等于**把评审覆盖删掉**，和这条记录的目的正好相反。

做了两件事压这个风险：只用一组我最有把握的键（`reviews.path_instructions`），
并且用 YAML 解析器核过语法合法。**但"语法合法"不等于"键名对"** —— 还是要看下一轮。

## 死亡条件

> **转发这一层什么时候撤**：某个评审器改成直接读 `AGENTS.md` 或 `REVIEW.md`、
> 不再需要专属文件名时，删掉它那份适配器。

> **`REVIEW.md` 本身什么时候撤**：它超过 30 行、或者里面出现任何一条
> 在 `process/` / `docs/` 里找不到出处的规则时 —— 那说明它已经从转发变成了副本，
> 而副本会漂。**撤掉它比修它便宜。**

**谁去数**：`wc -l REVIEW.md`。没有机器在数，同 ADR-80 那张欠条。

> ⚠️ 欠条：**`REVIEW.md` 里的指针没有任何东西核。** 它点名了 5 份文档、若干小节名
> 与两条 ADR 编号；那几份被重命名、或者小节被删掉，这里就成了悬空引用，而不会红。
> `docs/SYNC.md` 加了一行提醒，那是"靠执行"的一档 —— 而靠执行的规则执行率会趋近于零。
> · 重启条件：**下一次发现 `REVIEW.md` 里有一个指针指空了** —— 那时把它接进
> 「符号／路径存在钩」那道闸门一起查。
