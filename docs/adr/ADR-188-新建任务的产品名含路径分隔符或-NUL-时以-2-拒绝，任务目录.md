## 一、决定

collect --config（含 --budget）新建任务时，读的配置里 product 含 `/`、`\` 或 NUL（U+0000）任一字符，就在建目录、开账、预留与请求之前以 2 拒绝，stderr 写出配置文件路径、product 与按 JSON 写法的原值（D29.a）。

只拦这三种：`/` 在哪个系统上都是路径分隔符；`\` 在 Windows 上是，在 Linux、macOS 上会在 `output/` 底下建出一个名字里带反斜杠的目录，换台机器打开就成了两层；NUL 在哪个系统上都放不进文件名，原先要等到建目录那一步才出错。只由点组成的产品名（`..`、`.`）不拦 —— 时间戳接在它后面，目录名是 `..-<时间戳>`，不是上一级目录（D29.b）。

续跑不按本条判（D29.c）：任务目录由 `--resume` 给出，产品名不再拼进路径；task.json 是以前建出来的，拒绝它只会让那个任务续不上。

Windows 另外不许出现在目录名里的字符（`<>:"|?*`、结尾的点与空格、`CON` 之类的保留名）本条不拦：它们让目录建不出来、collect 以出错收尾，但落不出 `output/`。产品名是 `.` 时目录是 `.-<时间戳>`，在 Linux、macOS 上是隐藏目录，`ls` 不带 `-a` 看不见；它在 `output/` 底下，本条不拦。

本条的检查排在原有的「product 是不是非空白字符串」之后、紧挨着它；配置里没写 `budget_usd` 时，「未提供预算、采用默认 $2」那句在这两道产品名检查之前就打出了，被拒时 stderr 会先有这一句。D13.w 写明 product 等前置检查拒绝时不规定有没有这句，所以没把两道检查挪到预算那一段之前 —— 挪了，续跑那一路坏进度与坏产品名同时出现时先报哪个也跟着变。

## 二、按改需求逐条评定

- 红线：P1–P5 都不涉及。拒绝发生在开账与请求之前，不花钱（P3 不受影响）
- 缩范围还是降标准：收窄的是能接受的产品名。被拒的那几种原先能跑，但跑出来的任务目录不在用户以为的地方，或者建不出来；需求所有者 2026-11-08 06:01Z 在项目线程里说「这啥 这种路径或产品名不太好吧」。拒绝而不是改写，是本条替他选的，合入本条那条 PR 即拍板
- 覆盖还是可信：可信上升 —— 用户读到的「任务目录在 `output/` 底下」从此为真
- 可逆：可逆。被拒的配置原字节不变，改了产品名重跑即可
