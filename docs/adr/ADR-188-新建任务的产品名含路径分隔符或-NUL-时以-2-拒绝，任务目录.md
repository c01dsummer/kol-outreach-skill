# ADR-188 新建任务的产品名含路径分隔符或 NUL 时以 2 拒绝，任务目录落不出 output/

- 日期 · 2026-11-08 · 还 ADR-187 末尾那张既有缺陷的欠条（产品名不拦 `..` 与路径分隔符）；它的重启条件「本条那条 PR 已合入」在 #434 合入（`b3535ee`）时到了
- 类型：既有缺陷。collect --config 只查 product 是不是非空白字符串，新任务的目录由它与时间戳拼成 `output/<product>-<时间戳>`；product 写成 `../x` 时目录建在 `output/` 的上一级，`../../x` 落到工作目录之外。新增需求 D29，按改需求逐条评定，见第二节
- 触发它的事实：对着主干 `b3535ee` 的入口（只加了需求与测试，入口照旧）跑新测试：product 为 `../d29-up`、`../../d29-far`、`d29\back`、`d29/sub` 时，collect --config 与 collect --config --budget 2 每例都以 0 结束、预留 4 次、请求 4 次，任务目录分别建在工作目录里（`output/` 的上一级）、工作目录之外、`output/` 底下一个名字里带反斜杠的目录、`output/d29/` 底下一层；product 里有 NUL 时以 2 结束、零请求、没建目录，但 stderr 只有 Node 的内部异常（`TypeError [ERR_INVALID_ARG_VALUE]`，说的是 `creators.json` 无法检查），没写出配置文件路径与 product。D29.b、D29.c 两条在旧入口上就是绿的（不多拒、续跑不判，原先就如此）
- 冲击的需求：D29（新增）
- 结论：采纳。人批痕迹：需求所有者合入本条那条 PR
- 理由：任务目录建在 `output/` 底下是 `skill/references/output-format.md` 写给用户的目录结构，产品名是用户随手填的一句话，它不该能决定东西写到哪里。拒绝而不是把那几个字符换掉：配置里别的不合规字段都是以 2 退出、说出是哪个字段与原值，用户改一个字就能跑；换字符会让目录名与产品名对不上，而跨任务记忆里记的是产品名原文，用户按产品名找不到那个目录
- 连带改动：DOWNSTREAM（实现那个提交里补上）

## 一、决定

collect --config（含 --budget）新建任务时，读的配置里 product 含 `/`、`\` 或 NUL（U+0000）任一字符，就在建目录、开账、预留与请求之前以 2 拒绝，stderr 写出配置文件路径、product 与按 JSON 写法的原值（D29.a）。

只拦这三种：`/` 在哪个系统上都是路径分隔符；`\` 在 Windows 上是，在 Linux、macOS 上会在 `output/` 底下建出一个名字里带反斜杠的目录，换台机器打开就成了两层；NUL 在哪个系统上都放不进文件名，原先要等到建目录那一步才出错。只由点组成的产品名（`..`、`.`）不拦 —— 时间戳接在它后面，目录名是 `..-<时间戳>`，不是上一级目录（D29.b）。

续跑不按本条判（D29.c）：任务目录由 `--resume` 给出，产品名不再拼进路径；task.json 是以前建出来的，拒绝它只会让那个任务续不上。

Windows 另外不许出现在目录名里的字符（`<>:"|?*`、结尾的点与空格、`CON` 之类的保留名）本条不拦：它们让目录建不出来、collect 以出错收尾，但落不出 `output/`。

## 二、按改需求逐条评定

- 红线：P1–P5 都不涉及。拒绝发生在开账与请求之前，不花钱（P3 不受影响）
- 缩范围还是降标准：收窄的是能接受的产品名。被拒的那几种原先能跑，但跑出来的任务目录不在用户以为的地方，或者建不出来；需求所有者 2026-11-08 06:01Z 在项目线程里说「这啥 这种路径或产品名不太好吧」。拒绝而不是改写，是本条替他选的，合入本条那条 PR 即拍板
- 覆盖还是可信：可信上升 —— 用户读到的「任务目录在 `output/` 底下」从此为真
- 可逆：可逆。被拒的配置原字节不变，改了产品名重跑即可
