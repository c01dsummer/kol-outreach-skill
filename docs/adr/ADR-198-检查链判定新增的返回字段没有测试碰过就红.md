## 一、判什么

PR 上，`scripts/check/` 下非验证者文件里，导出函数的返回值比基线多出来的字段，在验证者文件里一处都没碰到、也没写具名豁免，就红。基线与体量闸门同一个起点（`size-rule.ts` 的 `resolveBaseline`）：PR 上是与主干的共同祖先，HEAD 在主干上时是上一版。主干上只报数、退 0，理由同体量闸门。

1. **字段**：每个导出函数的返回类型逐层展开 —— 数组、元组、联合、交叉、索引签名（`Record`）、`Readonly`／`Partial`／`Pick` 这类映射；类型参数按它的约束；`Promise`、`Map`、`Set` 这类库里的泛型取类型参数 —— 展开到的、声明在 `scripts/check/` 直属非验证者文件里的每一个属性。函数类型的属性本身算一个字段，它的返回值不展开。
2. **字段的名字**按声明位置算：文件、往上每一层有名字的声明（接口、类型别名、函数、属性、变量；数字名照写，计算属性名是字面量就取字面量，别的写成 `[表达式]`；无名元组的成员按位置记 `[0]`、`[1]`；有几个重载签名的函数，各签名带上类型参数与参数原文（空白压成一个空格），`pick(n: 0)`、`pick(n: 1)`、`gen<T extends 0>(n: T)` 分开，只有一个签名的函数不带；名字里带 `.`、`#`、`{`、`}`、`=`、`[`、`]`、`"` 的写成 JSON 字符串，`'a.b'` 记 `"a.b"`，不和 `a` 下面的 `b` 撞成一个名字；判别的 `{kind=…}` 里属性名与值同样处理），类型字面量若带一个取字符串字面量的属性（判别联合的 `kind`），记成 `{kind=…}`；推断出来的对象字面量同理，看那个属性推出来的类型是不是字符串字面量（`kind: 'a' as const`）。新加一个函数先走到旧字段，旧字段的名字不变。名字仍可能撞（判别值相同的联合成员……这类写法列不完），所以基线与现在**按名字数处数**：一个名字现在的处数比基线多（基线上没有算 0 处）就是新增，而且新增的名字要**每一处**都用到才算用到，没用到的每一处要有**它自己的**豁免，别处的豁免不替它挡 —— 撞了名最坏是多报红，不会漏。
3. **用到**：只认测试作者在验证者文件（`scripts/test.ts`、`scripts/check/selfcheck.ts`、`scripts/*-test.ts`、`scripts/independent-blackbox-tests/`）里**写出来的**，解析到这个声明上的：读属性（`.x`、`['x']`；下标按被索引对象的类型找字段（可选链 `?.[…]` 先去掉 `undefined`／`null`），键是常量、字面量联合、数字常量、`unique symbol` 的也认；只写不读的不算：`=` 左边（套括号、`!`、`as`／`<T>` 断言、在解构赋值的数组或对象字面量里、作 `...` 剩余的也算）、`for (… of/in …)` 的循环变量、`delete` 的操作数；`+=`、`++` 这类先读旧值的算读）、解构（含改名；解构赋值 `({ x: v } = r)` 按右边那个值的类型找），或**比对的期望值里写出来的键**：`eq`、`deepStrictEqual`、`deepEqual`、`strictEqual`、`equal` 的实参里的对象字面量，按同一次比对里**另一边**实参的类型找（嵌套对象按键、数组按元素往下找；联合逐个成员找；认数字名、字面量计算属性名，和第 2 条的名字一致）。
4. **不算的**：整个值交给 `eq`、`assert`、`deepStrictEqual`、`JSON.stringify` 或返回 `unknown`／`any` 的调用，不算碰到里面的字段；只为搭场景、过类型检查写的对象字面量（带类型注解的变量、传给别的函数的实参）里的键不算；黑盒测试自己重抄一份类型（`await import(…) as unknown as { … }`）读到的是重抄的那份声明，不算 —— 要算就写豁免。见第五节末「第十七轮前改设计」。
5. **豁免**：字段声明前面独占几行的注释里、或那一行行尾的注释里（行注释、块注释都认）写 `字段不入断言：<理由>`。理由去掉多行注释行首的 `*` 与首尾空白后必须非空，写了标记没写理由的新增字段照样红（用没用到都算）。上一个字段行尾的注释不算下一个字段的；字符串里的标记不算。给只能从子进程输出验到的字段用。

## 三、证不了的

- **碰到不等于断言了**。只拿来搭场景的一次读取也算用到；`eq('x', r.a !== undefined, true)` 算碰到 `a`。这道闸门回答的是「有没有测试碰过它」，不是「它的值有没有被验到」。后者仍靠变异与评审。
- 返回类型是类型参数的（`<T extends R>(v: T): T`）按约束 `R` 找字段。调用处 `T` 换成实参的类型，实参是对象字面量时验证者读到的是实参那份声明而不是 `R` 的，所以只经实参读过的字段也算没碰，**多报红** —— 按约束类型读一下或写豁免就过。
- 整个值交给比对不算碰到，会**多报红**：测试确实把整个值和一份写全了的期望值比对了，期望值写在别处（带类型的变量）时也算没碰。出路是把期望值直接写进比对、读一下，或写豁免。比较函数按名字认，`toEqual`、自写的比较函数、`'x' in r`、`Object.keys(r)` 都不算。
- 新字段在测试**永远不跑**的分支里被读一次，也算用到。
- 期望值按同一次比对里**另一边**的类型找，另一边不一定是实现交回的值：`eq('x', 场景对象 as R, { a: 1 })` 也算碰到 `R.a`。比对函数按名字认，别的对象上碰巧叫 `equal` 的方法也算。
- 看不见的新增：一个函数的返回类型改成仓库里已有的、更大的类型，或新加一个函数返回已有的类型，多出来的字段名字（按声明位置算）基线上都有，不算新增；`Record<某个联合, …>`、`{ [K in 某个联合]: … }` 给联合加一个成员，不算新增；声明成 `unknown`／`any` 的字段里装的新结构看不见。
- 打印出来的文字不是字段。检查链靠 stdout 行与退出码对外说话的那一大半（入口打的行、机器段里拼出来的 JSON 串）不在这道闸门里。
- 看不见的出口：不导出的函数、返回 `any` 的函数、返回值类型声明在 `scripts/check/` 以外（`scripts/lib/`）的、导出类的方法、导出对象上的方法（`export const api = { run() {…} }`）、`namespace` 里的函数、返回函数的函数、回调参数。今天 `scripts/check/` 下没有导出类。
- 判别联合只认字符串字面量的判别属性：`{ ok: true; value } | { ok: false; why }` 两个成员的同名字段合成一个名字；给一个成员加另一个成员已有的名字，按处数多出来照样算新增，而且每一处都要用到，可能**多报红**。推断出来的对象字面量没写 `as const`、判别值被放宽成 `string` 时同样合成一个名字。
- 撞了名的几处分不出哪处是哪处：处数不变、只是换了位置的（判别值相同的两个成员，字段从一个挪到另一个）看不见。
- 重载签名的参数原文进了名字：改参数类型、改参数名，这个签名下的字段都算新增，可能误红 —— 补断言或写豁免。
- 名字按声明位置算：只是挪了位置、改了外层名字的旧字段也算新增，可能误红 —— 补断言或写豁免。
- 现在这一边用的是工作区，基线用的是提交；没提交的改动算进「现在」。

> ⚠️ 欠条：字段断言闸门只问「有没有测试碰过」，不问「值有没有被验到」，也看不见第三节列的那几种出口（打印的行、不导出的、类方法、对象方法、返回 `any` 的）—— 只拿来搭场景的一次读取、永远不跑的分支里的读取、第三节「看不见的新增」那几种，都让一个没被验到的字段过闸 · 档：登记 · 重启条件：下一次发现一个过了这道闸门、值却没有任何断言验到的新字段；或下一条改 `field-use-rule.ts` 里认「用到」那一段（含 `COMPARE`）的改动；或定期清点

## 四、入口（第二片）

`scripts/check/field-use.ts`：照 `resolveBaseline` 定基线；`git archive` 把基线那一版的 `scripts/` 与 `tsconfig.json` 取到临时目录、借仓库的 `node_modules` 建程序，工作区另建一个，交给 `fieldVerdict` 照打。PR 上有没人碰的新字段或空理由的豁免以 1 退出；HEAD 在主干上只报数、退 0；基线算不出来、两边哪一边的 `tsconfig.json` 读不出或有错、现在这一边一个字段都没取到，都说「无从判断」以 1 退出，临时目录在退出之前清掉。接在 `npm run typecheck` 之后：类型检查不过的树上，字段与用到都认不准。

**这道闸门替代的是什么。** 替代的是「读」：这件事原先由每条 PR 的复核逐个字段读出来（触发它的事实那一串）；判据是一条命令（`npm run fields`）。它不替代变异：变异问「每条负片都被抓到」，这道问「每个新字段至少被一处测试碰过」，两边都不问对方那一头（ADR-70 第二节第①条那段原话）。

> **什么条件下退成只报数**：连续 20 条改过 `scripts/check/` 的 PR 里，它红过的每一次都是误红（补的是豁免或一条只为过闸的读取，而不是一条真验值的断言）时。那说明它挡下的不是漏测，是写法。

> **什么条件下整个撤掉**：变异测试改成按断言逐条记账（ADR-70 第二节第②条说的那张具名断言清册落地），能直接答「这个字段有没有一条断言因它变红」时。那时这道闸门问的是更弱的同一件事。

**已知边界，照实记。**
- 入口的验证放在第二片，且**必须有一个真起入口的独立验证者**（需求测试或自检组都行）：在玩具树上造出一个没人碰、没豁免的新字段，起入口，看退出码非零；同时核 `package.json` 的 `check` 里接着 `npm run fields`。只有规则模块的单测与变异证不了这两件 —— 把判红那一支的 `process.exit(1)` 删掉、或把 `npm run fields` 从 `check` 里拿掉，单测一条也不会红。第二片不带这个验证者不开 PR。
- 递归类型（`next?: Chain<T[]>`，或 `type Loop<T> = Loop<T[]>[]`、`type Tup<T> = [Tup<T[]>]` 这种直接递归的数组、元组别名）每展开一层都是新的类型实例，按实例去重拦不住。找字段按这一条停（整体比对、重抄的类型两路第十七轮前已删）：**数层数，不认类型是谁** —— 往下每走一步（属性、数组元素、联合成员、类型实参……）算一层，到 `DEPTH` 层（16）这一层整个不展开；另外一次从头走（一个导出函数的一个签名）总共展开超过 `BUDGET` 步（2000）也停 —— 一个泛型同时往几路递归（`a: N<T[]>; b: N<[T]>`）时每层分叉，层数没到就指数爆，光靠层数停不住。两条都有限，所以必停、也停得快。上限按仓库里实际的返回类型定：2026-11-16 量到最深 7 层；步数上限降到 200 时找到的字段、用到的字段一条不差，2000 留十倍。层数是一步一算，不是「套了几层」：`x?: Y[]` 走过去算三步（联合、数组、元素）。先判层数再记「走过」，在深处被停下的类型从浅处走到照样展开。**停下不悄悄少找**：找字段这一路一停，那个导出函数就记一条名字带 `<没展开完>` 的「字段」，算没用到，照新增字段报红；确认里面没有要验的字段，就在函数前写 `字段不入断言：<理由>` 放行。这一条**不按基线比、每次都判**：停下的地方里面后来加了字段，找不到、处数也不变，基线上那条要是能挡，就又悄悄放过了；所以它一直要有豁免才绿，删了豁免就红。今天 `scripts/check/` 下没有会停下的返回类型；哪天真有返回类型深过 16 层或大过 2000 步，它会以「没展开完」报红，到时再看是加豁免还是调上限。按路径数层数有两处会多报红，都在安全的一边：一圈互相引用的类型从一头走进去，路径长过上限也会停，哪怕每个类型离根都很近（记「没展开完」）；上限那一层正好是数字、字符串这种没有字段的类型，也照样记「没展开完」。
- 基线只取 `scripts/` 与 `tsconfig.json`：判定只读这两处，`tsconfig.json` 的 `include` 若伸到别处，基线那边会少文件、多报新增。
- 耗时还没有量：入口在第二片，第二片开 PR 前在同一棵树上量 CPU 时间与多次的区间再写进来。第一片不接进检查链，不加耗时。

## 五、第一片的欠条清点与独立复核（2026-11-14）

三份独立清点（台账 628 条）与一份独立复核，看的是判定加入口的整份（`df9d78b`）；拆片后入口那一半留给第二片。
