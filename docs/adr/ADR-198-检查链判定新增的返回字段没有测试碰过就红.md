## 一、判什么

PR 上，`scripts/check/` 下非验证者文件里，导出函数的返回值比基线多出来的字段，在验证者文件里一处都没碰到、也没写具名豁免，就红。基线与体量闸门同一个起点（`size-rule.ts` 的 `resolveBaseline`）：PR 上是与主干的共同祖先，HEAD 在主干上时是上一版。主干上只报数、退 0，理由同体量闸门。

1. **字段**：每个导出函数的返回类型逐层展开 —— 数组、元组、联合、交叉、索引签名（`Record`）、`Readonly`／`Partial`／`Pick` 这类映射；`Promise`、`Map`、`Set` 这类库里的泛型取类型参数 —— 展开到的、声明在 `scripts/check/` 直属非验证者文件里的每一个属性。函数类型的属性本身算一个字段，它的返回值不展开。
2. **字段的名字**按声明位置算：文件、往上每一层有名字的声明（接口、类型别名、函数、属性、变量），类型字面量若带一个取字符串字面量的属性（判别联合的 `kind`），记成 `{kind=…}`；推断出来的对象字面量同理，看那个属性推出来的类型是不是字符串字面量（`kind: 'a' as const`）。新加一个函数先走到旧字段，旧字段的名字不变。基线与现在按名字对，现在有、基线上没有的就是新增。
3. **用到**：验证者文件（`scripts/test.ts`、`scripts/check/selfcheck.ts`、`scripts/*-test.ts`、`scripts/independent-blackbox-tests/`）里，有一处读属性（`.x`、`['x']`）、解构（含改名）、按上下文类型写成的期望值对象的键（联合逐个成员找），解析到这个声明上；或把**整个值**交给 `eq`、`assert`、`deepStrictEqual`、`JSON.stringify`，或交给返回 `unknown`／`any` 的调用（`canon` 这类先规整再比的），这个值类型里的属性逐层都算碰到（穿过索引签名；`Map`／`Set`／`Promise` 这类库泛型里面只有 `deepStrictEqual` 进得去 —— 别的几种走 `JSON.stringify`，`Map`、`Set` 在那里成了 `{}`，里面的字段并没有被比）。整体比对算数，是因为加了字段、期望值没跟着改，比对本身就会失败（给 `LaunchTally` 加一个字段时 `canon(launchTally(…))` 那条就是这样红的）。
4. **黑盒兜底**：测试自己重抄一份类型（`await import('./check/mutate-rule.js') as unknown as { … }`）时，读到的声明落在测试文件里，按声明对不上。这时只要读到的那个属性在重抄的那份类型里（从那份类型逐层走得到，含它引用的本文件类型别名与函数返回值），这个验证者又 import 了字段所在的文件（`import` 语句或 `import()`，相对路径折掉 `..`），名字相同就算。本文件里别的同名属性不算 —— 不收窄时，`scripts/test.ts` 自己声明的 752 个属性名盖住了主干上 461 个字段里的 347 个，`ok`、`kind`、`path` 这类名字的新字段永远不红（独立复核实测）。
5. **豁免**：字段声明前面独占几行的注释里、或那一行行尾的注释里（行注释、块注释都认）写 `字段不入断言：<理由>`。理由去掉首尾空白后必须非空，写了标记没写理由的新增字段照样红（用没用到都算）。上一个字段行尾的注释不算下一个字段的；字符串里的标记不算。给只能从子进程输出验到的字段用。

## 二、量过的

- 原型（2026-11-14，主干 `5f68c8b`）配了对照：给体量闸门的 `SizeReport` 加一个没人读的字段，报没人碰；补一条读它的断言，转为用到；给 `LaunchTally` 加字段不报，因为已有的整体比对会让测试直接失败。独立复核在真仓库上重做了一遍：加字段并提交退 1 并点名、补断言退 0、写豁免退 0 打 `⊘`、空理由与纯空白理由退 1。
- 主干 `5f68c8b` 上：454 处声明，按名字合并后 416 个字段，63 个没有测试碰过（`observer-rule.ts` 24、`observer-run.ts` 23，其余散在 7 个文件；清单在项目共享目录 `dig/字段断言检查-可行性/`）。丸子定只管新增，这 63 个不处理、也不豁免。可行性报告里说过 23，那是收窄兜底、展开映射类型之前的数。
- 本条自己就是第一个用例：判定交回的 `Field` 与 `FieldVerdict` 是新字段；初版 `via` 没有断言碰，闸门报红；收窄兜底以后 `file` 也红了（原先是被测试里别处的 `file` 按名字盖住的），都补了断言。
- 变异 `M-H198-a`…`M-H198-an` 40 条（`al`…`an` 是 CodeRabbit 那一轮补的，见第五节末），逐条手工施变（读原字节、替换、跑 `npx tsx scripts/test.ts --only=h-check-rules`、写回）全部抓到。复核找到的 22 处活着的非等价变异，补了测试的写成了变异；剩下的见第三节。

## 三、证不了的

- **碰到不等于断言了**。只拿来搭场景的一次读取也算用到；`eq('x', r.a !== undefined, true)` 算碰到 `a`。这道闸门回答的是「有没有测试碰过它」，不是「它的值有没有被验到」。后者仍靠变异与评审。
- 整体比对的认法偏宽：交给 `eq` 的值里每一层都算碰到，哪怕期望值是从实现那边算出来的。比较函数按名字认，`strictEqual`、`deepEqual`、`toEqual`、返回 `void` 的自写比较函数，`'x' in r`、`Object.keys(r)` 都不算 —— 出路是读一下或写豁免。
- 打印出来的文字不是字段。检查链靠 stdout 行与退出码对外说话的那一大半（入口打的行、机器段里拼出来的 JSON 串）不在这道闸门里。
- 看不见的出口：不导出的函数、返回 `any` 的函数、返回值类型声明在 `scripts/check/` 以外（`scripts/lib/`）的、导出类的方法、导出对象上的方法（`export const api = { run() {…} }`）、`namespace` 里的函数、返回函数的函数、回调参数。今天 `scripts/check/` 下没有导出类。
- 判别联合只认字符串字面量的判别属性：`{ ok: true; value } | { ok: false; why }` 两个成员的同名字段合成一个名字，给一个成员加另一个成员已有的名字不算新增。推断出来的对象字面量没写 `as const`、判别值被放宽成 `string` 时同样合成一个名字。
- 名字按声明位置算：只是挪了位置、改了外层名字的旧字段也算新增，可能误红 —— 补断言或写豁免。
- 现在这一边用的是工作区，基线用的是提交；没提交的改动算进「现在」。

> ⚠️ 欠条：字段断言闸门只问「有没有测试碰过」，不问「值有没有被验到」，也看不见第三节列的那几种出口（打印的行、不导出的、类方法、对象方法、返回 `any` 的）—— 只拿来搭场景的一次读取、整体比对时从实现那边算出的期望值、按名字兜底撞上的同名属性，都让一个没被验到的字段过闸 · 档：登记 · 重启条件：下一次发现一个过了这道闸门、值却没有任何断言验到的新字段；或下一条改 `field-use-rule.ts` 里认「用到」那一段（含 `WHOLE_COMPARE`）的改动；或定期清点

## 四、入口（第二片）

`scripts/check/field-use.ts`：照 `resolveBaseline` 定基线；`git archive` 把基线那一版的 `scripts/` 与 `tsconfig.json` 取到临时目录、借仓库的 `node_modules` 建程序，工作区另建一个，交给 `fieldVerdict` 照打。PR 上有没人碰的新字段或空理由的豁免以 1 退出；HEAD 在主干上只报数、退 0；基线算不出来、两边哪一边的 `tsconfig.json` 读不出或有错、现在这一边一个字段都没取到，都说「无从判断」以 1 退出，临时目录在退出之前清掉。接在 `npm run typecheck` 之后：类型检查不过的树上，字段与用到都认不准。

**这道闸门替代的是什么。** 替代的是「读」：这件事原先由每条 PR 的复核逐个字段读出来（触发它的事实那一串）；判据是一条命令（`npm run fields`）。它不替代变异：变异问「每条负片都被抓到」，这道问「每个新字段至少被一处测试碰过」，两边都不问对方那一头（ADR-70 第 2048 行）。

> **什么条件下退成只报数**：连续 20 条改过 `scripts/check/` 的 PR 里，它红过的每一次都是误红（补的是豁免或一条只为过闸的读取，而不是一条真验值的断言）时。那说明它挡下的不是漏测，是写法。

> **什么条件下整个撤掉**：变异测试改成按断言逐条记账（ADR-70 第 2062 行那张具名断言清册落地），能直接答「这个字段有没有一条断言因它变红」时。那时这道闸门问的是更弱的同一件事。

**已知边界，照实记。**
- 入口自己没有夹具、没有负片：把判红那一支的 `process.exit(1)` 删掉，或把 `npm run fields` 从 `package.json` 的 `check` 里拿掉，没有一处会红。与 `size.ts` 同形：判定在规则模块里，有单测与变异；入口只定基线、取树、说话、设退出码。没加自检组，是因为自检起这个入口要在玩具树上造两次提交与一份 `node_modules`，成本与它守的那几行不相称。
- 基线只取 `scripts/` 与 `tsconfig.json`：判定只读这两处，`tsconfig.json` 的 `include` 若伸到别处，基线那边会少文件、多报新增。
- 一跑约 13–14 秒墙钟，同机另有一跑完整检查在跑（4 核）；不在 CI 上量过，第二片开 PR 前补 CPU 时间与多次区间。
