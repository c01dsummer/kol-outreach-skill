# ADR-02 变异存活时先分清是测试假，还是变异等价

- 2026-08-25 · 首次跑变异测试时
- 类型：**事实证伪**
- 触发它的事实：M-P1-a 和 M-P1-b 同时存活。诊断后发现两者原因完全不同 ——
  - M-P1-a：测试根本没调用 `fillEmail`，只测了底层的 `extractEmail`。**测试是假的。**
  - M-P1-b：变异把 `c.followers !== undefined && c.followers >= 5000` 改成
    `(c.followers ?? 0) >= 5000`。对 `undefined` 两者都是 false，**行为完全一致** ——
    这是个等价变异，杀不掉也不该杀。
- 冲击的需求：P1
- 结论：**采纳**（M-P1-a 修测试；M-P1-b 改写变异）
- 理由：`4-VERIFY.md` 说「变异存活 = 那个测试是假的，必须修测试（不是删变异）」。
  这条在绝大多数情况下对，但**它预设了变异本身是有效的**。
  等价变异是例外：它不改变可观测行为，因此任何正确的测试都杀不掉它。
  把等价变异当成"测试假"去改测试，只会写出一条断言实现细节而非行为的坏测试。
  M-P1-b 改写成「把未知粉丝当作**符合区间**给分」—— 那才是真的 P1 违规，且立刻被抓到。
- 连带改动：`scripts/check/mutations.json` · `scripts/test.ts` ·
  `scripts/lib/score.ts`（提取 `passesFollowerGate` 使闸门可测）
- 教训：**遇到变异存活，先问「这个变异真的改变了行为吗」，再问「测试为什么没抓到」。**
  顺序反了会污染测试集。判别办法：手工推演变异前后在边界输入上的输出，
  完全一致就是等价变异。
