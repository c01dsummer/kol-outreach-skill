# ADR-208 P3 红线测试隔离重写：比默认小的预算现有测试没守住

## 起点

ADR-202 里「P2–P5 几条红线还没做过隔离重写」那条欠条（登记着待还的问题）：一条红线一条 PR，各还一截。P2 那一截是 ADR-206（#487）。本条是 P3 那一截。

P3 的判据三条：P3.c（每次实际 HTTP 尝试发出前按已核单价查预算，超上限不发、账不变，恰好等于上限允许）、
P3.d（collect 或 enrich 因额度不足停下时，断点保存成功才以 3 退出并说已保存）、
P3.e（邮箱工具的调用不进预算账，只能靠自觉，变异集豁免）。需求单里另带八个交点：
D6、D12、D13、D14、D26、D27、D28、F9 各 × P3。

开工前先还了 ADR-206 第五节那张「包缺两样」（本条第一节）：P2 那次隔离会话写不到入口那一层，P3 的判据大半落在 collect、enrich 两个入口上，不先补就会再漏一次。

## 一、先补包：入口脚本的 import，报告 `meta` 的费用字段

1. **入口脚本。** `package.json` 的命令指到 `scripts/` 下一层的 `.ts`（`scripts/check/` 下的检查链与 `scripts/test.ts` 不算）就是入口。
   入口不导出函数，以前签名里没有它们。现在包里给每个入口一份 `02-签名/scripts/<名字>.d.ts`，
   只抄它从两个源目录 import 的那几行原文，看得出入口走哪个函数，看不出怎么走；函数体与别的语句一行不带，
   指到检查链、node 内置、第三方包的 import 不抄（只有 `./`、`../` 开头的才按路径算，`lib/a.js` 这种看着像路径的包名也不抄）。命令里写成 `./scripts/<名字>.ts` 的也算入口。命令指到不存在的入口时拒收、以 2 退出、点出是哪一个。
   - 判定是两个纯函数：`entryScripts`（哪些是入口）、`entrySheet`（入口那一份抄哪几行），都在 `scripts/check/admission-rule.ts`。
     最初抄哪几行写在入口里，三个指名自检的变异被「自己验自己」拦下（入口在自检的验证基础设施闭包里），挪成纯函数后由需求测试 `h-admission` 断言。
   - 变异 `M-H202-bj`…`bu` 十二个：测试脚本也当入口、不排序、别的目录下的 `scripts/` 也当入口、`.ts` 后面连着字也当入口、
     命令不是字符串时照样去匹配、入口那一份抄全部 import、名字以源目录名开头的别的目录也当源目录、入口的全部语句都带进包、
     连 import 上方与行尾的注释一起抄、名字以 `scripts` 结尾的别的目录（`xscripts/`）也当入口所在、带 `./` 的写法不当入口、非相对的 import 也按路径拼（后两个是 #489 上 CodeRabbit 第一轮）。逐个手施，各自点名的那条红。
     后两个是复核试出来的非等价改动（第九节）。
   - 认的形状是有意收窄的：命令里写成 `scripts/<名字>.ts` 或 `./scripts/<名字>.ts`、import 写成 `import … from '<./ 或 ../ 开头的相对路径>'`。
     `$PWD/scripts/a.ts`、`.mts` 与子目录下的入口不认；`export … from`、`import x = require()`、动态 `import()` 不抄。
     今天的 8 个入口没有这些写法；认不出时包里静默少一份，登在第七节那张欠条里。
   - render 原先 import 了 `loadCreators` 却不用（死 import），入口那一份会把它列出来，正是 ADR-206 说隔离会话挑错的那个函数。本条删了这个死 import。它在产品代码里没人用，却是变异 `M-D16-aj` 的替换要用的（往 render 拒收坏任务之前塞一次写记忆）；删了以后那条变异让 render 先因名字未定义崩掉、判成跑不起来，完整检查捞到。改成替换里自己 `await import` 那个函数，手施后点名那条照红。
   - 「命令指到不存在的入口时以 2 拒收」留在入口里、没有变异：今天的需求测试不起这个入口，指名自检的变异又会被「自己验自己」拦下，要负片得另加一组起入口的需求测试，本条不加（ADR-193 里「往入口脚本加只由自检够得到的取舍」那条欠条续挂，见第九节）。
   - `package.json` 读不出或没有 `scripts` 时入口照常出包、末行汇总写「入口 0」，不拒收：玩具树大多没有 `package.json`，真树上它总在。包里少了入口那一份时，末行与清单都看得见。
   - 多行 import 花括号里夹着的注释会原样进包、不在扫描的三种里；清单「没核的」那一行已写明。
   - 接线由自检组 `admission-entry` 证：有两个入口的玩具树出包、只给命令指到的两个入口各出一份、末行汇总单列入口个数、清单说明入口那一份只有 import；
     命令指到不存在的入口时以 2 拒收、不建包目录。
2. **`meta` 的费用字段。** `renderHtml` 的签名注释写明 `meta` 要带报告读的那九个费用字段（各字段的类型同 `budget.ts` 的 `CostView` 里同名那一项），缺 `cost_problems` 会抛。
   P3 的隔离测试一次也没调 `renderHtml`，这一半这次没被用到。
   先试过把 `meta` 的类型收紧成 `CostView & Record<string, any>`，现有测试有几处夹具因此编译不过，退回只写注释。

## 二、怎么做的

1. 在本条第一节那一版（`83abd74`）上跑 `npm run admission -- P3 <仓库外的目录>`，出包 62 个文件
   （清单 1、需求单 1、签名 40、入口 8、对外文档 11、变异说明 1）。入口自带的扫描报零处实现。
2. 一个清空上下文的会话只拿到包的路径，被告知只读这个目录、不碰仓库、不跑 node、不得发真实网络请求，
   写出一份测试文件和一份说明。
3. 事后读它的会话记录（JSONL），取 `type` 为 `tool_use` 的项。一共 35 次：24 次 Read、4 次 Grep、4 次 Bash、2 次 Write、1 次交回。
   Read 的路径、Grep 的 `path`、Bash 里 `cd` 到的目录都在包里（转录里逐条列着），唯一一次不 `cd` 进包的 Bash 是对输出目录里自己写的测试文件 `grep -c`；
   两次 Write 都在输出目录。**没有一次落在包与输出目录之外。** 它在交回里自己说了两次 `cat` 输出过长被工具转存到包外、它没去读转存文件，记录里也没有读那个路径的调用。
4. 测试搬到真代码上跑，再与现有测试比，再量原有变异抓得到差异里的几处（第三、四节）。

### 量的是什么

- **原测试遗漏：一处（H6）。** 作者挑的五处手改没找到，是复核自己试出来的；隔离测试那条「配置没有 budget_usd 而给了 --budget 0.001」管住了它。
- **新测试错误：没找到。** 没有一条在真代码上红；它判的方向与现有测试没有一处相反。
- **需求不清或包没写清：两处（H1、H4），都是隔离那边漏、现有那边管住。** 另有说明里列的几处只是隔离会话没写（第五节）。
- 上面的分母是六处手改，五处是作者挑的，不是穷举；说明里还有隔离会话主动没写的几处（第五节第 3 条），没逐个手改。
- ADR-89 里「隔离重写抓到的差异，原有变异抓得到几处，从没量过」那条欠条要的数：六处手改里两边结果不同的是三处（H1、H4、H6），算差异的只有这三处；
  H2、H3、H5 两边都红，不算差异。三处差异里，原有变异的锚点落在同一处、并且打红隔离测试的有两处 ——
  H1（`M-D14-m`，collect 收尾的保存失败分支）、H6（`M-D13-ag`，取 `--budget` 那一行）；H4（enrich 预算不足的退出码）那一处没有原有变异。
  H1、H6 两处原有变异打得红隔离测试，手改却只有一边红 —— 变异盖到了那一行，没盖到那一种错法。
  （两边都红的三处里，H2、H3 也有原有变异落在同一处：`M-D13-ab`、`ac` 在默认说明那一行，`M-D13-ad`、`ah` 在取默认那一段；H5 没有，`M-D12-c` 改的是 Reels 那一行。
  这一段起初把六处手改都算成差异、数成「六处里四处」，#489 上 CodeRabbit 第一轮指出后改正。）
  这和 ADR-206 量的「八处里原有变异打红五处」是同一个问法，但两次的差异都是作者挑的，数不宜直接比大小。只是两条红线的数，P4、P5 还要量。

## 五、隔离会话说写不出来或拿不准的地方

说明里列了 14 处。第 1、2 条是第四节的 H4、H1；其余按性质归：

   它按叙述拼了出来，在真代码上全对，但这是猜对的（说明第 4、5、6、7 条）。
2. **签名看不出：** `Budget.reserve` 超限时抛什么类型、`startBudget` 对 `state` 的要求、挡请求的注入点（说明第 3、8、9 条）。
3. **它主动没写的交点细节：** D13.d（目标 task.json 已存在时拒绝覆盖，目录名精确到分钟、写出来时灵时不灵）、
   D13.l 429 重试那一路（要等六秒以上）、D13.h render、D13.k、D14.j–l 终态保存失败。现有测试都有（说明第 11、12 条）。
4. **它自己写法上的交代：** 默认 $2 的先后靠预载文件钩住 `process.stderr.write` 看次序（说明第 10 条）；P3.e 那条旁证运行时读 `scripts/` 源码（第 13 条）；
   占用的算法按 D12.f 在测试里自己算（第 14 条）。都不是判据或包的问题。

这些没有一处是判据自相矛盾或两边判反，判据本身不动。
