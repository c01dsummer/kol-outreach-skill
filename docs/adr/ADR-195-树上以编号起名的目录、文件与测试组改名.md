## 二、没改的，与为什么

- **冻结包里按组号起名的 `cases/g1.ts`…`g56.ts`**：改它们要动包里 `suite.ts` 的 import，即改冻结字节，须需求所有者逐字确认，另案问他。
- **需求测试组名开头的需求编号**（如 `d6-pipeline`、`p1-plays`，数十个）：需求所有者选保留，见 ADR-194「例外怎么划」。
- **决策记录文件名 `ADR-编号-标题.md`**：编号是全仓引用的身份，后面跟着标题，属 ADR-194 的例外。
- **`process/1-REQUIREMENTS.md`…`6-INTEGRATE.md`**：数字是阅读顺序，属 ADR-194 的例外。
- **`scripts/check/observer-cert.sh` 的注释**：冻结认证命令（现行字节的 SHA256 记在 ADR-186），一字不改；它写的输出目录 `output/kol21-observer-cert/` 与 `observer-cert.ts`、自检里核的摘要格式名 `kol21-observer-cert/v1` 跟着它，要改须重新认证，另案。
- **冻结包里的夹具数据串**（如 `kol21 fixture: …`、`/kol21/control`）：是测试数据，在冻结字节里。
- **变异编号 `M-<需求>-<序>`、需求编号本身**：是编号体系，不是文件或组的名字。
- **远端分支名**（`claude/KOL-21-…` 等）：不在树上，合入即删。
- **自检临时目录下的夹具子目录名**（如 `d27-mixed`、`d27-same-names`）：只在一跑之内存在的临时目录，不在树上。
