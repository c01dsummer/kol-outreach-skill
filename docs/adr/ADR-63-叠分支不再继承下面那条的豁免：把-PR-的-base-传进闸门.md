# ADR-63 叠分支不再继承下面那条的豁免：把 PR 的 base 传进闸门

- 2026-09-02 · 还 ADR-59 的另一张欠条
- 类型：不属于反向输入的五类 —— 改的是检查链自己
- 冲击的需求：无
- 结论：**采纳**

## 触发它的事实

分支寿命的豁免只认第一父链（合进来的旁支的 `age-ok:` 不算）。但 B 直接从没合的 A 上
开出去时，A 的提交就在 B 的第一父链上，B 于是继承 A 那句豁免，自己一句话没说过。
ADR-59 只做到「看得见」（报告里点名那句理由写在哪个提交上），把「挡得住」记成欠条：
提交图分不出「叠上去」和「这些提交本来就是我写的」，分得出的事实只有「这条 PR 的
base 是谁」，而它只在调用方手里。

在一个临时仓库里复现（这个仓库造不出叠分支这个形状）：A 从主干开出、两个提交的作者时间
都在 2026-08-27（量的那一刻分叉 149.4 小时）、第二个写着 `age-ok: A 在等上游接口定稿`；
B 从 A 的头开出、一个提交、没有任何豁免。

| 跑法 | 结果 |
|---|---|
| `--ref B` | `⊘ B：分叉 149.4 / 48 小时` … `豁免（写在 A 的那个提交上）：A 在等上游接口定稿` … `没给 base，豁免扫的是整条第一父链` —— **继承** |
| `--ref B --base <A 的头>` | `✗ B：分叉 149.4 / 48 小时` … `先合一次` —— **拦下** |
| 对照：从主干开出、自己写了豁免的 B2，`--ref B2 --base <主干>` | `⊘` … `豁免只认 <主干>..头 这一段` —— 普通 PR 一点没变 |

## 改了什么

和 `AGE_PR_HEAD` 同一个形状：让调用方把 base 也传进来，传事实、不传推断。

- 三条跑法各接一个口：`AGE_PR_BASE`（check.yml 在 pull_request 事件下填
  `github.event.pull_request.base.sha`）、`--base`（age.yml 贴 PR 那一步，从 PR 清单的
  `baseRefOid` 或事件里取）、`--prs` 清单里的 `baseRefOid`（`--all`）
- 判定在 `age-rule.ts` 的 `ownSince`：第一父链截到与声明的 base 的分叉点，之前的不扫。
  base 是主干时分叉点不在链上，整条链本来就全是自己的 —— 普通 PR 的行为一点没变
- 给了 base 却找不到 → 拒答，不退化成扫整条：那正是叠分支继承豁免的那条路
- **没有 base 的跑法说清楚自己没收窄**：报告里在豁免下面多一行 ——
  有 base 时「豁免只认 `<base>..头` 这一段（截掉了下面那条分支的 N 条）」，
  没有时「没给 base，豁免扫的是整条第一父链 —— 这句理由可能是下面那条的」

## 仍然按不住的

- **本地 `npm run age` 与 `--all` 里没有 PR 的分支**：没有 base 可拿，照旧扫整条第一父链，
  报告里说，并点名出处 —— 那两条路上还是「看得见、挡不住」
- **下面那条分支在这条开出来之后被整个改写过**：分叉点不在链上，截不了；A 的旧提交还在
  链上，而服务端已经没有能指认它们的东西。出处照样打出来

## 教训

ADR-59 把「挡得住」记成欠条时写的理由是「要动工作流、要动三条路，而这条分支已经该合了」——
对的。欠条的价值在于**它写下了缺的是什么**（base 在调用方手里），于是这一次不必再论证，
只要接线。写不出「缺的是什么」的欠条，不是欠条，是免责声明。
