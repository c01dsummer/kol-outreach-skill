# 海外 KOL 建联助手

把"我卖什么"变成"给谁发信、为什么是他、第一句话说什么"。

## 何时触发

- "帮我找一批 TikTok/IG 博主合作"
- "我要做红人建联"
- "帮我搜一批 skincare 类的达人"
- "influencer outreach / KOL sourcing"
- 用户给了一个商品链接并问怎么推广

## 核心原则

**你的价值在判断，不在采集。**

采集谁都会做，SaaS 工具在筛选导出上做得比你好。你不可替代的是四件事：读懂产品、推导搜索策略、判断内容调性是否匹配、写出有针对性的第一封信。把力气花在这四件事上。

具体到执行：

1. **便宜的步骤先跑，贵的步骤只对幸存者跑** —— 先小样试探再放量，只对入围者做增强
2. **输出理由，不只输出分数** —— 运营看得懂"为什么这人排在前面"才会信任名单
3. **花费全程可见** —— 用户看不到请求在烧钱，你必须主动报告
4. **不确定就说不确定** —— 召回差、平台不匹配、识别不确定，如实讲，不要凑数

## 前置检查

开始前确认 `.env` 里有 `TIKHUB_API_KEY`。没有就告诉用户去 [tikhub.io](https://tikhub.io) 注册，充值 $5 足够跑很多次。

`INFLUENCERS_CLUB_KEY` 是**可选**的。没有就跳过 Phase 05，其余流程照常完整走完 —— 不要因为缺这个 key 就中断。

## 六个阶段

### Phase 01 — 产品理解

目标：用最少的提问拿到足够信息。

**能推的绝不问。** 用户给了商品链接（亚马逊/独立站/店铺页），先抓下来自己读：品类、卖点、价位带、目标人群、竞品。没给链接就问一句"有商品链接吗，有的话我直接看"。

**只问这三个**，因为都无法从链接推导，且都直接影响后续每一步：

| 问题 | 为什么必须问 |
|------|--------------|
| 目标市场 | 决定搜索 `region` 参数和受众降权规则 |
| **本次预算上限（美元）** | 成本闸门，见下方 |
| 要找多少人 | 决定采集深度和停止条件 |

**反模式**：把七个维度做成问卷逐个问。运营会在第三个问题时放弃。三个问题一次性问完，能合并成一句就一句。

详见 `references/product-intake.md`。

### Phase 02 — 关键词策略 + 小样试探 ★

这是整个流程最关键的一步。搜错词，后面每一步都在浪费。

1. 按品类词 / 场景词 / 竞品词 / 人群词四个维度生成候选词
2. 每个维度额外产出 **hashtag 变体** —— IG 侧主要靠 hashtag 发现
3. **每词每平台只抓 1 页**，把真实抓到的人摆给用户看
4. 问一句"这批对吗"，不对就调词重来

试探成本约 20 次请求（不到 3 美分），能避免整轮返工。**不要跳过这一步直接放量。**

若某个平台整体召回都差（例如该品类在 IG 上就是没人做内容），如实告知并建议单平台推进，不要硬凑数量。

详见 `references/keyword-strategy.md`。

### Phase 03 — 规模采集

策略确认后才放量。自动分页、跨关键词全局去重、跨平台同人识别。

- **单关键词页数上限 4 页**（实测值，第 4 页后新增人数明显衰减）
- 目标人数达标即停
- 请求间隔 150ms（限速 10 RPS）

TikTok 走视频搜索（按内容匹配，能过滤商家号），IG 走 hashtag。两个平台的路径和字段都不同，详见 `references/providers/tikhub.md`。

### Phase 04 — 语义筛选 ★

**硬指标按规则算分**：粉丝区间、活跃度、有无邮箱、商务合作信号。这部分是客观的。

**内容相关性靠你判断**：读 bio + 最近若干条视频/帖子文案，回答"这个人适合推这个产品吗"，并给出**理由**。

理由比分数重要。形如：

- ✅ 做 5 分钟早餐内容，出镜频繁，厨房场景多 —— 强相关
- ⚠️ 标榜健身，但最近十条都在带减脂代餐 —— 与本产品品类冲突
- ❌ 账号名含品类词但内容是搬运合集，无真人出镜 —— 疑似机构号

评分细则与分层规则见 `references/semantic-fit.md`。

### Phase 05 — 增强（可选）

**只对 A 级候选做**，不对全量做。500 人全量增强和 50 人精选增强成本差一个数量级，而后者覆盖了几乎全部决策价值。

没配 `INFLUENCERS_CLUB_KEY` 就跳过，直接进 Phase 06。**不要因此中断流程或反复提示用户去注册。**

详见 `references/providers/influencers-club.md`。

### Phase 06 — 交付

- 分层名单 CSV（UTF-8 BOM，Excel/Numbers 直接打开中文不乱码）
- **每个 A 级候选一封英文开发信草稿**，基于 Phase 04 实际读到的内容
- 可读的 HTML 报告
- 成本与召回统计

开发信只写英语，见 `references/outreach-draft.md`。输出格式见 `references/output-format.md`。

## 成本闸门

用户在 Phase 01 设定预算上限。**不预置默认数字** —— 不同人的预算和任务规模差异太大。用户不给就按 $2 走，并明确告知这是假设值。

估算方式：**累计请求数 × $0.001**。这是**上限**，日请求量大时有阶梯折扣，实际只会更低。报告时说明这一点，别让用户以为花超了。

| 时机 | 行为 |
|------|------|
| 每个 Phase 结束 | 报告累计花费与占预算比例 |
| 达 50% | 提醒一次，说明当前进度与预计总消耗 |
| 达 80% | 再次提醒，给出「继续 / 缩小目标人数 / 就此收尾」三个选项 |
| 达 100% | **停止采集**，用已有数据走完后续 Phase，如实说明名单未达目标数量及原因 |

提醒要简短，一两句话说清"花了多少、还剩多少、够不够跑完"，不要打断工作节奏。

## 跨任务记忆

每次任务结束后写入 `memory/creators.json`。开始新任务时先读，**已推荐过的人默认不再进新名单**。

详见 `references/memory.md`。

## 不做什么

| 不做 | 原因 |
|------|------|
| **实际发送邮件** | 送达率、SPF/DKIM、退信处理是另一个量级的复杂度，且必须用用户自己的邮箱服务。产出草稿，发信交给用户现有工具 |
| 多语言开发信 | 首版仅英语 |
| 主动索要效果回填 | 用户回填成功率太低。`contacted` 由用户手动标记 |
| 中国大陆平台 | 本 Skill 定位出海 |
