# 海外 KOL 建联助手

把"我卖什么"变成"给谁发信、为什么是他、第一句话说什么"。

## 何时触发

- "帮我找一批 TikTok/IG 博主合作"
- "我要做红人建联"
- "帮我搜一批 skincare 类的达人"
- "influencer outreach / KOL sourcing"
- 用户给了一个商品链接并问怎么推广

## 核心原则

**你的价值在判断，不在采集。**

采集谁都会做，SaaS 工具在筛选导出上做得比你好。你不可替代的是四件事：读懂产品、推导搜索策略、判断内容调性是否匹配、写出有针对性的第一封信。把力气花在这四件事上。

具体到执行：

1. **便宜的步骤先跑，额外请求只对幸存者跑** —— 先小样试探再放量；主页公开指标只对语义判断为 ✅/⚠️ 的候选执行
2. **输出理由，不只输出分数** —— 运营看得懂"为什么这人排在前面"才会信任名单
3. **花费全程可见** —— 用户看不到请求在烧钱，你必须主动报告
4. **不确定就说不确定** —— 召回差、平台不匹配、识别不确定，如实讲，不要凑数

## 前置检查

开始前确认 `.env` 里有 `TIKHUB_API_KEY`。没有就告诉用户去 [tikhub.io](https://tikhub.io) 注册，充值 $5 足够跑很多次。

当前仓库不接入外部增强供应商，也不读取任何第二方 key。不要声称邮箱已经验证或受众画像已经补全。主页公开指标仍使用 `TIKHUB_API_KEY`；用户不需要这批指标时可以跳过，主流程照常完成。

## 六个阶段

### Phase 01 — 产品理解

目标：用最少的提问拿到足够信息。

**能推的绝不问。** 用户给了商品链接（亚马逊/独立站/店铺页），先抓下来自己读：品类、卖点、价位带、目标人群、竞品。没给链接就问一句"有商品链接吗，有的话我直接看"。

**只问这三个**，因为都无法从链接推导，且都直接影响后续每一步：

| 问题 | 为什么必须问 |
|------|--------------|
| 目标市场 | 决定搜索 `region` 参数和受众降权规则 |
| **本次预算上限（美元）** | 成本闸门，见下方 |
| 要找多少人 | 决定采集深度和停止条件 |

**反模式**：把七个维度做成问卷逐个问。运营会在第三个问题时放弃。三个问题一次性问完，能合并成一句就一句。

详见 `references/product-intake.md`。

### Phase 02 — 关键词策略 + 小样试探 ★

这是整个流程最关键的一步。搜错词，后面每一步都在浪费。

1. 按品类词 / 场景词 / 竞品词 / 人群词四个维度生成候选词
2. **两个平台分别出词** —— IG 的 Reels 搜索对词组敏感，词要更短（实测 `smoothie recipe` 返回 0 条，`smoothie` 返回 12 条）
3. **每词每平台只抓 1 页**，把真实抓到的人摆给用户看
4. 问一句"这批对吗"，不对就调词重来

试探成本约 20 次请求（不到 3 美分），能避免整轮返工。**不要跳过这一步直接放量（F3）。**

若某个平台整体召回都差（例如该品类在 IG 上就是没人做内容），如实告知并建议单平台推进，不要硬凑数量。

详见 `references/keyword-strategy.md`。

### Phase 03 — 规模采集

策略确认后才放量。自动分页、跨关键词全局去重、跨平台同人识别。

- **轮转采集**：先给每个关键词各抓一页，再回头抓第二页。**不能顺序跑完一个词再跑下一个** —— 实测竞品词一个词就够 50 人，一个词就能把整轮配额翻完
- ✅ **任务列表里每个关键词×平台都至少被问过一次。** 达标之后**不是一律停** —— 还没抓过第一页的任务照抓不误，第一页之后才按达标停（F9）。所以**达标收尾时**（`stopped` 为 `target`）**task.json 的顺序不再决定谁被砍掉**，IG 写在前面还是后面都一样。⚠️ **预算先用尽时（`stopped` 为 `budget`）顺序照样决定谁被砍掉** —— 实测同一批任务、同样预算，IG 排最后时 IG 一次都没被问过，IG 排最前时被砍的换成 TikTok。所以**预算可能不够时，把最在意的平台排在前面**。⚠️ **它保证的是「问过」，不保证问到多少人** —— 一个 IG 词只有一页（约 12 条），补完 profile 还可能被粉丝闸门全筛掉。**要 IG 多就多出几个 IG 关键词**，脚本不设任何默认的平台配额。⚠️ **预算比这条保证优先**：不够抓齐第一页时照旧存断点、退出码 3（stdout 的 `stopped` 为 `budget`），没问到的那些仍在 `pending_keywords` 里，不会为了凑齐第一页超支。达标停下（`stopped` 为 `target`）时仍要把 `pending_keywords` 告诉用户 —— ⚠️ 它列的是**没跑完**的词，**不是没跑过的**：搜过一页、还没到页数上限的词也在里面，而 stdout 今天仍然分不出这两者 —— **P5.i 补的是 `meta.json` 与 HTML 报告那一半，没碰 stdout**（ADR-94 第十六节丁）。所以转述时说「这些词还没跑完」，**别说「这些方向没查过」**。**续跑会不会再发关键词搜索，照 stderr 那句话转述，别自己推** —— 脚本每次都按当时的数重算了才打那句话（详见下面「续跑」那一段）
- **单关键词页数上限 4 页，跨运行累计**（D6.h）—— 达上限的词记进 `done`，追加预算续跑也不会再翻它。⚠️ 在这条之前，这句话**只在一次运行内成立**：被预算卡停、或出错中止的那一跑不留页数记录，续跑于是又给一份满配额（实测跨四次续跑累计 12 页）。⚠️ **上一版留下的目录**（本条之前建的）里没有页数记录，那种目录里已经抓过页的词**此后一页都不再翻**，只补还欠着的第一页（D6.m）—— 要接着往下翻就新建一个任务目录
- 目标人数达标即停（数的是**能进名单的人**，不是采集总数）—— **但还没抓过第一页的任务不在「停」的范围里**，见上一条
- 请求间隔 150ms（限速 10 RPS）

TikTok 走视频搜索，**IG 走 Reels 搜索** —— 两者都是按内容匹配、能过滤商家号。IG 的 Reels 搜索没有分页游标，一个关键词只有一页（约 12 条）。字段命名两边不一致，详见 `references/providers/tikhub.md`。

### Phase 04 — 语义筛选 ★

**硬指标按规则算分**：粉丝区间、内容积累、有无邮箱、商务合作信号。这部分是客观的。

**内容相关性靠你判断**：读 bio + 最近若干条视频/帖子文案，回答"这个人适合推这个产品吗"，并给出**理由**。

理由比分数重要。形如：

- ✅ 做 5 分钟早餐内容，出镜频繁，厨房场景多 —— 强相关
- ⚠️ 标榜健身，但最近十条都在带减脂代餐 —— 与本产品品类冲突
- ❌ 账号名含品类词但内容是搬运合集，无真人出镜 —— 疑似机构号

评分细则与分层规则见 `references/semantic-fit.md`。

### Phase 05 — 公开指标评估（可选）

语义筛选完成后，对 `fit=✅/⚠️` 的候选抓取主页最近作品：

```bash
npm run enrich -- --dir output/{task}
```

分平台计算粉丝互动率、播放互动率、中位播放量、播粉比、触达稳定度、发帖间隔与
最后发布距采样时间。活跃标签为 `active`（≤45 天）、`cooling`（46–90 天）、
`dormant`（>90 天），只做提示，不改变 score 或分层。
`high` 受众质量风险只降一级进入人工复核，永不自动排除。

**这不是假粉率，也不是带货预测。** 公开信号只能发现相对同行的异常；实际带货需要订单、
点击和转化数据，本 Skill 不做归因。没有运行本步骤时保持“未查询”，不要补默认值。

合作报价只有用户提供 creator quote 或公开 rate card 时才记录；不根据粉丝数自动估价。
详见 `references/public-metrics.md`。第三方供应商的准入条件见
`references/providers/external-enrichment.md`，当前没有任何一家接入。

### Phase 06 — 交付

- 分层名单 CSV（UTF-8 BOM，Excel/Numbers 直接打开中文不乱码）
- **每个 A 级候选一封英文开发信草稿**，基于 Phase 04 实际读到的内容
- 可读的 HTML 报告
- 分平台公开指标、风险依据与数据边界（运行 Phase 05 时）
- 成本与召回统计

开发信只写英语，见 `references/outreach-draft.md`。输出格式见 `references/output-format.md`。

## 成本闸门

用户在 Phase 01 设定预算上限。**不预置默认数字** —— 不同人的预算和任务规模差异太大。用户不给就按 $2 走，并明确告知这是假设值。

估算方式：**累计请求数 × $0.001**。这是**上限**，日请求量大时有阶梯折扣，实际只会更低。报告时说明这一点，别让用户以为花超了。

| 时机 | 行为 |
|------|------|
| 每个 Phase 结束 | 报告累计花费与占预算比例 |
| 达 50% | 提醒一次，说明当前进度与预计总消耗 |
| 达 80% | 再次提醒，给出「继续 / 缩小目标人数 / 就此收尾」三个选项 |
| 达 100% | **暂停采集并保存断点**，报告现状，给用户三个选择：追加预算续跑 / 用已有数据收尾 / 缩小目标人数 |

提醒要简短，一两句话说清"花了多少、还剩多少、够不够跑完"，不要打断工作节奏。

### 超限后的续跑

达到 100% 时**不要直接收尾**。采集状态已保存在 `output/{task}/task.json`，报告现状后问用户：

```
预算 $2.00 已用完，当前进度：

  已完成 3/6 个关键词，收集到 94 人（目标 150）
  剩余关键词：#travelessentials(IG), iphone accessories, portable charger review

  1. 追加预算继续 —— 估计还需 $0.6 左右跑完
  2. 就用现在这 94 人收尾
  3. 缩小目标到 100 人，再跑一个关键词就够

怎么办？
```

用户选择追加后，用 `--resume` 续跑 —— **不要重新 `--config`**，那会新建一个任务目录，
已经付过费的那些请求要再花一遍：

```bash
npm run collect -- --resume output/{task} --budget <新额度>
```

脚本从断点继续，不重复已完成的关键词，也不重复计费已花掉的部分。
`collect.ts` 以退出码 3 结束就表示「预算用尽，可续跑」。

`--budget` 不是数（比如手误打成 `3.0.0`），或断点 `task.json` 里的 `budget_usd` / `requests` 不是数时，
`probe` / `collect` / `enrich` 都以**退出码 2** 结束，一次请求都不发 —— 闸门是一句比大小，
比不了就等于没有闸门。把 stderr 的原话报给用户（它会指名是哪个值、从哪来），**不要自己猜一个数替他填**。

选 2 就带着已有数据进 Phase 04。选 3 就调低目标后续跑。

用户看完报告后说「人不够，再多找点」也走同一条路 —— `--resume` 在 render 之后重入是安全的，
已采集的人不会丢（累加器 `creators.raw.json` 与交付物 `creators.json` 是两个文件）。

⚠️ **续跑会不会再发关键词搜索，看 stderr 那句话，不要自己推。**
它取决于**续跑那一刻 `qualified()` 还够不够目标**，而那个数会变 ——
达标判断用的是**补全之前**的粉丝数（未知一律放行，P1），
而 `enrichProfiles()` 跑在采集循环**之后**、把真实粉丝数写回累加器。
被闸门筛掉的人一多，`qualified()` 就掉回目标以下，续跑照常从第 0 个任务开始搜。
还有第二个理由：**一页都没抓过的任务不受达标判断约束**（F9），达标之后续跑照样会去抓它们。
**所以「以达标停下」既不意味着续跑一定不搜，也不意味着一定搜。**
实测：IG 三个词在前、粉丝数补全后全被闸门筛掉，`stopped=target` 而 `collected=0`，
原样 `--resume`（目标一字未改）把后面两个 TikTok 词整词补了回来。

**这也不等于续跑免费**：待补 profile 的人照样会被补，而那是付费端点。
两件事的口径都在下面「续跑要不要花钱」那一段 —— **照 stderr 说的转述，别自己下结论**：
那句话每次都按当时的两个剩余量重算过（`resumeCostLine`）。

所以用户说「人不够，再多找点」时：**先跑一次 `--resume` 看 stderr 怎么说**。
它说还有关键词要跑，那就是这条路走得通；说不产生新请求，才轮到考虑重新 `--config` ——
而那会把已经花掉的请求再付一遍，**先把这个代价说给用户，再问他要不要重跑**（ADR-94）。

**预算用尽停下时同理**，只是多一层：续跑从第 0 个任务按 task.json 的顺序重新排队，
排在前面那些词若还有下一页，会先被翻掉；若它们已经跑完（IG 一词只有一页，抓过就进 `done`），
续跑的第一个请求就落在被跳过的词上。**这一层也不要自己推**，同样照 stderr。
顺序仍然决定谁**先**被查到；**达标收尾时**它不再决定谁被**砍掉**（Phase 03 那条 ✅），**但预算先用尽时它决定** —— 排在后面的任务可能一个请求都没发出去。

## 跨任务记忆

每次任务结束后写入 `memory/creators.json`。开始新任务时先读，**已推荐过的人默认不再进新名单**。
但**同一个任务自己上一轮的推荐不算**，否则续跑会把自己的产出判成「已推荐过」而滤成空名单。

`collect.ts` 以**退出码 2** 结束且 stderr 提到 `memory/creators.json` 时，表示那个文件读不出来 ——
**停下来。不要重跑，不要拿旧名单往下走，也不要自己找路绕过它。**
采集结果和已花的预算都完好，把 stderr 的原话报给用户（它会说是哪个人的哪个字段不对），
让用户修好文件后按 stderr 给出的那条命令 `--resume`（预算用尽时那条命令会带上 `--budget`）。

stderr 还会给出另一条路：加 `--ignore-memory` 强出名单。**不要自己加。** 强出名单是用户的取舍，
不是你的 —— 他明确要求时才加，并按 `references/memory.md` 把代价说清。

**续跑要不要花钱，照 stderr 说的转述，不要自己下结论**：剩余关键词**和**
待补 profile 都为零才是零请求 —— profile 补全跑在续跑最前面，它是付费端点。
任一不为零就会继续花钱。把「已抓到的不会重抓」说成「续跑免费」，
用户会按错误的预算做决定（ADR-22 · ADR-25）。

详见 `references/memory.md`。

## 不做什么

| 不做 | 原因 |
|------|------|
| **实际发送邮件**（S1） | 送达率、SPF/DKIM、退信处理是另一个量级的复杂度，且必须用用户自己的邮箱服务。产出草稿，发信交给用户现有工具 |
| 多语言开发信（S2） | 首版仅英语 |
| 主动索要效果回填（S3） | 用户回填成功率太低。`contacted` 由用户手动标记 |
| 中国大陆平台（S4） | 本 Skill 定位出海 |
| CRM / 付款 / 寄样 / 归因（S5） | 超出 Skill 形态 |
