## 接入后只对 A 级做

**不要对全量做增强。**

| 方案 | 人数 | 成本 |
|------|------|------|
| 采集（TikHub） | 500 | ≈ $0.5 |
| 全量增强 | 500 | ≈ $75–115 |
| **只增强 A 级** | **50** | **≈ $8–12** |

后者覆盖了几乎全部决策价值。A 级本来就是"准备直接发信"的那批，验证邮箱和受众正是发信前该做的最后一道确认。B/C 级还没到发信阶段，增强了也用不上。

增强消耗要计入成本闸门，按 1 credit ≈ $0.15–0.23 估算。

## 计划接入的契约

按 `_interface.md` 的 `enrich` 契约实现，返回：

```ts
{
  email?:               string | null
  email_verified?:      boolean
  audience_geo?:        Record<string, number>   // { US: 0.62, GB: 0.11 }
  fake_follower_score?: number
}
```

拿到 `audience_geo` 后应用 `semantic-fit.md` 里的降权规则：

```
目标市场占比 < 30%  →  降一级（A→B）
目标市场占比 < 15%  →  排除
```

`fake_follower_score` 过高的直接排除，阈值按供应商的量纲定 —— 首次使用时先看几个样本再定，不要拍。

## 当前行为与未来降级要求

当前没有增强适配器，因此每次任务都按未增强状态交付。未来接入后，未配置 key 时仍必须：

- **跳过 Phase 05**，直接进 Phase 06
- 邮箱退化为 bio 正则提取（命中率约 46%，未经验证）
- 受众降权规则不生效，在交付说明里注明这一点
- **提一次可以补什么就够了，不要反复推销**

交付时如实说明：

> "邮箱来自 bio 提取，未做有效性验证，建议首轮小批量试发观察退信率。
> 受众地域数据缺失，无法确认这批人的粉丝是否在目标市场。"

这句话很重要 —— 让用户知道名单的边界在哪，比假装数据很完整强。
