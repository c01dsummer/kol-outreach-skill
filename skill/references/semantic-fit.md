# 语义契合判断与分层

> 相关需求：**F4**（必须输出理由）· **F6**（明确语义判断的基础分层）· **D21**（Agent 正本、平台独立证据与当前状态）· **D22**（冻结候选与来源）· **D25/U9**（有效建议及交付）· **P1**（未知不得当作 0）

Phase 04 用。这是整个 Skill 最不可替代的一步。

## 分工：什么归规则，什么归判断

| 类型 | 例子 | 归谁 |
|------|------|------|
| 客观、可量化 | 粉丝区间、发帖数、有无邮箱、bio 含商务合作信号 | **规则算分** |
| 主观、需理解 | 已见内容能否自然植入、是否有原创表达、有无品类冲突 | **你判断** |

前一版的错误是用 `bio.includes('juicer')` 这种字符串匹配去近似"内容相关性"。那是规则最不擅长、你最擅长的地方。**不要重复这个错误。**

## 第一步：硬指标算分（规则）

```
有邮箱                      +30
粉丝量在目标区间内          +20
来自竞品词搜索              +15
发帖数 > 30（内容积累）     +10
来自场景词搜索              +10
bio 含商务合作信号          +10
最佳内容播放量 > 100k       +5
跨平台同人（TikTok + IG）   +15
```

商务合作信号正则：

```
/\b(pr|collab|business|partner|brand|sponsor|inquiry|ugc|creator|media\s?kit|工作|合作|商务)\b/i
```

粉丝数是准入门槛；发帖数只代表历史内容积累，不代表当前仍在更新：

| 规则 | 当前处理 | 说明 |
|------|----------|------|
| 粉丝数 < 5,000 | 排除 | 互动数据噪声较大 |
| 粉丝数 > 5,000,000 | 排除 | 基本走 MCN，个人建联无效 |
| 发帖数 > 30 | 加 10 分 | 内容积累较多；不足或未知都不直接排除 |

当前是否活跃由主页样本的 `activity_status` 单独展示，固定采用 45/90 天口径；它不进入
score 或分层。累计作品很多但已经停更的账号仍保留，只提示运营先确认合作状态。

粉丝数未知时放行并标明“未查询”，不能当成 0。当前上下限由实现固定；若小众品类需要调整，必须同步修改需求、实现和验证。

## 第二步：语义判断（你来）

对每个候选，读 `bio` + 实际取得的作品证据，回答一个问题：

> **这个人适合推这个产品吗？为什么？**

把判断保存到 `agent-review.json` 的对应平台账号评审中，兼容 `fit` 和可读 `fit_reason` 仍明确保存。分别给出合格性与采用建议，并交代观察到的内容、作品证据来自搜索命中还是另取的主页样本、产品可能进入内容的方式及主要待核问题。没看到的部分直说未核实，不用分数或账号名替代内容判断。

`recent_posts` 装的是搜索命中的作品，不是主页最近作品清单。样本受关键词筛选，
只能描述本次实际读到的内容，不能称为「最近十条」或据此断言账号近期作品的构成。
搜索命中会按平台内作品 id 合并，缺 id 的旧记录或新记录仍逐条保留（D11）。因此条目数
不一定是不同作品数；相同文案且无可靠 id 时，不能仅凭重复出现就认定作者发了多条重复作品。

**没有 `recent_posts`（字段缺席，或是个空数组）= 本次搜索命中作品未查询，不是他没作品**（P1）。
IG 按账号名搜人的那条兜底路径拿不到作品，旧任务目录里它还凭空写过空数组（ADR-102）。
若也没有另取的主页作品证据，只凭 `bio` 判断，理由里写明「作品未查询」；下面第 2、3 条判不了就说判不了 ——
**不要因为看不到作品就判成非原创、判 ❌**；只能写出 bio 提供的线索及仍需核实的内容。

### 判断保存在哪里

`agent-review.json` 是 Agent 判断的唯一正本，`creators.json` 是脚本据此重建的交付投影。读取已有正本后，只更新对应 `reviews["平台:账号"]`，保留文档 `version: 1`、其他评审、已有合法 `account_keys` 别名，以及 `rounds` 中的轮次、候选、来源和时间。主键及别名按既有平台账号契约规范化；别名须含自身键，同平台别名不重复、不被两条评审争用，不把另一平台账号写成别名。

| 正本评审字段 | 写什么 |
|---|---|
| `eligibility` | 合格／不合格／待核实：内容与创作者身份是否适合本轮合作 |
| `adoption_priority` | 优先联系／备选／待核实／暂不采用：本轮实际采用建议 |
| `observed_content` | 实际读到的内容；观察范围未知就明说 |
| `work_evidence` | 实际作品证据及来源；没有作品时明确未查询，不拿发现路径代填 |
| `natural_integration` | 当前产品怎样自然进入已有内容；缺具体场景时不得建议优先联系 |
| `mismatch_risk` | 最大风险或未核问题；没看画面或评论就明确这一边界 |
| `fit` / `fit_reason` | 明确保存兼容态度与理由，不让脚本从新判断推导 fit |
| `brand_calibration_version` | 实际使用的任务校准版本；任务没有校准输入时保持缺席 |
| `outreach_draft` | 有资格写草稿时保存英文原文，未知产品信息仍用占位符 |

两平台分别判断、分别保存自身证据，不能把一平台的已评状态或结论复制到另一平台。完成一次评审时，更新正本 `updated_at`，可保存该条实际 `reviewed_at`；不为了通过校验编造证据、版本或历史时间。脚本根据正本与当前任务品牌版本投影已评／未评／待重评，Agent 不把状态写进正本替代实际重评。

只有正本路径确认缺席时，脚本才迁入旧名单中实际保存的 `fit`、理由和草稿；已有空正本也有权威性，不能借旧投影复活被删评审。Agent 不改采集原件或 `manual-feedback.csv`，人工空白和 unknown 保持各自含义；新增候选的轮次与来源由脚本冻结，不自行重划轮次或补历史来源。

### 判断维度

**1. 内容方向是否真的相关**

不是"提到过关键词"就等于"持续在做这个方向的内容"。一条搜索命中作品提到充电宝的旅行博主 ≠ 数码测评博主，但可能有自然的旅行使用场景。只有实际取得足够的主页作品证据，才能描述近期内容构成；搜索命中样本不能代替它。

**2. 是否有原创或个人表达的证据**

转载合集、重复模板、纯剪辑账号可能缺少适合合作的原创内容。看实际取得的作品是否有个人口吻、创作过程、转载标记等线索。**不露脸本身不是否决信号**：原创手帐、手作、画画或穿搭细节同样可能有自然植入场景。没看画面时，不能从文案推断出镜情况、画面审美或作品一定原创。

**3. 有无品类冲突**

最容易被忽略也最伤的一条。健身博主在本次搜索命中的作品里推广某款代餐，可能与蛋白粉存在品类冲突。写明实际见到的作品及品牌，建议确认合作情况；不能把命中样本说成他的全部近期内容。

**4. 内容语言与沟通可行性**

开发信只写英语。作品文案的语言可提示如何沟通，不能证明受众所在地区或回复率。创作者资料中的所在地只说明创作者所在地，也不能代替受众所在地；受众地域应依据有来源与时间的 `audience_geo`，没有则标为未知。

**5. 商业化程度**

没看到合作作品时，合作经验未知；本次实际读到多条广告作品时，可提示商业化密度风险，但搜索命中样本不能冒充完整近期主页。没读评论就不能判断评论真实性，也不能只凭点赞或评论数作这种判断。公开互动只作辅助：高互动不能挽救内容不匹配，低互动也不自动淘汰内容适合的账号。

**6. 品牌校准（任务有 `brand_calibration` 时）**

校准只说明本项目想找什么样的人：目标创作者类型、语气审美、自然使用场景和负面信号。对照已见内容写出吻合或不吻合的具体之处；没看画面时审美留作待核实。`kind=brand_preference` 的条目是偏好，不能当作产品功能写进理由或草稿；只有 `kind=verified_product_fact` 的条目才可当作产品事实。校准是本项目的补充输入，不替代上面五条，也不成为其他品牌的筛除规则。没有校准输入时照常判断，`brand_calibration_version` 保持缺席。

### 输出格式

用三档态度，理由要具体到看得出你真的读了：

```
✅ 本次搜索命中的作品文案描述 5 分钟早餐制作与本人演示 —— 厨房有自然使用场景；画面尚未核实
⚠️ 本次搜索命中的文案均提到某品牌充电宝，合作关系尚未核实 —— 建议先确认档期
❌ bio 标明是食谱聚合账号，本次读到的搜索条目均标注转载其他作者 —— 本轮不按原创创作者推荐
```

**反模式**：
- "内容相关，推荐合作" —— 没信息量，看不出你读过
- "该创作者的内容调性与贵产品高度契合" —— 套话
- 只给分数不给理由 —— 运营无法判断要不要信你

## 第三步：基础分层

分层的意义是**对应不同的建联动作**，不是给个好看的标签。

| 层级 | 条件 | 建议动作 |
|------|------|----------|
| **A** | 不为待重评，有非空邮箱且明确 fit=✅ | 准备个性化开发信草稿；邮箱有效性仍按原数据边界声明 |
| **B** | 待重评（优先于原 fit），或 fit 缺席 | 待重评先重做判断，缺判断先核实；不凭硬指标分数推荐发信 |
| **B** | 不为待重评，明确 fit=✅ 但邮箱缺席、null 或空串；或明确 fit=⚠️ | 核实联系方式或未确认的问题，再决定建联方式 |
| **C** | 不为待重评且明确 fit=❌ | 存入观察池，下次任务复用 |

**基础分层不按分数切。** 非待重评的 65 分账号若明确 fit=❌（比如高粉丝、有邮箱、但已见内容有明确品类冲突），仍为 C。待重评先为 B，保留原判断，不能继续把旧 ✅ 当作当前可发信依据，也不能把旧 ❌ 当作当前已核实的否定。

反过来，一个 45 分但语义强相关、只是缺邮箱的，应该进 B 而不是 C —— 他值得你花时间去站内私信。

新评审状态与兼容 fit 分开：仅有 legacy 明确 fit 的账号仍标未评，但不等于没有语义判断，非待重评时按上表的明确 fit 与邮箱规则分层；不据此补造新合格性或采用建议。缺 fit 时，eligibility、adoption_priority、关联平台判断或人工结论都不能代填它。三个命令按正本与任务当前品牌版本重建状态；版本不一致保留原判断并标待重评，须实际重新评审，不能只改版本号让历史建议变成当前建议。

上表只决定基础层级。随后仍按既有顺序执行受众地域规则与公开风险降级；基础 B 可被降为 C，地域占比低于 15% 仍可剔除。硬指标权重与粉丝闸门不变；交付排序先按当前有效采用建议，再按原层级、分数与同分规则，人工采用不改层级或越过 memory 过滤。

## 受众地域降权

未来有通过准入的外部来源并取得 `audience_geo` 时：

```
目标市场占比 < 30%  →  降一级（A→B, B→C）
目标市场占比 < 15%  →  排除
```

没有 `audience_geo` 时，受众地域为未知，不能用 `recent_posts[].desc` 的语言代算比例或触发地域降权。可以单独说明文案语言可能影响沟通；英语内容的受众未必在英语区，反之亦然。

## 公开信号风险降级（F8）

运行 `scripts/enrich.ts` 后，当前平台的 `audience_quality_risk=high` 才降一级：

```text
A → B
B → C
C → C
```

它发生在基础分层和受众地域规则之后，必须把 `A→B` / `B→C` 与触发理由写进
`tier_adjustments`。**不删除账号，不修改 score，也不把它叫作假粉率。**

`medium`、`low`、`unknown` 都不改变分层。关联账号的风险只展示，不影响当前行；
两个平台的互动率和播放量不能混算。具体信号与同行样本门槛见 `public-metrics.md`。
